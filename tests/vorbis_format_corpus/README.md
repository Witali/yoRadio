# Public raw Vorbis format corpus generators

These Python stdlib generators construct finite, complete public Vorbis
packets. They do not execute a codec, synthesize PCM, or run an SDK, compiler,
emulator or physical board. Their internal checks cover field/token parsing,
packet accounting, Ogg framing and CRC. Generated qualification fields remain
pending until a separate campaign binds the actual generated bytes to its
reference and target results.

`generate_books.py` produces eight stereo/192000 Hz codebook cases with short/long
blocks 256/2048. The cases cover ordered zero-count length groups, unordered dense
and sparse lengths, original entry indices, lookup1/lookup2, vector dimensions
2/4 and sequence accumulation 0/1. Every active entry and both scalar classbook
entries are used. Each case has 14 complete audio packets, 7040 overlap frames per
channel and 28160 expected PCM16 bytes. Floor1 and residue1 are retained.

`generate_floor0.py` produces nine stereo/48000 Hz cases: floor1/residue0 control,
even-order floor0/residue0, and odd-order floor0/residue0, each with block pairs
64/256, 256/2048 and 64/2048. Floor0 covers increasing dyadic LSP vectors,
multi-vector accumulation, one/two floor books, both selector values, and an
unused final LSP scalar. Residue0 retains its dimension2/interleave-step8 layout.
Each case has 14 complete audio packets. Packet metadata records the exact
per-packet overlap frames and expected PCM sizes.

`generate_mono_mapping.py` produces 21 cases: mono and stereo at each of nine
advertised rates (8000 through 48000 Hz), plus stereo coupling with all four
sign quadrants, two submaps with swapped channel mux, and bundled residue2.
Blocks remain 256/2048. All 294 packets produce 464640 expected PCM16 bytes.

`generate_floor_presence.py` adds the separate [39-case floor1 presence
supplement](../vorbis_floor_presence/README.md), including residue0/1/2,
coupling, explicit silence witnesses and packet-to-packet presence changes.
Its README gives the required explicit fresh-output and control-test commands.

`generate_floor1_positions.py` adds 14 floor1 setup cases: eight legal position
lists, including 65 total positions and unsorted/wide coordinates, and six
explicit duplicate/count rejection controls. Vorbis I section 7.2.2 requires
at most 65 total X positions and unique coordinates. All cases retain the same
two books, stereo/48000 Hz, 256/2048 blocks and 14 minimal audio packets;
subbook -1 makes interior Y values implicit, requiring no extra packet bits.
`fixture.h` exports payload-only identification/setup arrays, complete audio,
case validity and per-packet overlap arithmetic (28160 PCM bytes per valid
case). Full/raw headers, fields, coordinates, dimensions, carriers and hashes
remain in the manifest/matrix output. Invalid carriers are rejection inputs,
not decodable streams. Construction tests do not qualify decoder rejection,
PCM, target Ogg handling or the existing numerical NONPASS results.

`generate_map2_regression.py` produces eight stereo/192000 Hz cases. Four pairs
compare sparse lookup2 vectors of dimension16 against dense active rows, or a
mapped single-entry book against two identical dense rows, with sequence0/1.
The single-entry audio uses both one-bit values, as specified by Vorbis
Errata20150226. All 112 packets produce 225280 expected PCM16 bytes. Expected
within-decoder PCM equalities are metadata until actual PCM is compared.

All generators retain `SSLLLSLSSSLLSS`, all four short/long transitions and all
long-window neighbor flags. They emit full identification/comment/setup headers,
concatenated full audio packets with offsets, field audits, matrix metadata and
one-packet-per-page reference Ogg carriers with natural granules/EOS. These
carriers support separate host reference checks; they do not qualify target Ogg
handling. The raw target API may require stripping only the seven-byte setup
prefix; identification and audio packets remain complete.

## Reproduce construction

From any working directory, invoke the scripts by their checkout paths. From the
repository root, the default create-only commands are:

```powershell
python -B tests/vorbis_format_corpus/generate_books.py
python -B tests/vorbis_format_corpus/test_books.py
python -B tests/vorbis_format_corpus/generate_floor0.py
python -B tests/vorbis_format_corpus/generate_mono_mapping.py
python -B tests/vorbis_format_corpus/generate_map2_regression.py
python -B tests/vorbis_format_corpus/generate_floor1_positions.py
python -B tests/test-vorbis-floor1-positions.py
```

Defaults are this checkout's `.build/vorbis-books-corpus-01`,
`.build/vorbis-floor0-corpus-01`, `.build/vorbis-mono-mapping-corpus-01` and
`.build/vorbis-map2-regression-corpus-01`; floor1 positions defaults to
`.build/vorbis-floor1-positions-corpus-01`. Existing outputs are rejected. To choose a fresh
output beneath this checkout's `.build`, use `--output`; pass the corresponding
books directory to `test_books.py --data`. Relative arguments resolve from the
calling working directory. Parents are created only after the guard has accepted
the resolved output. An output outside the checkout's `.build`, its root, an
existing path, or a symlink escape is rejected. Do not use Python's `-O`: the
unchanged construction checks include assertions.

Each generator explicitly imports the existing
`tests/vorbis_block_matrix/generate_minimal.py` by checkout-relative file path
after checking its exact SHA256:
`8e3eff3fbe08f24399dd74c5ca449eb7ead0fe0f27e464f6d8314e7fbcaf64f1`
(17559 bytes). Only its definitions execute; its guarded main/generation is never
called. There is no copied helper, import search fallback, historical input
directory or mutable decoder setup source dependency. The eight methods in
`test_books.py` are the unchanged original construction tests; they perform no
reference decoding or PCM synthesis.

## Source adaptation and qualification limits

The canonical-path adaptation changes imports, provenance, output guards and CLI
only. All book/floor/residue/audio/CRC algorithms and fixture source payloads are
unchanged from the frozen construction sources. The [completed reproduction](../results/vorbis-format-generators-20261020/README.md)
ran both canonical generators and all eight construction tests. All 100
nonmanifest files across the 17 cases match the original corpora byte for byte.
The observed generated differences are limited to the two `manifest.json` files:
generator source hashes change in both;
floor0 replaces the old `inputs_sha256` field with
`source_references_sha256`, binding the adjacent `source_references.json`.
All other generated file bytes match. CLI output paths and reported
manifest hashes naturally change. The adjacent provenance file records the
canonical helper pin and public source identities without an absolute setup
source path.

The root-owned historical host campaign qualified all 17 original cases with
Xiph. Its FFmpeg native result remains **NONPASS: 7 accepted, 10 lookup2
refusals**. This adaptation does not turn that result into a dual-reference pass
or claim new target execution. These finite valid-input cases do not establish
complete Vorbis/G6 conformance, radio behavior, EOF/reset/OOM handling, physical
audio or support for unrelated codecs.

## Primary source basis

The [Vorbis I specification](https://xiph.org/vorbis/doc/Vorbis_I_spec.html)
provides book/Huffman/lookup rules in sections 3.2.1/3.3, packet/overlap rules in
4.3, floor0 rules in 6.2.1–6.2.3, residue rules in 8.6.1–8.6.3, and the related
setup and vector details in 4.2.4, 9.2.2 and appendix A. Public Xiph v1.3.7
source was reviewed for these specific operations:

- [sharedbook.c](https://github.com/xiph/vorbis/blob/v1.3.7/lib/sharedbook.c):
  `_make_words` and `_book_unquantize`.
- [floor0.c](https://raw.githubusercontent.com/xiph/vorbis/v1.3.7/lib/floor0.c):
  `floor0_unpack`, `floor0_inverse1` and `floor0_inverse2`.
- [lsp.c](https://raw.githubusercontent.com/xiph/vorbis/v1.3.7/lib/lsp.c):
  increasing-angle LSP and curve source review.
- [codebook.c](https://raw.githubusercontent.com/xiph/vorbis/v1.3.7/lib/codebook.c):
  `decodev_set` and `decodevs_add`.
- [res0.c](https://raw.githubusercontent.com/xiph/vorbis/v1.3.7/lib/res0.c):
  `res0_inverse` and `_01inverse`.

No Xiph implementation source was copied. These URL identities preserve the
original source basis; web source bytes were not snapshotted or given fabricated
raw hashes.
