# Isolated Xiph resource-port evaluation

This fixture builds native_vorbis_xiph_port beside the frozen upstream
native_vorbis_xiph component. The latter remains an immutable source input.
The port generator applies eight reviewed exact fragments to block.c,
sharedbook.c and libogg bitwise.c. PORTING.json records every generated byte
identity and22 compiled units: three ported files and19 unchanged files.
The original31 raw caller, packet metadata and nearest-even PCM16 conversion
are copied unchanged from the baseline fixture.

The coordinator uses core0; the worker uses core1, priority3/stack16384.
Arena, codebook and bit-reader tests run before the31 original public cases.
Allocator hooks are forced into library compilation only. The hook implementation,
resource tests and caller are separate fixture sources; host.c is excluded.
The ledger must report zero live allocations and bytes before/after resource
tests, after every public case closes, and before final completion. Records
use PORT_RESOURCE so the pinned baseline reader can replay the original PCM
protocol unchanged. Numerical comparison remains a separate gate.

The arena test covers11 optional-consolidation scenarios. Codebook tests include
the dense4096-entry case, sparse/singleton/empty and zero-dimension scalar books,
lookup types and allocation failures. Bit-reader tests cover both bit orders,
unaligned widths, signed-shift corrections and truncation. These finite tests
do not qualify every decoder allocation failure, arbitrary setup memory use,
or a complete maximum stack bound. Ordinary block-arena allocation/callers
remain outside the optional-consolidation repair.

Use the unchanged prepared31-case corpus. Activate the pinned ESP-IDF6.0.2
shell, set XIPH_PORT_QEMU and XIPH_PORT_ROM, and select a fresh campaign:

```powershell
$cases = (Resolve-Path .build/vorbis-xiph-prep-20261025-01).Path
$nativeArgs = @('--target','esp32','--output','.build/xiph-port-esp32-user-01','--cases',$cases,'--idf',$env:IDF_PATH,'--idf-tools',$env:IDF_TOOLS_PATH,'--powershell',(Get-Command pwsh).Source,'--sdk-python',(Join-Path $env:IDF_PYTHON_ENV_PATH 'Scripts/python.exe'),'--qemu',$env:XIPH_PORT_QEMU,'--rom',$env:XIPH_PORT_ROM)
$pins = @{ 'base-manifest'='idf/components/native_vorbis_xiph/component-manifest.json'; 'port-manifest'='idf/components/native_vorbis_xiph_port/port-manifest.json'; cases=(Join-Path $cases 'cases.json'); 'cases-header'=(Join-Path $cases 'cases.h'); qemu=$env:XIPH_PORT_QEMU }
foreach ($key in $pins.Keys) { $nativeArgs += @("--$key-sha256",(Get-FileHash -Algorithm SHA256 $pins[$key]).Hash.ToLowerInvariant()) }
python -B -X utf8 tests/run-vorbis-xiph-port-qemu.py @nativeArgs
```

Pure resource-record and generated-source binding checks are available through
`python -B -X utf8 tests/test-vorbis-xiph-port-protocol.py`. The capture reader
binds the measured host counts: arena11, codebook200864 and bit-reader124754.

The controller freezes both sibling components, original reader provenance,
six test helpers and exact data. It independently replays the declared fragment
replacements, verifies actual generated/base and generated/ported bytes, then
binds PORTING.json to native compile rows, dependencies, symbols and22 .su files.
All nine owned commands retain normal terminal receipts and logs; failed
attempts remain separate. CHECKED_XIPH_PORT_CAPTURED means completed capture
and focused resource assertions, not numerical qualification.

The library allocation ledger excludes adapter input buffers, which retain
their original canary/immutability checks. Heap minima and task high-water
observations are cumulative and include the preceding resource tests. Compiler
frames are individual estimates. QEMU measurements do not establish physical
timing, audio continuity, whole-decoder OOM safety or board acceptance. C3,
production integration and deferred container/reset work remain outside scope.
