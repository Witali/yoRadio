## Exact finite inputs and expectations

order. They are separate12 cases with six original/equivalent pairs; none is
substituted or dropped. ID headers establish each owned vi/ci rate, channels
and short/long context. The own `ci.books` equals the actual full setup book
count,3 for even6 and4 for odd5. No vendor or unrelated book allocation is used.

The bit reader begins at the **absolute** `floor0.order` bit offset in each
full original raw setup, and stops immediately after its book list. The six
fixed-width fields occupy58 bits; one/two8-bit book indices make66/74 bits.
Source assembly checks the metadata/raw bitspan, while the separate reviewed
bounded `fixture_reader.py` derives the offset independently by walking the
actual preceding setup signature/codebooks/time/floor syntax. It does not
derive those boundaries solely from construction metadata. Its mandatory
contract check runs before any future SDK action. It computes no LSP curve,
vectors, residue, synthesis or PCM.

Expected publications include exact order/rate/Bark/ampbits/ampdB/book-count
and every book index with bounds. Original/equivalent publication fields and
raw floor spans must match. The model deliberately records the independent
reader as pending at source assembly; future execution records a separate
actual witness without rewriting the frozen contract.

`project/main/unit_support.h` reuses the exact bounded reader, tracked zeroed
allocator, guards and normal-free seams extracted from the previously reviewed
owned-book unit. They are ordinary included test support, not parser macros.
The unit owns its vi and ci and requires both complete object representations

The finite native protocol has32 events: BEGIN,12 FIELDS+CASE records,6 PAIR

control is introduced.
