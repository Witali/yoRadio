# Target scope and retained evidence

The original fixture uses actual pinned ESP-IDF6.0.2 SDK, Xtensa ELF32LE machine94,
public mbedTLS config/defaults/setup/reset/free, public certificate provider,
canonical registry/reclaim and adaptive queue. It executes on no-NIC two-core
QEMU with assertions enabled, static/internal TLS RX16384/TX4096, dynamic/custom
allocation disabled and ordinary SDK free pairing. No record or task profiles
are tuned by archiving.

Enabled positive runs check pointer/numeric userdata without registry userdata
accesses, config init/free revocation and live RX across config-free/address
reuse, full8-entry soft fallback, actual esp_timer ISR initializer, two-core
ownership/erase handover, pre-RX public validation error and four scoped rollback
injections. Separate fixture heap pressure observes real SDK allocator NULL and
reserved RX survival, plus actual reclaim recovery when enabled. Fixture-owned
pressure memory is released before diagnostics/restart; a later panic invalidates
the outcome. This does not constitute a TLS handshake or physical memory result.

Eight exact controls must stop at their named predicates. Forget-loan and erase
publication controls are phase-scoped and retain that metadata. Reserve-disabled
profiles compile original SDK TLS source with no reserve module/static slot/RX
diagnostic wrappers and run16 ordinary public setup/reset/free cycles. All four
reserve/reclaim combinations have separate actual builds/configs/ELF identities.

Raw source manifests, sources, execution bundles and compiled header closure are
retained, alongside full command logs and selected actual build metadata. Offline
checks reconstruct exact declared source mutations and SDK overlay, verify
per-option actual source selections/link wraps/configs, raw SDK19 guards, nm and
disassembly calls, original child terminal status/timeout flags, SDK commit/clean
logs and unique runtime oracles. Parent runner completion additionally requires
the root-authored final terminal0 receipt and exact report SHA.

ELFs/application/bootloader/partition/merged flash images, archives, objects, ROMs
and tool executables are omitted by original identity. Derived allocator words
and flash-component ranges were read from original binaries at packaging and
record their original hashes. Offline replay checks these metadata/log bindings;
it cannot independently prove omitted binary contents or recreate a build.

The fixture is not the production audio-service or complete firmware. Whole
service cancellation/binding, canonical lint/application profiles, physical
protocol/resources/fragmentation/playback/usefulness and the default decision
remain separate gates. The original report's pending list is retained raw. Old
partial/nonpassing pointer prototype results are not relabelled. No deferred
codec, network/device operation or new test/build is performed by this archive.

Disabled capacity has its own unique marker: content16384, storage at least full
content, allocated_min at least storage, setups32. The public getter limit is
derived separately from actual MFL configuration (min(IN,OUT) when enabled, IN
otherwise). Getter4096 in this profile is not evidence of a 4096-byte RX buffer.
The old rxt01 predicate confused these values, remains terminal1/nonpass and is
preserved only in a bounded historical section, without requalifying other old
references or importing any old runtime artifacts into the new full gate.
