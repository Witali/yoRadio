## Controller result and PCM retention

On a later real zero-exit, uninterrupted, complete native protocol, the controller removes raw byte values from the validator result before assigning any result to JSON. It writes exactly17 create-only files under `observed-pcm/`, confirms their byte content/hash/length/packet offsets, and reports paths, case/source IDs, byte counts, hashes and offsets. PCM is never stringified, replaced by a checksum alone, or dropped. The full original stdout/stderr containing PCM_HEX is retained too. The final file set, all inputs/tools, frozen candidate/configuration and image bytes are checked before completion.

A successful capture is `RAW_CORPUS_PCM_CAPTURED`, `completed=true`, `target_capture_completed=true`, `vendor_checked_pcm_equal=true`. The general `passed` flag remains false. `independent_reference_compared`, `numeric_reference_qualified`, `format_corpus_qualified` and fullG6 remain false. Root must separately read these actual PCM files, bind the Xiph WAVs and apply an explicit measured numerical comparison policy. Same-vendor byte equality alone cannot establish that comparison. No tolerance or numerical PASS is invented here.

Any SDK error, nonzero process exit, timeout, interruption, panic, missing/duplicate/reordered event, byte/metadata/canary/count mismatch or changed input remains NONPASS with available logs/partial artifacts retained. Timeout alone never means success.

## Root-owned launch and retained infrastructure

After review, materialization and the separately owned rate qualification, root may launch from this checkout with a fresh campaign, the pinned host Python and explicit installed tool paths where defaults are unavailable:

```powershell
python -B .build/cyd-vorbis-format-corpus-sdk-prep-01/run-cyd-vorbis-format-corpus-qemu.py --output .build/cyd-vorbis-format-corpus-capture-01 --contract .build/cyd-vorbis-format-corpus-target-prep-01/contract.json --contract-sha256 6c95b8d52a7bd5a3ca8e2d1b519f5d0ec3172e7e76e83ade8c1e78d364fdd391 --data-header <reviewed-data.h> --data-sha256 <reviewed-header-SHA256>
```

This is a proposed invocation, not a recorded run. `--candidate` defaults to canonical `idf/esp32-cyd2usb-native/main` and must stay under the repository. Options `--idf`, `--idf-tools`, `--codec`, `--qemu`, `--powershell` retain the audited minimal controller defaults. A fresh campaign stores all actual source/tool/command provenance and owned terminal facts.

`set(COMPONENTS main)` remains before project include. The project has one public caller and the frozen candidate compiles only canonical setup.c/output.c with its ABI. The raw-only helper replaces only the helper in that frozen copy, wrapping raw open/decode; canonical source/helper bytes are untouched. There are no test source mutants. SDK6.0.2 HEAD/clean checks, both audited archive identities, source/public-header/runtime/ROM snapshots, pre-build compiler/nm identities, ELF94/public symbols and exactly one caller + two bridge compile rows remain required.

The actual setup compilation row is used for the macro probe with the original six-line generated @cflags preserved, its exact reviewed flags/quoted specs path and picolibc.specs frozen before/after. This is public raw format/capture scope only. It establishes no hardware/audio/radio/network, target Ogg/EOF/reset/ownership, allocator failure/OOM, AAC, private decoder-state or complete Vorbis conformance result. C3/RV32 requires its own later source/tool/target qualification.
