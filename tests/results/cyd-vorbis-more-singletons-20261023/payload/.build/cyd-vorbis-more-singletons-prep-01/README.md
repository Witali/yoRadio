# Additive singleton corpus: source-only preparation

This preparation supplies eight finite complete raw Vorbis candidates and an
independent construction witness. Nothing here has been generated, tested,
decoded, compiled or run on a target during preparation. Canonical generators,
production sources, prior campaigns, archives and Git remain unchanged.

| Candidate IDs (each has seq0 and seq1) | Declared lengths | Sole original index | Lookup values |
| --- | --- | --- | --- |
| map2_sparse_single_d4_seq{0,1} | [0,0,1,0] | 2 | All four original rows, four coordinates each |
| map2_sparse_single_d16_seq{0,1} | [0,0,1,0] | 2 | All four original rows, sixteen coordinates each |
| map1_dense_single_d16_seq{0,1} | [1] | 0 | One declared lattice scalar; lookup1_values is 1 |
| map1_sparse_single_d16_seq{0,1} | [0,0,0,0,1,0] | 4 | One declared lattice scalar; lookup1_values is 1 |

All have two channels, 192000 Hz, blocks 256/2048, floor1 with zero partitions,
rangebits10, both floor endpoints255, uncoupled mapping0, residue0 range0..16,
partition size16, and two scalar classifications using the same vector book.
The fourteen modes are SSLLLSLSSSLLSS. They cover SS/SL/LS/LL transitions and all
four long-window neighbor states. Complete identification, comment and setup
headers accompany concatenated raw audio plus fifteen packet offsets. Each
reference.ogg has seventeen independent complete-packet pages, exact cumulative
granules and BOS/EOS flags. Container construction is bounded to this finite
one-packet-per-page profile; it does not extend the production Ogg implementation.

Errata20150226 explicitly includes both dense and sparse singleton codebooks.
The single active codeword must have length1 and consumes one bit, returning the
sole used original entry for either bit value. The generator deliberately
alternates0/1 to exercise decoder tolerance. The specification recommends that
encoders write0, so the bit1 tokens are explicitly tolerance cases, not examples
of the preferred encoder representation. See PUBLIC-SOURCES.md for primary
references. No unresolved normative assumption is hidden in these eight cases.

The original map2 index2 row differs from the unused prefix rows. Every map2
multiplicand is written, including unused original rows. The d4 active row is
[2,0,2,0] with minimum-1 and delta1; d16 active rows and all map1 lattice scalars
are2. The witness uses exact Fraction equations for every original row and
residue0 interleave. Selected spectra are nonzero and have magnitude at most16.
That establishes a bounded nonzero spectral intention; actual nonzero PCM and
clipping behavior require future independent reference and target observations.
For map1, all original vectors happen to be equal because lookup1_values=1;
original index4 is established from the sparse length list and token semantics,
not by inspecting any decoder-private state.

Per sequence flag, the map2 d16, map1 dense d16 and map1 sparse d16 candidates
have identical raw audio and exact reconstructed spectra. Their setup headers
differ. The future same-decoder PCM expectation is equality within those two
three-case groups. Each of the four seq0/seq1 family pairs has different spectra;
their future same-decoder PCM expectation is difference. The witness checks
spectral relations and wire equality only. It never reports PCM equality.

The intended owned public setup storage paths are map2 dec_type1 for d4,
map2 dec_type3 for d16, and map1 dec_type2 for d16. With value_bits2, the public
formula for packed vector storage is (2*16+8)/8=5 bytes; map1's one-column offset
alternative uses2 bytes and has q_pack0. These are source-derived intentions,
not runtime observations, and are labelled accordingly in metadata. No vendor
handles, binaries, disassembly or opaque fields are accessed.

generate_singletons.py imports the exact canonical generate_books.py normally,
which imports the exact canonical minimal helper normally. It calls their
unchanged Bits/prefix/write_book/scalar_book/vectors/identification/comment/page/
read_pages interfaces. It does not monkeypatch any helper or borrow the existing
map2 generator's narrower dense-only singleton special case. The new generator
owns its sparse-single audio construction. Full original source snapshots and
raw hashes are retained in provenance/ and source-pins.json.

independent_witness.py imports neither generator nor helper. It independently
walks complete raw headers, all original codebook lengths and multiplicands,
all112 audio packets, every consumed singleton bit, and all136 Ogg pages. It
checks actual fields against every writer field report, full offsets, exact
Fraction vectors, original-index usage, residue0 placement, file hashes, page
CRC, serial, sequence, granules and flags. It preserves before/after source and
generated byte identities. Its successful receipt would establish finite raw
construction only; reference and target validation remain separate gates.

test_construction.py contains31 proposed host controls, including all112 positive
audio walks, singleton length1 and original-index checks, lookup hole retention,
Fraction arithmetic, residue0 interleave, spectral relations, and independent
rejection of changed metadata, truncated tokens, extra/padding bytes, wrong
modes/classwords, CRC, granules and serial. The negative bytes stay in host memory;
they are not proposed target input campaigns. No controls have been run here.
