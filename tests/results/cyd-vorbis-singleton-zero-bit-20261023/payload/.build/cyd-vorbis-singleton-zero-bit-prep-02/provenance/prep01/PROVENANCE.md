# Preserved actual inputs and source adaptation

source-pins.json records48 actual original/snapshot pairs, all retained byte for
byte. They include the complete prior15-file source preparation, four original
generation metadata files, twenty exact map1 raw files, original completed host
report and available actual command receipts/logs, and five canonical source
origins. The original eight-case manifest and matrix are preserved whole. Only
the four map1 cases' raw binaries are copied as finite input; map2 raw files are
not duplicated and are not needed for this additive comparison. They remain in
their immutable original generation. The full original host report preserves all
eight failure observations without rewriting or reclassifying them.

support.py owns only file identities, bounded output selection and normal helper
loading. generate_zero.py imports the exact reviewed generator source snapshot,
which uses the unchanged canonical generate_books/minimal modules with their
existing SHA256 gates. It does not call any generator main. It reuses only normal
page/read_pages/mode interfaces; its new raw-bit token rewrite is explicit source.
No existing helper is rebound or monkeypatched.

independent_zero_witness.py imports the exact reviewed independent witness
snapshot, not the new generator. Its new parse_zero_audio follows the original
parse_audio source with an explicit zero-token expectation for the new finite
map1 dimension16 profile. Its ordinary Reader/table/Fraction/interleave/header/
CRC dependencies stay unchanged. source_checks.py extracts both function texts
using AST only and writes zero-audio-function.diff. The original function source
and its original controls remain untouched and retain their original scope.

Source preparation is restricted to text assembly, raw-byte copying, AST parsing,
and file hashes. Existing raw input bytes are copied without reinterpretation;
no additive zero audio or Ogg is constructed yet. No generator/witness/control,
codec/reference/PCM, C/compiler/SDK/QEMU, Git, board/COM or external-system action
is run. No vendor binary/handle/private state/disassembly is used. Future actual
runtime evidence belongs to separate root-owned fresh campaigns.
