# Исправление унаследованных ошибок NVS

26 октября 2026 исправлены ошибки из [проверки до изменения](NVS_RECORDS.md).
Текущий app `34CBA103`, ELF `73BEB58C`. Исходные factory/4F2C/EB20 сохранены
в рабочей копии factory-аудита; прежние proof и их ограничения не переписаны.

## Поведение

- Удалённые слоты учитываются один раз: при удалении span, обработке ILLEGAL
  и проходе повреждённого хвоста через уже ERASED слот. Счётчики совпадают с bitmap.
- Кандидат HashList проверяется по namespace, полному ключу и chunk. Коллизия
  24-битного хеша больше не удаляет чужой ключ; поиск продолжается до настоящего
  совпадения. Замена типа значения того же ключа сохраняется.
- Последний поиск дубликата получает точный chunk. Разные части и поколения
  BLOB сосуществуют, пока опубликованный индекс определяет нужное поколение.
- Ошибки чтения, удаления и очистки в recovery возвращаются вызывающему коду,
  Page помечается INVALID, дальнейшие операции прекращаются. NOT_FOUND остаётся
  обычным результатом поиска. Раньше отдельные ветки возвращали успех после I/O
  failure: 32 factory и 50 current-before случаев в выбранной матрице.

Исправления применяются `tools/patch_nvs_page.py` к **копии** `nvs_page.cpp`
в build directory. Проверяется точный SHA исходника SDK6.1; неизвестный исходник
останавливает сборку. `cmake/nvs_recovery.cmake` заменяет ровно один translation
unit нашего component и сохраняет private include paths. Общий SDK не меняется.
В начале исправленных функций и сложных ветках стоят комментарии `FIXED_FACTORY`.

`build.ps1` до архивирования запускает `verify_nvs_recovery.py`: все функции
замыкания прямых вызовов должны полностью совпасть с объектами сборки, включая
локальные ветвления и назначения вызовов. Квалификация source patch и linkage
сохраняется рядом с app. Это статическая защита; семантические тесты выполняются
отдельно. App занимает 1475968 байт, на 128 больше 4F2C; в app partition остаётся
60032 байта. JPEG/OTA политика не менялась.

## Проверки

- 192 реальных ROM CRC, 528 заголовков, прежние 23 набора записей и 11 malloc
  failures на каждую прошивку. Заводские дефекты остаются видимыми; исправленные
  native counter/key contracts проходят.
- 27 native record cases и 27 стабильных повторных открытий; отдельно 12 FULL/
  FREEING случаев. Добавлены обе последовательности обновления коллидирующих
  ключей, поиск настоящего дубликата за чужим кандидатом, legacy BLOB→index и
  повреждённый хвост перед уже удалённым слотом.
- 130 сбоев Partition I/O: каждый наблюдавшийся ordinal в девяти сценариях,
  отказ до передачи или после половины байтов. Все возвращают 0x104/INVALID и
  прекращают I/O. Реальные программированные префиксы сохранены; для каждого
  случая новый Page восстанавливает ключи/счётчики, второе открытие стабильно.
  Это API byte fixture с NOR 1→0, не электрическое отключение питания и не SPI timing.
- Повторены 652 прежних partial-repair executions. Семь входных мутаций и пять
  production source/linkage controls отвергаются; шесть report/runtime mutations
  проверяют пропущенный fault, скрытую write error, неверный счётчик, потерю ключа,
  устаревший SNTP и несовпадение кадра.
- Native regression: 6298 проверок, отдельно 3727 JPEG privacy и 26 nothrow cases;
  16 correspondence controls и шесть artifact checks проходят.
- Отдельная ВМ без LCD: Wi-Fi setup, HTTP, сохранение настроек, cold boot/reset,
  три свежих SNTP observations. Отдельный display run: один factory и один native
  cold boot, все 57600 пикселей кадра настройки совпали. Четыре владельца QEMU
  завершены; итоговая проверка CIM выполнена успешно.

Остаточные данные после неуспешного purge по-прежнему не являются гарантированным
secure erase. Полный Storage::init на повреждённых многосекторных images,
arbitrary power cuts, полный функциональный suite, длительная и аппаратная
приёмка ещё открыты. Результаты сети и дисплея подтверждают указанные сценарии.

## Воспроизведение

[Proof](../../qemu/parity/nvs-recovery-validation-20261026.json): 23 gzip /
250808 байт, 51 source pin. `verify_nvs_recovery_evidence.py` требует явно
указанные factory, ROM, точные old/current ELF/app/NVS archive, исходный и
generated source, patch report и новую папку диагностики. Используются те же
аргументы, что у `check_nvs_recovery.py`, плюс `--evidence` на этот proof.
Consumer заново исполняет машинные проверки и сравнивает каждый phase, затем
независимо сверяет сохранённые network/SNTP/settings/LCD witnesses и input hashes.
Он не запускает новые ВМ и не объявляет whole-image/hardware приёмку завершённой.
