# Функциональные тесты Small TV ESP32-C2

Набор проверяет восстановленную прошивку и сохраняет результаты для конкретного
SHA-256 приложения и исходников. Он включает все имеющиеся функции устройства:
экраны, часы, сетевую настройку, погоду, подсветку, фотографии и веб-интерфейс.
Автоматические проверки дополнены приёмочными сценариями для платы и браузера.
Успех автоматического набора не означает, что эти приёмочные сценарии выполнены,
и не доказывает полное совпадение всех путей с заводской прошивкой.

## Запуск

Из корня репозитория в PowerShell 7.5 или новее:

```powershell
& .\Small_TV\src\tests\run-all.ps1
```

По умолчанию запускаются C-тесты на компьютере, проверка артефактов, выполнение
машинного кода обеих прошивок и полный запуск обеих прошивок в QEMU. Нужны MSVC
с поддержкой C11 atomics, локальный Python ESP-IDF, Node.js 18+ для JavaScript,
уже собранные BIN/ELF и
профиль Small TV в `C:\Work\QEMU-ESP32`. Пути можно передать через `-VsDevCmd`,
`-PythonPath` и `-QemuRoot`. Если производственные исходники изменились, сначала
выполните `Small_TV/src/build.ps1`: проверка целостности отклонит старую сборку.
При первом запуске машинных тестов зависимости устанавливаются явно:

```powershell
& .\Small_TV\src\tests\run-all.ps1 -InstallOracleDependencies
```

Для быстрого запуска без эмуляторов:

```powershell
& .\Small_TV\src\tests\run-all.ps1 -SkipMachine -SkipQemu
```

Такой отчёт помечается как `reduced`, а пропущенные группы — `not_run`.
При ошибке любой включённой группы скрипт возвращает ошибку. Полный JSON и логи
сохраняются в `.build/small-tv-functional/<время>/`; `-OutputDirectory` позволяет
выбрать каталог. Свежие результаты записываются заново, старые отчёты не служат
основанием для успешной проверки. Копия проверенных результатов находится в
[functional-validation.json](functional-validation.json).

Публикация компактной копии после полного запуска:

```powershell
& .\.idf\tools-v6.1\python_env\idf6.1_py3.12_env\Scripts\python.exe `
    .\Small_TV\src\tests\publish-report.py <каталог-запуска>\report.json
```

Публикация отклоняет неполный/неуспешный запуск, изменённые тесты и несовпадающие
образы приложения между группами. Логи ВМ и содержимое пользовательских настроек
в публикуемый отчёт не включаются.

После публикации `src/tools/verify_artifacts.py` обновляет `src/validation.json`
из этого полного отчёта и текущей сохранённой сборки. Он повторно проверяет
исходники/ресурсы, отклоняет старый образ или изменённые тесты, вычисляет размер
приложения и свободное место по таблице разделов, а расход DIRAM берёт из карты
линковщика через `esp_idf_size`. Количество функций и меток исправлений также
вычисляется из C-кода. Запуск из корня репозитория:

```powershell
& .\.idf\tools-v6.1\python_env\idf6.1_py3.12_env\Scripts\python.exe `
    .\Small_TV\src\tools\verify_artifacts.py
```

Расход DIRAM — статические данные линковщика; измерение свободной памяти на
работающей плате остаётся отдельной проверкой.

Скрипты не прошивают плату, не выполняют OTA и не меняют исходный дамп.
QEMU работает без SDL, с отдельными копиями флеша и синтетическими настройками;
созданные им виртуальные машины закрываются после тестов.

`weather_qemu.py` проверяет настоящий DNS/TCP/HTTP обеих прошивок через локальный
сервер заданных ответов: ошибку 503, повторный запрос, Kelvin/отрицательные значения,
влажность и ветер, смену данных через `/updateCity`. Значения читаются из живой RAM
без изменения программы; ABI нашей структуры берётся из DWARF текущего ELF.
После окончания заставки по виртуальному времени сравниваются непустые участки
LCD с температурой, влажностью, подписью и иконкой. Заводская обработка JSON при
HTTP 503 записана как ошибка; наша прошивка отклоняет его и сохраняет предыдущий
успешный кеш. Это проверка сетевого стека с синтетической погодой, а доступность
реального сервиса OpenWeatherMap остаётся отдельной ручной проверкой.

## Что проверяется автоматически

`report_aggregation` проверяет реальный общий JSON reader и serializer: даты
сохраняются строками с исходным country offset, включая midnight, DST overlap и
дробный offset. PowerShell `ConvertFrom-Json -DateKind String` предотвращает
неявное преобразование независимой календарной reference в host timezone.

Группа `machine_timezones` исполняет настоящий код преобразования времени и libc:
36,404 сравнения для 109 исходных ключей стран, все записанные переходы ±1 секунду,
будущие правила до выборок 2400 года, неизвестная страна и ошибки epoch/указателя.
Независимая модель — Python ZoneInfo с закреплёнными TZif IANA. Сценарии
`time_zone_boundaries`, `clock_timezone_classic` и `clock_timezone_simple`
проверяют реальные рабочие циклы при DST, смене страны и обратном скачке времени.
Транспорт повторов SNTP и признак успешной синхронизации этим не проверяются.
Подробности: [timezone-checks.md](../../qemu/parity/timezone-checks.md).

Группа `timezone_sources` проверяет офлайн-загрузчик закреплённых данных:
повреждение архива, разные версии IANA/package, отсутствующие и дублированные
файлы, неподдерживаемые будущие DST-правила и сохранность прежних данных при
отказе. Контрольный архив не устанавливается и его Python-код не выполняется.
При наличии настоящего wheel `timezone_update_test.py --wheel ... --output ...`
также сверяет все TZif и сгенерированный C header с текущим snapshot. Обновление
из открытых источников описано в [resources/timezones/README.md](../resources/timezones/README.md).
Обычная сборка и этот тест не требуют доступа к сети.
Отдельный результат настоящей загрузки и воспроизведения snapshot сохранён в
[timezone-update-validation.json](timezone-update-validation.json); он не заменяет
полную runtime-проверку прошивки.

Группа `machine_time_state` исполняет настоящий RV32-код notification/validity,
заводского calendar cache и restart counter. `qemu.time_http` дополнительно
проверяет реальные UDP NTP-пакеты, отказ серверов 1/2, настройку сервера 2,
2024/2026/backward/post-2038, отсутствие sync после reset и восстановление.
Системное время сверяется по настоящим RTC/HRT компонентам SDK, все пиксели
полосы даты — по независимым bitmap. Буквальные заводские ошибки сохранены
отдельно от ожидаемого исправленного поведения. Подробнее:
[time-sync-checks.md](../../qemu/parity/time-sync-checks.md).

`qemu.regional_http` проверяет исходный 20-байтный country slot, все 15
региональных ключей через реальные HTTP/SNTP, независимые IANA календари,
пиксели даты и холодный старт обеих прошивок. Host C дополнительно проводит
все 109 ключей через API/import/export/persistence и проверяет миграцию
344-байтного NVS v1 в 364-байтный v2. Рабочие задачи проверяются при смене
только региона, включая максимальную длину. Буквальная заводская задержка
перерисовки сохранена отдельно; для проверки оригинальных региональных пикселей
используется штатная смена темы, для нашей прошивки — прямое обновление.
Подробнее: [regional-settings-checks.md](../../qemu/parity/regional-settings-checks.md).

Новый обязательный `qemu.calendar_http` проверяет 14 natural calendar/DST
boundaries в classic/simple/dial обеих прошивок: 84 перехода и 168 полных кадров.
IANA календарь и factory instructions используются как разные эталоны; между
before/after не допускается новая синхронизация. Все шесть date/hour styles
чередуются по случаям в каждой теме. Полный результат этой новой матрицы пока
не опубликован. Подробнее: [calendar-transport-checks.md](../../qemu/parity/calendar-transport-checks.md).

`qemu.completed_scenes` сравнивает все пиксели завершённых classic, weather и dial
кадров с реальными инструкциями того же ELF/оригинала. Аппаратные точки наблюдения
не изменяют гостевой код/RAM/PC. Проверяются 24 кадра, включая чистый полный
эталон после 40 guest seconds, реальный HTTP и JPEG/BMP. Ещё 40 полных сцен
сопоставляют одинаковые входы и объявленные factory corrections. Яркость выводится
из настоящих LEDC/GPIO регистров; первый digital frame должен использовать
настроенную яркость. Подробнее: [completed-scene-checks.md](../../qemu/parity/completed-scene-checks.md).

Группа `machine_text` исполняет RV32 декодирование UTF-8, копирование полного
префикса, измерение и отрисовку: все ASCII и 452 non-ASCII глифа в трёх размерах,
границы полей, прозрачный вывод, ошибочные последовательности и защитные байты.
Независимая модель читает исходные BDF/factory bitmap, не generated C header.
`qemu.text_http` проверяет настоящий UTF-8 POST, фрагментированный ответ погоды,
15-byte границу, пиксели, защитные полосы и полный цикл Unicode-прокрутки.
Заводской сбой UTF-8 city/NULL HTTP-client проверяется в отдельной ВМ; штатные
сеансы обеих прошивок должны завершаться без panic. Подробности:
[text-checks.md](../../qemu/parity/text-checks.md).

Группа `qemu_profile` проверяет repo-owned `Small_TV/qemu/profiles/small-tv-c2.json`
через shared QEMU compiler: реальные GPIO из `board.h`, unchanged hardware-only /
offline defaults, NTP/SSID, generic ServicePort и URL overrides/metadata privacy.
Full QEMU tests и comparator используют тот же профиль; publisher сверяет точные
profile/launcher/comparison/compiler hashes. Нужен QEMU с новыми generic service
properties (`f4322a8a8f`); изменение checkout без пересборки бинарника недостаточно.
Тесты погоды/полей используют `service_port`, сохраняя оригинальный HTTP protocol.

При параллельной работе над QEMU можно передать `-HttpHelperOverlay <каталог>`
с точной копией закоммиченного `small_tv_http_test.py` и `manifest.json`, содержащим
его SHA-256 и source commit. Только UTF-8 fixture использует эту копию; остальные
helper modules и эмулятор берутся из `-QemuRoot`. Отчёт сохраняет фактическое
происхождение и отклоняет изменение QEMU/profile/helper во время полного запуска.
Обычный запуск использует текущий helper без overlay; для него нужен аргумент
`ensure_ascii` в HTTP-клиенте. Overlay не меняет файл или ветку репозитория QEMU.

Группа `machine_jpeg` исполняет оба настоящих JPEG-декодера для всех 107 изображений
и сравнивает 6,163,200 RGB565 пикселей с фоном. Дополнительно проверяет 35 сценариев
ошибок/повтора/валидации и семь вариантов размещения/кадрирования. Подготовка и
декомпрессия различаются наблюдением реального входа в `jd_decomp`; ошибки до
отрисовки сохраняют кадр, ошибки MCU очищают известную область. Имена/смещения
анимаций берутся из архивного контейнера. Метрики не являются процентом покрытия.
Подробности — [jpeg-checks.md](../../qemu/parity/jpeg-checks.md).

Группа `machine_classic` сравнивает 261 набор полей классической темы и идентичность
выбранных изображений, 1 545 переходов курсора GIF и три проверки недопустимого
числа кадров. JPEG/BMP-вызовы фиксируются как граница, а декодирование проверяется
отдельно. Заводская ошибка отбрасывания символа у края панели сохраняется в отчёте
как намеренное отличие; четыре проверки требуют точные видимые биты оригинального
символа. Объём проверки описан в [classic-checks.md](../../qemu/parity/classic-checks.md).
Сценарий `clock_animation_selection` исполняет основной цикл нашей прошивки:
проверяет выбор более короткого GIF и сохранение кадра при возврате из простой темы.

Новая группа `machine_weather` выполняет оба настоящих BMP-декодера для 18 иконок,
сравнивает последовательные смены длинных/коротких/пустых полей и отсутствие погоды,
191 кадр прокрутки и ошибки чтения заголовка/строк с успешным повтором. Исправления
очистки и границ сравниваются с отдельно объявленной исправленной заводской моделью;
буквальные отличия сохранены. Прокрутка — запрошенное расширение. Сценарии
`text_field_windows`, `weather_field_cleanup`, `clock_text_scroll` проверяют края,
паузы/развороты, неподвижность коротких строк, загрузочную блокировку и смену темы.
Подробности: [weather-checks.md](../../qemu/parity/weather-checks.md).

Группа `machine_calendar` проверяет 96 полных кадров обеих тем при скачках
года/календаря с теми же часами, минутами, секундами и номером дня года, повторе
одинакового состояния и замене длинной даты короткой. Два сценария
`clock_calendar_classic`/`clock_calendar_simple` также выполняют настоящий
основной цикл после скачка epoch без минутного флага. Описание и отрицательное
свидетельство: [calendar-checks.md](../../qemu/parity/calendar-checks.md).

В полном QEMU-наборе `field_qemu.py` проверяет реальные HTTP-смены города,
длинные и короткие поля, обе стороны/паузы прокрутки, задержанный ответ сервиса,
сохранение фазы после применения нового поколения погоды, возврат в тему,
недоступную погоду, повтор и неизвестную иконку. Пиксели города/названия/иконки
сравниваются с независимыми исходными bitmap и соседними полосами границ.
Пока внешний HTTP-ответ удерживается сервером, длинное поле обязано продолжать
двигаться. После публикации тех же данных фаза сохраняется; прежнее требование
замораживать UI удалено вместе с ненужным программным ожиданием.

Группа `frontend` компилирует JavaScript трёх страниц и проверяет удаление
APP/COM без изменения JPEG scan, ошибочные заголовки и 156 вариантов геометрии
кадрирования (края, масштаб, портрет/альбом и недопустимые параметры), а также
23 проверки изменения размера за все четыре угла, неподвижного противоположного
угла и границ изображения. Публикация
проверяет хеши страниц и модулей, чтобы не использовать результат старого UI.
Реальные Canvas, выбор области, отмена и загрузка в QEMU проверяются отдельно
через браузер; это не означает прохождение всех аппаратных сценариев H01–H09.
Последняя такая проверка сохранена в [browser-regression.json](../../qemu/browser-regression.json):
изменение размера рамки мышью, загрузка выбранной области из PNG 960×640,
JPEG 240×240 без APP/COM, отмена с неизменным хешем слота, пять превью после
перезагрузки и чтение настроек из реального HTTP виртуальной прошивки.

Для ручного открытия ВМ используйте команду и карту портов в
[описании QEMU](../../qemu/README.md). Режим `setup` выделяет соседние отдельные
порты AP/STA; `clock` — порт станции. Автоматический выбор начинается с 18080.
В заводском сценарии SSID вводится вручную: подтверждённая ошибка `/scan` при
нуле результатов отмечена как исключённая проверка. В нашем сценарии успешный
scan обязателен, а возврат `[]` без падения проверяет производственный HTTP-код.
Заводскому `/configure` отправляется компактный JSON его браузера; наш обработчик
дополнительно проверяется на обычных JSON-запросах с пробелами.

C-тесты исполняют производственные `.c`, а не копии их алгоритмов. В первом
наборе платформенные операции используют flash/NVS в памяти и модель HTTP I/O.
В `platform_test.c` адаптированы только ESP-IDF API, время и точки блокировки
задач; задания, обработчики событий, код HTTP-клиента, LCD и основной цикл часов
исполняются из производственных исходников. Тестовый дисплей декодирует реальные
SPI-байты в RGB565. При тестировании классической темы media-вызовы фиксируются
отдельно: настоящий JPEG/BMP decoder проверяется в первом наборе.

Детерминированная подача событий не проверяет гонки настоящего FreeRTOS.
Отдельный `startup_qemu.py` измеряет первый actual classic frame после настоящего
UDP SNTP notification через read-only аппаратные GDB breakpoints. Критерий —
не более 0,5 guest s после callback; отсутствие SNTP/IP и photo theme покрыты
платформенными сценариями. Он включён в обязательный QEMU suite; отдельный запуск:

```powershell
python Small_TV/src/tests/startup_qemu.py --dependency-root C:/Work/yoRadio `
  --qemu-root C:/Work/QEMU-ESP32/.worktree/small-tv-wifi-link `
  --output .build/startup-check
```

Число `checks` включает обходы диапазонов и пикселей и не является процентом
покрытия кода. Никакой результат успешного host HTTP не выдаётся за успешный
запрос погоды из QEMU или физической платы. Сравнение QEMU-снимков измеряет
разницу; процент совпадения не служит критерием успеха. Машинные тесты сохраняют
отличия от неизменённого оригинала и отдельно проверяют исправления известных
ошибок (воскресенье, геометрия стрелок, устаревающая минута).

## Приёмочные сценарии для платы и браузера

В отдельном [кандидате offline clock](../../qemu/parity/offline-clock-checks.md)
исправлены остановка активной темы и подмена IP при потере Wi-Fi. Новые
`clock_offline_dst_*` и `clock_offline_photo` проходят с production C и SDK
адаптерами; `network_oracle.py` сравнивает реальные RV32 event/cache instructions
и bounded original dispatch. `machine_network` обязателен для следующей полной
публикации. Текущие общие отчёты относятся к предыдущей сборке; естественный
QEMU link loss и полный прогон кандидата ещё требуются.

По уточнению о программных задержках удалён guard, который приостанавливал UI
до завершения асинхронного HTTP погоды. Новые `clock_weather_pending_*` дают
37 passing platform scenarios той сборки. Обязательный `weather_wait_qemu.py` удерживает
реальный внешний ответ и проверяет смену минуты при RUNNING=1; старый app
воспроизводит ожидание тайм-аута. См.
[software-weather-wait-checks.md](../../qemu/parity/software-weather-wait-checks.md).
Этот новый test ещё нужно включить в общий gate и пересмотреть старое ожидание
frozen scroll в `field_qemu.py`. Прежние published reports не подтверждают новый app.

Эти сценарии пока **не выполнены**. Для каждого нужно записать версию/SHA
приложения, дату, шаги, результат и свидетельства. Используйте отдельную
тестовую точку доступа и вымышленные SSID/города; не сохраняйте Wi-Fi пароли,
API-ключи и фото с личными метаданными в отчётах. Прошивку и аппаратные измерения
следует выполнять как отдельную согласованную работу.

подменой ESP-IDF API. Гонки задач, DST библиотек, успешная Internet-погода и работа
JavaScript в браузере также остаются отдельными проверками. OTA, звук и SD-карта
не входят в функционал этой восстановленной прошивки и здесь не добавляются.
