# Small TV: сверка поведения с заводской прошивкой, 2026-11-13

Проверена ветка `codex/small-tv-parity-20261103` на `1a2d160b8`.
**Найден один подтверждённый пробел совместимости** в просмотренных цепочках:
новая прошивка не принимает частичное обновление NTP и ключа погоды через
`POST /advancedset`. Все 34 заводские пары «метод + путь» найдены в таблице
42 маршрутов новой сборки. Это проверка зарегистрированных входов, а не
всех вариантов HTTP-ответов. Код прошивки и ранее внесённые исправления
не менялись.

## Подтверждённый пробел

Заводской HTTP-сервер регистрирует `POST /advancedset` в `0x4200fc26`:
дескриптор `0x3c0d6704`, обработчик `0x4200e9ea`. В обработчике две
независимые ветки записи: NTP (переход к записи в `0x4200eb4e`) и ключ
погоды (ветка `0x4200eb9a`). Записи по `0x4200eb88` и `0x4200ebd4`
запрашивают отложенное сохранение в основном цикле `0x42008e56` через
`0x42008a00`. Поле `clickCount` обрабатывается отдельно. В нашей сборке
обработчик [web_settings_post](../app/web/settings_api.c#L278)
(`0x42012d60`) требует все три поля одновременно.

| POST, компактный JSON с тестовыми данными | Заводская | Новая |
| --- | --- | --- |
| Только `ntp` | 200; NTP записан, ключ сохранён | 400; оба значения прежние |
| Только `openweathermapKey` | 200; ключ записан, NTP сохранён | 400; оба значения прежние |
| Оба поля без `clickCount` | 200; оба значения записаны | 400; оба значения прежние |
| Все три поля, контроль | 200; оба значения записаны | 200; оба значения записаны |

Воспроизведение: две отдельные ВМ с синтетическими настройками станции,
SLIRP `restrict=on`, HTTP только через loopback; дождаться завершения
заставки перед первым POST. Проверять не только ответ `Settings saved`,
но и два поля во временной flash ВМ по `0x3e7086` и `0x3e711c` после
отложенной записи. Обе ВМ штатно закрылись, без panic, входы неизменны.
Хеши: приложение `564ea463fc98…`, ELF `e01db928f75f…`, заводской ELF
`8c9fd166a653…`, QEMU `2df903276e66…`. Встроенный редактор сейчас
посылает все три поля, поэтому основной сценарий сохранения работает.
При переносе достаточно применить каждое переданное валидное поле
независимо, сохранить отсутствующее поле и оставить строгую проверку
JSON, маскирование ключа и действующие правила записи.

## Воспроизведение статической сверки

[audit_behavior_entrypoints.py](../tools/audit_behavior_entrypoints.py)
принимает `--factory-elf`, `--native-elf`, `--app`, `--factory-net`,
`--native-net`, `--output`. Нужны `pyelftools` и два закреплённых
`libnet80211.a` (factory `8f989ecd7104…`, native `c2df6fcca4c1…`).
Скрипт проверяет привязку нового ELF к приложению, читает адреса
дескрипторов из инструкций регистрации, проверяет исполняемость их
обработчиков и сравнивает полные пять тел из `wl_cnx.o` в каждом образе.
Отчёт содержит адреса, размеры и хеши, без содержимого настроек или SRAM.

Порядок дальнейшей проверки: частичное обновление `/advancedset`; создание,
публикация и освобождение внутренних peer-объектов при отмене ассоциации и
повторном соединении; аппаратная проверка RESET/DC и RF. По статическому
экспорту нельзя считать все косвенные вызовы разрешёнными и весь образ
эквивалентным. Суточный H10 идёт отдельно, его ВМ не использовалась здесь.
