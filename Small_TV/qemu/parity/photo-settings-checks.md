# Изменение фотонастроек во время перехода

`photo_settings_qemu.py` проверяет реальную смену маски и интервала через HTTP
во время fade. Production C и образы не изменены: app `daf5595d`, source
`c83941ff`, ELF `b06ce810`; QEMU `fde38d53` из commit `962cda7a`.

| Сценарий | Момент команды и ожидаемое действие |
|---|---|
| Отключить до изображения | После фазы0 убрать первый слот; фаза2 выбирает следующий разрешённый |
| Отключить следующий | После фазы2 текущая фотография остаётся до конца fade, следующий выбор пропускает отключённый слот |
| Отключить все | Завершить текущий переход; следующий цикл очищает фотографию, сохраняя IP-footer |
| Включить следующий | Сохранить текущий переход, затем выбрать вновь разрешённый слот |
| Сократить 60 → 3 | Сохранить фазу и накопленный счётчик, применить новый предел |
| Увеличить 5 → 9 | Сохранить накопленный счётчик, отложить следующее событие до нового предела |

Окончательный прогон `photo-settings-all-20261016-03` завершён успешно:
12 настоящих HTTP-сценариев, 24 полных кадра с нулём отличающихся пикселей,
14 отрицательных проверок контракта. Все ВМ этого набора закрыты; сохранены
защищённые области флеша и исходные BIN/ELF/ROM/test/helper identities.
74 test files зафиксированы до запуска и остались неизменны. Это проверка
указанных сценариев, а не повторное выполнение остальных тестов из этого дерева.

Каждый сценарий запускается на обеих прошивках в отдельной свежей raw-копии
флеша. `query-block` подтверждает прямой backend. HTTP-команда выполняется самим
сервером гостя; отладчик использует только аппаратные точки, чтение и обычное
продолжение. Guest RAM, PC, инструкции и время не переписываются.

Точки публикации заводских настроек: `0x4200e3b2` после записи маски и
`0x4200f78a`/`0x4200f78e` до/после записи интервала. В C наблюдается реальная
`settings_replace`, её возврат и фактический `factory_timer_t` из DWARF.
Сохраняются фаза и ISR counters до/после команды. Текущий и следующий полные
кадры сравниваются по всем 57 600 пикселям с буквальным factory replay,
включая настоящие JPEG decoder и glyph instructions; отдельно проверяется PWM.

Смена настройки не должна сбрасывать счётчик. В заводском наблюдении при
60 → 3 он оставался равен17. Это допустимо: callback `0x42008310` пропускает
событие только при `counter < interval`; native `0x40381fd6` выполняет `>=`.
Следующая секундная граница сбрасывает такой счётчик и поднимает photo flag.
Эта особенность включена в положительный сценарий, а не объявлена дефектом.

По фактическому состоянию после первого завершённого fade вычисляется окно
следующего события: `ticks = 11 * max(1, interval - counter) - subsecond`.
Сохраняется заводской шаг из одиннадцати 100-ms interrupts. Допуск окна
учитывает положение внутри текущего tick и проход UI. Проверка отклоняет
сброшенный счётчик и продолжение работы со старым периодом.

Оба кадра фиксируются аппаратными остановками **до** ожидания HTTP-ответа.
Иначе host thread может получить ответ поздно и пропустить первый конец fade,
зафиксировав уже следующую фотографию. Предварительный наблюдатель воспроизвёл
такое запоздалое наблюдение на неизменном C; после переноса response wait за
фиксацию кадров тот же сценарий shortening прошёл. Это исправление harness,
не изменение прошивки. В отчёте сохраняется порядок publication/capture/response.

После остановки сравниваются защищённые диапазоны флеша и проверяется UART.
BIN/ELF/ROM, профиль, helpers и observer inputs связаны SHA-256. ROM для QEMU
и отдельного instruction replay должен совпадать. `photo_settings_contract.py`
проверяет полноту шести сценариев × две firmware, полные кадры, хронологию,
естественный timer event и целостность; 14 испорченных отчётов должны отвергаться.
Gate обязателен в branch suite/publisher/verifier.

Отчёты: `photo-settings-candidate.json`, `photo-settings-contract-validation.json`.
Фактические инструкции восьми участков: `factory-photo-settings.asm`,
`native-photo-settings.asm`, `photo-settings-assembly-manifest.json`.
Прежние scoped/full reports сохраняют свои identities. Эти проверки не заменяют
браузерную приёмку crop/upload, физическую плату и длительное наблюдение памяти.
