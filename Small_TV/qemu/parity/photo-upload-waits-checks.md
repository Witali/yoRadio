# Загрузка фото без лишнего ожидания

`photo_upload.js` сохраняет заводской HTTP-протокол и отправляет следующий блок
после подтверждения предыдущего. Native `photo_upload_chunk` завершает синхронную
`esp_partition_write` до ответа HTTP. Дополнительная пауза 50 мс после успеха
удалена по запросу пользователя. Повторяемая операция использует те же байты и
поля; лимит остаётся пять попыток. Backoff применяется между попытками, поэтому
после последней неудачи больше нет лишней паузы 2,5 секунды.

Функция имеет начальный комментарий `REQUESTED_CHANGE`; exporter встраивает
канонический модуль, исходный заводской HTML остаётся в `local_site/source/`.
Серверная валидация, исправления заводских ошибок и требования к JPEG сохранены.

| Проверка | Результат |
|---|---|
| Успешная передача 1 / 3 / 25 блоков | Заданные JS-паузы 50 / 150 / 1250 мс → 0 |
| Пять неудачных попыток | Backoff 7500 → 5000 мс; пять попыток и ошибка сохранены |
| Управляемые ACK, точные multipart-байты, retry/start/finish/download errors | Все 11 случаев проходят |
| Тот же финальный тест на прежнем HTML | Шесть ожидаемых отрицательных результатов из-за лишних пауз |
| Native/platform и остальные host groups | 3924 проверки / 46 сценариев; reduced profile проходит |
| Реальный SDK photo HTTP в QEMU | 21 проверка, включая холодный старт и прерывание, проходит |
| Настоящий браузер, 47 837 байт / 12 блоков | До/после сохранены полностью одинаковые JPEG-байты, SHA `a73dc807…` |
| Raw flash, соседние слоты, исходники и исполняемые файлы | Все 22 проверки финального browser/storage набора проходят |
| Четыре native upload/HTTP функции | Машинные байты совпадают с прежним ELF B06 |

Измерены запрошенные таймеры JavaScript. Сетевое время и длительность записи
флеша остаются отдельными составляющими общей загрузки.

Сборка ветки: app `dd4eb76e` / source `96a111ec` / ELF `b7be7ccc`.
Размер приложения 1 176 880 байт, свободно 359 120 байт; экономия относительно
DAF — 688 байт. Сборка сохранена в `firmware/development/`.

Свидетельства: [before](photo-upload-waits-before.json),
[after/browser](photo-upload-waits-after.json), [host](photo-upload-waits-host.json),
[SDK HTTP](photo-upload-waits-http.json), [instructions](photo-upload-waits-instructions.json).
Первый browser-after запуск использовал CRLF metadata; его локальный отчёт
сохранён. Опубликованный final запуск заново выполнен после канонизации manifest
в UTF-8/LF; значения JSON и бинарные образы от канонизации не менялись.

Все ВМ и временные вкладки этих проверок закрыты. Эти результаты относятся
к данной сборке ветки и не заменяют новый общий прогон main, H09/H10 или
проверку на физической плате. Текущий набор не доказывает полного соответствия
всех путей заводской прошивке.
