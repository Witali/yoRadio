# Первый runtime heap/stack preflight

Наблюдение выполнено на неизменной восстановленной прошивке app DD41A536 /
source 96A111EC / ELF B4AF3C2A и QEMU 30F9A68E. Это ограниченная нагрузка,
не подтверждение 24-часового H10, отсутствия утечек при любой нагрузке,
соответствия памяти заводской прошивке или работы физической платы.
Численные данные, 41 снимок, хеши входов и ранние ошибки обвязки:
[runtime-memory-observation-20261017.json](runtime-memory-observation-20261017.json).

## Наблюдаемый результат

Пройдены 40 циклов за 121,076406 guest seconds, включая все четыре темы,
пять GIF, погоду и смену города, 10 завершённых загрузок публичного JPEG,
240 записанных HTTP-запросов и 80 параллельных GET настроек. Последние 80
вычислены из 40 завершённых итераций с двумя проверенными ответами на каждой;
они не включены в массив последовательных HTTP timing. Максимальное записанное
время HTTP — 0,405659 guest s при неизменной границе 6 s. Исходники, ELF/app,
ROM, SDK, QEMU/profile/helpers и архивные образы не изменились; ВМ закрыта,
panic/watchdog не обнаружены.

Снимки учитывают все 12 TCB: allocator/list links и фактическое число задач
согласованы. Свободная 8-bit heap в первом/последнем снимке — 87 668 / 86 268
байт, наименьшее sampled значение — 78 264. Минимальная сумма SDK per-heap minima
— 47 028 байт; это другая метрика, а не одновременный sampled минимум.
После начальных аллокаций свободная память колебалась около 86 КБ. Из этого
короткого наблюдения нельзя вывести отсутствие долговременной утечки.

Самый низкий stack fill watermark — 480 байт у `settings` при записанном span
2 045 байт. У `clock_display` минимум 1 748, у `httpd` 3 904, у `weather_http`
5 336 байт. Остальные задачи и полные измерения находятся в JSON. Это запас
на выполненных путях; не измерены отдельный ISR stack и недостигнутые пики.

## Проверка самого наблюдателя

15 host parser tests проходят: известные счётчики и стеки, разделение capabilities,
циклы, ошибочные pointers/размеры/counts, backlink/container, дубли задач, короткий
read и нулевой запас. Четыре ROM-теста проходят: два реальных getter, NULL,
изменяющиеся значения и намеренно ошибочные поля декодера. В runtime выполнены
164 сопоставления счётчиков точными ROM-инструкциями на копии typed headers.
ROM `multi_heap_free_size_impl` по `0x4005feea` читает `4(a0)`, а minimum getter
по `0x4005fef4` — `8(a0)`; эти offsets совпадают с DWARF текущего ELF. Код ROM
исполняется вне QEMU без адаптации чтений; внутри гостя хост его не вызывает.

Первый запуск не дошёл до создания ВМ из-за отсутствующего пути helper import.
Второй ожидал естественный вызов heap-size API, не используемый штатным release
путём, и завершился по deadline наблюдателя. Двухцикловый исправленный preflight
прошёл. Первый расширенный run остановлен ошибкой имени HTTP-модуля до передачи
binary chunk. Эти попытки сохранены отдельно как ошибки harness; ВМ закрывались
без panic. Только следующий полный 40-cycle run используется в положительной
сводке, его исходники и исходные данные проверены по хешам.

Модули и команды описаны в [RUNTIME_MEMORY.md](../../src/tests/RUNTIME_MEMORY.md).
Наблюдатель приостанавливает guest clock; host duration не является soak time.
Для H09/H10 остаются длительная работа, сетевые отключения, конкурентные записи /
upload / restart, отдельный ISR stack и аппаратная приёмка. Этот standalone
preflight не заменяет текущий immutable full firmware comparison.
