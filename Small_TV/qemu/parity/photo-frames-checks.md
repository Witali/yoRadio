# Полные кадры фотослайд-шоу

Текущий отдельный checkpoint2026-10-17 для6324/source53D3:
[102полных кадра,9сцен и14negative controls](photo-night-observation-validation-20261017.json).
Ночной тест намеренно удерживает внешние NTP-ответы первые два перехода, затем
продолжает полные циклы до настоящего synchronized night restore, максимум шесть.
В этом запуске потребовалось пять циклов: первые четыре восстановления имели
clock_validFalse, пятое — True с duty4095. Все кадры и PWM совпали. Это исправление
наблюдения, поведение прошивки не менялось. Оставшийся текст сохраняет прежние
checkpoints; новый scoped pass не заменяет полную регрессию или H10.

`tests/photo_frames_qemu.py` выполняет обе настоящие прошивки в QEMU. Аппаратные
GDB breakpoints останавливают завершённый шаг; RAM, PC, код и время гостя не
записываются. Для reference исполняется исходный `0x4200bc36`, включая выбор фото,
JPEG, IP glyphs и арифметику LEDC; адаптированы только границы SDK/LCD.

Baseline app `ad7a9009`, source `f411bf0e`, ELF `6d7b586f`, QEMU `fde38d53`:
84 полных кадра имеют 0 отличающихся пикселей из 57,600. Проверены обе прошивки,
все пять фото и шесть фаз fade, маска 10 с порядком 1→3, маска 0 с одним IP footer.
Профили яркости: full/day, night с day100/night500, dark/day1000.

Для native отдельно применяется уже заявленное исправление: после fade
восстанавливается расписание, тогда как factory заканчивает duty0 (полная яркость).
Первый native night-профиль завершился с day duty819 до SNTP, следующий — с
night duty4095 после подтверждённой синхронизации. Тест читает реально переданный
schedule calendar; фототема не должна ждать SNTP.

Каждый trace начинается на первом полном JPEG/clear, phase2. Первые два шага
заставки не сравниваются с разным намеренно сокращённым startup. Фазы0/1 покрыты
последующими переходами; первый full image, оставшиеся фазы и порядок не пропущены.
Дополнительно девять сцен с одинаковыми входами сравнили native C helpers и
factory на настоящих декодерах: все фото, skip/wrap, три IP и пустая маска.

`photo-frames-baseline.json` сохраняет точные input/image/helper hashes. Это
отдельный результат и будущий обязательный gate ветки; root full run92411 его
не содержит. Все собственные ВМ закрыты. Production code/image не менялись.

Открытые случаи: изменения настроек/маски во время idle и fade, произвольное
прерывание flash write, браузер/физическая панель и длительная работа. Предварительный
observer ошибочно ждал SNTP до первого кадра и пропускал первый slot; это ошибка
теста, не прошивки. Финальный baseline учитывает ранний запуск photo.
