# ESP32-C3 minimum-prefill TLS, EOF and OTA — 2026-10-09

## Result and scope

The `idf61-prefill-min250` diagnostic candidate passes all eight HTTP/TLS
completion scenarios, all 22 exact HTTPS EOF cases and all 15 original OTA
entries. After OTA, a 75-second full HE-AACv2 run with growing TLS records
passes with no recorded DMA queue events or write errors.

**The campaign is not an all-pass qualification.** The certificate-rejection
test loses its subsequent HTTP recovery request to Windows error 10048; its
cleanup request and the controller's next identity request time out. Both
original failed entries are preserved. Two TLS read-error messages also recur
after the separate final reboot command in the OTA test and remain under
review. No production default is changed.

The unchanged application SHA-256 is
`89d320f663bda6439456c95b6f47d09cd5cac2d434ff9fe85df568fa07fbae9c`, ELF identity
`5a17d251e0a7b308dd011e850b1b1016afba0b46bc7dee6263b82f8c624a4ff3`.
It retains full compact AAC/SBR/PS, a 17,058-byte RX-only TLS reserve, adaptive
input, 250/500 ms minimum/maximum prefill, QIO 80 MHz and fractional nominal
48 kHz. This is the [previously measured candidate](ESP32C3_PREFILL_MATCHED_20261009.md),
not a new firmware implementation or a quiet production image.

## HTTP/TLS completion and the failed recovery observation

The framing fixtures distinguish complete Content-Length/chunked bodies,
truncated framing, authenticated close-delimited endings and raw TLS socket
closure. All first produce full HE-AACv2 PCM. The three deliberately
incomplete cases finish as `stream read failed`; the five complete cases
finish as `stream ended`, with cleared PCM fields.

Three captured `-29312` (`-0x7280`, `MBEDTLS_ERR_SSL_CONN_EOF`) messages belong
to the deliberately short Content-Length, short chunked and raw close-delimited
cases. Their timestamps and expected terminal states are preserved. This
does not exempt other TLS errors. Definitions are captured from the actual
pinned SDK alongside the evidence; see the existing
[RFC audit](ESP32C3_HTTP_TLS_RFC_AUDIT_20261007.md) for the framing requirements.

In the untrusted-certificate test, all 24 observations over 12 seconds show
no playback. The server receives four `TLSV1_ALERT_ACCESS_DENIED` alerts,
and the board records certificate-bundle verification failures with handshake
return `-12288` (`-0x3000`). Independent replay therefore confirms rejection
only. The full acceptance case still fails because HTTP playback recovery
does not complete.

Client request 30 fails in `connect` with `winerror=10048`, before an HTTP
response, with a recorded duration of 0 ms. Connect and enclosing-request
rows describe the same failed request. Cleanup request 31 then times out
after 5,015 ms. The controller's next identity request also times out, which
aborts the campaign; its restoration path subsequently succeeds.

Microsoft defines 10048 as a local address-in-use condition; that error alone
does not prove global ephemeral-port exhaustion.
[Winsock connect documentation](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-connect)
The later host snapshot at 15:34:03 UTC records 321 TCP entries, including
198 TIME_WAIT sockets, 159 of them to the board. Windows reports a dynamic
range of 16,384 TCP ports and nine excluded ranges. This is not a simultaneous
snapshot of the failing call and does not establish its root cause. No host
network settings or connection timeouts were changed.

The continuation includes a read-only trace-file monitor that captures host
TCP metadata immediately if another 10048 appears. It does not change socket
creation, add retries or issue board requests. No repeat of 10048 is recorded
in that continuation. Its synthetic check verifies one snapshot per failed
request and correct handling of partially written JSONL lines.

## OTA timing and TLS error codes

Commit `f533f96a` adds persisted begin/returned/raised action boundaries to
the OTA report, using the same host monotonic clock as serial capture.
Callback return values and private exception messages are excluded. Four new
timeline checks, five existing playback-format checks and three existing
serial-health checks pass. A returned call is not automatically a passed
acceptance gate.

The physical OTA series rejects ten malformed/interrupted uploads, verifies
two partition changes, succeeds during full HE-AACv2 HTTPS playback, succeeds
with a slow upload and restores the saved station settings. Three consecutive
observations establish 44.1 kHz stereo, 16-bit HE-AACv2 with full SBR/PS before
the while-playing upload. All 32 timed actions complete. Five software-reset
banners fall inside their explicit upload/reboot intervals; no unexplained
reset is identified by the independent review.

Both additional TLS messages occur at host monotonic time **240962.312**:

- `Dynamic Impl`, `fetch_input`, return **-76**;
- `esp-tls-mbedtls`, `read`, return **-76**.

The pinned SDK defines this as `MBEDTLS_ERR_NET_RECV_FAILED` (`-0x004c`),
a socket read failure. It is not an allocation-error code. The separate
`restore-saved-station:reboot-request` returns at 240962.046; the software-reset
banner follows at 240962.406. Thus both messages arrive 266 ms after that
command returns and 94 ms before the reset banner, after the successful
uploads. The two rows may be one error propagated through two layers.

This narrows the [earlier unclassified observation](ESP32C3_TLS_FINAL_GATES_20261009.md)
to a socket-read error associated in time with the explicit restoration
reboot. It does not identify the underlying socket errno or prove cancellation
as the cause. The extended OTA runtime verdict remains `REVIEW_REQUIRED`;
the messages are not silently excluded because they are near a reboot.

The WebSocket reboot task currently delays 300 ms and calls `esp_restart()`
without first stopping audio. A useful next control is active-stream reboot
versus an explicitly stopped, settled stream, with the same numeric capture.
If that isolates the cause, evaluate bounded audio shutdown before reboot
without weakening TLS error reporting or changing saved playback settings.
