# AAC/SBR QMF BFP16 experiment — 2026-09-30

**Result: the tested 16-bit mantissa + shared-exponent representations fail the
required maximum PCM error of 1 LSB.** Even an exponent per complex sample gives
up to 3 LSB. Keep this experiment disabled in production.

The real ESP32-C3 Espressif decoder ran in QEMU, with full-rate HE-AAC and HE-AAC
v2/PS. Both unmodified decoders produced identical PCM in the control runs.
This is a numerical experiment, **not an implemented RAM saving**: the original
int32 matrices remain allocated. No physical board was flashed.

## Method and exact scope

The QEMU-only option `CONFIG_YORADIO_QEMU_AAC_BFP16_TEST` defaults to off and
requires `YORADIO_QEMU_AAC_TEST`, full AAC Plus, and neither cache tracing nor the
other instruction-profile suite. The
[implementation](../idf/esp32c3-oled-native/main/qemu_aac_bfp16.c) uses linker
wrappers around `calc_sbr_anafilterbank` and `calc_sbr_anafilterbank_LC`:

1. Call the original analysis filterbank with the original ABI and scratch.
2. Pack each new low-band QMF row into signed int16 mantissas. One exponent is
   shared by real/imaginary values for 32, 8 or 1 consecutive subbands in one
   time slot and channel. On the real-only LC-SBR path it covers real values.
3. Restore `int32 = mantissa * 2^shift` at the same location. Subsequent original
   high-band generation, envelope processing, PS and synthesis see these values.
   The original retained-history copies carry the quantized data into later
   frames. No other high-band/PS/synthesis state is narrowed by this experiment.

`shift` is the smallest nonnegative value permitting the block's truncated
values to fit signed int16. Packing rounds to nearest, ties away from zero;
a rounding carry is saturated at -32768/+32767. Reconstruction cannot overflow
int32, including `INT32_MIN/MAX`. Arithmetic checks exhaust all int16 values,
check int32 boundaries, and compare 4,096 random blocks at six block sizes
against a separate int64 division/rounding oracle.

Two independent decoder instances process identical 997-byte input chunks.
Compare **raw signed 16-bit PCM before output resampling, normalization or PDM**,
without a timing offset. Check consumed bytes, output length, full sample rate,
channels and PCM bit depth on every decoded frame; check buffer canaries.
Count exercised wrappers and changed QMF values so a skipped hook cannot pass.

The corpus consists of the existing six
[FDK-generated 0.5-second fixtures](../tests/fixtures/aac_stream_format/manifest.json).
Each case decodes the file twice without resetting between passes, then closes
both decoders. Run three times, alternating reference/candidate call order.
The second pass exercises retained histories across the repeated file boundary;
these passes are not a long continuous-source test.

Controls: all three AAC-LC fixtures, plus all three HE/v2 fixtures with both
wrappers bypassed (`bands=0`), produce **zero differing samples**. In total:
45 comparisons, including 27 quantized HE/v2 comparisons and 18 controls.
The original stream-format/transition suite also completes before this test.

## Measured precision

Maximum absolute error across both output channels, in signed 16-bit PCM LSB:

| Shared exponent covers | HE-AAC 44.1 kHz stereo | HE-AAC 48 kHz stereo | HE-AAC v2 44.1 kHz stereo |
| --- | ---: | ---: | ---: |
| 32 subbands | 5,689 | 5,016 | 1,818 |
| 8 subbands | 3 | 3 | 342 |
| 1 complex sample | 3 | 3 | 3 |
| Unmodified control | 0 | 0 | 0 |

All three repetitions give the same PCM error counts and maxima. For the finest
blocking, samples exceeding 1 LSB per run are:

- HE-AAC 44.1 kHz: **1,179 / 114,688** scalar samples.
- HE-AAC 48 kHz: **1,150 / 122,880** scalar samples.
- HE-AAC v2 44.1 kHz: **945 / 122,880** scalar samples.

These counts include both channels. Rates remain 44.1/48 kHz and outputs remain
stereo; the results do not use a lower-rate AAC-core fallback. HE v1 exercises
both complex and real-only LC-SBR analysis (mostly the latter); HE v2 exercises
complex analysis and PS. LC-SBR here is an SBR algorithm path, not AAC-LC audio.

The large errors with broad blocks show that small internal quantization steps
do not guarantee a small final PCM difference through this decoder. This test
does not identify the particular downstream operation responsible for each
large deviation. It rejects these schemes without claiming that every possible
16-bit adaptive representation is impossible.

## Instruction cost

Median increase versus the paired reference over three runs:

| Shared exponent covers | HE-AAC 44.1 kHz | HE-AAC 48 kHz | HE-AAC v2 44.1 kHz |
| --- | ---: | ---: | ---: |
| 32 subbands | +4.765% | +4.814% | +3.441% |
| 8 subbands | +5.136% | +5.147% | +3.415% |
| 1 complex sample | +7.971% | +7.985% | +4.970% |

These are **QEMU guest instructions**, not elapsed time or measured C3 CPU load.
`-icount shift=0,align=off,sleep=off` is required; a 1,024-NOP counter probe must
return 1,025. Count only decoder calls, including startup, packing/unpacking and
in-hook assertions/statistics; logging, comparison and voluntary sleeps are
outside the window. Tick interrupts and allocator placement effects remain.
Control instruction counts differ slightly (up to about 1.23% in the short
LC-mono case); that is not a demonstrated speed improvement. Per-run counts,
ranges and maximum decode-call work are retained in the JSON.

The old physical-board calibration is not applied automatically to this new
packing code. QEMU does not establish its Flash/cache stall cost on the board.
These overheads also do not predict a redesigned compact decoder that unpacks
at different access points.

## Memory and next steps

For the hypothetical original two-channel `80 × 32` complex low-band storage:

| Subbands per exponent | Mantissas | Exponents (1 byte each) | Total | Potential reduction from 20,480 B |
| --- | ---: | ---: | ---: | ---: |
| 32 | 10,240 B | 80 B | 10,320 B | 10,160 B |
| 8 | 10,240 B | 320 B | 10,560 B | 9,920 B |
| 1 | 10,240 B | 2,560 B | 12,800 B | 7,680 B |

These figures exclude unpacking workspace, alignment and allocation overhead;
PS aliases need separate accounting. **Measured saving of this prototype: 0 B.**
The binary's hard-coded int32 offsets prohibit shrinking the allocation alone.

- [x] Try BFP16 at the actual QMF analysis boundary; preserve measured failures.
- [ ] Try wider BFP mantissas (e.g. packed 24-bit) and compare with layout-only
  reductions. Retain the 1-LSB maximum and complete SBR/PS support requirements.
- [ ] If a compact scheme passes precision, recover speed: fuse exponent scans
  with QMF production, unpack only the active workspace, remove diagnostic
  counters from timed production code, and measure any additional copy/load
  cost. Repeat the same A/B and then physical C3 CPU/cache/underrun tests.
- [ ] For any surviving scheme, add long, transient, noise, silence, extreme
  envelope and channel-coupling vectors, resets/configuration changes, damaged
  input and OOM; prove a worst-case error/range bound. This short corpus already
  rejects the present scheme, but cannot qualify all AAC inputs.

## Reproduce

Use PowerShell 7 with the repository's ESP-IDF dependencies already installed.
From the repository/worktree root:

```powershell
.\idf\esp32c3-oled-native\build.ps1 `
  -DependencyRoot C:/Work/yoRadio/.idf `
  -BuildDirectory build-qemu-aac-bfp16 `
  -Sdkconfig build-qemu-aac-bfp16/sdkconfig `
  -SdkconfigDefaults @('sdkconfig.defaults', 'sdkconfig.qemu.defaults', 'sdkconfig.qemu-aac-bfp16.defaults')

& C:/Work/yoRadio/.idf/tools-v6.0.2/python_env/idf6.0_py3.12_env/Scripts/python.exe `
  tools/codec_benchmark/run_aac_bfp16.py `
  --dependency-root C:/Work/yoRadio/.idf `
  --qemu .build/qemu-cache-host/qemu-system-riscv32 `
  --bios /mnt/c/Work/QEMU-ESP32/share/qemu --wsl `
  --output .build/aac-bfp16

python tests/test-aac-bfp16.py
```

The QEMU path above is the local Linux Espressif QEMU 9.2.2 installation used for
this run. Supply your own matching executable/BIOS paths. For Windows QEMU,
omit `--wsl` and pass Windows paths. The runner merges a disposable flash image;
it never opens a serial port or performs OTA. **Expected experiment exit code:
2**, meaning the experiment completed but precision failed. Harness/build errors
are separate failures. The saved-evidence regression tests should exit 0.
