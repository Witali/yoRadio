# Opus ASM: ROM/reciprocal с полностью одинаковой компоновкой

Дата:2026-09-14. Только диагностический опыт, не production-профиль.

## Зачем

[Предыдущий tail-вариант](ESP8266_OPUS_ASM_SMALL_DIV_TAIL.md) замедлил
192 кбит/с до103,63% CPU против88,1%, хотя helper сам по себе выигрывал
в микробенчмарке. Тогда проверенные горячие функции ещё сдвигались на4 B.
Новый контроль отделяет смену callee от изменения этих адресов.

## Единственное различие

Исходный ELF: `esp8266-opus-small-div-tail-v1`.
Три `L32R a0; CALLX0 a0` в `ec_decode` / `ec_dec_uint` читают общий literal
по адресу0x402118ac. В B он содержит0x402e586c (`yoradio_opus_small_udiv`),
в A —0x4000e21c (исходный ROM `__udivsi3`). Это одно выровненное32-битное
слово, фактически меняются3 байта. Все остальные байты ELF идентичны:
инструкции, заголовки, символы, таблицы, адреса и RAM-секции.

В обоих образах присутствуют одинаковые helper/table. ROM-контроль их
не вызывает; ASM использует прежнее точное деление. Никаких runtime flags,
дополнительных branches, RAM-переменных или переключателей в hot loop.
ABI call0 и исходный C fallback не меняются.

`frozen_div.cjs` отказывается менять неожиданный, невыровненный или NOBITS
адрес. Родительский ELF связан hash с прошлым linked proof. Новый ELF не
перелинковывается: меняется только проверенное слово, затем вызывается
штатный SDK `elf2image --version=3`. Повторная упаковка B **побайтно**
совпала с исходным app. У A/B одинаковый размер903872 B; app отличается
только словом-адресом, XOR checksum и appended SHA256. Проверены обе суммы.

SDK QIO40 использует DIO в заголовке образа, затем bootloader включает quad;
это прямо задано `components/esptool_py/Kconfig.projbuild`, строки49–83.
Параметры взяты из реального build.ninja, не из предположения о manifest.
В этом опыте ни flash mode/frequency, ни кэш16 КиБ не переключаются.

## Воспроизводимость

- `node tools/esp8266_opus_asm/frozen_div.cjs` создаёт отдельные артефакты,
  не пишет в плату и не изменяет родительские бинарники.
- `firmware/development/esp8266-opus-frozen-div-{rom,asm}-v1/` содержит
  app, manifest, sdkconfig, проверку image_info; ASM-каталог дополнительно
  содержит `preflight.json` и исходный `linked.elf.gz` для воспроизведения
  даже при удалённом старом build directory. Его нужно восстановить в
  `.build/esp8266-opus-small-div-tail-v1/yoradio_esp8266_helix_native.elf`
  перед генерацией, проверив hash из preflight. Исходники целиком сохранены.
- Тест `esp8266-opus-frozen-div.test.js` проверяет весь ELF и оба app,
  отклоняет постороннее изменение payload даже с корректной новой checksum.
- Физический сценарий:10 ROM /10 ASM /10 ROM, CPU160, прежние fixtures
  12/24/64/128/192, пакеты заранее в RAM, без output/function/stage profiling.
- `report_frozen_div.cjs` сохраняет все30 попыток и проверяет PCM,
  samples/packets, OTA slots, manifests и профили. Ускорение относительно
  специально размещённого ROM-контроля само по себе не заменяет лучший88,1%.

18 предварительных регрессий проходят. Физическая серия начата;
результат будет добавлен после всех30 запусков. Цель70% не объявляется
достигнутой. Такой опыт не измеряет число cache misses и не отделяет
арифметику helper от его собственной конкуренции за кэш.
