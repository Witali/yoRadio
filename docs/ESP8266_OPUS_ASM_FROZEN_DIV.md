# Opus ASM: ROM/reciprocal с полностью одинаковой компоновкой

Дата:2026-09-14. Только диагностический опыт, не production-профиль.

## Зачем

[Предыдущий tail-вариант](ESP8266_OPUS_ASM_SMALL_DIV_TAIL.md) замедлил
192 кбит/с до103,63% CPU против88,1%, хотя helper сам по себе выигрывал
в микробенчмарке. Тогда проверенные горячие функции ещё сдвигались на4 B.
Новый контроль отделяет смену callee от изменения этих адресов.

## Единственное различие

Исходный ELF: `esp8266-opus-small-div-tail-v1`.
Три `L32R a0; CALLX0 a0` в `ec_decode` / `ec_dec_uint` читают общий literal
по адресу0x402118ac. В B он содержит0x402e586c (`yoradio_opus_small_udiv`),
в A —0x4000e21c (исходный ROM `__udivsi3`). Это одно выровненное32-битное
слово, фактически меняются3 байта. Все остальные байты ELF идентичны:
инструкции, заголовки, символы, таблицы, адреса и RAM-секции.

В обоих образах присутствуют одинаковые helper/table. ROM-контроль их
не вызывает; ASM использует прежнее точное деление. Никаких runtime flags,
дополнительных branches, RAM-переменных или переключателей в hot loop.
ABI call0 и исходный C fallback не меняются.

`frozen_div.cjs` отказывается менять неожиданный, невыровненный или NOBITS
адрес. Родительский ELF связан hash с прошлым linked proof. Новый ELF не
перелинковывается: меняется только проверенное слово, затем вызывается
штатный SDK `elf2image --version=3`. Повторная упаковка B **побайтно**
совпала с исходным app. У A/B одинаковый размер903872 B; app отличается
только словом-адресом, XOR checksum и appended SHA256. Проверены обе суммы.

SDK QIO40 использует DIO в заголовке образа, затем bootloader включает quad;
это прямо задано `components/esptool_py/Kconfig.projbuild`, строки49–83.
Параметры взяты из реального build.ninja, не из предположения о manifest.
В этом опыте ни flash mode/frequency, ни кэш16 КиБ не переключаются.

## Воспроизводимость

- `node tools/esp8266_opus_asm/frozen_div.cjs` создаёт отдельные артефакты,
  не пишет в плату и не изменяет родительские бинарники.
- `firmware/development/esp8266-opus-frozen-div-{rom,asm}-v1/` содержит
  app, manifest, sdkconfig, проверку image_info; ASM-каталог дополнительно
  содержит `preflight.json` и исходный `linked.elf.gz` для воспроизведения
  даже при удалённом старом build directory. Его нужно восстановить в
  `.build/esp8266-opus-small-div-tail-v1/yoradio_esp8266_helix_native.elf`
  перед генерацией, проверив hash из preflight. Исходники целиком сохранены.
- Тест `esp8266-opus-frozen-div.test.js` проверяет весь ELF и оба app,
  отклоняет постороннее изменение payload даже с корректной новой checksum.
- Физический сценарий:10 ROM /10 ASM /10 ROM, CPU160, прежние fixtures
  12/24/64/128/192, пакеты заранее в RAM, без output/function/stage profiling.
- `report_frozen_div.cjs` сохраняет все30 попыток и проверяет PCM,
  samples/packets, OTA slots, manifests и профили. Ускорение относительно
  специально размещённого ROM-контроля само по себе не заменяет лучший88,1%.

## Результат: 30 физических запусков, кандидат отклонён

Все 10 ROM / 10 ASM / 10 повторных ROM завершены. PCM hashes, число
samples/packets совпали во всех пяти fixtures каждого запуска. Каждый
fixture повторялся 10 раз (2,4 с аудио); интервал наблюдения 15 с.

| Поток, кбит/с | ROM CPU, медиана | ASM CPU, медиана | Повтор ROM | Max вызов ROM/ASM/ROM, мкс |
|---|---:|---:|---:|---:|
| mono 12 | 23,126% | 23,117% | 23,131% | 8370 / 7803 / 8962 |
| mono 24 | 54,943% | 55,421% | 54,966% | 15857 / 14463 / 15165 |
| stereo 64 | 65,960% | 69,099% | 65,964% | 18424 / 18848 / 18359 |
| stereo 128 | 79,153% | 86,818% | 79,163% | 25392 / 22255 / 21531 |
| stereo 192 | 91,202% | 103,620% | 91,189% | 23076 / 25191 / 23056 |

Максимумы CPU192: 91,254 / 103,769 / 91,294%. Наименьший sampled DRAM
остаток во всей серии — 8168 B; lifetime stack free — 1660 B. Static RAM
не меняется, что проверено по всем байтам ELF. Меньшее наблюдаемое
использование heap в отдельном запуске не считать экономией RAM.

Смена только callee увеличила время192 на **13,616–13,632%**,128 — примерно
на9,67–9,68%. На12 helper не вызывается, микроскопическое отличие — шум.
Результат лучше локализует регрессию, но не измеряет число cache misses:
арифметика helper и его конкуренция за flash-cache остаются совместными
факторами. Прежние17,6% нельзя целиком приписывать четырём байтам сдвига.

В `comparison.json` сохранён дополнительный расчёт: полная разница времени
декодера, делённая на число вызовов из host operand census, даёт9,42 мкс
на вызов при192. Это **не** исключительное время helper: сюда входят все
последствия для последующего выполнения/кэша. Входной census связан SHA256.

Архив содержит все30 JSON/log,3 OTA, сравнение и тесты. Повторный целевой
набор:15 PASS,0 FAIL,0 SKIP (`final-tests.log`); ранее19 предварительных
проверок сохранены отдельно. Новый тест пересчитывает весь A/B/A архив и
проверяет hashes/слоты/PCM/профили и отрицательное решение. Это не заявление
о зелёном полном наборе: его ранее найденные6 проблем перечислены в tail-отчёте.

Обычная прошивка `esp8266-opus-live512-idle3s-20260913` восстановлена OTA
(app SHA256 `661becd301b07885d493ceb1b513d9e874b7d86e4ada8231da8657aa90983c4b`,
slot0x10000). HTTP200 плейлиста, его прежний hash и ответы WS проверены;
current167, stopped, RSSI−61. Snapshot ждёт WS1,5с по сценарию — это не
замер задержки UI. UART/SPIFFS/настройки не изменялись.

Лучший исторический tell-inline остаётся **88,1% CPU192**, цель70% и live
квалификация не достигнуты. Этот диагностический вариант не принят.

## Следующие проверяемые гипотезы

- [ ] Обменять IRAM task-only `i2s_pdm_pack32` (456 B) на небольшой горячий
  ASM entropy-код; сначала проверить реальные секции, ABI и отсутствие
  роста RAM. ISR/DMA/Wi-Fi cache-off код не переносить. Перенос PDM во flash
  требует отдельной проверки вывода, даже если raw decoder ускорится.
  Важно: не просто выключать Pdm32Iram — связанный `pdm32_iram.lf` уже
  держит холодный `__moddi3` (959 B) во flash. Сохранить этот mapping,
  иначе исчезновение456 B вернёт959 B и увеличит расход IRAM.
- [ ] Рассмотреть branch для power-of-two делителя после выделения ctz.
  Однако census192 содержит только130/3163 таких вызовов (4,11%),128 —
  151/2017 (7,49%); выигрыша всего декодера заранее не обещать.
- [ ] Геометрию flash-cache проверить отдельно. `XCHAL_ICACHE_SIZE=0`
  и `LINESIZE=4` из core-isa.h не считать геометрией внешнего flash-cache.
  Случайный padding и вывод о cache misses без измерений не использовать.
