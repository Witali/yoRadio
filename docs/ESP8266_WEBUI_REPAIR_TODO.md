# ESP8266 native: незавершённые функции WebUI

Основание: [аудит 2026-09-05](ESP8266_WEBUI_AUDIT_2026-09-05.md).
Каждое законченное исправление — отдельный коммит с регрессионной проверкой.
Проверки исходников и проверки на физической плате отмечаются отдельно.
Общий WebUI сохраняет совместимость с Arduino, ESP32-C3 и CYD.

- [x] Начальная прокрутка к текущей станции: обе последовательности прихода
  списка/статуса; обновление списка сохраняет позицию; клик по строке и Stop
  не прокручивают список.

  команды и изменения станции/метаданных доставляются сразу.
- [x] Две вкладки одновременно: ограниченный набор подписчиков без взаимного
  отключения, фиксированная память, отключение медленного/исчезнувшего клиента.

- [x] Wi-Fi: чтение сохранённого CSV и безопасное сохранение из WebUI.
- [x] Загрузки: потоковое получение файлов ограниченными буферами, валидация,
  перестройка индекса и событие изменения плейлиста только после успеха.
- [x] Обслуживание: рабочая страница и корректное поведение доступных действий.
- [x] OTA: после согласованного переноса SPIFFS на 256 КиБ добавлены два

## Журнал

- Найден недостаточный бюджет lwIP PCB: SDK считает не только ESTABLISHED,
  но и listener, backlog, FIN/TIME_WAIT. При лимите 6 его tcp_alloc может
  вызвать tcp_kill_state(FIN_WAIT_1) -> tcp_abandon(..., 0), отбросив ответ без
  RST. Native-профили переведены на лимит 10: четыре HTTP-сессии, три места
  backlog, listener, радиопоток и один запасной контекст. Статический assert
  запрещает несовместимый лимит. MSS/окна/число HTTP-сессий не увеличены.

- HTTP, общий дедлайн: прежние 15 секунд относились к каждой отдельной записи.
  Частичное продвижение ответа позволяло удерживать HTTP-задачу значительно
  дольше. Теперь один дедлайн на весь ответ, проверяемый и при успешных
  частичных отправках. Истечение выводится как предупреждение с fd.
  Причина нестабильного прохождения TCP-пакетов и soak-проверка остаются открыты.

- Импорт плейлиста: одинаковый CSV сравнивается частями в существующем
  буфере и не вызывает переиндексации/события перезагрузки списка. Старый CSV
  сохраняется до успешной индексации нового, при ошибке восстанавливается.
  Старый индекс удаляется до публикации CSV, поэтому сбой питания не оставляет
  действительным индекс от другого файла такой же длины. Исполняемый C-тест
  проверяет неизменный файл, замену и откат после ошибки индекса.

- HTTP, пакетирование: CSV передаётся полными блоками по 512 байт, буфер
  статуса переиспользуется для одной строки; весь плейлист в RAM не читается.
  HTTP-заголовки и framing небольших чанков объединены в существующем scratch.
  Исполняемый C-тест проверяет реальные функции кодирования ответа, границы
  буфера и ошибки. На плате WebUI загрузил 511 станций, AAC/MP3 и команды
  работают, но холодная загрузка всё ещё занимала 43 секунды. Устойчивость
  и длительные задержки не считаются исправленными.

- Обслуживание/OTA: зарегистрированы Board, форма прошивки, reboot и сброс
  групп настроек. Форматирование и OTA сырого SPIFFS-образа не предлагаются:
  вместо них безопасный пофайловый импорт. Два слота по 960 КиБ, SPIFFS 256 КиБ;
  HTTP-стек увеличен до 5 КиБ для multipart. API показывает free/min heap,
  остаток HTTP-стека и адрес запущенного приложения. Сборка и 28 регрессий
  прошли; позднее разметка и OTA проверены на плате, см. отчёт выше.

- Импорт: GET Wi-Fi без кэша; POST upload/webboard/форма восстановления.
  Multipart разбирается частями (512 байт), запись через временный файл и
  резервное имя с восстановлением при старте. Плейлист валидируется и
  индексируется под его mutex; события изменения — после публикации файла.
  При многофайловом импорте каждый файл фиксируется отдельно, не вся форма
  транзакцией. Обслуживание останавливает радио. JS сообщает о неуспехе,
  не объявляет Wi-Fi сохранённым до HTTP-ответа и не обрезает пробелы.
  Десять регрессий прошли; проверка реальных загрузок ещё в приёмке.

- Время: повторное применение timezone в main, остановка/настройка/запуск
  SNTP — в lwIP callback. Сообщение переиспользуется, очередь неблокирующая;
  отдельная задача/стек и event group больше не выделяются. Сборка и 7 тестов
  прошли. Пользователь согласовал SPIFFS 256 КиБ + два OTA-слота с бэкапом.

- Настройки: Audio Info и AP reboot delay хранятся отдельными NVS-ключами,
  старый blob остаётся совместимым; delay применяется именно как задержка
  перезагрузки в AP, как в Arduino. Неподдержанные watchdog, screen-on,
  playing-saver не предлагаются. В headless-профиле настройки внешнего вида
  WebUI перенесены в System; выключенный OLED и отсутствующий энкодер скрыты.
  Неизвестные команды возвращают видимую ошибку; accepted означает приём
  изменения, а не уже завершённую запись flash. Аппаратная приёмка впереди.

- HTTP, первый этап: TCP_NODELAY для коротких записей, FIN через SHUT_WR после
  ответа (RFC 9112, §9.6), защита переиспользованной сессии от старого запроса
  закрытия. Сборка прошла. Причина всех задержек пока не установлена; пункт
  общей устойчивости остаётся открытым.

- Подписки: два фиксированных fd, общий буфер 1088 байт, HTTP-задача —
  единственный владелец форматирования/отправки. Активные WS не вытесняются
  LRU-загрузками. 22 регрессии и стандартная сборка прошли; две реальные
  вкладки и медленный клиент ещё требуют проверки в разделе приёмки.

- Битрейт исключён из причин немедленной рассылки, обновляется heartbeat
  раз в 2 секунды. Тест проверяет само выражение принятия решения: VBR ждёт,
  9 типов важных изменений не ждут. Замеры нагрузки — в аппаратной приёмке.

- Статусы: native передаёт connecting, API — также error; текст ошибки виден
  вместо метаданных. Новый поток начинает с пустого формата. 23 регрессии
  прошли; аппаратная проверка входит в общую приёмку.

- Прокрутка исправлена в общем JS; 18 тестов списка/управления прошли.
  Проверка реального scrollTop теперь обнаруживает отмену первоначального
  перехода, которую прежний тест вызова функции пропускал. Приёмка на плате ниже.
