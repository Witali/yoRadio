# ESP8266: время декодирования MP3 / AAC-LC / Opus, 19 сентября 2026

## Условия и результат

Физическая Wemos D1 mini, **160 МГц, QIO40**, PCM mono 48 кГц.
MP3 — актуальный Helix SSO mono/shared-reorder, AAC — Helix AAC-LC с выдачей
по 512 отсчётов, Opus — принятые 18 ASM-оптимизаций, перенесённые в main.
Для Opus использован сохранённый raw diagnostic образ принятой цепочки,
для MP3/AAC — новый отключаемый измеритель на текущих исходниках.

Десять запусков каждой матрицы: **2000 измеренных кадров на каждый MP3/AAC
битрейт и 1200 на каждый Opus битрейт**, всего 18000. Все 20 запусков
завершились успешно, без ошибок декодирования или несовпадения числа samples.
Opus PCM совпал с независимым generic32 эталоном. Прогревочный PCM hash Helix
стабилен между всеми повторениями; он не является независимым эталоном качества.

В таблице — медиана среднего времени CPU на кадр среди десяти запусков.
Измеряемый участок исключает копирование сжатых данных, HTTP/сеть, нормализацию,
PDM и ожидание DMA. FreeRTOS исключает время других задач, но ISR и небольшой
overhead измерителя остаются. Это не измерение CPU полного радио и не idle.

`CPU-бюджет = task_us / длительность декодированного аудио × 100%`.
Например, Opus 192 требует около **779 мс CPU на секунду аудио** по медиане.
Максимум wall включает вытеснение задачи; это НЕ максимум чистого CPU кадра.
Выброс AAC 48 до 60.212 мс сохранён, а не исключён как «сетевая задержка».
Причина этого конкретного вытеснения здесь не установлена.

## Разброс и ограничения

- MP3 320: 66.930–66.982% между запусками; AAC 320: 71.796–71.871%.
- Opus 192: **77.815–90.046%**, поэтому 77.88% — типичный результат,
  а не гарантия верхнего предела. Opus 128: 70.313–80.618%; 64: 61.174–68.809%.
  Медленные прогоны сохранены полностью. Нельзя объявить цель «всегда ≤78%» достигнутой.
- После вычитания оценки пустого интервала: MP3 320 — 66.77%, AAC 320 —
  71.64%, Opus 192 — 77.62%. В основной таблице overhead не вычитался.
- В среднем декодеры укладываются в realtime на выбранном контенте. Это не
  доказывает непрерывность всей цепочки с Wi-Fi/PDM: отдельные wall-вызовы
  превышают длительность кадра. Предыдущие live-ошибки этим тестом не исправлены.
- MP3/AAC используют один собственный tone/noise источник, Opus — ранее
  сохранённый собственный tone/noise корпус. Источники между этими группами
  не идентичны. Короткие клипы повторяются с reset состояния между кругами;
  цифры зависят от контента. Упрощённое сопоставление только по кбит/с неполно.
- AAC здесь **LC**, не HE-AAC/SBR. Opus 192 — последний измеренный битрейт,
  а не ограничение поддерживаемого потока.
- Измеряемый Helix-вызов включает обычный разбор MP3/ADTS и минимальный
  блочный callback, Opus — raw bounded decode без Ogg. Эти различия указаны
  явно; сетевой стек и аудиовывод не включены ни в одну строку.

## RAM и возврат обычной прошивки

Наблюдённый минимум свободной DRAM во время кадров: MP3 ≥11044 байт,
AAC ≥11400 байт, Opus ≥1376 байт. Остаток стека audio: Helix ≥3100,
Opus ≥1660 байт. Значения относятся к двум диагностическим образам,
не являются измерением всей занятой памяти декодера и не доказывают утечку.
После всех повторов Helix свободная DRAM возвращалась примерно к 24840–25040
байтам; накопительного снижения в этой серии нет.

OTA: main `0x10000` → Opus diagnostic `0x110000` → Helix diagnostic
`0x10000` → **обычная main `0x110000`**. Все три перехода подтверждены
HTTP 200/OK и адресом запущенного приложения. UART/reset не использовались.
Разметка, NVS и SPIFFS не перепрошивались; сохранение stopped при OTA —
обычный путь приложения. Байты плейлиста до/после совпали.

Возвращён `firmware/development/esp8266-main/app.bin`, 883264 байта,
SHA256 `671048e01e53790d875136d9f0136d60bc0dfd4242217de09a6f46c18b670cfe`.
Итог: «Ретро FM», stopped, RSSI −59 dBm, free heap 25756,
min heap 23052, web stack free 2312 байт; HTTP работает.
