# ESP32-C3: 19-bit high-QMF history for missing SBR frames

**Status: the expanded synthetic PCM gate passes; production qualification is
still open.** The maximum error falls from 5 to 2 signed-16 PCM units (LSB)
with 144 additional allocated bytes. The experiment remains QEMU-only and
does not change production defaults or the firmware installed on the board.

Follow-up: [five complete real recordings](ESP32C3_AAC_PC19_RECORDINGS_20261004.md)
also pass, with a 2-LSB maximum over 12,505,088 channel samples. Physical and
malformed-input gates remain open.

## Representation and lifetime

Only the persistent high-QMF history changes from 18-bit to 19-bit real and
imaginary mantissas, with a shared four-bit shift. The DSP scale, full decoded
sample rate, SBR/PS algorithms and channel support remain unchanged. Signed
32-bit inputs need shifts 0-13; rounding uses nearest with ties away from zero.

The existing aligned word holds the low 16 bits of each component. The original
metadata byte holds the shift and four high mantissa bits. Two additional bits
per complex pair live in the decoder context, 16 pairs per aligned 32-bit word.
For each channel's 288 pairs this is 72 bytes, or **144 bytes for two channels**.
The represented history uses 1,512 bytes per channel instead of the original
2,304 bytes, a **34.375% reduction** in that array. This is not a reduction in
all decoder memory by the same percentage.

The context owns the extra bits for exactly the owner's lifetime. New allocation
and SBR reopen clear them. A full history clear clears both components; a
real-only clear preserves the represented imaginary values. Channel selection
uses the active decoder's named frame fields, with membership assertions.
There are no added absolute addresses or numeric field offsets.

Two default-off Kconfig options control this experiment:

- `YORADIO_QEMU_AAC_HIGH_HISTORY_PC19`: three ten-bit metadata entries per word
  stored inside the SBR owner, used as a numerical/layout control.
- `YORADIO_QEMU_AAC_HIGH_HISTORY_PC19_SIDECAR`: the same arithmetic, with the
  additional two bits per pair moved into the decoder context.

## PCM comparison

The [SBR-gap corpus](ESP32C3_AAC_SBR_GAPS_20261004.md) plays each source with
extensions, without parser-identified SBR extensions, then with extensions
again. Every returned signed-16 sample is compared with native full-precision
history under the same retention controller. There is no alignment, resampling,
gain adjustment or skipped startup. The limit remains **3 LSB**.

## Actual allocation sizes

These are QEMU allocator measurements for the SBR owner plus native adapter.
The context is already contained in the adapter and is not counted twice.
They exclude AAC core/workspace, input, PCM, task stacks, Wi-Fi and TLS.

| Variant | Owner requested | Owner allocated | Adapter allocated | Owner + adapter allocated |
| --- | ---: | ---: | ---: | ---: |
| Full-precision history reference | 49,708 B | 51,188 B | 44 B | 51,232 B |
| PC18 baseline | 32,744 B | 32,756 B | 60 B | 32,816 B |
| PC19 metadata inside owner | 32,840 B | 34,804 B | 60 B | 34,864 B |
| **PC19 extra bits in context** | **32,744 B** | **32,756 B** | **204 B** | **32,960 B** |

Adding 96 bytes inside the owner crosses an allocator boundary and costs 2,048
allocated bytes. Keeping the extra bits in the context instead costs **144 B
relative to PC18**, retaining **18,272 B of savings against this reference**.
The reference already includes earlier lossless owner compaction; it is not the
original unmodified 55,128-byte owner. These measurements are not a claim about
total radio heap or physical fragmentation.

## Guest instruction work

The counter is checked with 1,024 NOPs (delta 1,025 including the counter read).
It surrounds only the first paired decoder's process calls. PCM printing, output
poisoning, the second decoder and explicit delays are outside the interval.
Enabled pointer/heap audits, memory-dependent checks and guest interrupts remain
inside. Chunk sizes, frame counts and process-call counts match in both builds.

| Source, all three phases | PC18 instructions | PC19 context instructions | Increase |
| --- | ---: | ---: | ---: |
| HE-AAC 44.1 kHz stereo | 59,964,548 | 62,248,760 | 3.81% |
| HE-AAC 48 kHz stereo | 65,040,436 | 67,494,994 | 3.77% |
| HE-AACv2 44.1 kHz stereo | 83,599,596 | 84,249,872 | 0.78% |
| HE-AAC 32 kHz mono | 37,944,948 | 38,438,647 | 1.30% |
| **Total** | **246,549,528** | **252,432,273** | **2.39%** |

This measures increased work in the audited harness, not physical CPU load,
cache stalls or real-time headroom. Do not apply the earlier board calibration
factor to this different audited workload. Performance remains a deployment
gate; batched metadata loads/stores are a candidate for reducing this overhead.

## Ownership and regression checks

- 971,369 pointer checks, 63,796 checked copies and 468 matched owner allocations
  and frees pass. The 16 KiB stack retains a measured 2,844-byte margin.
- Distinct signed data in the two channels expose incorrect channel selection.
  Real-only/full clears preserve the other channel and restore the selected
  channel cursor. Reopen clears extra bits while preserving the PS overlay.
- Existing reset-versus-fresh, partial-frame close, failure injection, concurrent
  decoder isolation, guarded buffers and heap integrity checks pass.
- Host ASan/UBSan tests cover all 524,288 signed-19 values at shift zero,
  1,000,000 random pairs, 289,025 boundaries and adjacent metadata slots. An
  independent int64 rounding oracle checks reconstructed values.
- A rerun caught a signed left shift in the new mask at bit 30. The mask is now
  explicitly `uint32_t`; the failing source/log are retained with the passing
  rerun. Existing 16/17/18-bit arithmetic regressions also pass.

## Reproduction and remaining gates

[Evidence](../tests/results/esp32c3-aac-pc19-20261004/) retains the four complete
configs, build and QEMU logs, patch audits, PCM, error histograms, instruction
counts, source snapshots and SHA-256 checksums. Build each saved config in a
separate fresh directory; do not build directly against the archived copy:

```powershell
$build = 'build-qemu-pc19-reproduce'
New-Item -ItemType Directory -Force "idf/esp32c3-oled-native/$build"
Copy-Item tests/results/esp32c3-aac-pc19-20261004/candidate/sdkconfig "idf/esp32c3-oled-native/$build/sdkconfig"
./idf/esp32c3-oled-native/build.ps1 -DependencyRoot C:/Work/yoRadio/.idf -BuildDirectory $build -Sdkconfig "$build/sdkconfig" build
python tools/codec_benchmark/run_aac_late_sbr_capture.py --help
python tests/run-aac-storage19.py
python tests/test-aac-pc19.py
```

Use the existing QEMU executable/BIOS paths with the capture runner, separate
`--build` and `--output` paths for each variant, and `--full-precision` for the
reference. Run `compare_aac_sbr_gap_pcm.py` and `compare_aac_late_sbr_pcm.py`
against that reference. `summarize_aac_pc19.py` takes baseline/candidate logs to
recompute actual memory and work changes. The evidence tests also reject missing,
duplicated or mismatched measurement records; they do not establish new physical
or extended-corpus results.

Before deployment: extend PC19 qualification to the saved real recordings;
repair HE-mono/PS metadata; test malformed extensions and allocation failures
during late activation; then run physical CPU/heap, HTTP/HTTPS, switching, OTA
and all supported codecs. The full playback goal remains open.
