# Opus: алгоритмическая переработка без роста RAM

2026-09-19. Accepted ASM eBands-final, ESP8266/LX106160МГц. Это анализ,
не новая прошивка и не подтверждённое ускорение. Дополнительная экономия
RAM желательна; побитный PCM, все режимы и C fallback обязательны.

## Вывод и ограничение

Имеет смысл перерабатывать горячие этапы, а не весь Opus с нуля. Формат
задаёт entropy-последовательность и зависимости состояния, но не способ
поиска по таблице и организацию временных массивов. Наше требование точного
PCM дополнительно запрещает произвольную перестановку округлений.
Основания: [RFC6716 range decoder](https://www.rfc-editor.org/rfc/rfc6716.html#section-4.1),
[shape decoding](https://www.rfc-editor.org/rfc/rfc6716.html#section-4.3.4),
[CWRS Xiph](https://github.com/xiph/opus/blob/v1.5.2/celt/cwrs.c).

Медиана77.880896% CPU192 требует сокращения времени ещё на3.6991%,
или576.18мкс на20-мс кадр (около92189тактов), чтобы достичь75%.
Это требуемый выигрыш, не прогноз. Затем нужны20с I2S PDM с WebUI.
Исторический coarse profile отводил bands67.49% инструментированного времени,
но profiler сильно искажал скорость: это приоритет поиска, не текущая доля CPU.

## 1. Другой поиск PVQ: новое предварительное исследование

В cwrs.c:cwrsi, many-pulses row-path, ищется наибольший j с U(n,j)<=i.
После определения знака и проверки U(n,n)<=i текущий код уменьшает k
последовательно. В рассматриваемой области n>=3,j>=n таблица возрастает.
Можно искать тот же индекс двоичным или комбинированным поиском, сохраняя
вектор, энергию и entropy-состояние. Дополнительный массив не требуется.

Host observer сначала вызывает неизменённый decoder, затем извлекает
начальный/конечный k из точного вектора импульсов. Модель заменяет сравнение
U(n,j)>i на j>конечный_k. Это не исполнение нового cwrsi или target ASM.
Двоичный поиск переиспользует уже прочитанный q=U(n,n) как нижнюю границу;
общая первоначальная загрузка q в счётчики не входит. Найденное значение
предполагается сохранённым, без дополнительного финального чтения.

Это суммы по файлам разной длительности, не CPU. Для192 файл0.24с:
6672 пробы меньше, около27800/с аудио. Prefix2+binary экономит12.50%,
galloping+binary16.61%. На12кбит/с CELT-PVQ отсутствует.
Проверено171436 диапазонов/ответов четырёх моделей;10 полных файлов12..510,
включая320 при2.5/5/10/20мс, exact PCM, одинаковые state/scratch/guards,
ASan/UBSan без ошибок. Это ограниченный корпус, не доказательство всех потоков.

Выигрыш27.50% относится только к пробам выбранного поиска. Binary добавляет
midpoint, границы, ветви и регистры; текущий ASM-loop короткий. Кроме того,
доступ к flash становится менее последовательным. Ускорение пока неизвестно.
Actual U-table/rank proof и ASM-кандидат теперь подготовлены:
[точный PVQ binary](ESP8266_OPUS_PVQ_BINARY.md).303906 linked случаев,
24 host-сценария проходят без роста RAM/frame. Физический10A/10B/10A2
завершён:77.872438/78.451979/77.871979% CPU192, binary отклонён.
Важное уточнение: на192 чтений меньше на27.50%, но
исполняемых инструкций поиска119961→237196, почти вдвое больше. Поэтому
гипотеза CPU-ускорения из одного числа проб не следует.

## 2. Удалить временный iy[N], переиспользуя X

alg_unquant выделяет int iy[N] (align8(4N) word-scratch), получает полный Ryy,
нормализует импульсы в int16 X, вращает X, затем читает iy для collapse mask.
Возможен отдельный decoder, который пишет импульсы непосредственно в X,
считает прежний Ryy, а затем нормализует X на месте. Для B>1 маску нужно
получить из исходных импульсов до их перезаписи; для B=1 она уже равна1.

Статические23 строки cache имеют max q40, get_pulses(40)=128: такие импульсы
помещаются в int16. Это анализ таблицы, ещё не полный range/alias proof.
Нужен fallback для неподтверждённых форм, без ограничения битрейта.
Нельзя просто alias существующей normalise_residual: вход int32, выход int16
и restrict требуют нового явно in-place цикла. X должен остаться в памяти,
допускающей16-битные обращения, а не word-only IRAM.

Потенциальная локальная экономия — align8(4N) байт. **Общее уменьшение RAM
не доказано:** пик может приходиться на другой этап. В текущем host-корпусе
пики byte/word scratch на192 —5488/15600B; это не размер всего приложения.
Резерв арены уменьшать только после lifetime-профиля, PLC/переходов/OOM и платы.
Старый отклонённый normalization+mask оставлял iy; новый подход отличается
удалением массива, но его скорость также нужно измерить. Начать с B=1.

## 3. Компактные продолжения вместо тяжёлой рекурсии

Accepted quant_partition имеет112B stack frame. Возможна DFS-машина
состояний, сохраняющая только параметры второго ребёнка, rebalance и маску.
Но второй бюджет зависит от remaining_bits после первого ребёнка:
порядок entropy/арифметики менять нельзя. Explicit stack не бесплатен;
его размер и глубину надо сравнивать с полной прежней глубиной стека.
Сначала измерить частоту N=2/4 и глубину рекурсии; короткий leaf может быть
проще полной переписи. Экономия и скорость пока не измерены.

## Что не повторять без новой причины

- Большой flash lookup уже ухудшал CPU19292.896→104.139%; flash/cache имеют цену.
- Уплотнение decoder-only quant_all_bands ухудшало77.860→81.875%, хотя кода меньше.
- Удалять второй спектральный канал из-за mono нельзя: CELT уже сводит спектр
  до IMDCT, но обе полосы/энергии/entropy и история остаются необходимы.
- Нельзя окончательно нормализовать первые импульсы, пока неизвестен полный Ryy.
- Другой FFT ниже по приоритету и требует проверки округлений/временной памяти.

## Контроль памяти и следующие действия

Сравнивать state, static DRAM/IRAM, резерв/пики обеих арен, stack high-water
и heap живого радио. Перенос из heap в stack не считать экономией. Проверять
SILK/Hybrid/CELT, mono/stereo, PLC/FEC,120мс, высокие битрейты и OOM-unwind.
Экономия RAM ценна, но не отменяет точность PCM и цель75% CPU.
