# Opus ASM: таблицы переходов вместо switch

2026-09-19. Предложение пользователя: заменить подходящие switch вычисляемыми
таблицами переходов. Аудит исходников, сохранённого GCC ASM и accepted linked
eBands-final ELF. Никакой новой оптимизации в firmware пока не включено.

## FFT: реальная цена до нового опыта

Сохранённый GCC snapshot использует1..4 условных сравнения. Linker расширил
дальние ветви в accepted ELF (function0x40253834,3627B):

```asm
40253ade: bnei a2, 3, 40253ae4
40253ae1: j    40253ec1
40253ae4: bgei a2, 4, 40253aed
40253ae7: beqi a2, 2, 40253afd
40253aea: j    40254630
40253aed: bnei a2, 4, 40253af3
40253af0: j    40253c0c
40253af3: bnei a2, 5, 40253af9
40253af6: j    40254085
40253af9: j    40254630
```

Для radix3/2/4/5 реально исполняется2/3/4/5 инструкций этого dispatch
соответственно. Это не число тактов: взятые ветви/cache имеют свою цену.
Четыре указателя требуют16B flash плюс literal/guard/addressing/JX.
Даже если ADDX4 заменит SLLI+ADD, таблица может проиграть короткому пути.
Dispatch выполняется на стадию FFT, а не на каждый butterfly.

## Более содержательная версия идеи: готовый план FFT

Для фиксированных стандартных размеров заранее во flash хранить порядок
стадий и параметры m/m2/fstride, при необходимости и метки обработчиков.
Это может убрать не только switch, но и повторный обход factors/умножения.
Сейчас fstride[MAXFACTORS] — восемь int,32B исходного stack-массива.
Удаление массива не гарантирует уменьшение frame на32B: нужны фактические
register allocation/spills. Никакого per-decoder RAM-кэша не добавлять;
custom/неподтверждённые конфигурации сохранять на общем пути.
Это отдельный более крупный кандидат, а не уже доказанное улучшение.

## План проверки

- [x] Проверить наличие switch и уже сгенерированных таблиц, сверить linked ASM.
- [ ] Снять частоты FFT radix dispatch на128/192 и меньших битрейтах.
- [ ] Независимо проверить таблицу локальных меток во flash: guard/default,
  ABI/SAR, все destinations/relocations, нулевой рост RAM/стека.
- [ ] Доработать verifier явным перечнем достижимых JX destinations из
  аутентифицированной таблицы. Текущий report_layout.reachableDisassembly
  намеренно отвергает JX; просто разрешить opcode без обхода всех целей нельзя.
- [ ] Проверить exact PCM/PLC/ошибочные входы и10A/10B/10A2. Меньшее число
  сравнений не является результатом бенчмарка.
- [ ] Отдельно проверить precomputed FFT plan: RAM/stack и flash/cache,
  не смешивая его с первым опытом простой таблицы переходов.

Вывод: идея применима выборочно и совместима с отсутствием роста RAM,
если таблица действительно остаётся во flash. Ускорение надо подтвердить,
не переводить все switch на function pointers/indirect calls автоматически.
Для локальных case-меток JX не требует нового call frame; CALLX0 через
указатель функции — другая трансформация с другой ценой и ABI.
