# Opus ASM: пропуск последней пробы PVQ

2026-09-15. ESP8266 / LX106160, QIO40. Отдельный raw-эксперимент, не production.
Контроль — принятый PVQ row-loop с tell-inline/MDCT pairs. Неподтверждённый
partition-points и другие кандидаты в контроль не включены.

## Реализация

После пяти шагов bits2pulses проверяется hi-lo. При разнице<=1 сразу
выполняется прежнее правило nearest endpoint; иначе остаётся шестая проба.
Математика и реальные частоты описаны в
[host-census](ESP8266_OPUS_BITS_FIFTH_PROFILE.md): на192 подходящий случай
встречается в1544 из1765 вызовов за0.24с, но это не процент ускорения.

Два фиксированных диапазона внутри quant_partition:

- 0x4024e209..0x4024e21d,20 B: SUB/MOV/BGEI/J; оставшиеся9 B недостижимы.
- 0x4024e27b..0x4024e297,28 B: исходный редкий шестой шаг и переход назад;
  6 B недостижимого padding. Прежний encoder-only участок недостижим при
  доказанном private encode=0, кроме нового decoder-перехода.

Все остальные байты ELF, адреса функций/инструкций/таблиц неизменны.
Frame112 B, static RAM и арены прежние; app903216 B. Нет новой таблицы,
вызова helper, стека или runtime-предела битрейта. Исходный C/GCC snapshot
сохранён; новый C-код используется только как host semantic model.

На быстром пути экономятся2 или4 команды, включая переходы; редкий путь
длиннее на3 или4 команды. Убирается как минимум одно чтение byte-таблицы.
Её linked адрес0x402d57fc находится во flash; это не измерение цены чтения
или cache misses. Ускорение всего декодера определяется только на плате.

## Доказательства и ограничения

Проверяется прежний decoder call-chain, неизменный ctx.encode=0 и
недостижимость занятого encoder-диапазона. Вне двух диапазонов инструкции
сравниваются полностью. Внутри нет store, вызовов или изменения SAR.

Исполнитель фактических linked-инструкций проходит все23 стандартные
таблицы и378304 бюджета(-64..16383), включая исходные пять шагов и выбор
конечного q. Совпадают выход q=0/ненулевой и все регистры, кроме a10/a11.
Для них отдельный проход по ВСЕМ продолжениям графа доказывает отсутствие
чтения до перезаписи/call-clobber/возврата caller-saved регистра.
Новое чтение вне строки запрещено. Все исполняемые patch-инструкции покрыты.

Математическое правило gap<=1 не зависит от выбранного битрейта. При
остальных gap выполняется исходный шестой шаг. Бюджеты перебора не являются
введённым ограничением поддержки. Encoder API не поддерживается этим
private decoder-overlay; исходная библиотечная C-реализация не удаляется.

Host24: точный PCM, mono/stereo, смена режимов, PLC/reset/OOM, phase и
составные пакеты до120мс/48frames,320/510 кбит/с. Host-модель возвращает
результат shortcut; это не только пассивный счётчик предыдущего опыта.
ASan/UBSan проходят; память/scratch/state sizes сохранены.

В первом отрицательном тесте неверно выбиралась первая L8UI во всей функции,
до моделируемого участка. Тест исправлен: мутация привязана к0x4024e1ad.
Исходный FAIL сохранён как negative-test-draft.log. Ошибки прошивки этим
FAIL не обнаружено; при мутации исполняемого чтения проверка должна отказать.
Связанный набор89 регрессий PASS/0skip, включая отрицательные тесты,
родительский ASM и прошлые физические отчёты. Это не весь тестовый набор
репозитория. Итоговые физические проверки этого кандидата ещё выполняются.

## Физическая проверка

10 A /10 B /10 A, приложения только через native OTA. Пакеты в RAM,
без audio output/function/stage profiler, одинаковые CPU/flash/fixtures.
Сохранять каждую попытку, max CPU/wall, RAM и ошибки; не фильтровать выбросы.
Критерий128/192 против низких битрейтов и цель80% — по основному плану.
Пока физический результат неизвестен; default не меняется.

Рецепт `tools/esp8266_opus_asm/bits_fifth.cjs`, комментарии ASM в bits_fifth.s,
proof в bits_fifth_proof.cjs. После серии восстановить ordinary через OTA,
проверить HTTP/WS и прежний плейлист/станцию. Это не live20с квалификация.
