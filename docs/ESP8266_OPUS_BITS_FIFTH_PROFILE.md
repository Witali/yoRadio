# Opus: нужен ли шестой шаг поиска bits2pulses

2026-09-15. Предварительная проверка следующего ASM-кандидата, не изменение
прошивки и не измерение скорости ESP8266.

## Гипотеза

Текущий quant_partition выполняет шесть развёрнутых шагов двоичного поиска
по cache_bits50. Если после пятого шага hi-lo<=1, можно сразу выбрать
ближайший из концов прежним правилом. При разнице больше1 оставить шестой
шаг. Новых таблиц, рабочего массива или ограничений битрейта не требуется.

Для hi=lo результат не меняется. Для hi=lo+1 шестой mid равен hi:
если cache[hi]>=bits-1, границы остаются прежними; иначе шестой шаг выбирает
hi, и правило ближайшего конца также выбирает hi. Проверка включает
особый sentinel стоимости -1 для lo=0, равные стоимости и выбор при равенстве.
Это доказательство результата поиска, ещё не регистрового/ABI контракта ASM.

Полный перебор23 существующих таблиц и бюджетов -64..16383:
378304 совпадения,377706 случаев с gap<=1. Эта доля не отражает частоту
реальных вызовов: большие бюджеты часто сразу насыщают поиск. Поэтому
дополнительно измерены вызовы на нашем воспроизводимом звуковом корпусе.

## Host-census

Копия tell-inline C-модели вызывает исходный bits2pulses, независимо
проверяет shortcut и возвращает исходный результат. Оригинальные исходники
и ASM не изменяются. ASan/UBSan, точный PCM и прежние размеры/пики scratch
подтверждены на10 файлах, включая320 с кадрами2.5/5/10/20мс и510 кбит/с.
Это не PLC/reset тест и не выполнение будущего ASM на компьютере.

Числа относятся к одному проходу каждого файла; длительность и hash каждого
сохранены в [summary.json](benchmarks/esp8266-opus-bits-fifth-2026-09-15/summary.json).
Не суммировать разные длительности как один профиль. На192 это1765 вызовов
за0.24с, из них1544 с потенциальным пропуском; не87.48% ускорения декодера.

Счётчик: `node tools/esp8266_opus_asm/profile_bits_fifth.cjs`.
Три Node-регрессии PASS: сохранённый exhaustive report,42240 дополнительных
проверок границ/равных значений и независимая проверка счётчиков/PCM/scratch.
Первый запуск остановился до анализа файлов из-за неверного ожидания имени
bands.c.o. Исправлены точный путь generated model object и порядок include:
celt/config.h должен оставаться первым для WORD_SCRATCH. Итоговая серия
завершилась после исправления; прошивка платы этим опытом не менялась.
