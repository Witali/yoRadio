# Opus ASM: N3 finite differences, четыре шага

2026-09-19. Независимый кандидат `esp8266-opus-pvq-n3-unroll4-{control,candidate}-v1`
над принятой eBands-final базой. Предыдущий N3-diff отклонён и не становится
production parent. Развёртывание проверяется против принятой прошивки.

## Изменение

Начальная проба U(K), первый fast return и site43B0x40253329 такие же, как
в скалярном N3-diff. Другие N сохраняют линейный поиск. Только helper в94B
decoder-dead storage0x40251024 заменён на23 инструкции/66B вместо8/21B.

При входе в группу p=U(3,K), delta=4*(K-1). Первые три стадии выполняют
p-=delta и проверяют результат до следующей стадии. При раннем выходе K
уменьшается на1/2/3 соответственно. Четвёртая стадия уменьшает K сразу на4
и либо возвращает результат, либо начинает следующую группу. Нельзя выполнять
все четыре вычитания без промежуточных проверок: это нарушило бы границу13.

Используются те же a2(index),a8(p),a12(K),a6(delta),a13(N). Перед возвратом
a6=N-1. CALL0/RET и48B исходного frame остаются; a0 мёртв до старого epilogue.
Нет новой таблицы, stores/SAR, scratch или дополнительных stack slots.
C fallback production не меняется, bitrate cap не вводится.

Для d=начальная_K-конечная_K,q=floor(d/4),r=d%4 предполагается
4+13*q+(r?3*(r-1)+4:0) инструкций helper вместо4+4*d, если d>0.
Это нужно сверить с actual linked кодом. Число чтений U остаётся таким же,
как у N3-diff; больший код может ухудшить кэш. CPU измерять, не выводить из
числа инструкций. Историческая скалярная серия не заменяет свежий контроль.

## 2026-10-04: выполнение целевого ASM в QEMU

По просьбе пользователя работа продолжается только на компьютере. Плата,
OTA, UART и production-конфигурация не затрагивались. Использован QEMU 9.2.2
из `C:/Work/QEMU-ESP32`, машина `sim`, CPU `lx106`: это эмуляция процессора,
не всей платы ESP8266. Стенд: `tools/esp8266_opus_qemu/`.

Декодер не перекомпилируется: исходный linked ELF восстанавливается из
`parent.elf.gz` и проверенных patches/preflight обоих вариантов. SHA256
проверяется до и после применения изменений. Адреса функций, литералов и
таблиц сохранены. Только отсутствующие функции ROM заменены функциональными
аналогами: memcpy, memmove, memset, signed/unsigned division, modulo и muldi3.
Оригинальные decoder/scratch/setjmp/longjmp исполняются как в ELF.

### Корректность и память

- 13 фрагментов ×2 варианта = **26 побитово точных сравнений PCM**.
  Вход: mono12/24, stereo64/128/192/320/510 кбит/с; выход декодера mono48kHz.
  Для320 проверены кадры2,5/5/10/20мс; дополнительно пакеты120мс и48 кадров.
- Первые пять фрагментов сравниваются с сохранёнными независимыми generic32
  PCM-хешами. Дополнительные — с vendored generic32 C под ASan/UBSan;
  этот второй эталон не является независимым pristine-декодером.
- В каждом случае проверены границы decoder state/PCM/byte/word arenas,
  преднамеренный scratch OOM и восстановление после повторной инициализации.
  Намеренно повреждённый canary завершается ошибкой, не ложным PASS.
- Decoder state6582B; максимальные пики byte5488/6144B и word15600/16384B
  одинаковы. Word peak включает размещённую там историю. Это не полная RAM
  прошивки. Watermark стека стенда2580/8192B также не заменяет стек FreeRTOS.

### Динамические инструкции, не такты

Считаются исполнения инструкций всей `decode_pulses` и helper N3;
вызываемые ими функции исключены. `exec,in_asm,nochain` учитывает повторные
исполнения блоков. Повторный192k-прогон дал те же счётчики.

| Вход, кбит/с | Принятая база, инструкций | N3-unroll4 | Изменение | Load-инструкций: база → кандидат |
|---|---:|---:|---:|---:|
| 128 | 473703 | 476166 | +0,52% | 68812 → 66928 |
| 192 | 639001 | 641480 | +0,39% | 94454 → 88552 |
| 320, кадр20мс | 763406 | 748496 | −1,95% | 127598 → 95485 |
| 510 | 4398487 | 4307767 | −2,06% | 735880 → 557082 |

Сравнивать нужно только варианты внутри строки: длительности фрагментов
различаются. Load-инструкция не равна транзакции flash или cache miss.
ROM-подстановки не моделируют скорость реального ROM; QEMU не моделирует
точные такты LX106, flash/cache, Wi-Fi и I2S. Адрес word-арены находится в
IRAM, но запрет узкого доступа ESP8266 здесь не эмулируется; статические
проверки ширины доступа обязательны отдельно. Большая память машины `sim`
не подтверждает достаточность RAM платы.

**Решение:** кандидат остаётся экспериментальным. На192k меньше чтений,
но больше инструкций; на320/510 есть перспективное снижение инструкций.
Это не основание объявлять снижение CPU или достижение цели75%.

### Воспроизведение

Из корня этого checkout:

```powershell
node tools/esp8266_opus_qemu/run.cjs --fixture stereo-192
node tools/esp8266_opus_qemu/run.cjs --variant esp8266-opus-pvq-n3-unroll4-candidate-v1 --fixture stereo-192 --no-self-tests --trace-pvq
node tools/esp8266_opus_qemu/suite.cjs --output .build/opus-qemu-repeat
node --test tests/esp8266-opus-qemu.test.js tests/esp8266-opus-qemu-results.test.js
```

Каталог `--output` должен быть новым; существующие доказательства не
перезаписываются. Нужны Node.js, установленный QEMU с `sim/lx106`,
xtensa-lx106-elf GCC8.4 и полученные Git LFS ELF-артефакты.
`run.cjs` допускает `--qemu` и `--toolchain` для других путей.
Расширенная серия также использует существующий WSL/GCC sanitizer-host и
FFmpeg/libopus для фиксированных тонально-шумовых фрагментов320k.
Никаких подключений к плате или сетевых интерфейсов у гостя нет.

Сохранены [сводка](../tests/results/esp8266-opus-qemu-20261004/summary.json),
PCM-вывод, сжатые динамические трассы, ошибки отрицательного теста,
версии/хеши инструментов, ELF/рецептов/фрагментов и inventory с SHA256.
