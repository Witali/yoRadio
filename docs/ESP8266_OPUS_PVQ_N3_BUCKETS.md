# Opus PVQ: fixed buckets for N=3 (next hypothesis)

2026-09-19. Host-модель, не новая прошивка и не измерение CPU.

В192k trace из24259 линейных U-reads7030 приходятся на N=3 и7003 на N=4:
вместе57.85%. Для всех174 сохранённых значений строки N=3 проверена формула
U(3,k)=2*k*k-2*k+1. MCU-вычисление sqrt/деления пока не предлагается:
более простой кандидат использует фиксированные buckets без NSAU/N-stride.

## Предлагаемый путь

1. Сохранить исходный первый U(K)-probe и немедленный возврат при index>=U(K).
2. Если N!=3 или K ниже порога12/16, оставить линейный поиск.
3. При N=3 проверить domain: index<16384 для shift6 или<65536 для shift8.
   Вне domain работает старый поиск. Это не ограничение битрейта или формата.
4. Читать table[index>>shift].256 полных32-битных верхних границ занимают1024B
   flash. Указатель и значение — два чтения, оба учтены в модели.
5. Начать точный поиск с min(K-1,bound): первый probe уже доказал answer<K.
   Нельзя снова начинать с K и терять известное сравнение.

## Проверено локально

- 570828 N=3 случаев по всем сохранённым U-интервалам, обе стороны каждой
 64-индексной границы, в том числе переход domain16384 и полная ширина строк.
- Две регрессии: испорченная формула отвергается; index16383 использует table,
 16384 — fallback; initial successful probe не вызывает helper; все10 trace
 файлов12..510 воспроизводят сохранённые значения.
- Точный residual index не сохранён в трассе; min..max — границы, не среднее.
- Никакой код прошивки/ASM пока не изменён этим исследованием. Проверка ранга
 не подменяет linked ABI/SAR/PCM/stack тесты будущей реализации.

| Поток | Исходные чтения | Shift6, K>=12 | Shift6, K>=16 | Helper calls K>=12/16 |
| --- | ---: | ---: | ---: | ---: |
|128кбит/с|11682|11038..11193|11106..11203|189/115|
|192кбит/с|24259|21333..21867|21479..21913|623/471|

Вариант K>=12 даёт на1929.86..12.06% меньше чтений всего этого поиска, включая
metadata. Это НЕ такой же выигрыш CPU. Текущий общий prefix0 вызывает helper3159
раз в той же трассе; новый специальный путь затрагивает существенно меньше
случаев. Количество инструкций, их адреса, flash/cache и дешёвый fallback ещё
надо проверить. Shift8 хуже на128/192 по чтениям, но лучше на320/510;
сохранены оба варианта, а не только лучший для одной записи.
