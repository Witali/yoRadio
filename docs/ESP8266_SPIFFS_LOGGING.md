# ESP8266 native: локальный журнал в SPIFFS

Опциональный диагностический режим. По умолчанию **выключен**.
HTTP-маршрута, WebSocket-команды или страницы выдачи журнала нет: по запросу
пользователя файлы предназначены для последующего чтения через USB.

## Включение при сборке

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esp8266_audio_profile/build_i2s_pdm_production.ps1 -Variant esp8266-spiffs-log -WebAudioPause short -SpiffsLog
```

Эквивалент для обычной CMake-сборки:
`-DYORADIO_ESP8266_SPIFFS_LOG=ON`. Для выключения — `OFF`, либо убрать
`-SpiffsLog` из команды сборочного скрипта. Скрипт явно передаёт ON/OFF,
поэтому старое значение в CMake cache не включает журнал неожиданно.
Этот скрипт **собирает, но не прошивает плату**.

Производственный профиль сохраняет только уже включённые сообщения об
ошибках (`CONFIG_LOG_DEFAULT_LEVEL=ERROR`). Файловый журнал сам не повышает
уровень логирования. `-MemoryProfile` можно добавить отдельно, но частые
диагностические строки могут переполнить небольшую очередь.

## Формат и ограничения

- `/spiffs/log/current.txt` — текущий файл, до 8192 байт.
- `/spiffs/log/previous.txt` — предыдущий файл, до 8192 байт.
- При ротации удаляется только прежний `previous.txt`, затем текущий файл
  переименовывается. Иные файлы, включая wifi.csv и playlist.csv, не удаляются.
- При перезапуске файл продолжается с меткой `application start`, не очищается.
- 512-байтная статическая очередь, без дополнительной задачи/стека и без
  malloc/FILE-буфера в модуле журнала. Точные дополнительные DRAM/ROM — по
  сравнению сборок ON/OFF, не только размеру очереди.
- Штатный `esp_log_set_putchar` дублирует обычные `ESP_LOGx` в RAM и сохраняет
  прежний вывод UART0 TX. В callback нет файловых операций или ожидания.
- App task сбрасывает до 256 байт не чаще раза в секунду. До успешного mount
  SPIFFS никаких файловых операций нет. При выключенной опции модуль не входит
  в сборку; вызовы инициализации/poll становятся пустыми inline-функциями.
- Полная очередь отбрасывает новые байты, не блокирует задачу. Когда появляется
  место, записывается метка `dropped ... bytes total`. Переполнение может
  обрезать строку/UTF-8 символ. Это best-effort журнал, не гарантированная трасса.
- При занятости более 75% SPIFFS или остатке менее 8192+256 байт запись
  откладывается. Ошибки info/stat/open/write/rename/unlink повторяются через
  30 секунд, а не на каждом проходе цикла. Пользовательские файлы ради места
  не удаляются. Учитывайте также служебные страницы файловой системы.
- Ошибки самого SPIFFS из writer task не добавляются обратно в его очередь:
  это предотвращает самовоспроизводящееся логирование. Логи других задач
  во время записи принимаются, пока есть место.

SPIFFS/flash не имеют гарантированного времени записи: GC и отключение
flash cache способны задержать звук даже при небольшом блоке. Профиль
предназначен для диагностики, а не бесконечного verbose-логирования;
постоянная запись также изнашивает flash. Уже существующая реализация SDK
форматирует сообщения через asprintf/vasprintf: сам новый callback не выделяет
heap, но он не устраняет выделения внутри SDK. При крайнем OOM сообщение может
не дойти до callback вообще.

Обычный printf, ROM/bootloader, panic и ESP_EARLY_LOGx обходят этот hook.
Журнал не заменяет crash dump. При сбросе/отключении питания хвост очереди
и незавершённая запись могут пропасть; принудительный flush из panic/ISR
не выполняется. Внутри SPIFFS каталогов нет, `log/` — часть имени объекта.

## Ошибка закрытия файла: важная особенность SDK

В используемом SDK `SPIFFS_close` сначала сбрасывает cache. При неудаче
внутренний handle может остаться занят, но VFS уже удаляет внешний fd.
Поэтому нельзя повторять close по старому fd: он может принадлежать другому
файлу. При такой ошибке журнал прекращает дальнейшие записи до reboot,
не открывает новые дескрипторы и не создаёт цепочку утечек. Возврат RAM/handle
внутри неисправной SPIFFS в этом случае не гарантируется. Это осознанный
fail-stop режима журналирования, радио/WebUI продолжают работать.
Счётчики `spiffs_log_get_status()` содержат pending/dropped/io_errors,
low_space и storage_fault; сетевого доступа к ним нет.

## Получение через USB позже

Это отдельная операция обслуживания, не автоматическое действие при
подключении кабеля. UART RX/GPIO3 используется как I2S DATA: для чтения flash
через ROM-загрузчик нужно освободить RX от аудиоцепочки или отдельно
согласовать безопасный переход. UART-команды приложению не отправляются.

1. Считать partition table/проверить установленную разметку. В текущей native
   разметке SPIFFS расположен по `0x3c0000`, размер `0x40000` (256 КиБ).
2. Сохранить этот диапазон командой esptool `read_flash` в приватную
   игнорируемую папку `.build/`. Это чтение, не erase/write, но переход в ROM
   прерывает радио и требует отдельно разрешённого сброса.
3. Распаковать копию совместимым mkspiffs: block=4096, page=256,
   OBJ_NAME_LEN=32, META_LEN=4, USE_MAGIC=1, USE_MAGIC_LENGTH=1,
   **ALIGNED_OBJECT_INDEX_TABLES=4**. Обычный Arduino mkspiffs с alignment=0
   не подходит. См. [разметку](ESP8266_OTA_LAYOUT.md).
4. Читать `log/current.txt` и `log/previous.txt`. Не публиковать полный дамп:
   кроме журнала он содержит Wi-Fi credentials. Сам журнал тоже может
   содержать имена/адреса сети и URL радиостанций.

Установка прошивки с опцией OFF не удаляет сохранённые журналы из SPIFFS.
Никаких изменений Wi-Fi компьютера, UART RX-команд и автоматического сброса
этот режим не делает.

## Проверки

`node --test tests/esp8266-spiffs-log.test.js` исполняет реальный код logger
с mock FS/SDK: сохранение UART, idempotent init, очередь до mount, лимиты
записи/файлов, ротация, tick wrap, полный раздел, short write, отказы
info/stat/open/write/rename/unlink/close, рекурсивные сообщения и имитация
поступления данных от другой задачи во время записи. Также проверяются
отсутствие HTTP-экспорта и отсутствие динамических выделений в модуле.

Проверка на ПК не измеряет задержки реальной flash. Перед длительным
использованием профиля на плате нужны замеры audio underrun и RAM.

API сверено с [официальной документацией Espressif](https://docs.espressif.com/projects/esp8266-rtos-sdk/en/latest/api-reference/system/log.html)
и исходниками установленного ESP8266_RTOS_SDK: log.c, esp_spiffs.c,
spiffs_hydrogen.c и vfs.c.
