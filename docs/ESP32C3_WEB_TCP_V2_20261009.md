# ESP32-C3 compact TCP telemetry and extended HE-AACv2 playback

The [first TCP probe](ESP32C3_WEB_TCP_PROBE_20261009.md) lost USB log
characters and could not qualify its trace. The compact v2 repeat passes
**17/17 controller checks**, including a separate integrity gate during 180
seconds of HE-AACv2 TLS playback. Additional whole-phase replay rejects two
EOF trace intervals because event records are missing. The previous intermittent WebUI connection timeout
does **not** reproduce here and remains unresolved.

## What changed

Verbose TCP/listener lines become **58-byte ASCII frames**, or 59 bytes when
the VFS translates LF to CRLF. Each carries CRC-32/ISO-HDLC over its header
and five data words. The CRC uses the ESP32-C3 ROM routine at `0x40000628`.
It and console output run in the existing WebSocket task, outside lwIP's
core lock. No packet ownership, TCP timeout, retry or audio operation changes.

A once-per-second watermark reports generated/emitted event sequences,
queued count and drops. It exposes lost final events even if no subsequent
connection is made. The host rejects damaged/merged frames, sequence gaps,
duplicates, queue drops, inconsistent watermarks and gaps over 2.5 seconds.
Qualification is explicitly limited to complete first/last anchors; edge
durations are reported. See [wire format and tests](ESP32C3_TESTING.md#webui-tcp-handshake-diagnostic).

The 64-event RTC ring remains 1,024 bytes. Compared with the previous probe,
BSS grows by 8 bytes while linker alignment padding shrinks by 8 bytes:
the ordinary heap boundary remains **`0x3fc9a0c0`**. RTC/IRAM sizes are
unchanged, and the application grows by 352 bytes. No extra task is added.
This comparison does not measure maximum stack use.

## Build and host validation

- Two ASan/UBSan wrapper variants, with TCP backlog enabled/disabled, pass
  destructive packet-lifetime, forwarding, state/filtering and queue tests.
- Each emits 70 real C-generated frames, independently decoded and checked
  using Python's CRC implementation.
- Eight parser tests cover field mapping, every hex-digit replacement and
  deletion, merged lines, missing final events, sequence gaps, drops and wrap.
- The ELF audit verifies actual lwIP wrapper routes and independent sampling.
  GCC inlines the frame encoder; the supplementary audit checks all three
  inlined CRC/output paths and the `crc32_le` / `esp_rom_crc32_le` ROM alias.
- Full AAC, HTTP and TLS allocator audits pass. **128 code/constant sections
  in 18 AAC/FLAC objects remain identical** to the retained-queue baseline.

Controls remain ESP-IDF 6.1 revision
`9a97f6c54ec638111ce55cd36581b3c192f15207`, QIO 80 MHz, full compact AAC/SBR/PS,
17,058-byte TLS RX reserve, four experimental extra FLAC slots, 500/250 ms
prefill and the experimental fractional PDM clock. The runtime flash probe
confirms QIO/80 MHz and four matching complete-image CRC reads. The separate
clock readback confirms the intended laboratory fractional divider.

## Physical observations

The trial repeats three FLAC 48 kHz -> HE-AAC 48 kHz -> HE-AACv2 44.1 kHz
switch cycles and four HTTPS EOF cases (FLAC/HEv2, AUTO/explicit). HEv2 TLS
record growth is extended from 75 to **180 seconds**, followed by stopped
memory checks and one minute without HTTP polling.

The dedicated TLS trace qualifies **178.609 seconds** between its complete
anchors: 2,955 events, 170 listener samples and 171 watermarks. Its edge
intervals of 0.797 and 0.688 seconds remain explicitly unqualified. The
first observed event after boot is sequence 34; no claim is made about
earlier startup events. Of 11 phase intervals long enough for bounded replay,
nine pass and two fail: HEv2 HTTPS EOF with AUTO and explicit AAC. Event
sequences **1067** and **1198** are missing, one in each interval. Their
surrounding valid records are separated by about 250 ms. Intact ring-drop
counters remain zero. The filtered capture cannot establish whether an
entire USB frame or only an unrecognized prefix was lost; the complete
TCP trace is not qualified across these gaps.

Independent DMA replay covers **165.281 seconds** with 34 complete samples:
15,495 writes / 31,733,760 bytes, zero increments in descriptor-reuse overruns
or write errors. This is digital progress/counter evidence, not an analog
continuity or listening test. These diagnostic runs are not a matched
production-speed comparison, and heap-layout differences between boots
must not be interpreted as a new memory saving.

## Interpretation and remaining work

All retained v2 frames have valid CRC in this run, while sequence checks
correctly expose two missing event records. The longer TLS interval passes
both checks. Compact framing does not guarantee USB delivery, and CRC alone
cannot detect the absence of a whole record. The prior failed telemetry and WebUI
connection attempts remain preserved in their original reports.

The next qualification work is heavy FLAC/AAC continuity and the complete
format/network/OTA matrix with the intended production settings. Retain
this default-off probe for correlating another WebUI timeout; do not infer
that the timeout is fixed merely because this longer run passes. Optional
extra FLAC slots and exact-clock output are not enabled in production by
this diagnostic change. Exact-clock listening remains deferred.
