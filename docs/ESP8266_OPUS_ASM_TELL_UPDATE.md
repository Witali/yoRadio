# Opus ASM: tell-inline + update-fast

2026-09-13. Отдельный backend `bands-tell-update-asm`, default не меняется.
Проверяем, даст ли fast update дополнительный выигрыш к лучшему tell-inline,
а не только к исходному GCC-ASM. Цель 70% пока не достигнута.

## Проверки

- [ ] Побитно точная композиция прежних макросов: 4 tell и 2 update места.
- [ ] Проверки инструкций родителей, полный host PCM/PLC/reset/OOM/guards.
- [ ] Одинаковый профиль сборки, без увеличения static RAM/арены/стека.
- [ ] 10 новых tell-inline контролей, 10 комбинаций, 10 повторных контролей.
- [ ] Все попытки, максимумы, абсолютные и относительные разницы CPU.
- [ ] Вернуть обычную прошивку через OTA; GPIO3 не использовать для UART.

Отдельный update-fast дал на 12 кбит/с +84–85 мкс CPU на 20 мс аудио
(+0,42 процентного пункта загрузки), на 128 экономию 405–407 мкс,
на 192 — 193–207 мкс. По запросу пользователя не отбрасываем гипотезу
сочетания лишь из-за относительного замедления низкого битрейта.
Прежний относительный критерий сохраняется в отчёте отдельно от абсолютного
результата; критерий достижения 70% не меняется. Выигрыши не складываем.

ABI и арифметика описаны в `tell_inline.inc.s` и `update_fast.inc.s`.
Исходные макросы и protected GCC/C snapshot неизменны. Таблица correction
остаётся одна, общая entropy-функция сохраняется для холодного пути.
