# Частота путей PVQ: выбор следующей ASM-оптимизации

Дата: 2026-09-14. Это host-анализ нагрузки, не замер скорости Xtensa.
Текущий лучший физически проверенный raw ASM: около87.48% CPU192;
цель70% и непрерывный I2S PDM ещё не достигнуты.

## Методика и границы

`node tools/esp8266_opus_asm/profile_pvq_paths.cjs` собирает fixed-point
host-декодер с ASan/UBSan и отдельный observer через `--wrap=decode_pulses`.
Сначала исполняется неизменённый декодер, затем анализируется точный вектор
целочисленных импульсов. Observer не читает entropy повторно и не изменяет
вектор или состояние. Контроль и observer декодируют каждый файл один раз;
PLC/self-test не запускаются, чтобы не удваивать счётчики.

Для каждой координаты, кроме двух заключительных, известны оставшиеся N/K
и модуль импульса M. По исходному cwrsi:

- K>=N: ветвь many-pulses. Если K-M<N, поиск по столбцу делает N-(K-M)
  проб; иначе поиск по строке делает M+1 проб, включая начальную row[K].
- K<N, M=0: быстрый путь нулевой координаты.
- K<N, M>0: поиск по уменьшающемуся индексу строки делает M проб,
  из них M-1 дополнительных после первой.

Это семантические числа проб исходного алгоритма, не буквальные счётчики
ветвлений развёрнутого ASM и не оценка тактов/flash misses. Проверяются сумма
модулей K и энергия, равенство PCM, размеры состояний и пики scratch.
Девять ручных unit-векторов покрывают оба знака, оба поиска, граничный N=2,
нулевые координаты и переход между ветвями. Полный декодер проверен отдельно
на десяти файлах; все PCM побитно совпали, ошибка0, arena guards целы.
Это не универсальное доказательство всех допустимых битовых потоков.

шум: первые12 кадров по20мс, 0.24с аудио. 12/24 — mono, остальные stereo;
декодированный выход mono48кГц соответствует текущему benchmark.

## Изменение приоритетов

На192 many-pulses — 62.6% нетерминальных координат. Поиск по строке делает
24259/0.24=101079 проб на секунду аудио; сверх первой — 79392 проб/с.
Ранее предложенный cache ROW[k-j] для дополнительных many-dimensions проб
затрагивает лишь301/0.24=1254 проб/с. Первый поиск завершается сразу в
1316/1593=82.6% случаев. Не отменяем эту гипотезу, но понижаем приоритет.

- [x] Проверить observer и сохранить статистику без изменения прошивки.
- [ ] В частом many-pulses row-loop убрать повторный перенос счётчика
  между регистрами и лишний безусловный обратный переход; использовать уже
  вычисленный указатель row[K], не строить его заново. Проверить весь
  linked CFG, регистры на выходе и точную последовательность чтений.
- [ ] Проверить отдельный frozen-layout ASM-кандидат на плате:10 A/B/A,
  прежние160МГц/QIO40/RAM, точный PCM, все режимы и никакого лимита битрейта.

Никаких данных, кода observer или счётчиков в прошивку не добавлено.
Нулевое число PVQ-вызовов в mono12 ожидаемо: этот файл декодируется SILK.
Частота вызовов сама по себе не доказывает ускорение; принимать только по
физическим измерениям полного raw-декодера и прежнему high-bitrate gate.
