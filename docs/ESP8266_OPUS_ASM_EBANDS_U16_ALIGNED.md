# Opus ASM: EXTUI с сохранением выравнивания ветвей

2026-09-17. Независимый опыт по сохранённому плану. Контроль — принятый
eBands-final, не отклонённый eBands-u16. Обычный C fallback не меняется.

## Гипотеза

Ранее замена SLLI+SRAI на EXTUI в шести helpers уменьшила число исполняемых
инструкций, но не прошла критерий скорости. У пяти helpers начало cross-ветви
сместилось с entry+16 на entry+13. Новый кандидат оставляет ту же EXTUI,
но возвращает адрес cross entry+16 тремя недостижимыми байтами после RET.
У шестого split-helper cross остаётся0x4024dd14, как в обоих прежних опытах.
Число исполняемых инструкций остаётся на одну меньше контроля; padding
не исполняется. Связывать прежние тайминги с cache без измерений нельзя.

## Корректность и память

Сохраняются все адреса вызовов и остального кода, регистры/SAR, стек192B,
чтения памяти и размер образа. Используется только неизменяемая стандартная
таблица eBands:22значения0..100. Произвольный signed16 к этой замене
не относится; сами PCM-сэмплы остаются знаковыми. Битрейт не ограничен.

Проверяются оригинальные helpers, таблица, каждое входящее ребро, обе ветви,
401280 числовых случаев и символические биты. Дополнительная проверка
требует исходных адресов cross и отсутствия входов в недостижимые3B.
Никаких новых RAM-буферов, heap-выделений или роста стека нет.

## Воспроизведение

```powershell
node tools/esp8266_opus_asm/ebands_u16_aligned.cjs
node tools/esp8266_opus_asm/check_bands.cjs ebands-u16-aligned
node --test tests/esp8266-opus-ebands-u16-aligned.test.js
# OTA явно для каждой серии; raw packets in RAM, no output/profilers:
& tools/esp8266_opus_profile/run_raw_series.ps1 -Directory .build/opus-ebands-u16-aligned-board-20260917/before -Fixtures firmware/development/esp8266-opus-asm-library/fixtures -Attempts 10 -IntervalMs 15000
node tools/esp8266_opus_asm/report_ebands_u16_aligned.cjs
```

Нужны три отдельные серии before/candidate/after с соответствующим образом:
минимум10/10/10. Сохраняются все попытки, maxima и низкие битрейты. Два
high-bitrate критерия должны пройти одновременно. Цель75% отдельно от
критерия принятия маленького улучшения; live I2S/WebUI проверяется отдельно.

## Результат: кандидат не принят

Все30 физических попыток A/B/A2 завершены, по10 на вариант. На плате
совпали PCM hashes, packets/samples; ошибок декодера и HTTP-наблюдения нет.
Пять локальных preflight-регрессий и15 итоговых тестов метрик/архива прошли,
без пропусков; все24 host-сценария exact PCM до510kbps/120ms.

| Поток | A: eBands-final | B: EXTUI aligned | A2: повтор контроля |
|---|---:|---:|---:|
| mono12 |23.095479%|23.084438%|23.092646%|
| mono24 |53.886396%|53.889625%|53.881500%|
| stereo64 |61.182271%|61.209271%|61.191292%|
| stereo128 |70.385687%|70.404708%|70.372021%|
| stereo192 |77.875625%|77.859187%|77.879229%|

На192 относительный выигрыш0.021107%/0.025734% против A/A2;
на128 замедление0.027024%/0.046450%. Максимальное замедление низких
битрейтов0.044130%/0.029382%. **Оба high-bitrate gate FAIL.**
Ускорение192 всего0.016438 процентного пункта против A (около3.29мкс
на20мс аудио) не компенсирует ухудшение128. Перекрывающийся разброс не
позволяет объявить выравнивание доказанной причиной предыдущих таймингов.
Не складывать этот результат с другими улучшениями и не принимать
один удачный поток отдельно. Принятый baseline остаётся eBands-final.

Максимальный вызов на192 A/B/A2:19.949/20.980/20.771ms.
Минимальный sampled free DRAM по всем пяти потокам:2940/5184/7484B;
audio stack free минимум1660B. Static RAM/IRAM и стек функций прежние:
колебания общей свободной кучи не являются новой экономией памяти декодера.
В A2/run2 mono12 task_us превысил wall_us на2615мкс. Этот случай сохранён,
не отфильтрован, не подрезан; empty-loop из итогового CPU не вычитается.

Цель75% raw CPU192 не достигнута. Этот тест без аудиовывода не подтверждает
ни20sнепрерывного I2S, ни отзывчивость WebUI при воспроизведении.
Runtime flash QIO40, CPU160; DIO40 в заголовке образа — стадия загрузки.
