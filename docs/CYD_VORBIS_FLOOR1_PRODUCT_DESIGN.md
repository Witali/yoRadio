# Exact floor1 spectrum multiplication

This component advances the wide Vorbis synthesis path from inverse coupling
through the floor1 part of the elementwise product. It does not select a new
production decoder. Floor0 gain application, inverse MDCT, windowing, overlap,
PCM conversion, decoder lifecycle integration and native resource gates remain
required by the transfer plan.

## Reference and retained table

[Vorbis I sections4.3.6 and7.2.4](https://xiph.org/vorbis/doc/Vorbis_I_spec.html)
require a length blocksize/2 floor curve multiplied by the corresponding
channel's residue after inverse coupling. The specification explicitly warns
against prematurely narrowing the residue to a32-bit fixed-point domain.

The256 decimal float literals are copied unchanged from the pinned
libvorbis1.3.7 `lib/floor1.c`, not regenerated by an exponential approximation.
The component retains the complete Xiph license in `COPYING`. Every literal
matches the official inverse-dB table when rounded to binary32. A compile-time
check requires binary32 float storage; multiplication itself uses integer
arithmetic and reads table bits with `memcpy`, without aliasing casts.

All factors are positive finite normal binary32 numbers at most1. Each is
represented exactly as an odd unsigned integer m times2^e:

- e is in[-47,0]; m uses at most24 bits.
- Index0 is7494175 times2^-46, a quiet present floor, not zero.
- Index1 is15962377 times2^-47.
- Index255 is exact unity.

## Exact product representation

`native_vorbis_floor1_scale_measure` accepts the coherent numeric shape of a
planar residue grid and the actual bins-byte curve. For source integers S
with abs(S)<2^M and source exponent E, calculate:

```
low = min(e[i])
high = max(e[i] + ilog(m[i] - 1))
result.exponent = E + low
result.magnitude_bits = M + high - low
result.limbs = (result.magnitude_bits + 32) / 32
```

Here ilog(0)=0. Thus m[i]<=2^ilog(m[i]-1), and each aligned product is strictly
smaller in absolute value than the result magnitude bound. Every coefficient
is at most1, so high<=0 and high-low<=47. Constant quiet curves use fewer bits
than curves containing both index1 and unity.

The existing format-derived residue bound is M<=1079, hence at most1126
product magnitude bits. The arithmetic helper also accepts coherent signed
34-word shapes up to M=1087; its maximum is1134 bits. Both require at most36
uint32 words including sign. These bounds follow from the encoded format and
table, rather than adding a new accepted-stream limit. Output exponent
arithmetic uses int64 and returns RANGE if it cannot fit int32.

Each source sample is sign-extended to the result width, multiplied by a
positive at-most24-bit integer, then shifted left on the common exact grid.
An unsigned64-bit partial product suffices: (2^32-1)*(2^24-1)+carry<2^56.
Unsigned modular arithmetic yields the two's-complement result; the proved
magnitude bound prevents signed wrap in the represented mathematical value.
No rounding, saturation, division or conversion of the residue to float occurs.

## Frame composition and ownership

The frame wrappers use the existing unchanged floor1 reconstruction and curve
renderer. They retain original floor presence; a channel whose residue was
needed for coupling still produces zero if its own floor was absent. All
floor1 factors are finite, so a present floor over implicit-zero residue also
produces zero without materializing a curve. This shortcut does not establish
a floor0 pole or indeterminate-domain policy.

Process one channel at a time with caller-owned bins-byte curve scratch and
caller-owned exact output storage. No heap, VLA, mutable global state or in-place
operation is introduced. Setup, frame, raw Y and residue borrows must remain
alive and immutable. The floor1-specific API returns INVALID if called for a
floor0 channel; the eventual decoder dispatcher must select the floor0 path.

Measurement publishes its layout only on success. Scale remeasures and checks
shape, object-byte addressability, capacities and every selected source sample
before writing any output. INVALID, RANGE and CAPACITY preserve published
result and output bytes. In particular, the excluded negative boundary -2^M
is rejected even though its upper words are valid sign extension. Curve scratch
may change on attempted frame reuse, including failures. Zero results retain
bins but have zero numeric fields and a NULL samples pointer.

Production CMake lists, tasks, core bindings, priorities, stacks, pins and output
backends are unchanged. Qualification results are recorded separately; a host
product comparison does not prove complete PCM or runtime conformance.
