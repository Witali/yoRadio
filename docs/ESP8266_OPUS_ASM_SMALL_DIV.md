# Opus ASM: точное деление rng/ft без 64-битных операций

Дата: 2026-09-14. Backend `bands-small-div-asm`, отдельно поверх лучшего
`bands-tell-inline-asm`; default C и исходный GCC snapshot не изменены.
Продолжение A3 общего плана и entropy/PVQ-пункта ASM-плана.
Цель <=70% CPU на 192 кбит/с ещё не подтверждена.

## Изменение

Три сохранённых GCC call site в `entdec.c.s`: первый `rng/ft` в `ec_decode`
и два раскрытых экземпляра в `ec_dec_uint`. Последующее `val/ext` не меняется,
как и `ec_decode_bin`, нормализация, чтение пакета, состояния и таблицы кодека.
Весь исходный диапазон делителей сохраняется: `d>256` и `d=0` направляются
tail-call в прежний `__udivsi3` (в этой сборке адрес 0x4000e21c). Нулевой
делитель не становится определённой операцией — наследуется исходный путь.

Используются коэффициенты оригинального Xiph `celt/entcode.c:SMALL_DIV_TABLE`:
129 слов во flash, из которых 128 явно инициализированы, последнее нулевое.
Для `d<=256` индекс не превышает 127. Диапазон helper не ограничивает битрейт:
вне него выполняется исходное деление.

## Почему результат точный

Пусть `d=2^t*o`, где o нечётное, `a=n>>t`, `M=floor(2^32/o)`.
Для o=1 берётся UINT32_MAX, как в upstream. Тогда
`q=high32(a*M)` не превышает `floor(n/d)` и отстаёт не больше чем на единицу:
ошибка коэффициента меньше `1/2^32`, а `a<=UINT32_MAX`.
Для o=1 произведение также даёт a или a-1. Следовательно,
`q + (n-q*d >= d)` всегда равно исходному unsigned-частному.
Произведение q*d не переполняется, поскольку q*d<=n.

High32 вычисляется четырьмя MUL16U, с разбиением обоих операндов на половины:

```
lh  = a_lo * b_hi
mid = (a_lo*b_lo >> 16) + a_hi*b_lo + (lh & 65535)
q   = a_hi*b_hi + (mid >> 16) + (lh >> 16)
```

Максимум mid: `65535^2+65534+65535 = 4294967294`, помещается в uint32.
Здесь нет приблизительной замены результата range decoder и нет runtime
64-bit multiply/divide. Генерация констант использует BigInt только на ПК.

ABI call0: вход a2=n, a3=d; выход a2; scratch a2..a11/SAR;
a0/a1/a12..a15 сохраняются. Helper — leaf без стека и записей в RAM.
Все загрузки таблицы — выровненные 32-битные.

## Проверки и план эксперимента

- [x] Более 1 млн тестов модели **самих ASM-инструкций**, включая границы
      частного, UINT32_MAX, ABI и fallback. Ещё 4,2 млн предварительных
      арифметических проверок выполнены в памяти процесса (не board timing).
- [x] 20 Node-регрессий, полное совпадение исходной таблицы, CFG fallback.

      C semantic mirror не является выполнением LX106; ISA проверяется отдельно.

      Padding после RET не декодируется как код: проверяется реальный CFG,

      App 903856 B (+640), flash text +120 B, rodata +520 B; static RAM прежняя.
- [ ] 10 исходных A, 10 кандидатов B, 10 повторных A2 без output/profiler.

Артефакты: `firmware/development/esp8266-opus-bands-small-div-v1/`.
Генератор: `node tools/esp8266_opus_asm/small_div.cjs <xtensa-lx106-elf-gcc.exe>`.
Host: `node tools/esp8266_opus_asm/check_bands.cjs small-div`.
Preflight/отчёт: `node tools/esp8266_opus_asm/report_small_div.cjs [--preflight]`.
Физические серии используют `tools/esp8266_opus_profile/run_raw_series.ps1`,
Attempts 10, IntervalMs 15000, исходные fixtures `esp8266-opus-asm-library`.

Первичная конфигурация останавливалась на ошибке экранирования verifier;
ещё одна тестовая ошибка выявила неинициализированный последний элемент
upstream-таблицы. Обе исправлены до OTA, логи первых проверок сохранены.
Скорость host и меньшая длина последовательности не доказывают ускорение платы.
