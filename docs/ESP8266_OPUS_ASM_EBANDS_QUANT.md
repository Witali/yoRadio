# Opus ASM: пара eBands в quant_all_bands

2026-09-18. Независимый опыт поверх принятого
`esp8266-opus-ebands-final-candidate-v2`. Цель остаётся <=75% CPU на
192 кбит/с, затем непрерывный I2S PDM и работающий WebUI. Этот raw-опыт
сам по себе не подтверждает воспроизведение или отзывчивость WebUI.

## Изменение

В `quant_all_bands` два L16SI из flash по0x40250ab6/abf заменены
вызовом уже принятого signed-pair helper по0x4024dd48. Никакой новой
области хранения для helper не требуется. Изменены только15 байт
по0x40250ab3; размеры секций,903216-байтного app, RAM/IRAM и384-байтного
frame функции не меняются. Это не означает, что весь стек равен384 байтам.

Вход `a8=eBands+2*i` копируется в a5; результаты возвращаются в a2/a3.
Для чётного i достаточно одного выровненного32-битного чтения, для
нечётного — двух. Все чтения остаются внутри прежней44-байтной таблицы
из22 signed16 значений. Диапазон i0..20, нет ограничителя битрейта.

Три исходных чтения stack116/428/200 сохранены с теми же получателями.
Только a0 и a5 дополнительно меняются: все пути перезаписывают a0 при
CALL0 по0x40250afa, a5 — при MOVI по0x40250ace до использования.
SAR и остальные регистры не меняются. OR выбран3-байтным намеренно,
чтобы сохранить адреса всего последующего кода. C fallback не изменён.

## Проверка корректности

- 132416 числовых случаев по linked-инструкциям, signed16 крайние значения,
  обе фазы выравнивания, все21 пары и64 состояния SAR.
- Символическая проверка независимых битов пары; идентичность уже
  принятого helper проверяется по байтам ELF и независимому proof.
- Отрицательные тесты: живой a5, изменение stack load, изменение helper,
  нечётный/выходящий за таблицу указатель.
- CFG-проверка инициализации указателя и обоих инкрементов цикла.
  Только60-байтный band_ctx frame[32,92) передаётся по указателю;
  slots116/144/224+ не входят в этот объект.
- 24 host-сценария с ASan/UBSan: точный PCM, reset/OOM/PLC/состояния,
  смешанные режимы,320/510 кбит/с, до120 мс и48 кадров в пакете.
  Ошибка PCM16=0; SNR относительно контроля бесконечен. Это проверка
  семантической host-модели, а не измерение скорости LX106.

Существующая host-перепись выражений даёт252 обращения к паре за0,24с
в192-кбит/с fixture (1050пар/с). Это не счётчик cache misses и не замер
целевых инструкций. Счётчик подтвердил приоритет normal-frame цикла,
в отличие от ранее найденного PLC/CNG пути celt_decoder.

## Воспроизведение

1. `node tools/esp8266_opus_asm/ebands_quant.cjs`
2. `node tools/esp8266_opus_asm/check_bands.cjs ebands-quant`
3. Сохранить `.build/opus-bands-ebands-quant/correctness.json` как
   `firmware/development/esp8266-opus-ebands-quant-candidate-v1/host.json`.
4. `node --test tests/esp8266-opus-ebands-quant.test.js`
5. По10 физических A/B/A2 через `run_raw_series.ps1 -IntervalMs 15000`.
6. `node tools/esp8266_opus_asm/report_ebands_quant.cjs`

CPU160/runtimeQIO40, пакеты заранее в RAM; output/function/stage profiling
выключены. DIO в заголовке OTA app не меняет runtimeQIO40. Только OTA,
не UART; настройки и SPIFFS не переписываются. Сохраняются все попытки,
неудачи, максимумы и метрики памяти. Успех определяют оба повторных
high-bitrate критерия, а не уменьшение числа инструкций.

## Результат

Первый локальный запуск регрессий: 4/5 PASS. Отрицательный тест менял
первое одноимённое чтение выше исследуемого участка, а не целевую
инструкцию, поэтому ожидаемо не вызывал отказ проверяющего кода.
Тест исправлен на замену всех точных совпадений; машинный код кандидата
и его доказательства не менялись. Кандидат до этой проверки не прошивался.
Повторный запуск: 5/5 PASS, полный лог сохраняется рядом с образом.

Все30 независимых физических A/B/A2 завершены. Ошибок декодера/PCM hashes
нет. Оба критерия high-bitrate FAIL: кандидат **отклонён**, baseline остаётся
eBands-final. На192 кбит/с замена замедляет декодирование на0,4405%
относительно A (на0,4096% относительно A2), а не ускоряет его.

Все исходные попытки сохранены, включая A/run4: CPU19290,066125%,
wall2,975001s и task2,161587s на2,4s аудио. Исключать его из выборки
как «просто сеть» оснований нет. Максимальный вызов192:27,899/20,224/
19,927ms для A/B/A2 соответственно; это wall maximum, не CPU average.
Минимум свободной DRAM1224/904/896B; минимум stack-free1660B одинаковый.

минимумы не скрываются и не означают, что live-прошивке хватает памяти.

Замена не меняет RAM по linked-секциям, не выделяет память и не расширяет
стек; различие наблюдаемых heap-минимумов не доказывает утечку от helper.
Причины выброса и низкого heap отдельно не установлены.

Цель75% не достигнута. В обычное радио этот вариант не переносится.

## Следующие гипотезы, не готовые оптимизации

По первым измерениям нельзя считать любую замену L16SI на L32I выгодной.
Проверять нужно суммарный эффект CALL/RET, инструкций извлечения,
расположения helper и flash-кэша. Причина эффекта кэша отдельно не доказана.

- Проверить безветвевой signed-pair leaf через выравнивание адреса,
  два L32I и SSA8L/SRC. До сборки доказать точную семантику SRC и
  мёртвость SAR у всех вызывающих участков, а не только нового.
- Не читать слово после последней пары без доказательства допустимой
  адресуемой backing-области. Старый44-байтный proof не разрешает такой
  дополнительный read; предпочтительно обойтись без него.
- Отдельно проверить локальное расположение/встраивание: повторное
  использование удалённого helper экономит ROM, но не гарантирует CPU.
  Нужны независимые matched A/B/A, без подмены baseline этим кандидатом.
- Для переноса будущего принятого изменения в обычное радио добавить
  quant_all_bands в проверяемую карту relocation. Текущий live_variant_v2
  проверяет четыре другие функции; использовать его неизменённым нельзя.
- Отдельная более крупная гипотеза: decoder-only специализация всего
  quant_all_bands по encode=0, как ранее для quant_partition. Сначала
  аудит всех вызовов, алиасов band_ctx, theta_rdo и копий контекста;
  удалять только доказанно недостижимые encoder-пути. Сохранить все
  допустимые аудиоветви и PLC. Это ещё не проверенный выигрыш.
