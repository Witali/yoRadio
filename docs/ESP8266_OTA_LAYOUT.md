# ESP8266 native: OTA и SPIFFS 256 КиБ

Новая разметка согласована пользователем 2026-09-05. Старая разметка имела
factory по 0x10000 и SPIFFS 3 МиБ по 0x100000. Нельзя прошивать новую таблицу
без предварительного чтения и переноса старого SPIFFS.

| Раздел | Смещение | Размер |
| --- | --- | --- |
| NVS | 0x9000 | 24 КиБ, не перемещается |
| PHY | 0xf000 | 4 КиБ, не перемещается |
| app0 | 0x10000 | 960 КиБ |
| otadata | 0x100000 | 8 КиБ |
| app1 | 0x110000 | 960 КиБ |
| SPIFFS | 0x3c0000 | 256 КиБ |

Оба приложения имеют одинаковое смещение внутри мегабайтного окна flash:
это важно для линковки ESP8266 (APP_OFFSET & 0xfffff в штатном SDK).
Не используется экспериментальное копирование app1 поверх app0.
Остальное пространство не назначено; размер раздела не расходует RAM.

На момент аудита файлы занимали около 86 КиБ без служебных данных SPIFFS.
Для безопасной замены плейлиста дополнительно нужен его временный экземпляр.
Использовать mkspiffs с ALIGNED_OBJECT_INDEX_TABLES=4, block=4096, page=256,
size=262144. Проверять распаковку и сравнивать файлы до записи.

## Первичный перенос по USB

1. Считать полную flash в приватный игнорируемый каталог, включая NVS.
2. Извлечь старый SPIFFS, сохранить wifi.csv и playlist.csv без изменений.
3. Обновить gzip-файлы www, собрать и распаковать образ 256 КиБ для сравнения.
4. Записать bootloader, новую таблицу, app0 и новый SPIFFS. Очистить только
   otadata 0x100000..0x101fff. NVS/PHY не стирать.
5. Проверить подключение, настройки, файлы, WebUI; затем настоящее OTA туда
   и обратно между слотами.

## Обновление через браузер

/update.html принимает **app.bin** native ESP8266 через POST /update.
Разбор multipart и запись выполняются частями. Штатные esp_ota_begin/write/end
проверяют образ; esp_ota_set_boot_partition вызывается только после полного
и корректного запроса. Обрыв не должен менять загрузочный слот.

Пакет gzip-файлов WebUI обновляется через /webboard, а не вместе с app.bin.
Сырой образ SPIFFS через OTA намеренно не принимается: запись поверх
смонтированной файловой системы уничтожила бы Wi-Fi/плейлист и активные файлы.
Для этого предусмотрена пофайловая загрузка с временными файлами.

HTTP API не имеет аутентификации/TLS; предназначен только для доверенной
локальной сети. Не публиковать его напрямую в Интернет.
