# Decoder-only quant_partition с неизменным остальным ELF

2026-09-14. Независимый кандидат поверх принятого PVQ row-loop,
не повтор отвергнутой полной перелинковки partition-decode-v1.
Лучший raw CPU192 перед этим опытом87.30769%; текущая цель80% не достигнута.

## Гипотеза и границы

Прежний decoder-only уменьшил приложение на544 B, но замедлил192 до98.32%.
Одновременно сдвинулись quant_band/quant_all_bands и другие функции.
В этом опыте **все байты вне одной функции, адреса символов, таблицы,
стек и RAM сохраняются**. Внутреннее расположение самой функции меняется;
это не опыт с неизменным расположением каждой отдельной инструкции.

Основа — сохранённый GCC ASM, linked в принятый контроль. Генератор читает
реальные инструкции, удаляет только доказанный encoder-код при ctx.encode=0.
Затем отдельно собирает блок на исходном адресе0x4024dafc длиной2382 B.
Исполняемый код1859 B и недостижимое заполнение523 B помещаются в старый
диапазон `[0x4024dafc,0x4024e44a)`. Остальное приложение не перелинковывается.
Повторная упаковка SDK elf2image сохраняет903216 B; XOR/SHA проверены.

## Доказательство

- Тот же контракт decoder-only, что в [прежнем аудите](ESP8266_OPUS_ASM_PARTITION_DECODE.md):
  immutable ctx.encode=0, private helpers/copies и рекурсивные вызовы.
  Заново проверены текущий caller CFG и нулевой аргумент quant_all_bands;
  исходники/ASM manifest закреплены хешами. Encoder API не добавляется.
- Данные аудио остаются неизвестными анализатору; обе стороны всех
  зависящих от них ветвей сохраняются. Нет лимита битрейта/длительности.
- В raw disassembly185 недостижимых инструкций, в нормализованном графе179:
  различие связано с развёрнутыми переходами/ROM callx, не с качеством звука.
- Независимая проекция готового ELF даёт тот же decoder CFG, операнды,
  округления, ширины памяти и вызовы. При неизвестном encode ничего не удаляется.
- ROM L32R/CALLX0 пары сохраняются физически, не заменяются более коротким
  CALL0. До/после3/2 пары: одна находилась в удалённом encoder-пути.
  Адреса всех оставшихся литералов и внешних/рекурсивных вызовов совпадают
  в том же порядке. Новые литералы в заменяемом диапазоне запрещены.
- Стек112 B, callee-saved/return, SAR и буферы не меняются. Последняя
  достижимая инструкция RET, в padding нет входящих переходов.
- C fallback и исходные GCC snapshots не редактируются. Комментарии ABI,
  происхождения и удалений сохранены в generated `patches.s`.

## Результат: отклонён

Все30 физических попыток завершены с точным PCM, без ошибок декодера или
HTTP observation errors. CPU160/QIO40; пакеты заранее в RAM, аудиовывод
и function/stage profiling выключены. Wi-Fi/WebUI остаются включёнными;
task CPU включает начисленные ISR и служебные измерения, это не идеальный
счётчик только инструкций. Сравнение последовательное A/B/A, не interleaved.

Время192 выросло на3.255–3.288%,128 — на3.390–3.403%; оба high-bitrate
gate FAIL. Порог80% тоже не пройден. Максимальные CPU192 по сериям:
87.39271 /90.22800 /87.41525%. Удаление инструкций не стало ускорением.

Статическая RAM,112-byte frame и динамические арены/scratch прежние;
минимум свободного стека1660 B во всех группах. Минимумы наблюдаемой DRAM:
8176 /388 /8352 B. В B/run3 минимум388 B отмечен в первых четырёх cases;
к192-case минимум10152 B, после всей попытки свободно26652 B. Ошибок
декодирования/HTTP в этой попытке нет, причина временного провала RAM
не установлена. Это не доказательство утечки или увеличения памяти кодека,
но и не основание объявлять запас RAM достаточным для production.
Медианы DRAM после запуска:26652 /26480 /26580 B.

A/run9, mono12: task window больше wall window на1751 мкс. Окна измерения
различны; выброс сохранён без вычитания overhead, ограничения или фильтрации.
Все30 JSON/log, максимумы, данные RAM и SHA находятся рядом с
[comparison.json](../firmware/development/esp8266-opus-partition-frozen-candidate-v1/comparison.json).

Замедление осталось при неизменном остальном ELF: сдвиг соседних функций
не является необходимым условием этой регрессии. Причина внутри изменённой
функции не локализована: положение инструкций, расстояния переходов и
кэширование не измерялись отдельно. Нельзя приписывать3.3% именно cache misses
или вычитать их из прежних11.6% полной перелинковки: родители опытов различны.
Повторять это семейство без новой проверяемой гипотезы не следует.

Обычное радио live512-idle3s восстановлено OTA в0x10000, SHA
`661becd301b07885d493ceb1b513d9e874b7d86e4ada8231da8657aa90983c4b`.
Главный HTTP-ответ200 за102.0052 мс,27249 B gzip; это не полная браузерная
загрузка. WS/getindex, playlist SHA и stopped station167 совпали с исходными;
error пусто, RSSI−51, free heap27448 B, min24748 B, web stack2324 B.
Сохранены initial-snapshot и restore-*; аудио не запускалось при восстановлении.

Кандидат не становится default. Лучший сохранённый ASM — PVQ row-loop,
около87.3%, а текущая цель80% и20 секунд непрерывного I2S PDM/WebUI
ещё не подтверждены. Следующий независимый пункт — общая `ec_dec_bits`:
извлечение low bits через уже вычисленное high, с проверкой entropy state/ABI.
