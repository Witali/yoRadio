# Принятый ASM Opus в обычной радио-прошивке

2026-09-17. По просьбе пользователя проверяется именно полноценное радио
с ранее принятыми ASM-оптимизациями, не ещё один raw-бенчмарк.

## Перенос

Прежний live-образ `esp8266-opus-live512-idle3s-20260913` использовал C.
Новый `esp8266-opus-live-asm-ebands-final-20260917` использует сохранённый
GCC ASM `bands-tell-inline-asm` и **всю принятую цепочку из18 post-link
этапов до eBands-final**, включая MDCT, PVQ и allocation/eBands.
Отклонённый eBands-u16 не включён. Арифметика не переписывается заново.

Обычная компоновка отличается от raw: поэтому недостаточно скопировать
старые машинные байты. `live_accepted.cjs`:

1. Проверяет одинаковые размеры, смещения инструкций и графы четырёх
   затронутых функций обычной сборки и исходного ASM-контроля.
2. Собирает те же18 сохранённых ASM-патчей, сохраняя комментарии и ABI,
   с новыми адресами переходов и литерала. Неизвестные адреса запрещены.
3. Проверяет единственного читателя изменённого литерала exp2 и неизменные
   значения таблицы. Сверяет конечные графы всех четырёх функций с принятым
   eBands-final, включая helpers в ранее доказанных свободных участках.
4. Повторяет унаследованные доказательства; проверяет каждый байт ELF вне
   объединения патчей. Патчами охвачено1155B flash; RAM/IRAM/стек не растут.
5. Упаковывает приложение штатным esptool SDK, проверяет SHA/контрольную
   сумму и фактические загрузочные сегменты. Тест учитывает штатное удаление
   esptool первых8служебных байт секции `.flash.rodata`, а не объявляет
   такое преобразование повреждением прошивки.

| Функция | Адрес raw-контроля | Адрес обычного радио |
|---|---|---|
|clt_mdct_backward_c|0x402471c8|0x402470b8|
|clt_compute_allocation|0x402482b0|0x402481a0|
|quant_partition|0x4024dafc|0x4024cd44|
|decode_pulses|0x402531c0|0x40252400|

C fallback и обычный профиль по умолчанию не изменены. Выбор новой сборки
явный: отдельный build script ниже. Пока не пройдёт live-квалификация,
она не объявляется стабильным production-профилем.

## Образ и проверки

- App885792B; SHA256
  `6914f484fd86fd9bb2044ebe6925cfc4cc31dc9df0a23629753fc361ba276e70`.
- CPU160/QIO40, I2S PDM32 GPIO3,2×512слов DMA; LED10Hz. Параметры вывода
  сохранены. Opus input1024B/scratch6144B/reserve4096B, idle timeout3000ms.
- Raw benchmark, генератор, runtime CPU stats и function profiling OFF.
  Диагностические health/stages API ON для оценки настоящего радиопотока.
- Статические секции: DRAM data1652B/BSS18488B; IRAM text22848B/BSS4040B
  плюс vectors128B. Равны непатченой обычной ASM-сборке; новых буферов нет.
- Все24 host-сценария exact PCM/guards/state/PLC/OOM/reset, включая510kbps
  и120ms. Все11 регрессий переноса/упаковки/измерений/сохранённой серии PASS.
- OTA HTTP200/OK, подтверждён переход0x110000→0x10000; начальное свободное
  heap27628B. SPIFFS/NVS/плейлист не перепрошивались; UART/reset не использован.

Этот перенос меняет размещение кода относительно raw-бенчмарка. Поэтому
77.8808958% raw CPU192 предыдущего опыта нельзя выдавать за новое измерение
CPU обычного радио. Live stages измеряют wall time с вытеснениями и DMA,
а не чистый CPU. Цель75% плюс20sнепрерывного I2S с WebUI ещё требует проверки.

## Воспроизведение

```powershell
& tools/esp8266_opus_asm/build_live_accepted.ps1
node tools/esp8266_opus_asm/check_bands.cjs ebands-final
node --test tests/esp8266-opus-live-accepted.test.js tests/esp8266-opus-live-accepted-board.test.js tests/esp8266-stage-wall-report.test.js tests/esp8266-audio-continuity.test.js
node tools/esp8266_audio_profile/check_prefill_board.cjs ota --firmware firmware/development/esp8266-opus-live-asm-ebands-final-20260917/app.bin --output .build/new-live-test/ota.json
& tools/esp8266_opus_profile/run_station_series.ps1 -Directory .build/new-live-test/stations -Attempts 10
```

Build script не прошивает автоматически. Нужны настроенные SDK/toolchain;
пути можно передать параметрами. Датированные варианты сохраняют точный
опыт: генератор отказывается перезаписывать отличающиеся доказательства,
поэтому для нового исходного состояния нужна новая именованная сборка.
Рецепт может восстановить reference ELF из сохранённых gzip-доказательств.
Приложение, оба ELF, manifest/config, preflight и результаты находятся в
[`firmware/development/esp8266-opus-live-asm-ebands-final-20260917`](../firmware/development/esp8266-opus-live-asm-ebands-final-20260917/manifest.json).

## Физические испытания

Завершены все **10 попыток** обычными WebSocket-командами выбора станции.
Чередовались512 R2Rock и513 Nightwave Plaza. По сообщениям самого плеера:
R2Rock116–127kbps, Plaza59–65kbps, оба48kHz stereo. В каждой попытке после
команды и3sожидания запрашивались две группы health/stages с паузой27s.
Во время серии не менялись прошивка, буферы, Wi-Fi и не выполнялся reset.

|2|Plaza|нет: WS timeout|0 /26.984s|остался предыдущий generation; не считать запуском Plaza|
|3|R2Rock|нет нового current|нет полного окна|таймаут измерения; повтор той же станции|
|4|Plaza|да|нет полного окна|таймаут измерения|

|6|Plaza|да|нет полного окна|таймаут измерения|

**0/10 квалифицированных непрерывных окон.** Это не утверждение, что
декодер сломался10раз: в семи попытках не удалось собрать полную пару
снимков, а два WS timeout не подтвердили даже отправку Play. Повторный
выбор той же станции не обязан присылать новый current. Все исходные
данные, ошибки команд и неполные окна сохранены, не исключены из отчёта.
Underrun — счётчик событий, не длительность тишины; после остановки он
тоже может расти, поэтому нельзя суммировать его как пропуски звучащего
потока. Акустической записи нет: проверен цифровой путь по телеметрии.

Последняя диагностика до Stop: PCM age28390ms, RX age13828ms, вход0B,
transport_result4/errno116 (таймаут), free heap22852B. Latched диагностика
инициализации Opus: stage0, то есть ошибки init в этом снимке нет.
В отличие от последнего C-опыта здесь не зафиксирован DECODER INIT ERROR.
Это не доказывает отсутствие любых прежних ошибок или устранение
проблем памяти. Причинность «ASM вызывает сетевые таймауты» не установлена.

Ресурсы:

- RSSI в полученных стартовых сообщениях от−54 до−59dBm.
- Минимум free heap с момента OTA: **1440B**, после Stop/возврата станции
  27208B (отдельный health-снимок27028B). Запас кучи всё ещё мал; одного
  восстановления heap недостаточно, чтобы объявить отсутствие утечек.
- Минимальный свободный стек audio1464B, WebUI2288B; free IRAM112B.
- В окне9 decode_exclusive27.24%, output3.52%, input_wait11.92% — только
  wall-time этапов в окне с провалами, **не CPU-бюджет нормального потока**.
  Поэтому сравнивать эти проценты с прежними77.88% raw CPU192 нельзя.

После серии оставлена **новая ASM-прошивка**, slot0x10000. Восстановлены
выбор167 и stopped; volume100/balance0 и SHA плейлиста сохранены.
В остановленном состоянии HTTP200: главная страница121.1ms,
settings.html99.0ms; WebSocket/getindex также ответил. Это не измерение
отрисовки браузера и не проверка всех кнопок: запуск встроенного браузера
не удался из-за ошибки sandbox helper. Во время воспроизведения HTTP
часто превышал5s, поэтому отзывчивость WebUI под нагрузкой не подтверждена.

Вывод: перенос принятых ASM-оптимизаций выполнен и испытан на плате,
но готовой стабильной радио-прошивкой эту сборку считать нельзя.
Следующая диагностика — сетевые остановки/повторное подключение и
низкий запас heap, затем повтор непрерывного вывода с WebUI.
Живые радиопотоки меняются: эта серия не является синхронным C/ASM
A/B-тестом производительности на одинаковых входных пакетах.

`board/restored.json`, `board/web.json`, `host.json`, `tests.log`.
