# ESP8266 short pause: прошивка и аппаратная проверка 2026-09-09

По запросу пользователя пересобран и установлен вариант `short`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/esp8266_audio_profile/build_i2s_pdm_production.ps1 -Variant esp8266-web-pause-short -WebAudioPause short
```

Бинарник: `firmware/development/esp8266-web-pause-short/app.bin`, 760800 байт.
Исходники сборки: `527953a8b52c9b237a7d2967898ae9debed4d181`.
SHA-256: `8F22523F459ADB94368CE31BFBF96F13C92A253102178E2491312294F965267E`.
Определение `YORADIO_ESP8266_WEB_AUDIO_PAUSE=1` проверено в `build.ninja`.
CPU160/QIO40; mono Helix MP3 SSO + AAC; I2S PDM32/SLC-DMA GPIO3/RX;
input 6144 байта, prefill 1000 мс, два DMA-буфера по 512 слов, ERROR-логи.

## Установка

- До установки плата отвечала по `http://192.168.100.6`, RSSI -71 dBm,
  радио было остановлено на «Ретро FM», громкость 128.
- Перед HTTP-загрузкой обнаружена несовместимость OTA-скрипта с BOM в
  JSON-манифесте Windows PowerShell. Исправлен reader, генератор теперь пишет
  UTF-8 без BOM. Семь targeted-тестов манифеста и режимов паузы прошли.
- POST `/update`: HTTP 200, `OK`, 17.89 с. После перезапуска подтверждён
  новый слот `0x110000` вместо `0x10000`.
- Только приложение: разделы NVS/SPIFFS/таблица разделов не записывались.
  SHA-256 отданного плейлиста до/после совпал; в WebUI 511 станций.
- После запуска free heap 23956, минимум SDK 21076 байт. Это реальные
  показания кучи, не размеры статических секций ELF.
- COM8 использовался только для пассивного TX-лога без команд и сброса;
  за окно проверки ошибок в нём не было. USB-прошивка не потребовалась.

## Результаты

| Проверка | Результат |
| --- | --- |
| Две вкладки WebUI, радио остановлено | PASS; загрузка до плейлиста и WS 403/291 мс |
| 10 кликов громкости, обе вкладки получают статус | PASS; ACK 20-55 мс; громкость затем восстановлена |
| MP3 128 кбит/с, «Ретро FM», станция 510 | Запустился, декодер выдавал PCM |
| 30 секунд непрерывности MP3 | **FAIL**; 5 из 7 health-опросов неполные/тайм-аут, росли underrun-счётчики |
| Stop через WebSocket | Подтверждён статусом: playing=false, connecting=false, error пустой |
| Повторные две вкладки после Stop | PASS; загрузка 256/241 мс; 10 кликов ACK 22-53 мс |

В начале воспроизведения free heap 8884, минимум SDK 7540 байт. В двух
полных samples минимум свободной памяти составил 7236 байт; позднее
показание SDK min_heap опустилось до 4548 байт. Минимальный остаток
стека HTTP — 2284 байта. RSSI во время успешных ранних опросов был -65/-66,
после Stop -76 dBm; эти данные не доказывают причину зависаний.

Начальные счётчики underrun — 8364 и 8387 с интервалом около секунды;
следующий частичный опрос показал 8426. Из-за отсутствующих health samples
непрерывное воспроизведение за 30 с не подтверждено. На слух звук не
оценивался: проверены только программные PCM/DMA-счётчики.

**Вывод:** установка `short` успешна, WebUI в простое отзывчивый. Под
воспроизведением остаётся прежняя проблема пропусков/HTTP-тайм-аутов;
повышение приоритета HTTP само по себе её не устранило. По этому прогону
нельзя обещать задержку страницы <500 мс и команд <200 мс под аудионагрузкой.

Плата оставлена на прошивке `short`, остановлена на станции 510 с громкостью
128, подключена к роутеру. Настройки и WebUI-файлы сохранены.

Отчёты находятся в [каталоге проверки](benchmarks/esp8266-web-pause-short-deploy-2026-09-09/):
`ota.json`, `webui-idle.json`, `play.json`, `mp3-128.json`, `stop.json`,
`webui-after-stop.json`. Полные snapshots с содержимым плейлиста и UART-лог
оставлены только в локальной `.build/esp8266-web-pause-short-deploy/`.
