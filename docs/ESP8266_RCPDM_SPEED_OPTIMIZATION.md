# ESP8266: план побитно точной оптимизации RCPDM

Начат 2026-09-06. Не менять RC-модель alpha=1/16, 32 бита на сэмпл,
порядок MSB-first, состояние между пакетами и нейтральный DMA-поток.
Обычный PDM остаётся профилем по умолчанию. SPIFFS/NVS не перепрошивать.

## Критерии принятия

- Сравнивать каждое выходное слово и конечное RC-состояние с исходной
  реализацией и независимой двухкандидатной моделью, не только checksum/SNR.
- Все 65536 PCM при граничных состояниях, случайные непрерывные потоки,
  ноль, края, границы пакетов и reset; проверка на host и на Xtensa.
- CPU160/QIO40, прежние 2×512 DMA-слов. Время отдельно для модуляции и
  полного пути без ожидания DMA. Проверять underrun, RAM, стек и ассемблер.
- Принимать только измеримый выигрыш. Не усложнять production-код ради
  проигравшего варианта; сохранять эксперимент и результат в тестах.

## Пункты

- [x] 1. Вычислять ограниченный снизу порог один раз на сэмпл.
- [x] 2. Проверить разворачивание 4, 8 и 32 шагов; не переносить проигравшие варианты.
- [x] 3. Пакетная запись прямо в зарезервированный DMA-участок, без нового
  промежуточного буфера. Сохранять границы владения и состояние при выходе.
- [x] 4. Проверить маски/безусловное вычисление бита вместо ветвления;
  оставить только при выигрыше и полном совпадении битов.
- [ ] Итог: повторный A/B, регрессии обычного PDM, обычная сборка и возврат
  обычной прошивки. Сохранить бинарники, манифесты и измерения.

Перенос в IRAM — отдельный резерв, не обязательный пункт этого эксперимента:
он расходует память декодеров. Увеличение DMA-буферов и изменение приоритетов
не входят в план: они не сокращают число операций модулятора.

Исходный физический результат: 119216 мкс / 48000 слов и 157903 мкс полного
пути без DMA-ожидания на секунду звука. Подробности:
[исходное сравнение](benchmarks/esp8266-output-compare-2026-09-06/README.md).

## Результаты выполнения

Заполняются по мере проверки каждого пункта; непроверенные варианты не
считать ускорением. Тесты выводят временный шум, после них вернуть радио.

### 1. Порог — принят

`target > down + HALF` заменён на `down < max(target - HALF, 0)`, причём
вычитание выполняется только после проверки, без unsigned wraparound.
Host: все 7 кандидатов совпали с независимой двухкандидатной 64-битной моделью
на 493216 словах/состояниях каждый. Физическая ESP8266: оригинал и `limit`
также прошли прямое сравнение 493216 слов и состояний.

Медиана трёх замеров: **119216 → 112275 мкс / 48000 слов**, -5,82% времени.
Полный путь без ожидания DMA: 158586 → 149798 мкс на секунду аудио.
DMA underrun/partial/FIFO empty=0, free/min heap=108532/105752 Б в обоих
диагностических вариантах. Исходный вариант заново измерен с той же проверочной
обвязкой; не подменять этот контроль прежним бинарником с другим layout.

### 2. Разворачивание — проверено, отдельно не принято

| Вариант | Модуляция 48000 слов, мкс | Полный путь без ожидания / с аудио, мкс | Код пакера, Б |
| --- | ---: | ---: | ---: |
| limit | 112275 | 149798 | 63 |
| unroll4 | 108560 | 150841 | 790 |
| unroll8 | 108560 | 150841 | 790 |
| unroll32 | 108710 | 150930 | 786 |

Все варианты прошли на плате 493216 прямых сравнений слов/состояний,
underrun/partial/FIFO empty=0. GCC сам полностью развернул варианты 4 и 8;
повторные загрузки констант и больший flash-код съедают выигрыш. Изолированный
пакер немного быстрее, но путь вывода не ускорился. Сложность и рост кода
не оправданы; варианты сохранены только в `tests/native/rcpdm_variants.h`.

### 4. Безветвленные варианты — проверены, отклонены

Проверены обычное булево сравнение с маской (`mask8`) и действительно
безветвленное получение бита через старшие 16 бит midpoint (`branchless8`).
Второй вариант точен, потому что target кратен 65536, а разность двух
16-битных величин позволяет безопасно получить бит заёма без signed overflow.

| Вариант | Модуляция, мкс / 48000 слов | Полный путь без ожидания / с аудио, мкс | Код пакера, Б |
| --- | ---: | ---: | ---: |
| limit | 112275 | 149798 | 63 |
| mask8 | 114233 | 157273 | 921 |
| branchless8 | 126454 | 166421 | 300 |

Оба варианта побитно точны на host и Xtensa, но медленнее. У `branchless8`
также появился 16-байтовый стековый кадр пакера; у original/limit/unroll/mask
пакер без стекового кадра. Арифметика/регистровое давление дороже сэкономленного
ветвления. В production сохраняется обычное сравнение; эксперименты оставлены
в тестах. Этот независимый пункт измерялся общей матрицей до пакетного вывода.

### 3. Пакетный вывод — принят после специализации моно/стерео

Первый общий цикл с проверкой channels на каждом сэмпле оказался хуже:
160155 против 149798 мкс/с у scalar limit. Ассемблер показал повторное
`l32r` для STEP в самом битовом цикле. Этот вариант не принят.

Разделение моно/стерео перед циклом позволило держать STEP в регистре.
При входных 48 kHz пакер заполняет непосредственно выданный драйвером span,
сохраняя состояние в регистре на весь span. Иные частоты используют прежний
ресэмплер; длина DMA, IRQ, частота несущей и выдаваемые биты не меняются.
Сохранены также состояние и незавершённая фаза scalar-пути при timeout.

Физический A/B: **149798 → 124764 мкс/с**, -16,71% относительно одного
вынесенного порога, и **-21,33%** относительно исходных 158586 мкс/с.
Это время producer без блокирующего DMA-ожидания, не полная загрузка CPU.
Сам scalar-пакер: 112273–112275 мкс/48000 слов. В каждом запуске пройдено
493216 прямых сравнений scalar-слов/состояний, дополнительно 2144 слова
реальной Xtensa-функции пакетного заполнения в моно/стерео. Underrun,
partial start, blocked partial и FIFO empty — 0.

Host-регрессия всего пути: 6 частот (8/16/22,05/32/44,1/48 kHz), моно/стерео,
нормализация on/off, пакеты 1/32/64/128/256/512/576 кадров; **каждое** DMA-слово
сравнивается с замороженным исходным RCPDM, также проверяются EOF/ownership,
отмена, timeout/состояние RC и stop. Обычные PDM32/PDM128 также проходят тест.

Новых буферов, DRAM/IRAM или heap-выделений нет. Дополнительный стековый кадр
batch-функции — 16 Б; кадр `native_audio_output_write` остался 80 Б.
Выделенные размеры стеков не увеличены. В диагностических сборках
free/min heap=108532/105752 Б; финальная обычная сборка: статическая DRAM
20848 Б, IRAM (vectors+text+bss) 27464 Б. Функция batch занимает 203 Б flash.

### Дополнительная идея пользователя: серии одинаковых битов

Исследована математически, **не включена** в рабочий алгоритм и не измерена
на плате. В текущем коде уже нет вычисления двух порогов: есть одно сравнение.
Но для гарантированной серии можно сократить и число этих сравнений.

Обозначим STEP=0x0fffffff, HALF=STEP>>1, T=target, S=RC-state. Достаточное
условие для N одинаковых битов: `abs(T-S) >= N*STEP-HALF`. Разность вычислять
безопасно как большее минус меньшее (uint32), не signed abs. При T>S это
серия единиц, при T<S — нулей. Для N=4 порог равен **939524093**.
Это консервативная граница: изменение состояния за шаг не превосходит STEP.

Во время серии нужно сохранить **каждый** шаг целочисленного округления.
Для нулей повторяется `S -= S >> 4`; для единиц можно взять `E=UINT32_MAX-S`,
повторить `E -= E >> 4` N раз, затем вернуть `S=UINT32_MAX-E`. Биты дописываются
одной группой. Формула с `(15/16)^N` без поправок не эквивалентна: например,
S=15 после двух исходных разрядов остаётся 15, а округление общей формулы даёт 14.

Группы 2/4/8 прошли отдельную арифметическую проверку **1479648** слов/состояний
с исходной последовательностью. Выигрыш пока неизвестен: проверка серии сама
стоит инструкций, а большой скачок после ограничения громкости/на реальном
PCM может встречаться редко. Следующий эксперимент должен учитывать частоту
срабатывания на тишине, синусе и декодированном PCM, не только случайном шуме.
