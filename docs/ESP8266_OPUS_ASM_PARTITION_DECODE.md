# Opus ASM: decoder-only quant_partition

2026-09-14. Отдельный backend `bands-partition-decode-asm`, default OFF.
Основа — лучший tell-inline. Это не повтор C decode-only: не перекомпилируем
bands.c, не меняем распределение регистров, spills, вызовы или стек112 B.
Удаляем только недостижимый машинный код encoder из одной горячей функции.

## Инвариант и доказательство

Вызов quant_all_bands в готовом ELF находится в celt_decode_with_ec_dred,
а не в короткой оболочке celt_decode_with_ec. Аргумент encode приходит через
movi a8,0 /mov a2,a8. Аудитор прослеживает его до нулевого определения,
проверяет отсутствие обходящего перехода; map cross-reference подтверждает
единственную вызывающую единицу celt_decoder.c.obj.

В закреплённом bands.c единственное прямое присваивание — ctx.encode=encode.
Контекст передаётся только приватным bands helpers. Они меняют remaining_bits,
seed и другие поля, но не encode. Две операции восстановления ctx используют
копии этого же контекста, поэтому также сохраняют0. Рекурсивный quant_partition
получает тот же указатель. Это свойство вызовов **декодера**, а не ограничение
входного битрейта, режима mono/stereo, количества полос или размера пакета.
Эксперимент не предоставляет encoder API; C fallback и остальные backend
остаются без изменений.

Анализатор отслеживает только указатель ctx и неизменный encode=0; прочие
значения остаются неизвестными. Поэтому сохраняются оба направления каждой
ветви, зависящей от аудиоданных. Учтены call0 clobbers, spills и объединение
путей. Внутренний стековый frame не передаётся по указателю: при появлении
такого доступа проверка прекращается. Incoming/outgoing by-value аргументы
и возможность их изменения рекурсивным вызовом не считаются immutable.

Найдены три постоянные проверки и179 недостижимых исходных инструкций,
включая вызовы alg_quant, stereo_itheta, ec_encode/ec_enc_uint. Общие decoder
хвосты, alg_unquant и точная арифметика сохраняются. Затем независимо читается
ELF: после проекции encode=0 графы контрольной и новой функций сравниваются
с точными регистрами, константами, ширинами памяти и целями переходов/вызовов.
Нормализация CALL0/CALLX0 и переходов учитывает семантику, но не объявляет
их цену одинаковой. Влияние компоновки на скорость требует реальной платы.

## Контрольный список

- [x] Исходный ASM overlay, воспроизводимый генератор, C fallback не изменён.
- [x] Тесты отказа при записи ctx.encode, утечке указателя на стек, новом opcode.
- [x] Host PCM через510 кбит/с, phase/PLC/reset/OOM и составные120мс пакеты.
  Последние потребовали исправить только desktop-probe: прежний лимит4096 B
  не принимал корректный составной320-кбит/с пакет. Используется полный
  uint16-размер контейнера; встроенные буферы прошивки от этого не растут.
- [x] Linked CFG/call-chain и RAM по готовому ELF: 179 удалённых инструкций,
  quant_partition2382→1870 B; app903216→902672 B (−544 B). RAM и стек прежние.
- [ ] 10 физических A /10 B /10 A, все попытки/максимумы, критерий128/192.
- [ ] Сохранить решение и вернуть ordinary через OTA. Только при принятии —
  live I2S PDM/WebUI не менее20 секунд; цель70% отдельно проверяется по raw CPU.

## Воспроизведение

`partition_decode.cjs <LX106 gcc>` генерирует overlay;
`check_bands.cjs partition-decode` выполняет24 PCM-сценария;
`audit_partition_decode.cjs` проверяет ELF;
`report_partition_decode.cjs` архивирует все30 измерений.
Все скрипты находятся в tools/esp8266_opus_asm.

Профиль: CPU160/QIO40/cache16, Diagnostic/OpusWordAsm/IcdfFlashWord/FirFlashWord,
NoSpiffsCache/Pdm32Iram/Pdm32Batch, OpusBenchmark (output/function/stage OFF),
WebAudioPause off. Контроль: esp8266-opus-folding-control-v1 (tell-inline).
Кандидат: firmware/development/esp8266-opus-partition-decode-v1/app.bin.
До физических замеров это только кандидат, не подтверждённое ускорение.
