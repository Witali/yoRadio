# Opus: sin/cos и табличные замены

Проверка 2026-09-14, ESP8266 CPU160. По уточнению пользователя для этой
отдельной гипотезы допустима ошибка до 2 единиц **готового PCM16**,
а не только коэффициента. Исходники декодера, GCC snapshot и default не менялись.

## Текущая реализация

- В linked ELF лучшего bands-tell-inline нет sin/sinf/cos/cosf.
  FIXED_POINT включён, CUSTOM_MODES выключен. Floating-point тригонометрия
  генераторов custom modes не входит в текущий путь декодирования.
- FFT/MDCT уже используют fixed-point таблицы из celt/static_modes_fixed.h.
  mdct_twiddles960 занимает 3600 байт flash.
- SILK NLSF2A использует silk_LSFCosTab_FIX_Q12 и линейную интерполяцию:
  258 байт во flash.
- celt_cos_norm — целочисленный полином, не libm. В ELF занимает 238 байт.
  exp_rotation вычисляет два коэффициента перед обработкой вектора, не на sample.
- bitexact_cos в bands влияет через bitexact_log2tan на распределение битов
  mid/side. Неточная замена может изменить разбор потока, не только PCM.
  Здесь нужна точная таблица/формула. Прямой LUT четверти периода потребует
  около 32 КиБ int16 — больше 16-КиБ кэша, поэтому ускорение не очевидно.

Исходники относительно esp8266/rtos-sdk-native/components/opus_decoder/upstream/:
celt/mathops.c:140, celt/vq.c:84, celt/bands.c:66 и 908,
celt/static_modes_fixed.h:104 и 506, silk/NLSF2A.c:91.

## Локальная проверка celt_cos_norm

tools/esp8266_opus_asm/check_trig_tables.cjs получает 32769 значений
четверти периода настоящей исходной fixed-point C-функцией. Затем создаёт
отдельный host object: линейная интерполяция, исходная симметрия периода.
Таблица uint32 предназначена для выровненного 32-битного flash-доступа.
Даже при шаге 256 сумма <=32767*256+128, поэтому достаточно uint32.
Таблица генерируется на ПК, не при старте платы. RAM для таблицы не нужна.

ASAN/UBSAN: 15 файлов — пять коротких raw fixtures 12/24/64/128/192 кбит/с,
320 кбит/с с пакетами 2,5/5/10/20 мс, 510 кбит/с, пять полных фрагментов
по 1,22 с. Выход harness — mono PCM16 48 кГц; fresh decoder на каждый файл.
Это не доказательство предела ошибки на любом сигнале или stereo-output.

| Шаг аргумента | Значений | Flash | Макс. ошибка коэффициента | Макс. ошибка PCM16 |
|---|---:|---:|---:|---:|
| 256 | 129 | 516 B | 2 | **1** |
| 128 | 257 | 1028 B | 2 | 1 |
| 64 | 513 | 2052 B | 2 | 2 |
| 32 | 1025 | 4100 B | 2 | 2 |

Ошибка коэффициента проверена на всей четверти. Более плотная таблица
не обязана лучше повторять округления исходного полинома. Для 516 B на
коротком 192 кбит/с: PCM <=1, SNR 87,60 dB. Больший LUT не предпочтительнее.
Все PCM SHA, ошибки, SNR, входные SHA и числа вызовов:
tools/esp8266_opus_asm/trig-tables-results.json.

| Короткий файл, 240 мс | Вызовов celt_cos_norm |
|---|---:|
| mono12 | 0 |
| mono24 | 84 |
| stereo64 | 450 |
| stereo128 | 254 |
| stereo192 | 138 |

На 192 это 575 вызовов/с. LUT заслуживает небольшого ASM-эксперимента,
но не обещания большого снижения CPU. Host runtime не используется как
оценка скорости LX106. Прошивка с такой заменой ещё не собиралась.
