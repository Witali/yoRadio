# Точная таблица qn: предварительный census

2026-09-17. Следующий опыт после отклонённого byte-phase. Это **частота
вызовов на компьютере**, не измерение скорости LX106 и не новый код прошивки.
Контроль — host-модель принятого ASM exp2-table32. Исходный C fallback и
прошивка платы не изменены.

## Что измерено

Наблюдатель вызывается перед возвратом исходного `compute_qn`, проверяет
результат, но не подменяет его. Раздельно считает `stereo=0` (узкий целевой
клон внутри `quant_partition`) и стереофонический расчёт theta. Название
nonstereo здесь — параметр функции, а не число каналов исходного файла.

| Поток | Длительность, с | Целевые расчёты qb>=4 | Расчётов / с аудио |
|---|---:|---:|---:|
| mono12 | 0.2400 | 0 | 0 |
| mono24 | 0.2400 | 54 | 225.00 |
| stereo64 | 0.2400 | 171 | 712.50 |
| stereo128 | 0.2400 | 700 | 2916.67 |
| stereo192 | 0.2400 | 1261 | 5254.17 |
| stereo320, 2.5ms | 0.2425 | 650 | 2680.41 |
| stereo320, 5ms | 0.2450 | 1276 | 5208.16 |
| stereo320, 10ms | 0.2500 | 1734 | 6936.00 |
| stereo320, 20ms | 0.2600 | 2119 | 8150.00 |
| stereo510 | 1.2200 | 17189 | 14089.34 |

В этих10 файлах ветвь qb<4 не встретилась. Это **не доказательство её
недостижимости**: сохранить исходный результат qn=1 для всего qb<4, включая
отрицательные значения. Проверяемая таблица покрывает весь qb=4..64, а не
только наблюдённые индексы. qb=64 реально встречается и на192кбит/с.
На192 были также231 стереофонических theta-расчёт: они не добавлены в
1261 целевых вызовов и не входят в будущую узкую ASM-замену.

## Предлагаемое преобразование и ограничения

После исходного clamp qb<=64 результат зависит только от qb:

```
v = exp2_table8[qb & 7] >> (14 - (qb >> 3))
qn = ((v + 1) >> 1) << 1
```

Все61 значения проверены независимой целочисленной формулой на host.
Таблица с32-битными элементами займёт244байта flash до учёта literal и
выравнивания; RAM для неё не нужна. Это размер данных, не готовый размер
патча. Указатель, адресация с qb-4, размещение, живые регистры/SAR и
состояние в точке слияния ветвей ещё требуют доказательства по linked ASM.
Нельзя считать место во flash свободным только по размеру: действуют
прежние проверки encoder-only областей и всех входящих переходов.

Расчёт необходимого выигрыша полезен для масштаба: от принятого79.626521%
до78% требуется сэкономить16.265мс CPU на секунду аудио. Если делать это
только данной заменой при5254.17 вызовах/с, нужно экономить **3.096мкс,
или примерно495 тактов160МГц на каждый вызов**. Это необходимое условие,
**не прогноз** стоимости вызова и не результат измерения. Поэтому нельзя
обещать достижение78% одной qn-таблицей; небольшой выигрыш можно проверять
в комбинации с другими независимо принятыми правками. Кэш может также
сделать увеличенную таблицу медленнее.

## Корректность и воспроизведение

- Все10 файлов дают побитно одинаковый PCM; максимальная ошибка0.
- Совпадают количество пакетов/отсчётов, размеры состояния, пики byte/word
  арен и защитные области. Для192 пики5488 и15600байт; `words` в имени
  счётчика — word-safe арена, значение измеряется в **байтах**.
- Сборка host с ASan/UBSan; отключён только LeakSanitizer, как в исходном
  harness. Это не отдельный тест отсутствия утечек в целевой прошивке.
- Счётчики и observer находятся только в host-программе, вне decoder arena.
  Размеры состояния на64-битном компьютере не приравнивать к ESP8266 RAM.
- Три регрессии проверяют точную вставку, полный домен таблицы, ошибочные
  статистики, все исходные JSON, хеш модели и неизменность PCM/арен.

Запуск: `node tools/esp8266_opus_asm/profile_pvq_qn.cjs`.
