# План общей шкалы громкости 0–100

Дата: 2026-09-09. Сейчас реализуется ESP8266 **native**. Другие чипы и
Arduino WebRadio на этом этапе не меняются. KaRadio ESP8266 подключает
native `radio_control.c`/`web_service.c` через CMake и унаследует изменение
при пересборке; отдельно этот экспериментальный target ещё не проверен.

## Единый контракт

- Пользовательская громкость — целое число 0..100 включительно, шаг ползунка 1.
- 0 — цифровая тишина; 100 — прежнее максимальное усиление, без нового boost.
- Слайдер, числовое показание, API, кнопки и энкодер используют одну шкалу.
  Настройка шага 1..10 означает процентные пункты; для ESP8266 default 2.
- Проценты описывают регулятор линейного усиления, не акустическую громкость
  и не децибелы. Закон регулирования специально не меняется.
- Сохранённая до обновления фактическая громкость должна остаться прежней.
  Внутренние единицы аудиобиблиотеки/NVS могут отличаться от пользовательских.
- Пересчёт только при управлении/выдаче статуса, не в цикле PCM; без float,
  новых задач, буферов или динамического выделения памяти.
- Один общий WebUI. Возможность `volumeMax=100` включает новую шкалу;
  без неё общий скрипт сохраняет старый максимум 254.

## ESP8266 native — выполнено в исходниках

- [x] Добавлены целочисленные преобразования `volume_scale.h`:
  `raw = (percent * 254 + 50) / 100`,
  `percent = (raw * 100 + 127) / 254`, с ограничением диапазонов.
- [x] Команда WebSocket `volume=N`, ответы текущей громкости и периодический
  статус используют 0..100. Некорректные строки отвергаются; числа за
  пределами диапазона ограничиваются до 0/100, отрицательные не дают максимум.
- [x] Абсолютная установка и относительное изменение выполняются под одним
  mutex; устранён прежний read-before-lock при абсолютной установке.
- [x] `volp`/`volm` и опциональный энкодер используют новую шкалу.
- [x] Общий слайдер выбирает максимум до обработки начального статуса.
  Обновлены и обычная страница, и встроенные сжатые player/settings bundles.
- [x] NVS v1 и внутренний gain оставлены в исходных единицах 0..254.
  Например, сохранённые 160 отображаются как 63, 128 как 50, 254 как 100.
  Чтение не изменяет gain; после управления сохраняется ближайшее значение
  raw. Все 101 пользовательское значение восстанавливаются без дрейфа.
- [x] Тесты фактических C-функций: все уровни, старые raw-значения, ±1,
  крайние значения/переполнение delta, mutex timeout, отсутствие лишних
  записей при повторной установке; команды WebSocket и шкала общего JS.
- [x] Браузерный smoke-скрипт выбирает кнопку относительно DOM `max`, а не
  фиксированного 254, поэтому пригоден для старой и новой прошивки.
- [ ] При следующем развёртывании обновить SPIFFS `script.js.gz`, затем app;
  проверить реальную перезагрузку, слайдер 0/1/50/99/100 и сохранение.
  В рамках изменения шкалы плата ещё не перепрошивалась.

Не использовать старый WebUI с новой семантикой API: значение 128 теперь
будет ограничено до 100. Сначала новый скрипт (совместим со старой прошивкой),
затем новая прошивка; перезагрузить открытые вкладки. Обновить сторонние API
клиенты. Старые результаты PCM-бенчмарков 0..254 не пересчитывать задним числом.

## Очерёдность остальных вариантов

### 1. ESP32-C3 OLED native — `idf/esp32c3-oled-native`

- [ ] Найти общий владелец громкости и все точки изменения: WebSocket/HTTP,
  энкодер, физические кнопки, консоль и автоматическое восстановление.
- [ ] Применить контракт 0..100 на пользовательской границе, сохранив NVS
  и внутренние единицы, если это позволяет избежать миграции.
- [ ] Проверить подписи OLED, громкость при startup/stop/play, шаги и mute.
- [ ] Объявить `volumeMax=100` во всех вариантах HTML/variables/bundle.
- [ ] Проверить MP3/AAC/FLAC, mono/stereo, баланс и normalizer: 100 не должен
  менять прежний уровень, 0 не должен оставлять ненулевой PCM.
- [ ] Прогнать host-тесты, собрать production, проверить на плате и сохранить
  бинарник/конфигурацию/описание в `firmware/`.

### 2. ESP32 CYD native — `idf/esp32-cyd2usb-native`

- [ ] Синхронизировать контроллер громкости и API с C3; не дублировать
  расхождения в общем WebUI.
- [ ] Обновить TFT/touch/энкодер и вывод числа, пределы, шаги, mute/unmute.
- [ ] Сохранить совместимость NVS; протестировать цифровые и аппаратные
  варианты аудиовыхода, которые поддерживает этот target.
- [ ] Проверить несколько вкладок, восстановление питания, 0/100 и
  отсутствие новых затрат в PCM; собрать и сохранить production.

### 3. Исходная Arduino YoRadio — `yoRadio/`

- [ ] Инвентаризировать единицы `Config::setVolume`, `store.volume`, player,
  WebSocket, telnet/MQTT/IR/кнопок/энкодера и всех дисплеев по профилям.
- [ ] Согласовать шкалу на пользовательской границе, сохраняя исходную
  EEPROM/NVS и привязку к аудиобиблиотекам; если нужна смена формата хранения,
  добавить явную версию и одноразовую миграцию, не определять её по значению.
- [ ] Проверить I2S software decode, внешние DAC/VS1053 и остальные включённые
  профили: конечные уровни и прежние настройки не должны изменяться.
- [ ] Включить capability и обновить все локальные регуляторы/подписи.
- [ ] Проверить C3 OLED, классический ESP32 OLED, CYD и остальные поддержанные

  контроллер и WebUI уже используют общий native-код, отдельный порт шкалы

- [ ] Для новых профилей закрепить один контракт в документации и тестах.

## Приёмка каждого переноса

- [ ] 101 достижимый уровень; 0 = mute, 100 = прежний full scale.
- [ ] Установка/±шаг/физическое управление дают одинаковые значения во всех
  вкладках; обновление страницы и перезагрузка платы их не изменяют.
- [ ] Старые сохранённые низкие/средние/максимальные уровни восстанавливаются
  без скачка громкости; repeated save/load не накапливает округление.
- [ ] Невалидные команды не повышают громкость неожиданно; переполнение,
  timeout и одновременные команды обработаны без повреждения состояния.
- [ ] Общий WebUI работает также с ещё не перенесёнными платами.
- [ ] Отдельный логичный коммит на каждый порт/проверенный этап; binary,
  checksum, конфигурация и changelog сохранены, измерения не выдуманы.
