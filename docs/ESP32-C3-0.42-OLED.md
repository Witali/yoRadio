# ESP32-C3 0.42-inch OLED board

This page documents YoRadio support for the compact 01Space-style ESP32-C3
development board with USB-C, RST and BOOT buttons, and a built-in 0.42-inch
OLED. The dedicated build profile is `YORADIO_BOARD_ESP32C3_OLED_042`.

The board used for this profile visually matches the
[ESP32-C3 SuperMini OLED documented by Michiel van der Wulp](https://michiel.vanderwulp.be/domotica/Modules/ESP32-C3-SuperMini-OLED/).
That variant identifies the ordinary blue LED on GPIO8 and does not identify
an onboard WS2812 LED.

The board is sold under several similar names. Check the fitted components and
PCB markings before assuming that two visually similar boards are electrically
identical; the LED population in particular varies between revisions.

## Hardware summary

- ESP32-C3FH4 RISC-V microcontroller with 4 MiB embedded flash
- 2.4 GHz Wi-Fi and Bluetooth LE
- USB-C connection to the ESP32-C3 native USB interface
- 0.42-inch, 72x40 monochrome OLED on I2C address `0x3c`
- approximately 25 x 20.5 mm PCB, with 17.78 mm between header rows
- RST and BOOT push buttons
- two-line hardware PDM stereo output for passive RC reconstruction filters

## YoRadio pin assignment

| Function | ESP32-C3 GPIO | Notes |
|---|---:|---|
| OLED SDA | 5 | Built-in display and auxiliary I2C connector |
| OLED SCL | 6 | Built-in display and auxiliary I2C connector |
| BOOT / radio control | 9 | Active low; also a boot-strapping pin |
| Right PDM audio | 3 | Right channel; connect through its own RC filter |
| Left PDM audio | 10 | Left channel; connect through its own RC filter |
| Blue audio-level LED | 8 | Fitted on the matching SuperMini OLED variant |
| Optional RGB LED in source schematic | 2 | Not fitted on the matching SuperMini OLED variant |

GPIO9 must not be held low while the board is reset unless ROM download mode
is wanted. GPIO2 and GPIO8 should not be used for external peripherals until
the actual board revision has been inspected.

## Schematic and hardware revisions

The original one-page schematic is stored in this repository as
[ESP32-C3-0.42-OLED-schematic.pdf](schematics/ESP32-C3-0.42-OLED-schematic.pdf).
It was copied without modification from the
[01Space repository at commit `3c42956`](https://github.com/01Space/ESP32-C3-0.42LCD/blob/3c429569d0fc9cd50b8e350410277c368f36a78d/Schematic/ESP32-C3-0.42OED%20Schematic.pdf).
Its SHA-256 checksum is
`7BE47A67C62B214E4954681FCFC195AD275532BA8E831E67387C4B3C17DE1203`.

The source schematic confirms OLED SDA on GPIO5, OLED SCL on GPIO6 and BOOT on
GPIO9. It also shows a WS2812B-1515 RGB LED on GPIO2, a 10 kOhm pull-up on
GPIO8, and a separate blue power LED connected directly to the supply. This
LED circuit differs from the visually matching SuperMini OLED board, whose
ordinary blue LED is connected to GPIO8.

The official PDF and the matching board page therefore describe different PCB
revisions. The physical board used for this YoRadio profile has no fitted or
usable WS2812 LED.
Consequently:

- do not assume that Arduino's generic `RGB_BUILTIN` definition is correct;
- do not send NeoPixel data to GPIO8;
- treat the current GPIO8 audio-level LED setting as revision-specific;
- verify GPIO2/GPIO8 with the actual PCB before enabling either LED circuit.

The upstream `RGB_strandtest_wheel` example is generic NeoPixel strand code and
is not proof that an addressable LED is fitted to a particular board.

## OLED

YoRadio uses the display as a native 72x40 SSD1306 panel at I2C address `0x3c`.
The driver applies the controller's 28-column RAM offset, so a generic 128x64
SSD1306 setup will produce incorrect geometry or a blank display. The default
brightness for this profile is 38% to make the tiny panel less bright. The
shared WebUI exposes the same `brightness` control used by TFT boards; its
0..100 value is mapped to the SSD1306 hardware contrast command. The setting
is retained across resets.

## Audio output

ESP32-C3 has no internal analogue DAC, but its I2S peripheral can convert PCM
to two independent PDM bit streams. This profile uses GPIO10 for the left
channel and GPIO3 for the right channel. The converter runs at a fixed 48 kHz
PCM rate with a 6.144 MHz PDM carrier. There is no external clock wire.

Build the following circuit twice, once for each channel:

```text
GPIO ── R1 1 kOhm ──●── R2 1 kOhm ──●── C3 1..4.7 uF ── amplifier input
                    │                │
                  C1 4.7 nF        C2 4.7 nF
                    │                │
                   GND              GND
```

| Channel | ESP32-C3 pin | Filter output connects to |
|---|---:|---|
| Left | GPIO10 | Amplifier left input (`L`, `LIN` or `IN-L`) |
| Right | GPIO3 | Amplifier right input (`R`, `RIN` or `IN-R`) |
| Common | GND | Amplifier signal ground |

Use the same component values in both channels:

| Part | Recommended value | Purpose |
|---|---:|---|
| R1, R2 | 1 kOhm each | Isolate the GPIO and form the two low-pass stages |
| C1, C2 | 4.7 nF each | Suppress the PDM carrier; each RC pole is about 33.9 kHz |
| C3 | 1 to 4.7 uF | AC-couple the reconstructed audio to the amplifier |
| R3 | 47 to 100 kOhm, if needed | Tie the amplifier side of C3 to GND when its input has no DC return |

A non-polar film or ceramic capacitor is preferable for C3. If an electrolytic
capacitor is used, connect its positive terminal toward the ESP32-C3 filter and
its negative terminal toward an ordinary ground-referenced amplifier input.
Some amplifier modules already contain an input coupling capacitor and bias
network; in that case follow the module schematic and do not duplicate parts
unnecessarily.

Connect only to a high-impedance analogue input of a powered stereo amplifier,
active speakers, mixer or line input. Join the ESP32-C3 and amplifier signal
grounds. Power the amplifier according to its specification. Never connect a
speaker, headphones or another low-impedance load directly to GPIO10 or GPIO3;
the GPIOs provide a logic-level PDM signal, not speaker power.

To reduce CPU load on the single-core ESP32-C3, this profile disables the
three-band software equalizer. Bass, middle and treble remain fixed at zero,
their commands are rejected by the firmware, and the common WebUI hides those
controls for this profile. Balance control remains available.

## BOOT button controls

After normal startup the BOOT button controls the radio:

| Gesture | Action |
|---|---|
| Single click | Play / pause |
| Double click | Next station |
| Long press | Previous station |

Holding BOOT while pressing and releasing RST deliberately enters the ESP32-C3
ROM download mode. Release BOOT after the reset to program the board.

## Audio-level LED

The current board profile drives GPIO8 as an active-low PWM LED from the peak
audio level. It samples the higher of the left and right channel peaks every
50 ms, uses 5 kHz eight-bit PWM, and lets the displayed level decay gradually.
This is the same peak-envelope concept used by the on-screen VU meter.

This feature matches the GPIO8 blue LED documented for the visually identical
SuperMini OLED variant, but conflicts with the GPIO8 pull-up shown in the
original PDF. It is therefore an explicit compile-time board capability, not
an assumption made for every ESP32 board.

The Arduino profile uses these `myoptions.h`/board-profile definitions:

| Definition | C3 OLED default | Purpose |
|---|---:|---|
| `AUDIO_LEVEL_LED_ENABLED` | `1` | Compile the indicator (`0` disables it) |
| `AUDIO_LEVEL_LED_PIN` | `8` | Verified ordinary-LED GPIO |
| `AUDIO_LEVEL_LED_ACTIVE_LOW` | `1` | Invert PWM polarity |
| `AUDIO_LEVEL_LED_PWM_HZ` | `5000` | PWM carrier frequency |
| `AUDIO_LEVEL_LED_MAX_BRIGHTNESS` | `255` | Maximum 8-bit duty amplitude |
| `AUDIO_LEVEL_LED_UPDATE_MS` | `50` | Peak sampling interval |
| `AUDIO_LEVEL_LED_DECAY_STEP` | `8` | Envelope decay per update |

All ordinary Arduino board configurations default to
`AUDIO_LEVEL_LED_ENABLED=0`; the C3 OLED profile enables it explicitly. For
native ESP-IDF builds, the same settings are under
`menuconfig -> yoRadio audio level LED`. The C3 OLED defaults enable GPIO8;
the CYD native build defaults to disabled and requires a verified free GPIO
before enabling it. The driver controls a normal PWM LED, not a WS2812.

## Default native ESP-IDF build

The primary firmware is the entirely Arduino-free implementation in
[`idf/esp32c3-oled-native`](../idf/esp32c3-oled-native/README.md). It has its
own ESP32-C3 configuration, native SSD1306 driver and two-line stereo PDM
output, while retaining the same GPIO and passive-filter wiring documented
above. The repository-root setup and build commands select this target by
default.

To prepare the pinned ESP-IDF toolchain explicitly, run this once from the
repository root:

```powershell
.\setup.ps1
```

Then build the firmware:

```powershell
.\build.ps1
```

The build script invokes setup automatically when dependencies are missing, so
a fresh checkout can be built with only `.\build.ps1`. Dependencies are pinned
under the ignored `.idf` directory. Application sources compile with `-O3`,
and the ESP-IDF component manager is disabled so builds cannot silently update
dependencies. Internet access is needed only for initial setup.

The older Arduino implementation remains optional. Prepare and build it with:

```powershell
.\tools\Setup-Esp32C3OledArduino.ps1
.\tools\Build-Esp32C3OledFirmware.ps1
```

For initial programming, install the bootloader, partition table, OTA selector,
application and `spiffs.bin` at the offsets recorded in the corresponding
release manifest. For later updates, flashing only `app.bin` at `0x10000` (or
through WebUI) preserves saved Wi-Fi settings and SPIFFS files. Writing
`spiffs.bin` replaces the WebUI and station data stored in SPIFFS.
