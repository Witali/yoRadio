# ESP32-C3: ten-minute RX transport experiments

## Outcome

Two additional physical HE-AACv2 44.1 kHz stereo runs lasted **600 seconds
each**, following the requested ten-minute limit. CPU usage is informational.
Neither experiment qualifies a new default firmware or proves gap-free audio.

- **Compact RX ownership records with CRC:** the complete capture still fails.
  Whole RX block records are missing, and one CPU record is truncated/merged.
  CRC validates received records; it cannot recover missing records.
- **Native lwIP packet copies:** minimum sampled free heap was **28,440 B**,
  versus 20,952 B in the previous verbose diagnostic run. The original
  progressive-heap-loss gate still fails. Stop releases the accumulated memory;
  the idle median differs by 240 B, and the largest block returns fully.

Both candidates passed installation and restoration through WebUI OTA while
playing a controlled stream. The ordinary priority-8 firmware is back on the
board, playing its saved AAC 44.1 kHz stereo station with deep sleep disabled.
No firmware defaults, codec precision or supported sample rates were changed.

## Comparable measurements and their limits

All runs use the same ADTS fixture, paced at 1.02 times its nominal rate, and
WebUI polling with a 100 ms interval. Each playback observation lasts 600 s;
CPU/decoder analysis excludes the first 10 s. Playback heap endpoints are
medians of the first/last three valid CPU samples. Minima below are sampled
values, not allocator low-water marks. Idle values are settled medians.

The native-copy minimum is 7,488 B (7.31 KiB) higher than the previous verbose
run, and 7,420 B higher than the compact run. This is an **observed difference**,
not an isolated measurement of bytes saved by the flag: the RX diagnostic
itself costs 552 B of BSS, layout/logging differ, and the RF conditions were not

differences therefore cannot establish the cost of packet copying or CRC.

the full 590-second analysis window still fails. Keep that original result.
Post-Stop recovery distinguishes active memory pressure from a large lasting
leak; it does not establish that every allocation has the expected lifetime.
No captured decoder/allocation fault, watchdog or reboot occurred during either
load. Decoder progress and REST status cannot count missing output samples.

## What changed

### Compact ownership telemetry

The diagnostic replaces verbose owner/block payloads with ordered numeric
fields and a CRC32 over their little-endian 32-bit values. The host parser also
checks sequence continuity, owner counts, address ranges and live ownership.
The legacy record format remains readable. Native host tests exercise the
production C source under AddressSanitizer and UndefinedBehaviorSanitizer;
the independent CRC oracle and Python parser agree.

The new physical capture has valid CRCs on the received compact records, but
snapshot 55 declares six owners and contains no block rows; snapshot 65 declares
nine and contains five. The full trace is rejected for ten missing rows. The
separate malformed CPU record also remains in the saved evidence.

The pinned ESP-IDF USB Serial/JTAG VFS can drop bytes after its 50 ms transmit
wait while still returning the requested write size. This is a possible loss
mechanism, not proof of the cause of each missing row. Shorter output does not
make the transport lossless. See the preserved
[VFS source](../tests/results/esp32c3-rx-compact-20261007/sdk/usb_serial_jtag_vfs.c)
and [ownership format description](ESP32C3_RX_OWNERSHIP_20261005.md).

### Native Layer-2 to Layer-3 copies

The candidate enables `CONFIG_LWIP_L2_TO_L3_COPY=y` and its generated deprecated
alias, `CONFIG_L2_TO_L3_COPY=y`. This is the only semantic sdkconfig change from
`esp32c3-output-first`; RX ownership diagnostics remain disabled.

In the pinned [wlanif.c](../tests/results/esp32c3-rx-copy-20261007/sdk/wlanif.c),
this branch allocates a `PBUF_RAM` packet sized for the frame, copies it, and
immediately releases the original Wi-Fi receive buffer. The ordinary branch
retains the driver buffer through `esp_pbuf_allocate`. The actual candidate's
[disassembly](../tests/results/esp32c3-rx-copy-20261007/verify/wlanif_input.txt)
confirms `pbuf_alloc` and `esp_netif_free_rx_buffer` calls instead.

This can reduce retained allocation size for small packets, but adds an
allocation and copy, including a period when both buffers exist. It does not
impose a hard total TCP heap limit. TCP window, mailbox and Wi-Fi buffer counts
were not reduced. TLS and other codec regressions still need measurement.

The existing RX tracer observes the ordinary `esp_pbuf_allocate` path. The
copy branch bypasses that allocation hook: **missing ownership telemetry must
not be interpreted as zero network RAM**. The summary explicitly records
`Missing RX ownership telemetry`.

`SO_RCVBUF` was also considered, but the pinned lwIP
[TCP receive callback](../tests/results/esp32c3-rx-copy-20261007/sdk/api_msg.c)
does not use that limit to reject already-acknowledged TCP data. Enabling it
alone would not supply the desired memory bound. No such change was made.

All three use stream/decoder/output priorities 5/7/8, awake mode, four DMA
blocks, three-block prefill and full-rate AAC. Both experimental images remain
explicitly `production_qualified: false`.

After restoring from the compact diagnostic, the saved station initially
stayed at `connection failed`. One WebUI retry of the same station succeeded;
that action and the failed initial status are preserved. The
[automatic retry TODO](ESP32C3_OLED_NATIVE_TODO.md) records this separate defect.
After the copy experiment, the restored ordinary firmware resumed the saved
station without a manual retry. OTA reports verify unchanged Wi-Fi, playlist
and settings by in-memory comparisons; no credentials are saved in evidence.

## Reproduction and remaining checks

Both evidence archives contain original failures, full source identities,
firmware manifests/configurations, SDK snapshots, OTA results and final board
state. Rebuilding each archive produces a byte-identical manifest.

- [Compact telemetry evidence](../tests/results/esp32c3-rx-compact-20261007/manifest.json)
- [Native packet-copy evidence](../tests/results/esp32c3-rx-copy-20261007/manifest.json)
- [Previous verbose ten-minute evidence](ESP32C3_HEV2_RX_OWNER_20261007.md)

```text
python tests/test-rx-transport-evidence.py
python tools/esp32c3_tests/stream_memory_study.py --board http://BOARD_IP --host PC_LAN_IP --serial-port COM_PORT --firmware firmware/development/esp32c3-rx-copy/app.bin --case hev2-44100-stereo --seconds 600 --output NEW_DIRECTORY
python tools/esp32c3_tests/summarize_stream_memory.py NEW_DIRECTORY --output SUMMARY.json
```

The six evidence tests pass; this verifies the records and reproduces their
failures, not successful playback qualification. Next steps are a matched
ordinary/copy comparison, all-codec and TLS coverage for this candidate, and
DMA/sample-continuity evidence. Keep sustained trials at ten minutes unless
the user requests a longer run. A lossless ownership capture and the initial
connection retry defect also remain open.
