# Opus-радиостанции на обычной прошивке, 2026-09-17

**Итог: стабильное воспроизведение не подтверждено.** Обе доступные в плейлисте
Opus-станции запускаются и дают PCM, но есть опустошения выходной очереди,
сетевые таймауты и отказ повторного создания декодера из-за остатка DRAM.
Успех raw-бенчмарка нельзя считать доказательством работы интернет-радио.

## Что проверено

Плата `192.168.100.6`, установленная обычная радио-прошивка
[`esp8266-opus-live512-idle3s-20260913`](../firmware/development/esp8266-opus-live512-idle3s-20260913/manifest.json).
Это диагностический radio-профиль, **не production без диагностики**, не
генератор и не raw-бенчмарк. C backend Opus, CPU160, I2S PDM32 GPIO3,
две DMA-области по512слов, Opus input1024B, scratch6144B, резерв4096B,
таймаут отсутствия данных3000ms. Последние frozen ASM-патчи в этот образ
не входят. Во время этой проверки прошивка не менялась.

Происхождение образа — предыдущее подтверждённое OTA-восстановление:
SHA256 `661becd301b07885d493ceb1b513d9e874b7d86e4ada8231da8657aa90983c4b`,
885552B. HTTP подтвердил неизменный слот `0x110000`, но API не выполняет
удалённое хеширование приложения; это не новая независимая аттестация SHA.

В плейлисте платы две Opus-записи по обычному HTTP. Остальные Opus-записи
исходного плейлиста используют HTTPS и этой сборкой не поддерживаются;
их не добавляли и не подменяли URL. По два выбора каждой станции командами
`play=512` / `play=513` через штатный WebSocket `/ws`.

## Результаты

| Станция | Реальный поток | Наблюдение |
|---|---|---|
|512, R2Rock|Opus CELT stereo48kHz, около127кбит/с|Первый запуск даёт короткие фрагменты; PCM замирает на6–12с. После повторного выбора — только227msPCM за29.980s, затем0 за26.974s. Итог `DECODER INIT ERROR`.|
|513, Nightwave Plaza|Opus CELT stereo48kHz, около62–64кбит/с, **не128 из названия**|В устойчивом окне27.420sPCM за28.234s, отношение97.12%, +704события underrun. При повторном выборе25.5935sPCM за27.389s,93.44%, +888событий.|

Всего7окон наблюдения, ни одного с подтверждёнными≥20sбез разрыва:
4окна содержат достаточно данных и отвергнуты по PCM/DMA; 3неполны из-за
HTTP-таймаутов и также не могут считаться успешными. Неудачи не исключались.
Первое окно R2Rock опрашивало audio/status примерно раз в секунду, но
status часто ждал5s. Остальные6окон используют по две группы health/stages
с паузой27s, без запросов внутри паузы. Ошибки есть и при редком опросе.

`underruns` — количество моментов, когда следующая DMA-область не готова,
**не длительность тишины и не число слышимых щелчков**. Счётчик может расти
после фактической остановки/ошибки; окно без PCM не трактуется как активное
декодирование. Акустической записи/прослушивания здесь нет: проверялись
счётчики после успешной передачи PCM в выход и работа физического DMA.

## Что установлено о причинах

- В R2Rock зафиксированы `transport_result=4`, `errno=116`: таймаут входа,
  `input_bytes=0`, последующие фазы HEADER/CONNECT и длительное отсутствие PCM.
  Причина первоначального сетевого замирания этим тестом не установлена.
- После повторного запуска R2Rock диагностика stage10 (`INIT_RESERVE`):
  доступно4020B DRAM при резерве4096B, наибольший блок2276B. Это прямое
  объяснение отказа создания декодера. Резерв не уменьшали. В предыдущем
  снимке Plaza stage была0; отказ stage10 появился во время этой проверки.
- В устойчивом окне Plaza время этапов: decode74.66%, output18.15%,
  read3.86%, post-decode wait2.70%, input wait0.13%.
  Это **wall time, не чистый CPU**: включает вытеснения, а output — ожидание
  DMA. Max decode36.193ms накоплен с запуска платы, не максимум только окна.
  В этом окне пропуски происходили также внутри decode/output, не только
  ожидания сети. Это указывает на недостаточный запас времени/готового PCM,
  но не выделяет точную долю прерываний Wi-Fi в замере декодера.
- RSSI в сохранённых статусах примерно−53…−63dBm; отключения Wi-Fi в них
  нет. Слабым сигналом все обнаруженные дефекты объяснить нельзя.
- Остаток audio stack1464B, web stack2288B. Минимум общей кучи за время
  работы упал с23540 до896B. После остановки свободно27344B против27628B
  перед тестом. Это не доказательство постоянной утечки; запас RAM во время
  потока/переподключения явно мал. DRAM reserve и общая free_heap — разные
  показатели, их нельзя смешивать.

Оба источника независимо отвечали HTTP200 на компьютере. Короткие захваты
прошли CRC всех полных Ogg-страниц и FFmpeg-декодирование без ошибок:

| Источник | Пакеты | Размер пакета, max | Формат каждого пакета |
|---|---:|---:|---|
|R2Rock|1400|635B|1×20ms CELT stereo|
|Plaza|1600|280B|1×20ms CELT stereo|

Захват ограничен25s; выход curl28 здесь означает **заданный предел захвата
бесконечного потока**, а не установленную неисправность сервера. Длительность
полученного аудио может быть больше из-за стартового burst сервера. На
запрос R2Rock с `Icy-MetaData: 1` также получен200, без `icy-metaint`.
Успех ПК не доказывает отсутствие потерь именно на Wi-Fi-соединении платы.
Аудиофрагменты оставлены в игнорируемой `.build/`, в Git только метаданные.

## Воспроизведение проверки

Сначала сохранить `snapshot`, затем явно выбрать станцию, выполнить
`run_stage_wall`, после всех окон снять read-only `/api/native/opus-stream`.
Не запускать raw benchmark и не использовать POST тестового URL вместо
реального выбора станции. Примеры:

```powershell
node tools/esp8266_audio_profile/check_prefill_board.cjs command --command play=512 --output .build/new-test/start.json
node tools/esp8266_opus_profile/run_stage_wall.cjs --seconds 25 --output .build/new-test/window.json
```

Полные результаты, включая ошибки запросов и восстановление:
[`tests/results/esp8266-opus-live-stations-20260917`](../tests/results/esp8266-opus-live-stations-20260917/report.json).
Пересчёт/регрессия без доступа к плате:

```powershell
node tools/esp8266_opus_profile/report_live_stations.cjs tests/results/esp8266-opus-live-stations-20260917
node --test tests/esp8266-audio-continuity.test.js tests/esp8266-stage-wall-report.test.js tests/esp8266-opus-live-stations-results.test.js
```

После проверки восстановлена станция167 `Radio Caprice - Broken Beat / Bruk [1]`,
остановка, volume100/balance0; плейлист и слот не изменены. HTTP/WS снова
ответили, ошибка очищена обычным переключением/остановкой. Не было OTA,
UART, сброса, изменения Wi-Fi компьютера или настроек буферов. Код прошивки
не изменён: это квалификационный тест, а не исправление найденных проблем.
