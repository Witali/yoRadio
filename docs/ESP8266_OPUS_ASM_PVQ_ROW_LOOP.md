# PVQ row-loop: прямой счётчик и условный обратный переход

2026-09-14. Принят как новый экспериментальный raw ASM baseline после30 A/B/A.
Это не production-квалификация и не достижение70% CPU.
Основание: [host census](ESP8266_OPUS_PVQ_PATH_PROFILE.md), а не предположение
о том, что в исходном коде отсутствует pointer decrement: он уже есть.

## Изменение

Родитель — принятый `esp8266-opus-mdct-post-pair-candidate-v1`,160МГц/QIO40,
raw benchmark без output/stage/function profiling. Отрицательные FFT-опыты
не включены. Меняется только диапазон decode_pulses
`[0x40253331,0x40253354)` длиной35 B; прочие ELF-байты/адреса неизменны.

Вход в блок происходит только после неуспешной проверки row[K]. Указатель
`a15=&row[K]` уже вычислен, повторные SLLI/ADD не нужны. Следующие пробы:

```asm
addi    a6, a15, -4
probe:
l32i.n  a8, a6, 0
addi    a6, a6, -4
addi.n  a12, a12, -1
bltu    a2, a8, probe
mov.n   a3, a12
```

Далее сохранены исходные sign-extension в a9/a11, a6=N-1 и переход на
общую точку0x40253361. В исходном continuing-loop шесть инструкций, здесь
четыре; для J дополнительных проб экономится2J-1 выполненных инструкций
на вход в блок. Это не число тактов и не гарантия ускорения полного декодера.
26 B выполняемого кода и9 B недостижимого padding сохраняют соседние адреса.

## Точность, ABI и память

- Все16 регистров при выходе совпадают, включая временные a3/a6/a9/a11;
  SAR не меняется. Стек48 B, callee saves/return/entropy calls вне патча.
- Индукция по номеру пробы J: оба варианта читают ровно row[K-J],
  выходят при том же unsigned сравнении, без prefetch следующей строки.
  Вектор, entropy index и энергия не меняются внутри блока.
- 2298 численных случаев фактического linked ASM,2035278 проб: границы
  unsigned сравнений, короткие и длинные поиски, значения через32767/32768.
  Они дополняют индукцию, не вводят ограничения K/N/битрейта.
- Проверены реальные CFG-входы/выходы, недостижимость padding, остальные
  функции/секции, XOR/appendedSHA образа. RAM/frame/app-size не увеличились.
- Исходный C fallback и сохранённый GCC ASM не изменены; рецепт отдельный.

Артефакты: `firmware/development/esp8266-opus-pvq-row-loop-{control,candidate}-v1`.
Оба app903216 B; кандидат SHA256:
`9069d279220b60c7da9b8615fa0d47e54e9e5ace2428ac66ba1a00300ad87164`.
`preflight.json` хранит linked инструкции/индукцию/хеши; `parent.elf.gz`
и `patches.elf/.s` позволяют проверить побайтовую изоляцию.

## Физические результаты

Пять RAM-fixtures,10 попыток каждого варианта,120 кадров на поток/попытку.
Входной поток не скачивается, аудиовывод и function/stage profiler выключены.
CPU — task_us / длительность исходного аудио; включает начисленные ISR и
служебные измерения, без вычитания оценочного overhead. Все30 попыток точны.

| Поток | A CPU,% | B CPU,% | A2 CPU,% | Max вызов A/B/A2,мкс |
|---|---:|---:|---:|---|
| mono12 |23.09677|23.07821|23.09227|7591 /7001 /8381|
| mono24 |54.33308|54.31898|54.32244|14299 /14815 /17433|
| stereo64 |64.68779|64.66358|64.67117|17443 /17445 /23705|
| stereo128 |76.76092|76.67685|76.72144|20305 /22301 /28512|
| stereo192 |87.46700|87.30769|87.49450|22505 /21639 /30802|

На192 относительное сокращение времени0.18214% и0.21351%, на128 —
0.10951% и0.05811%. Обе проверки high-bitrate-first проходят. Это небольшой
выигрыш:31.9–37.4мкс на20мс аудио на192. Mono12 не использует PVQ; его
разницу нельзя приписывать выполнению нового цикла, это вариация измерений.
Максимумы улучшились не во всех режимах; B19221.639мс всё ещё больше20мс.

RAM/стек/арены не выросли. Минимальная свободная DRAM A/B/A2:
7492 /3816 /1400 B; минимальный запас стека1660 B во всех сериях.
Медиана DRAM после raw cleanup26300 /26422 /26564 B. Особые случаи:

- B/run7: временный минимум3816 B, PCM точен, после теста память восстановилась.
- A2/run4: HTTP observation timeout, CPU192100.73471%, минимум1400 B,
  raw dram_after18280 B, последующий status free_heap26576 B. Декодер
  завершился успешно. Причина просадки/выброса не установлена; начальный
  RSSI-55dBm и RSSI-54dBm после этого запуска не доказывают сетевую причину.
- B/mono12: task window больше wall window на2782мкс(run2) и1424мкс(run5).
  Разные окна учёта сохранены без вычитания, clamping или исключения попыток.

Все JSON/логи/OTA и независимый расчёт находятся в каталоге кандидата:
`comparison.json`, `controls/before`, `runs`, `controls/after`. Ни одной
неудачной или медленной попытки не заменено. Это raw-тест, не live20с.
Итоговые46 связанных регрессий PASS/0skip, включая независимые медианы,
SHA/PCM всех30 запусков, сохранение выбросов и восстановление. Это не
утверждение о прохождении полного набора тестов всего репозитория.

## Восстановление и следующий шаг

Обычная C-backend прошивка возвращена OTA в0x10000:
SHA256 `661becd301b07885d493ceb1b513d9e874b7d86e4ada8231da8657aa90983c4b`.
Главная страница HTTP200,27249 B за104.0566мс (передача, не отрисовка браузера).
WebSocket getindex/current167/stopped, прежняя станция/плейлист сохранены.
RSSI-53dBm, free_heap27448 B/min24748 B, web stack free2324 B. UART/reset
не использовались. Цель70% не выполнена; обычный профиль не менялся.

Следующий независимый пункт основного плана — decoder-only quant_partition
при замороженных адресах остального ELF. Прежняя компактная перепоновка
дала регрессию и не принимается заново без этого отличия. Цель остаётся
70% raw CPU192 и последующий непрерывный I2S PDM/WebUI, а не число инструкций.
