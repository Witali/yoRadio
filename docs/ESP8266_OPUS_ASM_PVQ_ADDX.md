# Opus ASM: точная адресация PVQ через ADDX4

Эксперимент `bands-pvq-addx-asm` поверх лучшего `bands-tell-inline-asm`.
Сохранён как компактный экспериментальный вариант, не включён по умолчанию.
Код меньше, но на 192 кбит/с немного медленнее лучшего tell-inline.
Цель 192 <=70% CPU не достигнута.

В `decode_pulses` заменяются20 пар SLLI(index,2)+ADD(base) на ADDX4.
Результат — то же 32-битное значение адреса по модулю2^32. Второй оператор
перезаписывает промежуточный регистр; других читателей или точек входа между
инструкциями нет. ADDX4 масштабирует первый входной операнд, не второй.
Ни SAR, ни память не меняются; call0 ABI, stack, таблицы и entropy остаются
исходными. C fallback и зафиксированный GCC snapshot не редактируются.

Рецепт `tools/esp8266_opus_asm/pvq_addx.cjs` воспроизводит отдельный overlay.
Проверка нормализует фактический object/linked граф с перенумерацией всех
branch targets и запрещает fusion, если есть переход внутрь пары.

## Результат на плате, 2026-09-14

CPU160 / QIO40, 10 исходных A, 10 компактных B, 10 повторных A2.
Пакеты заранее в RAM; сетевое чтение аудио, PDM и function/stage profiling
выключены. Wi-Fi и WebUI остаются включены: измеритель task CPU учитывает
попавшие в его окно ISR и служебные операции. Это не проверка live-воспроизведения.
Все 30 попыток сохранены, ошибок наблюдения и несовпадений PCM нет.

На 192 кбит/с B медленнее на 0,291–0,296% относительно контроля:
дополнительные 51,35–52,19 мкс на 20 мс звука. На остальных проверенных

лучшим скоростным вариантом остаётся tell-inline. Компактный вариант **не удалён**:
меньший размер сам по себе полезен, даже без выигрыша CPU на 192 кбит/с.

### Размер и память

- `decode_pulses`: 985 -> 945 байт (-40 байт, около 4,1%).
- Весь `app.bin`: 903216 -> 903184 байт (-32 байта с учётом компоновки образа).
- Static DRAM/IRAM не изменились; стек функции 48 байт, scratch тот же.
- Минимальный остаток стека benchmark: 1660 байт во всех трёх сериях.
- Минимальная наблюдаемая свободная DRAM: A 904, B 8164, A2 8176 байт.
  Низкий остаток A/run6 сохранён, причина не установлена; это не доказательство
  экономии RAM кандидатом. После cleanup: минимум 26124 / 26008 / 26192 байта.

Максимум wall-вызова включает вытеснение и не равен чистому времени функции.
В A/run5, A/run10 и A2/run6 task-окно оказалось чуть длиннее wall-окна:
служебные операции измеряются в разных границах; значения не обрезаны.
Сдвиг flash-компоновки может объяснять смешанную скорость, но cache misses
не измерялись, поэтому это гипотеза, а не установленная причина.

Артефакты: `firmware/development/esp8266-opus-bands-pvq-addx-v1/`.
`comparison.json` содержит все метрики и ссылки/SHA всех 30 попыток;
`preflight.json` — проверку linked-кода и секций. Воспроизведение отчёта:
`node tools/esp8266_opus_asm/report_pvq_addx.cjs`.

Восстановлен исходный `esp8266-opus-live512-idle3s-20260913` через OTA,
без UART и изменений SPIFFS: I2S PDM32 GPIO3, 2 x 512 слов, исходное stopped.
OTA подтвердил слот 0x110000; статус без ошибки, Wi-Fi RSSI -58 dBm,
free heap 27452 байта. Результаты — `restore-ota.json` и `restore-snapshot.json`.
