# ESP8266 Opus: длинные пакеты через один короткий PCM-буфер

2026-09-10. Это исправление совместимости и гранулярности выдачи, не заявление
об ускорении математики декодера или непрерывности физического звука.

## Найденная причина

DLF24 по HTTP проходил headers/redirect, но получал ошибку `Opus packet
exceeds20ms`. Локально захвачен ограниченный фрагмент:66 CRC-проверенных
полных Ogg-страниц,576 аудиопакетов. Каждый TOC=123: Hybrid mono, **три кадра
по20мс**, пакет60мс, максимум180 байт. Это не один SILK60мс кадр.
240 байт незавершённого хвоста не декодировались и явно отмечены в отчёте.
Аудиозапись остаётся локально; в Git сохраняются только метаданные/хэши.

Opus допускает объединение совместимых кадров в один пакет. Его штатный
[repacketizer](https://opus-codec.org/docs/opus_api-1.5/group__opus__repacketizer.html)
разделяет такие кадры. В прошивке дополнительный repacketizer и копия packet
не нужны: существующий parser уже определяет размеры всех кадров.

## Изменение

- Общий внутренний decode-loop получил необязательный синхронный callback
  после завершения каждого coded frame: history, transitions и gain уже
  обработаны, временная память кадра возвращена.
- Native mono48k использует этот путь с прежним PCM960×int16=1920 байт.
  После callback этот же PCM переиспользуется для следующего кадра.
- Лимит всего Ogg-пакета120мс/1536 байт; отдельного кадра20мс. Один SILK40/60мс
  кадр всё ещё отвергается до decode. Не делим его entropy stream по байтам.
- Исходный opus_decode/FEC/PLC интерфейс сохранил полный PCM-контракт.
  Новый bounded API не допускает рекурсивного decode из callback.
- Pre-skip и EOS trim применяются к пересечению каждого блока с диапазоном
  вывода; granule проверяется по полной длительности пакета. Bitrate также
  считается по полному сжатому пакету, не по длительности одного блока.
- Отмена на любом блоке немедленно прекращает остальные кадры, сбрасывает
  codec state на уровне native adapter и защёлкивает ошибку до reset.
  Уже выданный PCM отменить нельзя. Счётчик пакетов растёт только после
  полного успешного пакета; decoded_samples учитывает реально готовые кадры.
- Новых постоянных буферов нет. Нужны лишь контекст позиции/trim на стеке
  вызова и callback-параметры. Стек проверяется отдельно в target build.

## Локальная проверка

`run_block_regressions.cjs`:11 собственных наборов + приватный DLF24.
SILK/Hybrid/CELT,40/60/120мс пакеты, CBR/VBR/padding,48 кадров по2.5мс,
смена режима и неполные последние группы. Все исходные кадры сохраняются;
генератор использует opus_packet_parse, а не предположение о TOC code0.

Эталон — независимо подготовленный pristine generic32 libopus с полным
PCM на пакет. Candidate — bounded+FIR с callback и PCM960. Все сравнения
exact, max PCM error0. После каждого callback тест перезаписывает PCM,
проверяя, что будущий кадр не зависит от уже переданного буфера.
Проверены guards, ноль packet-time malloc/calloc/realloc и запрет re-entry.

Scratch DRAM:1808B SILK,2904B Hybrid (включая DLF),5488B CELT20ms,
5968B смешанный переход; word arena peak<=15600B из16384B. Это high-water
данного корпуса, не универсальное доказательство верхней границы всех Opus.
Native-тест: trim через границу кадра, EOS и cancel после второго кадра,
reset/replay, отклонение одиночных SILK40/60, недостаток памяти, цепочки.

```powershell
node tools/esp8266_opus_profile/run_block_regressions.cjs
node --test tests/esp8266-opus-block-output.test.js tests/esp8266-native-opus.test.js
```

аппаратного прогона; host exact не закрывает эти пункты.
