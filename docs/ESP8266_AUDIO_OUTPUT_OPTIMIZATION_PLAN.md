# План ускорения и асинхронного вывода звука ESP8266

Цель — уменьшить время, которое Helix-декодер теряет на подготовку и выдачу
PCM, не ухудшая звук и не уменьшая безопасный запас RAM Wemos D1 mini. Основной
выход платы — mono I2S-PDM на GPIO3/RX, 48 кГц, 8 PDM-бит на PCM-сэмпл.
Непрерывный поток выдаётся кольцом SLC DMA; legacy SPI-PDM на GPIO13/D7 и
стандартный PCM I2S для внешнего ЦАП остаются альтернативными профилями.

## Ограничение SPI DMA

ESP8266EX не имеет DMA для SPI/HSPI. Аппаратный SPI FIFO содержит 16
32-битных data-регистров, поэтому одна транзакция ограничена 64 байтами. Нельзя
дать SPI кольцевой список PCM/PDM-буферов и получить непрерывную передачу без
участия ядра, как на ESP32.

Текущий тракт использует максимально близкую замену: статическая очередь
64-байтных блоков, прерывание завершения SPI и загрузка следующего блока прямо
из ISR. Это освобождает задачу декодера от ожидания физической передачи, но ISR
всё равно должен скопировать 16 слов в регистры SPI1 и запустить следующую
транзакцию. Production по умолчанию использует периферию I2S/SLC как
непрерывный DMA-тракт для уже сформированного однобитного PDM. Ограничение
этого раздела относится к оставленному для сравнения SPI-PDM на GPIO13/D7.

## Исходное состояние

- [x] SPI работает асинхронно относительно физической передачи: очередь из 12
  блоков по 512 бит опустошается из `SPI_TRANS_DONE_EVENT`.
- [x] Задача audio спит через task notification, только когда очередь заполнена;
  активного ожидания регистра SPI нет.
- [x] Очередь статическая, ограниченная и не фрагментирует heap.
- [x] Остановка сначала опустошает очередь, выдаёт нейтральный PDM-блок и только
  затем переводит GPIO13 в ноль.
- [x] Воспроизводимый профилировщик отдельно считает decoder, normalization,
  PCM output, PDM compute, SPI queue wait, CPU idle и heap.
- [x] Добавлен отдельный generated-PCM профиль: 128 stereo frames/512 bytes из
  статической RAM, без Wi-Fi, HTTP и декодера. Выход выбирается тем же Kconfig,
  что и в production; старый `YORADIO_ESP8266_FIXED_I2S` оставлен только как
  deprecated alias стандартного PCM I2S.

Один 512-битный блок содержит 32 выходных сэмпла и занимает примерно 0,667 мс.
Двенадцать блоков дают около 8 мс развязки. Сейчас декодирующая задача выполняет
normalization, volume/balance, stereo-to-mono, resampling и sigma-delta сама.
Она строит блок в локальном массиве, копирует 64 байта в очередь, а ISR затем
копирует те же 64 байта в регистры SPI1.

## Этап 1. Убрать лишнюю копию без увеличения RAM

- [x] Получать свободный слот очереди до преобразования и строить PDM сразу в
  `spi_pdm_chunk_t::words`.
- [x] Публиковать готовый слот короткой критической секцией; ISR не должен видеть
  блок, пока producer его заполняет.
- [x] Оставить единственную неизбежную копию из очереди в 16 data-регистров SPI1.
- [x] Добавить тест, запрещающий промежуточный 512-битный стековый массив и
  копирование producer -> queue.
- [x] Сравнить baseline и новый путь generated-PCM профилем, QIO80, 160 МГц,
  с включённым физическим SPI-PDM выводом и без влияния декодера/сети.

Критерий принятия: PCM/PDM не меняется, heap не уменьшается, ошибок/тайм-аутов
очереди нет. Если ускорение не измеряется, более сложный код не оставляем.

### Результат этапа 1 — 2026-09-01

Обе сборки использовали одну Wemos D1 mini, 160 МГц, QIO80, `-O3`, один и тот
же статический stereo PCM-блок 128 frames/512 bytes, 48 кГц и выключенную
нормализацию. После двух секунд прогрева измерялись десять секунд. Wi-Fi, HTTP и
декодеры не запускались.

| SPI-PDM GPIO13 | Producer copy | Direct queue fill | Изменение |
| --- | ---: | ---: | ---: |
| PCM callbacks | 3 622 | 3 622 | одинаково |
| Физический realtime | 96,5% | 96,5% | одинаково |
| Средний `native_audio_output_write()` | 2 754 us | 2 753 us | одинаково |
| CPU compute вне SPI wait за 10 с | 2 272 467 us | 2 134 604 us | -6,07% |
| CPU busy / idle | 67,3% / 32,7% | 66,1% / 33,9% | -1,2 п.п. busy |
| Free / minimum heap | 109 816 / 107 108 B | 109 816 / 107 108 B | 0 B |
| App binary | 130 416 B | 131 088 B | +672 B flash |

Прямое заполнение принято: оно не меняет буферизацию и физическую скорость, но
освобождает около 1,2% времени всего ядра без расхода RAM. Увеличившееся время
SPI wait ожидаемо: producer быстрее подготавливает те же блоки и раньше засыпает
на заполненной очереди. Ограничение 96,5% остаётся в переключении коротких
512-битных SPI-транзакций и будет отдельно сравнено с непрерывным I2S DMA.

## Этап 1b. Сократить ISR и измерить межблочный разрыв

- [x] Обойти универсальный SDK dispatcher `spi_intr()` и подключить к общему
  SPI level-1 вектору прямой IRAM-обработчик HSPI.
- [x] Вынести редкий `vTaskNotifyGiveFromISR()`/yield в отдельную noinline
  функцию: обычное завершение блока её не вызывает.
- [x] Запретить GCC встраивать большой FIFO path обратно в ISR.
- [x] Добавить profile-only счётчик start-to-start gap. Он использует
  `g_esp_os_cpu_clk + CCOUNT`, потому что ESP8266 RTOS SDK обнуляет CCOUNT на
  каждом системном тике.
- [x] Проверить assembly и физический A/B на Wemos D1 mini.

Production assembly прямого ISR занимает 95 байт, имеет 16-байтный frame и
сохраняет локально только `a0`. Штатный `spi_intr()` занимает 195 байт и до
вызова callback сохраняет `a0`, `a12`, `a13`, `a14`; затем callback создаёт ещё
один frame. Полное сохранение A2-A13 общим входом FreeRTOS level-1 происходит
раньше нашего C ISR и остаётся неизменным. Убрать его локальным атрибутом C
функции нельзя: для этого пришлось бы заменять общий вектор всех прерываний.

Физический generated-PCM A/B: 160 МГц, QIO80, PDM8 384,615 кГц, 512-битные
транзакции, две секунды прогрева и десять секунд измерения.

| Параметр | SDK dispatcher | Прямой ISR | Изменение |
| --- | ---: | ---: | ---: |
| Физический realtime | 96,8% | 96,8% | без ухудшения |
| Средний write | 2 747 us | 2 746 us | -1 us |
| Средний gap | 7 423 цикла / 46,39 us | 7 393 цикла / 46,21 us | -0,19 us |
| Максимальный gap | 7 528 циклов / 47,05 us | 7 466 циклов / 46,66 us | -0,39 us |
| Chained transfers | 7 272 | 7 274 | одинаково |
| Minimum free heap | 106 636 B | 106 564 B | -72 B |

Проверен и отклонён ping-pong эксперимент через `USR_MOSI_HIGHPART`: заранее
подготовленные половины FIFO почти не изменили gap (7 340 циклов), но удвоили
число прерываний до 14 083 и снизили physical realtime до 93,7%. Следовательно,
копирование FIFO не является главным источником паузы; доминирует общий
FreeRTOS interrupt entry/exit. Прямой ISR оставлен как небольшое безопасное
улучшение, ping-pong код удалён. Полностью непрерывный вывод на ESP8266 можно
получить только через I2S/SLC DMA, а не через master HSPI без DMA.

## Этап 2. Измерить backpressure и подобрать очередь

- [ ] Добавить счётчики high-water mark, ожиданий полного буфера, тайм-аутов и
  моментов, когда SPI закончил последний блок раньше следующего callback.
- [ ] Выводить их только в profile-сборке, чтобы production hot path не логировал.
- [ ] Сравнить 8, 12 и 16 блоков. Размер должен быть compile-time параметром.
- [ ] Выбрать минимальную очередь без underrun на 32/128/320 кбит/с MP3 и
  48/128/320 кбит/с AAC.

Увеличение очереди скрывает краткие пики времени декодера, но не создаёт CPU.
Каждый дополнительный блок стоит 68 байт статической RAM и добавляет до 0,667 мс
задержки.

## Этап 3. Ускорить fixed-point PDM kernel

- [ ] Снять ассемблер и профиль `spi_pdm_emit_sample()` отдельно от gain/mix.
- [ ] Проверить branchless carry, разворот по 2/4 бита и упаковку полного
  32-битного слова за один вызов.
- [ ] Проверить маленькую IRAM-функцию только после измерения размера и скорости.
- [ ] Не использовать большую LUT: RAM важнее небольшой экономии циклов.
- [ ] Для каждого варианта сравнить PDM-биты либо восстановленный PCM/SNR с
  точной реализацией.

Вариант сохраняется только при ускорении на физическом LX106. Оптимизация, которая
лишь усложняет C-код или увеличивает spills в ассемблере, отклоняется.

## Этап 4. Блочная обработка gain, mix и resampling

- [ ] Кэшировать gain-коэффициенты до изменения volume/balance, а не вычислять
  их для каждого PCM callback.
- [ ] Объединить stereo-to-mono и volume/balance в один проход без записи
  масштабированного stereo обратно в decoder PCM.
- [ ] Проверить блочный resampler с тем же фазовым аккумулятором и без делений.
- [ ] Не менять буфер декодера, если дальнейший тракт может читать его `const`.

Это должно уменьшить проходы по PCM и cache traffic. Нормализатор пока остаётся
отдельным in-place этапом, поскольку он использует peak всего блока.

## Этап 5. Отдельный output worker — только как контролируемый эксперимент

- [ ] Реализовывать лишь если этапы 1–4 не дают нужного запаса и измерения
  показывают существенное SPI wait в задаче decoder.
- [ ] Начать с двух статических PCM-блоков по 512 байт и минимально проверенного
  стека; никаких динамических выделений во время воспроизведения.
- [ ] Decoder публикует блок и продолжает работу, output worker выполняет
  gain/mix/PDM и заполняет SPI-очередь.
- [ ] При заполнении обоих блоков decoder блокируется через notification/queue,
  а не опрашивает состояние.
- [ ] Stop/station switch инвалидирует поколение, будит worker и гарантированно
  освобождает оба блока до смены декодера.

На одном ядре worker не уменьшает суммарное число инструкций. Он полезен только
для правильного backpressure и перекрытия ожидания SPI/Wi-Fi. Цена — около 1 КБ
PCM плюс стек и context switches. Эксперимент принимается только если после
старта Wi-Fi, WebUI и MP3 остаётся не менее 8 КБ свободной heap и не менее 6 КБ
minimum-free в длительном тесте.

## Этап 6. Непрерывный PDM через I2S/SLC DMA

- [x] Сделать I2S-PDM выходом production по умолчанию и сохранить выбор
  SPI-PDM/PCM I2S на этапе сборки.
- [x] Использовать четыре кольцевых DMA-буфера по 128 32-битных слов и заранее
  заполнять их нейтральным PDM `0xAAAAAAAA`, а не нулевым DC.
- [x] Переносить незавершённое 32-битное PDM-слово между callback декодера,
  чтобы не вставлять паузы и padding на границе PCM-блоков.
- [x] Маршрутизировать DATA GPIO3, BCLK GPIO15 и LRCLK GPIO2 как в
  ESP8266Audio. К RC-фильтру подключается только DATA; два тактовых вывода
  нужны периферии для надёжного запуска непрерывного SLC DMA.
- [x] Заменить проблемный output-only путь драйвера RTOS SDK минимальным
  локальным backend: статическое кольцо 4 x 128 слов, companion SLC link,
  DMA mode 1, BBPLL audio clock и task notification из EOF ISR.
- [x] Добавить аппаратную самопроверку: инициализация считается успешной,
  только если DMA вернул первый буфер не позднее 100 мс.
- [x] Документировать конфликт GPIO3 с UART RX: приложение не читает UART,
  host не должен передавать данные во время звука. GPIO16 прошивка не управляет;
  электрическое ограничение тока обеспечивает установленный резистор 470 Ом.
- [ ] Снять физический A/B I2S-PDM против legacy SPI-PDM и выполнить длительный
  тест MP3/AAC на реальной плате. Короткий тест Wemos D1 mini от 2026-09-01
  подтвердил старт DMA, подключение Wi-Fi, MP3/ICY и отсутствие DMA timeout;
  прослушивание RC-выхода и полная матрица битрейтов ещё нужны.

равно требуется пройти оставшуюся матрицу на реальном ESP8266.
