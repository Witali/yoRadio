# Typed AAC memory layout — 2026-10-01

## What changed

The SBR adapters used fixed **offsets from allocated objects**, not absolute RAM
addresses. That still made layout changes fragile: a channel stride or field
move required updating independent numeric expressions in several functions.

[`aac_sbr_abi.h`](../idf/esp32c3-oled-native/main/aac_sbr_abi.h) now describes the
audited core, channel, smoothing, PS, hybrid and overlay storage with named C
members. For example, `owner + 0xc984` becomes `owner->ps`, and right-channel
synthesis is `owner->channel[1].frame.synthesis`. Allocation sizes use `sizeof`;
translation between original and compact layouts uses `offsetof` and array
element sizes. These are views of existing allocations, not additional copies.

This replaces raw field-address arithmetic in the smoothing experiment, PS
relocation adapters, PC16 PS implementation and repaired reset. Unknown regions
remain explicitly opaque. The header does not claim to reconstruct the whole
decoder's original source or authorize shortening any other array.

## Private binary boundary

The closed archive still has a fixed private ABI. Its verified field offsets and
sizes therefore remain as `_Static_assert` checks in one header. The code rejects
non-32-bit pointer layouts. The PS overlay must end before synthesis history;
all four smoothing data matrices remain `[5][64]`.

The compact-table patcher now reads original/compact offsets from an **RV32
compiler-generated ELF object** built from this same header. It no longer has a
second handwritten table of replacement offsets. All 53 replacement immediates,
and the bytes of all seven patched objects, match the previous tested build.

Instruction locations and original instruction words necessarily remain pinned
to the audited archive. They identify instructions to verify, not runtime RAM
addresses. Archive SHA, original words, relocation checks and immediate bounds
still fail closed. The known invalid vendor reset offset is retained only in
the padded fault-reproduction test; the repair uses typed fields.

Before changing a member's storage, complete its function/access/lifetime map
as required by the [RAM plan](ESP32C3_HE_AAC_RAM_EXECUTION_20261001.md).
Successful struct compilation alone is not evidence that memory is unused.

## Verification

| Check | Result |
| --- | --- |
| Compile layout with the ESP32-C3 toolchain | All size/offset assertions pass; deliberate channel-layout drift fails compilation |
| Compiler-derived binary patches | 53 immediates and seven object hashes identical to the previous experiment |
| Smoothing: six synthetic inputs and ABBA capture | 45 paired runs including controls, 9,019,392 candidate scalar PCM samples; maximum/RMS error 0 LSB |
| Smoothing mode/FIR and lifecycle checks | Enabled/disabled FIR, pointer rotation, allocation guards, 21 format segments and two injected allocation failures pass |
| Direct reset | 24 paired resets, 887,808 subsequent scalar PCM samples, exact output and intact guards |
| PC16: synthetic inputs and ABBA | Existing error counts and ABBA error distributions unchanged; maxima remain 2 / 3 LSB against native decoding |
| Per-decoder production adapters in QEMU, with PC16 cache | Ten format cases; 328,770 output stereo frames byte-identical to the previous cached implementation |
| Host ASan/UBSan | Seven adapter/state/framing/ownership suites pass |
| Saved evidence and compiler regression tests | Five new tests and 31 historical evidence tests pass |

The lossless smoothing path retains its measured instruction overhead. PC16's
extra guest instructions versus native decoding changed from 32.387% to 32.727%
on synthetic HEv2 and from 42.733% to 43.043% on ABBA. This is approximately
0.26% / 0.22% more work relative to the previous PC16 implementation, not a
physical CPU measurement. Follow-up: optimize the typed PS access path while
retaining valid alias handling and verify PCM again. PC16 and its slower cache
remain experimental and disabled by default.

This refactor frees **no additional RAM** and changes no production defaults.
The original / compact-table / PS-relocated owner requests remain 55128 / 53240 /
51596 bytes. It does not combine those two reductions or fix the radio's remaining
full-HE HTTP/HTTPS memory failures. No board firmware was installed in this step.

## Evidence and reproduction

[`tests/results/esp32c3-aac-abi-20261001`](../tests/results/esp32c3-aac-abi-20261001/)
retains six QEMU logs/results/configurations, the compiled layout object, patch
audit, source snapshots and host sanitizer output. Historical evidence keeps its
original source snapshots and hashes; it is not relabeled as a new test run.

Build the existing `smoothing`, `reset`, `pc16-write` and `ps-pc16-owner` QEMU
configurations using the commands in their reports. The saved owner config has
`CONFIG_YORADIO_AAC_PS_PC16_CACHE=y`; other PC16 results here have the cache off.
Run their corresponding `tools/codec_benchmark/run_aac_*.py` runners. Use the
unchanged ABBA capture for the two external-input runs. The owner runner compares
against the retained pre-refactor output WAV. These are emulator images.

```powershell
python tests/test-aac-abi.py --compiler PATH/TO/riscv32-esp-elf-gcc.exe
```

Without `--compiler`, the saved-evidence checks run but the fresh compilation
and intentional layout-drift check are explicitly skipped.
