# Opus ASM: отложенное сохранение регистров ec_dec_bit_logp

Эксперимент 2026-09-14, `bands-logp-asm` поверх лучшего
`bands-tell-inline-asm`. Это отдельная проверка пункта 4
[плана](ESP8266_OPUS_ASM_BANDS_OPTIMIZATION_PLAN.md), не принятие в production.

## Почему выбран этот участок

Host-счётчик `tools/esp8266_opus_asm/profile_logp.cjs` считает реальные вызовы
`ec_dec_bit_logp` после обновления range/value. Он отсутствует в firmware.
Один проход каждого основного файла — 12 пакетов / 11520 mono PCM отсчётов
48 кГц, **0,24 секунды**, не 2,4 секунды физических десятикратных повторов.

| Файл, кбит/с | Без нормализации | С нормализацией | Доля простого пути |
|---|---:|---:|---:|
| mono12 | 24 | 0 | 100% |
| mono24 | 174 | 3 | 98,3% |
| stereo64 | 869 | 95 | 90,1% |
| stereo128 | 821 | 101 | 89,0% |
| stereo192 | 812 | 98 | 89,2% |

Счётчик также проверен до510 кбит/с; PCM совпадает с контролем.
Это частоты путей, не CPU-профиль и не прогноз тактов LX106.

## Изменение ASM

Исходный GCC leaf выделяет 16 байт стека и сохраняет a12..a15 при каждом
вызове. Новый префикс использует caller-saved a3..a6/a9 и возвращает результат
сразу, если обновлённый range > EC_CODE_BOT. Только при нормализации
выделяется прежний стек, сохраняются регистры и результат копируется в a13.
Повторная одинаковая ветка сравнения val/range объединена.

- ABI call0: a2=context, a3=logp, a2=result; a0/a1/a12..a15 сохранены.
- SAR получает исходный logp; никаких новых таблиц, арены или аллокаций.
- Равенство range == EC_CODE_BOT обязано попадать в нормализацию.
- Сложный цикл и его epilogue остаются исходными GCC-инструкциями.
- Быстрый путь: минус11 исполненных инструкций и 8 обращений к стеку.
- Сложный путь: число инструкций прежнее, стек16 байт, быстрый стек0 байт.
- Object text этой функции 172 ->176 байт. В ec_dec_uint выравнивание
  изменяет размер на −1 байт, но нормализованный граф команд совпадает.
  Итоговые адреса/литералы и linker relaxation проверяются отдельно.

Это не массовый inline во всех callers. C fallback и GCC snapshot не меняются.
Файлы: `tools/esp8266_opus_asm/logp.cjs`, `logp_prefix.inc.s`,
`logp_model.cjs`, overlay `asm/lx106/bands-logp`, manifest `bands-logp.json`.

## Физический результат: отклонён

Все30 raw-запусков сохранены в
`firmware/development/esp8266-opus-bands-logp-v1/`: `controls/before`,
`runs`, `controls/after`, плюс `comparison.json`, host/census/OTA отчёты.
Десять повторов каждого12-пакетного файла на запуск дают120 пакетов /
115200 mono PCM отсчётов, **2,4 секунды аудио**. Пакеты заранее в RAM,
без физического вывода и function/stage profiler; Wi-Fi остаётся включён.
Task CPU исключает вытеснение другими задачами, но включает начисленное ISR.

| Поток | A: tell-inline, CPU | B: logp, CPU | A2: tell-inline, CPU | Рост времени B к A |
|---|---:|---:|---:|---:|
| mono12 | 23,0919% | 23,1197% | 23,0928% | 0,120% |
| mono24 | 54,9811% | 54,9988% | 54,9784% | 0,032% |
| stereo64 | 65,3239% | 66,2042% | 65,3386% | 1,348% |
| stereo128 | 77,3801% | 79,7615% | 77,3805% | 3,077% |
| stereo192 | 88,1001% | 92,4418% | 88,1211% | 4,928% |

Медианы всех10 попыток каждой серии. На192 B добавляет примерно868 мкс
на20 мс аудио относительно A; относительно A2 —864 мкс. В обоих сравнениях
кандидат не проходит критерий скорости. Цель70% CPU не достигнута.

Все PCM hashes точны, ошибок декодера нет. Максимальный wall-вызов192:
21899 /32718 /22620 мкс (A/B/A2). В B/run9 сохранён выброс106,260% CPU192:
после запуска heap восстановилась с26400 до26568 B; lifetime minimum1196 B,
sampled minimum во время теста1356 B. Причина давления памяти не установлена;
выброс не исключался из статистики и не объявляется утечкой либо дефектом ASM.

Минимальная sampled DRAM серий8168 /1356 /5152 B; минимальная свободная heap
после завершения26568 /26432 /26568 B. Это **свободная память**, не расход
декодера. Пики byte/word scratch5488/15600 **байт**, запас стека>=1660 B у
всех вариантов. Static IRAM/DRAM одинаковы; stack16B в сложной ветви.

### Размещение кода и границы вывода

Вход ec_dec_bit_logp остался40246a88, функция172 ->176 B. Неизменённые
quant_partition4024dafc ->4024db00, quant_band4024e44c ->4024e450,
quant_all_bands402507d8 ->402507dc сдвинулись на4 B. Их CFG, литералы,
число прямых/косвенных вызовов в проверенных функциях сохранены.
Меньше исполненных инструкций в leaf **не означает** меньше времени всего
декодера. Flash/cache/layout — возможное объяснение, но не измеренные misses
и не доказанная единственная причина. Этот overlay не включать по умолчанию
и не повторять без новой проверяемой гипотезы.
