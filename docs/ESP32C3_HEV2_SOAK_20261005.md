# HE-AACv2: thirty-minute continuous HTTP load

## Outcome

**FAIL: the unchanged progressive-heap-loss gate fails.** The board completed
30 minutes of HE-AACv2 44.1 kHz stereo at real-time speed, with responsive WebUI,
no captured panic/reboot/decoder/allocation errors, and post-Stop heap recovery.
Those positive results do not turn the complete load test into a pass.

The test used the previously installed `esp32c3-flac-bounds` image, ELF
`3a30ce4278babd7b1a9de879aa6bc2b912b0cf69f3a263801360060d09da6ee4`,
full-rate PC19 AAC, no deep sleep and the experimental three-block DMA prefill.
This run precedes the FLAC depth update. No emulator calibration was used.

## Measurements

The local server repeated the known HE-AACv2 ADTS fixture at its existing
**1.02 pacing ratio** (2% above the manifest's nominal encoded rate), so sustained
TCP backpressure is expected. That is part of the test, not a newly introduced
server change or a measurement of allocated RAM. The firmware was
polled over HTTP approximately every 100 ms. Serial capture remained passive.
The whole steady-state window excludes only the original first ten seconds.

Both idle samples agree at each checkpoint. Total idle loss is 276 bytes, inside
the unchanged 2,048-byte recovery budget. The largest free block fully returns.
The runner confirmed the same firmware after its final software reboot.

## Interpretation and remaining work

The complete window and two of its six five-minute subwindows fail the original
heap-growth rule. The other four subwindows pass the same rule. No malformed
CPU record or runtime fault was retained. This is evidence of changing live
allocation pressure, not attribution of its owner or proof of a permanent leak.

The existing network snapshots also show live block counts changing while the
TCP receive window varies. They are aged snapshots, and their TCP queue fields
do not account for every allocation owned by netif/socket buffers. Do not assign
the missing bytes to a codec or Wi-Fi solely from this correlation. Earlier
[RX-owner measurements](ESP32C3_RX_OWNERSHIP_20261005.md) on other streams are
background evidence, not a substitute for tracing this HE-AACv2 run.

Next checks: reproduce this duration with RX/allocation-owner tracing; establish
the maximum retained receive storage and reserve headroom for WebUI/HTTPS;
repeat the uninstrumented run after any repair. Keep the original failing
result. The one-hour criterion in C3-T08, public HTTPS long runs and physical
sample-level continuity remain unqualified. Task/HTTP timing alone cannot prove
that there were no audible gaps.
