# Opus: проверка N=4, PVQ без iy и коротких листьев

2026-09-19. Независимые экспериментальные C-модели поверх semantic mirror
принятой ASM-цепочки `ebands-final`. Production, сохранённый ASM, исходный
C fallback и прошивка платы не менялись. Это **локальная проверка корректности
и аудит GCC LX106**, не измерение ускорения на ESP8266.

## 1. N=4: один порог внутри префикса

Проверена формула всех сохранённых значений U(4,k):

```text
U(4,k) = (4*k^3 - 6*k^2 + 8*k - 3) / 3
U(4,k+1) - U(4,k) = 4*k*k + 2
```

Куб и деление нужны лишь генератору на компьютере, не MCU.
Сохраняются начальная проба U(K), быстрый возврат и остальные N. После
неуспешной пробы для N=4/64<=index<65536 используется 261 запись uint32:

- index 64..511: блоки по 64;
- index 512..65535: блоки по 256;
- запись содержит k (6 бит), U(4,k) (16), смещение следующего порога (9);
- в каждом таком блоке не более одной границы U;
- одно сравнение выбирает k либо k+1; p корректируется через `4*k*k+2`.

Обязательны точные **k и p**, а не только k: p вычитается из остаточного
индекса. Все 65472 индекса проверены по реальной сохранённой U-таблице;
проверено 9658561 допустимых сочетаний с исходным K. Вне области используется
старый поиск, ограничения битрейта нет. Runtime-построения дерева/heap нет.

На прежних трассах (полный residual index там не сохранён) получены границы
числа чтений исследуемого row-search, с учётом literal + записи новой таблицы:

| Трасса | Исходные чтения | Модель N4 | Сокращение |
| --- | ---: | ---: | ---: |
| 128k | 11682 | 10896..11000 | 5.84..6.73% |
| 192k | 24259 | 21111..21227 | 12.50..12.98% |
| 320k/20ms | 66093 | 62249..62494 | 5.45..5.82% |

Это **не проценты CPU**. Распаковка, MULL, ветви и кэш ещё требуют измерения.
LX106 GCC: `.text.decode_pulses` 989→1105 B, literal 8→16 B, таблица 1044 B.
Суммарная прибавка text/literal/rodata объекта 1168 B; frame прежний 48 B,
data/bss не выросли. Это объект из C-модели, не fixed-address ASM patch.

## 2. PVQ непосредственно в 16-битный X

Изолированная копия cwrsi сохраняет порядок entropy-декодирования, Ryy и
арифметику, но пишет через opus_int16*. При K<=32767 модуль каждого импульса
не больше K; за пределами этого условия остаётся исходный int32 путь.
Сам формат/высокие битрейты не ограничиваются. X уже допускает 16-битные
обращения в исходной нормализации; переносить его в word-only IRAM нельзя.

В общем варианте raw collapse mask получается **до** normalise/rotation.
Получать маску из нормализованного сигнала нельзя, особенно при gain=0.
Нормализация in-place не использует restrict между входом и выходом и сохраняет
прежние округления. Нормализовать до получения полного Ryy по-прежнему нельзя.

На быстром пути удалены все три операции арены: mark, alloc(iy), restore.
decode16, mask, normalise и rotation не выделяют scratch. В fallback они
сохранены. Старый и новый `alg_unquant` в GCC имеют frame 112 B; оба варианта
`decode_pulses`/`research_decode16` — 48 B. C-прототип хранит отдельные функции
для fallback: прибавка суммарного text/literal/rodata объектов 1663 B для B=1
и 1743 B для общего пути. Эти размеры не равны приросту готовой прошивки.

На трассе 192k/.24 s — 1648 вызовов, 1360 с B=1, всего 12752 коэффициента;
максимальный N=64, K=128. Удаляется локальное выделение до 256 B, но
**общие пики остаются byte=5488 B, word=15600 B**, включая историю в word arena.
Это не вся RAM приложения. Для mixed byte peak=5968 B, word=15600 B — тоже
без изменения. Все остальные тестовые пики тоже прежние.

Наблюдатель подтвердил причину: word peak появляется в `celt_synthesis`
при выделении `freq[960]` (3840 B), уже **вне alg_unquant/PVQ**.
Удаление iy не позволяет уменьшить резерв арены по текущим данным. Возможный
выигрыш — более узкие обращения и меньше операций арены, не доказанный CPU.
Нормализующий проход всё ещё нужен; утверждения об удалении всех проходов нет.

## 3. Короткие листья

Рекурсивное разбиение не строит heap-дерево. Новый эксперимент отделяет
no-split ветвь с сохранением полного бюджетного цикла, q=0, noise/folding,
seed, entropy и порядка remaining_bits. Нельзя объявить всякое N=4 листом:
в трассе 192k действительно найден один N=4 вызов, который делится дальше.

| Трасса | Все вызовы partition | Простая гарантия листа | N=2/4 с бюджетной проверкой | Максимальная глубина |
| --- | ---: | ---: | ---: | ---: |
| 128k | 1904 | 0 | 114 | 5 |
| 192k | 3026 | 8 | 485 | 5 |
| 320k/20ms | 4784 | 894 | 1375 | 5 |
| 510k | 36940 | 13290 | 13317 | 5 |

GCC заинлайнил разделённые C-функции обратно. Простой вариант оставил frame
160 B, расширенный увеличил до 176 B. **Это сравнение C-моделей:** принятый
frozen ASM quant_partition имеет 112 B; нельзя называть 160 B его текущим
стеком. Из этого опыта не следует экономии аппаратного стека.
Повторять в production C-вариант с увеличением frame не следует. Для ASM
нужен отдельный вход до общего пролога и самостоятельный небольшой frame,
не дополнительный wrapper-frame поверх каждого рекурсивного вызова.

## Статус и следующие проверки

- [x] N4 exact lookup, полный PCM/state, диапазонный proof и GCC LX106.
- [x] PVQ→X для B=1 и общего B, fallback и direct-vector/zero-gain tests.
- [x] Атрибуция общего пика памяти: synthesis, а не iy.
- [x] Частоты/depth коротких листьев; проверено два конкретных прототипа.
- [x] Сохранить отрицательный результат GCC frame, не включать его по умолчанию.
- [x] Перенести B=1 in-place путь в [отдельный ASM overlay](ESP8266_OPUS_PVQ_INPLACE_ASM.md): проверить S16I
  только в X, регистры, ABI, ветви, отсутствие arena calls на fast path.
- [x] Отдельный fixed-address N4 ASM lookup; не смешивать с PVQ→X.
  QEMU/linked результат от2026-10-04 ниже; физические speed gates отложены.
- [ ] Если продолжать leaf: пролог/epilogue short-entry на ASM без роста стека.
- [ ] Только после linked-проверки: минимум 10A/10B/10A2 на плате для каждого
  кандидата, RAM/stack, все выбросы, затем 20s live I2S/WebUI для принятого.

Нового физического CPU-бенчмарка в этом исследовании нет. Ни один кандидат
не принят в production. Цель 75% CPU этим исследованием не подтверждена.

Последующий отдельный [B=1 ASM/board опыт](ESP8266_OPUS_PVQ_INPLACE_ASM.md)
завершён:150 PCM exact, но CPU19277,878→78,883% при прежних пиках RAM.
Кандидат отклонён. N4 ASM и short-leaf ASM ещё не проверены на плате.

## 2026-10-04: N4 перенесён в настоящий linked ASM и проверен в QEMU

Отдельная пара `esp8266-opus-pvq-n4-prefix-{control,candidate}-v1` над принятой
eBands-final базой, без N3-unroll4 и без отклонённого in-place. Рецепт:
`tools/esp8266_opus_asm/pvq_n4_prefix.cjs`; комментированный ASM — соседний
`pvq_n4_prefix.s`. Production и C fallback не изменялись, плата не использовалась.

Первый U(K) fast return сохранён. После его неудачи только N=4 вызывает
helper32 инструкции/86B. Для64<=index<65536 он читает точную таблицу1044B;
вне области выполняется прежний линейный поиск. Лимита битрейта нет.
Оригинальные секции/адреса/48B frame сохранены; helper не делает stores или
SAR writes. Таблица с literal1048B и helper размещены в отдельно проверенном
недостижимом для native-декодера encoder-коде. Это не библиотека для encoder.

### Проверки

- 305482 linked случая границ/середин всех сохранённых U-строк, с двумя
  произвольными заполнениями регистров; 65472 плотных индекса области N4.
- Математический перебор9658561 допустимого сочетания с начальным K;
  точные конечные K/p, все живые регистры и границы word-load.
- Дизассемблирование повторно получено из настоящего patched ELF, не только
  из описания патча. Проверены изменения только трёх разрешённых flash-областей,
  неизменная U-таблица, canary и отрицательные мутации инструкций.
- **24 фрагмента ×2 варианта =48 точных PCM-сравнений в QEMU LX106**:
  SILK/hybrid/CELT,12..510k, фазовые/CBR/VBR, смешанные режимы,120мс/48 frames.
  Выход mono48kHz; проверки OOM/reinitialization выполнены для всех48 случаев.
- Пики byte5968/6144B и word15600/16384B, state6582B и watermark стека
  стенда2772/8192B одинаковы. Это не полная RAM/стек FreeRTOS приложения.

### Динамическая трасса

Исполненные инструкции `decode_pulses`+helper, без callees. Сравнивать только
варианты внутри строки, не разные по длительности фрагменты между строками.

| Вход, кбит/с | База, инструкций | N4 | Изменение | Load-инструкции: база → N4 |
|---|---:|---:|---:|---:|
| 12 mono SILK | 0 | 0 | PVQ не вызывается | 0 → 0 |
| 24 mono | 43554 | 43647 | +0,21% | 6721 → 6723 |
| 64 stereo | 319789 | 321129 | +0,42% | 47894 → 47822 |
| 128 stereo | 473703 | 477956 | +0,90% | 68812 → 68068 |
| 192 stereo | 639001 | 639888 | +0,14% | 94454 → 91364 |
| 320 stereo,20мс | 763406 | 762214 | −0,16% | 127598 → 123917 |
| 510 stereo | 4398487 | 4409497 | +0,25% | 735880 → 724361 |

На192 helper вызывается1055 раз:979 обращений к таблице и76 fallback.
182 раза нужен MULL и коррекция p; ветка крупных256-wide bucket выполняет
лишний J750 раз, маленьких64-wide bucket —229 раз. Поэтому меньше чтений
ещё не даёт даже уменьшения общего числа инструкций на128/192.

**Решение:** оставить экспериментальным, не включать в production и не
называть ускорением. QEMU не измеряет реальные такты, flash/cache и ROM;
результат CPU на ESP8266 остаётся неизвестным. Цель75%/20s live не достигнута.

### Следующие независимые варианты

- [ ] Переставить ветки: частому256-wide bucket дать fall-through; потенциально
  убрать521 J на192 в текущем корпусе. Это только инструкция, не оценка тактов.
- [ ] Единая таблица256-wide для256<=index<65536, а меньшие индексы оставить
  линейному пути.255 слов/1020B; убрать выбор ширины bucket и поправку его номера,
  сместив literal base на один word. Проверить все индексы и цену fallback.
- [ ] Отдельно проверить путь с таблицей только ранга и загрузкой p из
  оригинальной U-строки: меньше арифметики/распаковки, но дополнительное чтение.
- [ ] Каждый вариант отдельно: linked ABI/PCM/trace; физические10A/10B/10A2
  и20s I2S/WebUI только после разрешения пользователя на работу с платой.
