# Opus PVQ: частота повторного использования обеих стоимостей

2026-09-15. Следующий host census после accepted bits-fourth86.51781% CPU192.
Не измерение скорости LX106 и не изменение production.

Принятый поиск после4/5 шагов заканчивается чтением cache[hi] и, при lo!=0,
cache[lo]. После выбора ненулевого q тот же cache[q] читается повторно для
pulses2bits. Предлагается удержать обе стоимости в регистрах. При q=0
стоимость должна остаться0, а не cache[0]+1: cache[0] хранит длину строки.
Равенства и sentinel−1 сохраняются. Последующее уменьшение q по remaining_bits
по-прежнему должно читать новую стоимость, не переиспользовать старую.

Observer выполняет принятый поиск, сравнивает q и выбранную стоимость
с исходными bits2pulses/pulses2bits, но возвращает исходный q. Новый алгоритм
вывода ещё не внедрён. Десять файлов дают exact PCM, прежние scratch/state,
ASan/UBSan/guards. Это не отдельные PLC/reset/OOM тесты будущего кандидата.

Первые пять файлов по0.24с аудио; прочие длительности сохранены в отчёте.
Для192 это1648 устранённых повторных чтений на0.24с, около6867/с аудио.
Количество вызовов воспроизводит предыдущий независимый census.

Перебор23 таблиц/378304 бюджетов и42240 synthetic sentinel/tie/duplicate/
endpoint случаев сохраняет q и стоимость. Частоты равномерного перебора
не подменяют частоты звукового корпуса. Runtime-лимит битрейта не вводится.
