# CELT exp_rotation1: эксперимент LX106 assembly

2026-09-10. По запросу отдельный чистый ассемблерный вариант обоих проходов
вращения; исходный C остаётся fallback для других процессоров и выключенного
флага. `-OpusRotationLx106` требует `-Diagnostic -EnableOpus`, default OFF.
CMake: `YORADIO_OPUS_ROTATION_LX106`. Обычный production-профиль не меняется.

`opus_rotation_lx106.S` рассчитан на call0,16 регистров и MUL16S: проверяются
core-isa.h и __XTENSA__. Обработка в DRAM int16, не narrow-доступ к IRAM.
Коэффициенты c/s приходят готовыми; -s, байтовый stride, счётчики и указатели
подготовлены до цикла. Forward/backward зависимости, округление,32-bit wrap
и порядок записи сохраняются. Нет вызовов, новых malloc, MEMW, маскирования
IRQ или копирования функции в дефицитную IRAM. Стек16B, сохранены a12/a13/a15.

## Проверено локально

- Целевой ассемблер принимает функцию:152B, восемь статических MUL16S sites
  (по четыре в каждом проходе), без MULL/call/rsil/MEMW.
- 512 векторов /78880 исходных отсчётов: длины1..960, разные stride,
  предельные PCM и коэффициенты. Исполняемый C fallback под ASan/UBSan
  побитно совпал с моделью семантики **реального текста** assembly.
- Проверены guard-области и сохранение call0-регистров.
- На host даже при флагеON выбирается C; недопустимое значение флага запрещено.
- Общая проверка Opus:69 тестов,65pass,4optional skip,0fail.

Это модель инструкций, **не исполнение прошивки на LX106 и не CPU-замер**.
Полная target-сборка/линковкаf37def7 прошла, сохранена в
`firmware/development/esp8266-opus-rotation-on192-check` (902400B), без OTA.
Нужны физический golden PCM и затем10+10 raw A/B
на корпусе12/24/64/128/192. После этого flash→PDM и реальное радио.
ASM может проиграть inlining/реестровому планированию GCC: не включать в
production до измерений; при отсутствии выигрыша убрать эксперимент.

```powershell
node --test tests/esp8266-opus-rotation.test.js
```
