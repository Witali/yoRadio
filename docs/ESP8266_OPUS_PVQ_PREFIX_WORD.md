# Opus PVQ: direct32-bit prefix table

2026-09-19. Независимый вариант над принятой eBands-final ASM-цепочкой.
Packed/long-guard варианты ранее отклонены; они не входят в production parent.
Word-вариант также отклонён: свежий10A/10B/10A2 дал оба speed gate FAIL.

## Гипотеза и ограничения

При K-N>=8 используется тот же exponent-prefix0 upper bound, затем точный
линейный поиск. Только представление таблицы меняется:352 полных32-битных
значения/1408B flash вместо352 упакованных байтов. Дополнительного long guard
и K-=5 нет: не смешивать эти гипотезы с форматом таблицы.

В helper удалены8 инструкций: выделение фазы байта, деление индекса на4,
сохранение/восстановление SAR и динамическое извлечение байта. Осталось18
инструкций/46B. Таблица в4 раза больше, поэтому cache footprint может ухудшиться.
Заранее считать это ускорением нельзя.

Адреса site/helper/table прежние; literal теперь table-384 вместо table-96.
Первым1412B доказанно недостижимого alg_quant заменяем literal+table; область
имеет1788B. Все остальные ELF-байты/адреса/размеры секций неизменны.
RAM,48B frame и размер app не растут, C fallback production не изменён.
Начальный index>=U(N,N)>0, K>=N>2; таблица ограничивает ответ сверху,
MIN с исходным K сохраняет корректность для всех доступных U-строк, без cap192.

## Физический результат

CPU160/runtime QIO40, RAM-пакеты, без аудиовывода/function/stage profiling,
Wi-Fi/WebUI включены.30 прогонов, каждый по120 пакетов/2.4s каждого битрейта.
Все150 PCM-хешей точны, decoder/observation errors отсутствуют, попытки не отбирались.

Не добавлять в принятую ASM-цепочку или production. Исторический packed-кандидат
тоже давал около79.58%, но это не свежая серия packed-vs-word: нельзя объяснять
точную долю задержек одним только размером таблицы или её распаковкой.

MinDRAM A/B/A2:1748/2948/376B, stack-free1660B во всех случаях.
Runtime minimum не означает изменение static RAM/арены/стека: они совпадают.
Очень малый запас A2/run10 сохранён, даже при точном PCM его нельзя скрывать.
Max192 call:20634/20917/19686us. Ни75% raw CPU, ни20s live этим тестом не достигнуты.

`671048e01e53790d875136d9f0136d60bc0dfd4242217de09a6f46c18b670cfe`.

Это проверка восстановления исходного состояния, не20s квалификация звучания.
Итоговый объединённый запуск:59 регрессий PASS. Проверены оба предыдущих
prefix-варианта, новый word ASM, все30 run-хешей и критерии CPU, сохранение
малого heap, новая N3-модель и восстановленный WebUI. Лог — `regression-tests.log`.
