# Opus ASM: точное деление inline

Дата: 2026-09-14. Эксперимент отклонён по скорости; по умолчанию выключен.

## Проверяемая гипотеза

Микротест прежнего reciprocal-helper дал выигрыш, но полный декодер с
отдельным flash-вызовом замедлился. Здесь убирается только этот вызов:
арифметика раскрыта ASM-макросом в трёх существующих местах rng/ft
(`ec_decode` и два GCC-inlined пути в `ec_dec_uint`). Общая таблица остаётся
одной: 129 выровненных слов, 516 байт flash, без копирования в RAM.

`bands-small-div-inline-asm` основан на лучшем `bands-tell-inline-asm`.
Не используется отвергнутый обмен IRAM или tail-helper. Для d=1 возврат n,
для 2..256 точное reciprocal-деление с коррекцией остатка, для d=0/>256
исходный ROM `__udivsi3` с исходными аргументами. Лимита битрейта нет.
Деления val/ext и другие функции не изменены. Стек и C fallback сохранены.

Вход/выход a2=n,a3=d -> a2; a2..a11/SAR допускают изменения по исходному
call0 ABI. Fast path не трогает a0/a1/a12..a15, не пишет память. Обе внешние
GCC-функции уже сохраняют a0. ROM fallback остаётся обычным call0.

## Проверки до платы

- [x] Source/recipe hashes и обратимое изменение ровно трёх вызовов.
- [x] Реальные linked expansions: 112/114/112 байт; после схлопывания
  назад к ROM-call CFG обеих функций совпадает с контролем, включая стек.
- [x] Исполнение модели реальных инструкций: 1 050 880 входных случаев,
  20 fallback, точное unsigned-частное, сохранность ABI и word-only loads.
  GAS преобразует SRLI16 в EXTUI16,16; модель учитывает машинную инструкцию.
- [x] Неизменённая семантическая C-модель: точный PCM до 510 кбит/с,
  mixed/PLC/reset/OOM. Это host-модель, не исполнение LX106 на компьютере.
- [x] Статическая RAM одинакова; app 903216 -> 904080 B (+864 B flash).
- [x] 10 физических контрольных +10 candidate +10 повторных контрольных.
- [x] Все попытки/максимумы сохранены; отклонён по 128/192.
- [x] Обычная прошивка возвращена; HTTP/WebSocket проверены.
- [ ] Live-проверка кандидата: не выполняется, поскольку raw-вариант
  замедлился и при192 кбит/с уже не укладывается в realtime.

## Воспроизведение

Генератор: `tools/esp8266_opus_asm/small_div_inline.cjs <LX106 gcc.exe>`.
Сборщик: `tools/esp8266_audio_profile/build_i2s_pdm_production.ps1` с
`-Diagnostic -EnableOpus -OpusBackend bands-small-div-inline-asm
-OpusWordAsm -OpusIcdfFlashWord -OpusFirFlashWord -NoSpiffsCache
-Pdm32Iram -Pdm32Batch -OpusBenchmark -OpusBenchmarkFixtures
firmware/development/esp8266-opus-asm-library/fixtures -WebAudioPause off`.
Контроль отличается только backend `bands-tell-inline-asm` и именем variant.
CPU160/QIO40/cache16; сеть и вывод не входят в raw-путь декодирования.

`node tools/esp8266_opus_asm/report_small_div_inline.cjs --preflight`
проверяет обе сборки. Без ключа собирает результаты A/B/A. Series runner:
`tools/esp8266_opus_profile/run_raw_series.ps1`, Attempts10, IntervalMs15000.
Прошивки: `firmware/development/esp8266-opus-inline-control-v1/` и
`firmware/development/esp8266-opus-small-div-inline-v1/`.

## Физический результат: отклонить

Все 30 запусков завершены, ни одна попытка не исключена. Пакеты заранее
в RAM; сетевого чтения, PCM-вывода и function/stage profiling в raw-пути нет.
Task-время исключает другие задачи, но может включать начисленное время ISR;
это тот же измеритель, что у контроля. Все PCM hashes, числа samples/packets,
пики scratch совпадают, ошибок декодирования нет.

При192 время выросло на15,6938–15,7067%, при128 — примерно13,9%.
Максимумы CPU192 A/B/A2: 88,3457 /102,1550 /88,2130%.
Минимальная наблюдавшаяся DRAM по сериям: 8168 /8168 /8344 B;
минимум остатка стека1660 B во всех трёх сериях. Разницу наблюдавшегося
heap не считаем экономией памяти: статическая RAM одинакова.

Flash text вырос на348 B, rodata на516 B. `ec_decode`:63 ->170 B,
`ec_dec_uint`:564 ->776 B. Прочие проверенные горячие функции сохраняют
инструкции, но сдвинулись по адресам. Mono12 не вызывает заменённое rng/ft
деление по прежнему census, однако тоже замедлился примерно на1,1%.
Это указывает на необходимость учитывать размещение, но **не доказывает**
конкретное число cache misses или причину всей регрессии. Удаление отдельного
helper-call не спасло кандидат; повторять эту форму без новой гипотезы не нужно.

Архив `comparison.json` содержит все исходные наблюдения, хеши, максимумы,
две независимые проверки критерия выбора; оба результата отрицательны.
Генератор/сборки/начальные тесты: коммит `38633a83`. Регрессии расширены до
29 связанных тестов, включая пересчёт всего архива и OTA-восстановление.

Обычная `esp8266-opus-live512-idle3s-20260913` восстановлена OTA в0x10000,
SHA256 `661becd301b07885d493ceb1b513d9e874b7d86e4ada8231da8657aa90983c4b`.
Главная страница HTTP200, один ответ120,46 мс (не время загрузки браузера);
плейлист HTTP200 с прежним SHA256, 6 WebSocket-сообщений, current167,
прежняя станция/остановленное состояние. RSSI−61 dBm, free heap27628 B,
web stack2324 B. Это восстановление базовой прошивки, не live-квалификация
отвергнутого кандидата.

Лучшим остаётся tell-inline примерно88,1% CPU192; цель70% не достигнута.
Размер кэша и частота flash в этом опыте не менялись.
