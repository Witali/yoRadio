# ESP32-C3 OLED: часы в deep sleep

Режим включается **только ключом сборки `-DeepSleepClock`**. Обычная сборка
оставляет существующее поведение часов. Целевая прошивка:
`idf/esp32c3-oled-native`, ESP-IDF v6.0.2.

## Сборка

Из корня репозитория/worktree:

```powershell
.\build.ps1 -DeepSleepClock
.\idf\esp32c3-oled-native\build-production.ps1 -DeepSleepClock
```

При использовании уже установленного toolchain из основного checkout:

```powershell
.\idf\esp32c3-oled-native\build-production.ps1 -DeepSleepClock -DependencyRoot C:\Work\yoRadio\.idf
```

Обычная сборка с ключом использует `build-deep-sleep-clock`, production —
`build-production-deep-sleep-clock`. Production-образ сохраняется в:

`firmware/development/esp32c3-oled-native-deep-sleep-clock/app.bin`

Пути можно переопределять существующими параметрами скриптов. Скрипт явно
записывает `CONFIG_YORADIO_DEEP_SLEEP_CLOCK=y` при передаче ключа и снимает
его без ключа, в том числе при повторном использовании того же sdkconfig.
Профиль QEMU не поддерживает этот режим. Ключ не изменяет разделы flash,
Wi-Fi, плейлист или настройки заставки и сам не запускает прошивку платы.

## Использование

1. В WebUI включить заставку для остановленного радио и выбрать **Clock**.
2. Дождаться синхронизации времени по SNTP.
3. Остановить радио. После сохранённого тайм-аута заставки чип уйдёт в deep sleep.
4. Для возвращения к экрану станции удержать BOOT чуть дольше 500 мс.
   Отпустить кнопку и нажать ещё раз для Play.

Первое обнаруженное нажатие только будит интерфейс; оно не превращается в
команду Previous от долгого удержания. Далее single/double/long press работают
как раньше. На опциональном энкодере проверяются фазы и кнопка; обнаруженное
движение/нажатие возвращает обычный режим. Полный оборот или короткий клик между
двумя проверками могут остаться незамеченными.

Во сне **Wi-Fi, WebUI и USB Serial/JTAG недоступны**. Они возвращаются при полной
загрузке после обнаруженного ввода. BOOT/GPIO9 не является RTC-выводом C3:
его уровень проверяется по таймеру, поэтому короткие клики могут пропускаться.
Обычный reset/включение питания запускает приложение штатно.

Заставка во время воспроизведения и режим Blank не включают deep sleep.
Настройка сети через AP, подключение к станции, активные команды/загрузка
файлов и часы без достоверного времени остаются в обычном режиме.

## Как работает

- Перед сном сохраняются отложенные настройки громкости; задача аудиовыхода
  выполняет спад PDM, отключает I2S и подтверждает остановку.
- GPIO10/GPIO3 удерживаются в нуле, level LED выключен. OLED остаётся включённым
  и хранит изображение в собственной памяти.
- RTC-таймер будит чип на границах полусекунды. Watchdog сохраняет свою роль
  защиты от зависания и не используется как таймер часов.
- `rtc_wake_stub_clock.c` исполняется из RTC-памяти до загрузки приложения.
  I2C работает через короткие операции GPIO; обычные драйверы, сеть,
  FreeRTOS, NVS и flash в этом обработчике не используются.
- При обычном тике передаются только 15 байт области двоеточия. При изменении
  минуты передаётся весь framebuffer 72×40 (360 байт).
- Десять цифр кэшируются из существующего OLED-рендерера один раз при входе.
- Время продвигается по реально прошедшим RTC-тактам, включая время
  пробуждения и передачи I2C. Дробная часть калибровки сохраняется, сутки
  корректно переходят с 23:59 на 00:00.
- NACK или зависший SCL прекращают цикл сна и запускают обычное приложение.
  Если обычная повторная инициализация OLED успешна, повторный вход в сон
  блокируется до reset. Постоянный отказ OLED обрабатывает штатный запуск.

По умолчанию RTC использует внутренний RC-генератор с температурным дрейфом.
Дополнительный ключ `-Rtc32kCrystal` выбирает внешний кварц 32 768 Гц на GPIO0/1:
[подключение и сборка](ESP32C3_RTC_32K_CRYSTAL.md).
SNTP возобновляется после полного пробуждения. Точность RTC,
фактическое потребление платы, удержание GPIO и звук при Stop/Play требуют
измерения на реальной плате. Численные обещания по потреблению здесь не делаются.

## Проверки

Исполняемые тесты настоящего C-кода wake stub с моделью проводов I2C/GPIO:

```sh
python3 tests/run-esp32c3-deep-sleep-clock.py
```

Требуются Python 3 и host C-компилятор `cc` (либо переменная `CC`). На Windows
можно использовать WSL. Проверяются полусекундные границы, состав I2C-пакетов,
смена минуты/часа/суток, более суток нерегулярных пробуждений без накопления
ошибки, BOOT, NACK и ограниченный тайм-аут SCL.

Проверка размещения скомпилированного обработчика:

```sh
python3 tests/check-esp32c3-rtc-elf.py --objdump /path/to/riscv32-esp-elf-objdump --build idf/esp32c3-oled-native/build-production-deep-sleep-clock
```

Дополнительно: `node --test tests/esp32c3-*.test.js` и сборка без ключа.

Проверка на плате перед использованием: запуск станции → Stop → часы →
несколько смен минуты → удержание BOOT → Play; повторить несколько раз,
проверить возврат Wi-Fi/WebUI, оба PDM-канала и отсутствие коротких импульсов
на аудиовыходах во сне. Оставить часы на ночь и оценить дрейф.
