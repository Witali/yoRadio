# ESP8266: RC-PDM с накоплением ошибки и интерполяцией

2026-09-06. Новый **экспериментальный** вариант `CONFIG_YORADIO_RCPDM_FEEDBACK`.
Это изменение алгоритма, а не побитно эквивалентное ускорение прежнего RC-PDM.
Обычный PDM32 остаётся профилем по умолчанию. Качество ниже — симуляция на ПК,
не измерение аналогового выхода. Позднее выполнен отдельный
[физический замер скорости](benchmarks/esp8266-rcpdm-feedback-board-2026-09-06/README.md):
Feedback требует в 6,66 раза больше времени на пакер, чем прежний RC-PDM.
Это диагностическая прошивка без декодеров/Wi-Fi, не проверка обычного радио
с новым модулятором. Включать Feedback по умолчанию пока не следует.

Позднее [упрощена подготовка и упаковка битового цикла](benchmarks/esp8266-rcpdm-feedback-hoist-2026-09-06/README.md)
без изменения битового потока. Код и стек функций уменьшились; скорость
оптимизированной версии на плате ещё не измерена. Коэффициент 6,66 относится
к реализации **до** этой оптимизации.

Отдельная [симуляция включения/отключения feedback, включая Simple](benchmarks/esp8266-rcpdm-simple-feedback-ab-2026-09-06/README.md)
показала близкое качество двух правил выбора бита с feedback и существенно
более высокий шум без него при одинаковых интерполяции/dither. Новый
Simple + feedback существует только в настольном тесте, не в прошивке платы.

Продолжение — [полное отключение dither](benchmarks/esp8266-rcpdm-no-dither-2026-09-06/README.md):
с feedback шум уменьшается и SINAD обычных тонов улучшается, но усиливаются
гармоники и меняется передача очень слабого сигнала во времени. Без feedback
проверенные тоны −40 dBFS и тише исчезают. Производственный профиль не менялся.

## Что изменено

1. Ошибка между требуемым PCM и модельным напряжением RC накапливается и
   влияет на следующие решения. Слабое воздействие не теряется после одного бита.
2. Между предыдущим и текущим PCM строится линейный переход за 32 битовых
   интервала. Дробные промежуточные значения сохраняются в fixed-point.
3. К порогу решения добавлен детерминированный TPDF dither. Он разрушает
   периодические циклы, но не добавляется в исходный PCM или накопленную ошибку.
4. Состояние сохраняется между сэмплами и DMA-блоками; новых промежуточных
   PCM/PDM-буферов нет. Прежняя двойная буферизация I2S не изменена.

Исходник: [rc_pdm_feedback.h](../esp8266/rtos-sdk-native/main/rc_pdm_feedback.h).
Все операции рабочего варианта — 32-битные целочисленные; 64-битная арифметика
используется только в независимом тестовом эталоне. Модулятор ничего не выделяет
в куче. Его состояние выросло с 4 до **16 байт**: RC, ошибка, предыдущий PCM,
состояние генератора dither. DMA по-прежнему занимает два буфера по 512 слов.

## Уравнения и границы

Масштаб полного размаха `F = 2^29`; значение PCM переводится в униполярный
target как `(pcm + 32768) * 8192`. На один младший разряд PCM приходится 8192
единицы состояния. Это оставляет 13 дробных разрядов, в том числе для перехода
на ±1 LSB, и запас для отрицательной/положительной обратной связи.

Для выбранного профиля `N=32`, `shift=4`, коэффициент обратной связи равен 1:

```text
increment = (target - previous) / N
desired = previous + increment * (bit_index + 1)
step = F >> shift
down = rc - (rc >> shift)
high = desired + error + dither > down + step/2
rc = down + (high ? step : 0)
error = clamp(error + desired - rc, -2^30, +2^30)
```

Разность двух target кратна 8192, поэтому деление для N=8/16/32/64/128
точное. В 32-битном аппаратном профиле GCC устраняет деление на константу.
`rc` и `desired` лежат в `[0, 2^29]`; `|error| <= 2^30`.
Даже максимальный тестовый dither вместе с этими величинами не переполняет
знаковый 32-битный промежуточный результат. Для отрицательных значений
вспомогательное деление с округлением вниз определено явно.

На точном нижнем пределе PCM целочисленное затухание RC может оставить остаток
меньше 16 единиц состояния и довести накопитель до ограничителя. Это меньше
одного PCM LSB. Проверяются ограниченность и выход из ограничителя при возврате
к аудионулю, а не невозможность его достижения на полном размахе.

Это **не прежняя модель с увеличенной разрядностью**: добавлена интегральная
обратная связь. Старые predictive/Simple и их ASM-пути оставлены без изменения.

## Почему выбран dither

Перебор коэффициентов обратной связи, интерполяции и уровня dither сохранён
в [скрипте sweep_rcpdm_feedback.py](../tools/esp8266_audio_profile/sweep_rcpdm_feedback.py).
Ниже один и тот же 32-битный выход 1,536 МГц, RC 10 мкс, unity feedback:

| Вариант | SINAD 1 кГц −3 dBFS | SINAD 7 кГц −3 dBFS | Передача тона ±1 LSB, дБ |
| --- | ---: | ---: | ---: |
| Без dither, без интерполяции | 60,71 | 35,35 | +2,92 |
| Без dither, с интерполяцией | 62,58 | 61,40 | +2,91 |
| TPDF ±полшага, с интерполяцией — выбран | 55,95 | 54,92 | −0,17 |
| TPDF ±целый шаг, с интерполяцией | 52,03 | 50,36 | −0,08 |

Первая оценка ±1 LSB здесь — короткое односекундное окно одного seed.
Для выбранного варианта ниже выполнена более длительная когерентная проверка.
Без dither результат громкого тона лучше, но передача самого тихого нелинейна.
Dither повышает шум; полный шаг увеличивает его без существенного выигрыша.
Выбран компромисс ±полшага: сумма двух 16-битных частей xorshift32, центрированная
относительно нуля. Seed фиксируется для воспроизводимости, это не крипто-ГСЧ.

## Качество на одинаковых частотах

Все строки сравнивают **одинаковую частоту однобитного выхода**, одинаковый PCM,
физический RC=10 мкс и полосу 20 Гц–20 кГц. Общая расчётная сетка 6,144 МГц;
односекундные окна Hann, начальные/конечные 250 мс исключены. Исходный RC32
повторно проанализирован как контроль: его метрики совпали со старым отчётом
с допуском 1e−8. Полная матрица, в том числе RC=40 мкс и двухзвенный фильтр:
[quality.json](benchmarks/esp8266-rcpdm-feedback-2026-09-06/quality.json).

SINAD, синус 1 кГц, −3 dBFS; больше лучше:

| Выход, МГц | N | shift / alpha | Обычный PDM | Прежний predictive RC-PDM | Новый RC-PDM Feedback |
| --- | ---: | --- | ---: | ---: | ---: |
| 0,384 | 8 | 2 / 1/4 | 29,75 | 25,60 | 29,78 |
| 0,768 | 16 | 3 / 1/8 | 39,01 | 34,25 | 43,17 |
| 1,536 | 32 | 4 / 1/16 | 44,25 | 44,61 | 55,95 |
| 3,072 | 64 | 5 / 1/32 | 50,87 | 49,66 | 69,51 |
| 6,144 | 128 | 6 / 1/64 | 57,04 | 54,87 | 83,56 |

RC shift меняется с частотой. Значения 3,072/6,144 МГц — только моделирование,
не обещание, что ESP8266 успеет вычислять этот алгоритм с таким битрейтом.
В собранной прошивке выбран только N=32, shift=4; аппаратные делители дают
примерно 1,538461 МГц вместо номинальных 1,536 МГц.

Выбранный выход 1,536 МГц, SINAD:

| Сигнал | PDM32 | Прежний RC32 | Новый Feedback32 |
| --- | ---: | ---: | ---: |
| 1 кГц, −3 dBFS | 44,25 | 44,61 | 55,95 |
| 1 кГц, −20 dBFS | 26,64 | 20,61 | 43,87 |
| 1 кГц, −40 dBFS | −1,43 | Тон отсутствует | 23,86 |
| 7 кГц, −3 dBFS | 43,88 | 35,31 | 54,92 |

Универсального превосходства нет: на 0,384 МГц для 7 кГц новый вариант дал
28,64 дБ против 29,61 дБ у PDM. Приведённые цифры не включают реальный шум GPIO,
усилителя, допуски RC и прерывания/опустошение DMA.

## Доказательство передачи младшего разряда

Вход — строго нулевой по среднему периодический сигнал 1 кГц с отсчётами
только −1/0/+1, а не случайное изменение битов после включения dither.
Проверены противоположные фазы, DC ±1 и нулевой вход для трёх seed. Длительность
входа 10 с, когерентное окно 8 с, RC=10 мкс:

- модуль дифференциального коэффициента передачи: **1,00014**;
- фаза: −3,75° (включает задержку интерполяции);
- паразитный когерентный тон при нулевом PCM: 0,00266 от тестового тона;
- выход DC: +1,00089 / −1,00089 PCM LSB после вычитания нулевого контроля.

Подробности и допуски: [lsb.json](benchmarks/esp8266-rcpdm-feedback-2026-09-06/lsb.json).
В широкой полосе шум dither остаётся выше такого слабого сигнала: короткое
измерение SINAD для ±1 LSB даёт около −25,65 дБ. Отрицательное SINAD не означает
пропавший тон; когерентная проверка отдельно показывает его передачу. Это не
обещание полноценного 16-битного аналогового динамического диапазона.

## Интерполяция, задержка и радиозаписи

Рампа эквивалентна скользящему среднему длины N на битовой сетке и добавляет
фиксированную задержку `(N−1)/(2*f_bit)` — **10,091 мкс** при N=32.
Не нужно ждать будущий PCM: переход идёт от предыдущего отсчёта к текущему.
Амплитудный спад относительно удерживаемого PCM — около −0,01 дБ на 1 кГц
и −0,29 дБ на 7 кГц. Это ограничение линейной интерполяции, не потеря LSB.

Сравнение радиозаписей с исходным PCM без совмещения фаз штрафует эту задержку.
Поэтому некоторые сырые SNR хуже прежнего RC32. Приведены **оба** результата;
правая колонка компенсирует только известную задержку, без подгонки усиления
или поиска лучшего временного сдвига. Её нельзя сравнивать со старыми сырыми
SNR как с одинаковой метрикой.

| Запись | PDM32, исходный SNR | RC32, исходный SNR | Feedback32, исходный SNR | Feedback32, с фиксированной компенсацией задержки |
| --- | ---: | ---: | ---: | ---: |
| Маяк | 15,61 | 13,64 | 15,63 | 35,21 |
| Record | 17,78 | 30,94 | 16,40 | 34,34 |
| Ретро | 17,31 | 28,31 | 16,18 | 35,28 |
| Symphony | 13,78 | 9,13 | 28,42 | 36,04 |
| Вести | 16,62 | 12,48 | 18,09 | 36,93 |

Выход для всех колонок 1,536 МГц, RC=10 мкс. Расчёт:
[delay.json](benchmarks/esp8266-rcpdm-feedback-2026-09-06/delay.json).
SINAD синусоидальных тестов не штрафует фазу основного тона и не требует
такого выравнивания; его улучшение не объясняется одним сдвигом сигнала.

## Проверки и воспроизведение

- 32-битная реализация сравнена с независимой 64-битной моделью по каждому
  выходному слову и всем полям состояния: полный диапазон PCM, пять частот,
  разные режимы обратной связи/dither, случайные и граничные состояния.
- Проверены mono/stereo, пустые блоки, размеры вокруг границ 32 и 512 слов.
- Общий тест производственного пути PCM→DMA проходит для PDM32, старого RC32,
  Simple32, нового Feedback32 и PDM128: шесть входных частот, нормализация
  вкл/выкл, таймауты, владение буферами, остановка и отмена.
- Новая обычная радиопрошивка успешно собрана Xtensa GCC 8.4.0. В изолированных
  scalar/batch-функциях нет внешних арифметических helper-вызовов; после
  переноса инвариантов стек 32/32 Б вместо первоначальных 48/64 Б.
  Это не замер всего стека задачи и **не измерение времени на плате**.

Команды из корня репозитория (для Python нужен NumPy):

```powershell
node --test tests/esp8266-rcpdm-feedback.test.js tests/esp8266-direct-pdm.test.js
python tools/esp8266_audio_profile/sweep_rcpdm_feedback.py --help
python tools/esp8266_audio_profile/measure_rcpdm_feedback_lsb.py --output radio_output/rcpdm-feedback-lsb
python tools/esp8266_audio_profile/measure_rcpdm_feedback.py --output radio_output/rcpdm-feedback-quality
python tools/esp8266_audio_profile/measure_rcpdm_feedback_delay.py --capture radio_output/rcpdm-feedback-quality --output radio_output/rcpdm-feedback-quality/delay.json
powershell -ExecutionPolicy Bypass -File tools/esp8266_audio_profile/build_rcpdm_feedback.ps1
```

Проверка LSB сама генерирует входы. Полная матрица требует ранее сохранённых
радиофрагментов/тонов и контрольных битовых потоков; скрипт проверяет их SHA-256
и не подменяет отсутствующие записи новыми. Эти аудиофайлы не добавлены в Git.
Ссылки на данные и все хеши есть в JSON. Архив проверок:
[benchmarks](benchmarks/esp8266-rcpdm-feedback-2026-09-06/README.md).

Сборочный скрипт объединяет `sdkconfig.i2s-rcpdm.defaults` с новым
`sdkconfig.rcpdm-feedback.defaults` в отдельном `.build/rcpdm-feedback-radio`.
Установленному SDK нужен один составной defaults-файл. Опция по умолчанию
выключена; старые диагностические RC-кандидаты нельзя смешивать с новой моделью.
Профиль — нормальное радио, без генератора синуса и бенчмарка.

Готовое приложение, manifest и changelog:
[firmware/development/esp8266-rcpdm-feedback](../firmware/development/esp8266-rcpdm-feedback/).
Приложение не является полным дампом flash. Не стирать NVS/SPIFFS ради проверки.
