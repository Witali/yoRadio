# Opus PVQ: packed prefix0 + NSAU

2026-09-19. Отдельный эксперимент над принятой ASM-цепочкой eBands-final.
Production и C fallback не меняются. Цель остаётся75% raw CPU на192кбит/с
и последующая20s live I2S PDM/WebUI квалификация.

## Алгоритм и размещение

При K-N<8 — прежний линейный поиск. Иначе NSAU получает CLZ(index).
352B таблица хранит11×32 верхних границ: для каждого N=3..13 и показателя e
максимальный сохранённый j, для которого U(N,j)<=2^(e+1)-1.
Начальная точка min(K,j) не ниже истинного результата, затем работает точный поиск.

Таблица упакована по4 байта в выровненное слово. Используются L32I, сдвиг и
EXTUI, не byte-load из flash/IRAM. SAR сохраняется в регистре и восстанавливается
до первого data-dependent перехода. Начальный index>=U(N,N)>0 проверен прежним кодом.
C-модель нужна только для тестов; исходный переносимый декодер не изменён.

Патчи:43B по0x40253329,94B по0x40251024 (helper26 инструкций/70B),
356B по0x40248cb4 (4B literal +352B данные). Последняя область — начало alg_quant.
Единственный linked вызов alg_quant по0x402518fa доказан недостижимым при encode=0;
внешних переходов и address-taken ссылок нет. Это decoder-only упаковка:
не использовать такой образ как энкодер.

Все остальные ELF-байты, адреса функций, размеры секций, RAM и48B decode_pulses
frame сохраняются. Контроль идентичен принятой raw-базе; оба app903216B.

## До физической проверки

- 337686 linked случаев: U-границы/середины и обе стороны каждой степени двойки,
  два набора произвольных регистров. Все26 инструкций helper покрыты.
- Ещё256 случаев проверяют все64 состояния SAR для каждой из4 фаз упакованного байта.
- 24 exact host PCM/state/ASan/UBSan сценария, включая320/510кбит/с,
  PLC/reset/смену режима и120ms/48-frame пакеты.
- Семь тестов PASS: негативные мутации инструкций, packed table/literal,
  сохранение SAR, encoder-dead storage и address-taken reference.

В реальных старых трассах нет остаточного index. Поэтому instruction census
перебирает все совместимые CLZ-подынтервалы и сообщает **границы**, не среднее:

| Поток | Исходные инструкции | Prefix: min..max инструкций | Исходные чтения | Prefix: min..max всех чтений |
| --- | ---: | ---: | ---: | ---: |
|128кбит/с|60732|73956..79144|11682|9933..11120|
|192кбит/с|119961|136815..148056|24259|18203..20795|

Включены и загрузка literal-указателя, и чтение packed-слова. Предыдущая чисто
алгоритмическая модель считала только второе; скрывать цену literal нельзя.
Чтений меньше, но инструкций больше. Вывод о скорости — только по плате.

## Физическая проверка

Предстоит10A/10B/10A2 с RAM-пакетами, без вывода и function/stage profiling,
CPU160/runtime QIO40. Сохранять все попытки, точность PCM, max call и min RAM/stack.
После тестов вернуть ordinary main через OTA и проверить HTTP/WS/playlist.
Не переносить кандидат до двух пройденных speed gate.

## Следующие независимые гипотезы

- [ ] Тот же prefix0 с прямыми32-битными границами:1408B flash. Убирает упаковку
  и работу с SAR, но увеличивает cache footprint. alg_quant имеет1788B decoder-dead
  места, поэтому возможно сохранить адреса и размер app и для этого опыта.
- [ ] Один раз загрузить базовый указатель перед PVQ-вектором, а не на каждый поиск.
  Рассмотреть a0, мёртвый после ec_dec_uint до прежнего восстановления из SP+44.
  Для этого внутренний helper должен перейти с CALL0/RET на доказанные J-переходы.
  Сначала доказать всю живость a0 и CFG, отсутствие обхода инициализации;
  нельзя просто убрать сохранение SAR или занять живой регистр.
- [ ] Отдельно проверить обновление указателя строки при N--, чтобы вынести
  N*stride из внутреннего поиска, сохранив альтернативные ветви и все режимы.
