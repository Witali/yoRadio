# RC-PDM и обычный PDM: устройство, варианты и результаты YoRadio

Сводка на 2026-09-06. Описание относится к нашим реализациям; измерения
скорости выполнены на ESP8266/Wemos D1 mini. Качество рассчитано на ПК по
сохранённому PCM и модели аналогового фильтра, **не измерено на аналоговом
выходе платы**. Результаты не следует автоматически переносить на другие
микроконтроллеры, реализации модуляторов или RC-компоненты.

## Краткое заключение

Дополнение: реализован отдельный [RC-PDM Feedback с интерполяцией и dither](ESP8266_RCPDM_FEEDBACK.md).
На ПК он передаёт ±1 LSB и улучшает SINAD, но
[на ESP8266 пакер оказался в 6,66 раза медленнее](benchmarks/esp8266-rcpdm-feedback-board-2026-09-06/README.md)
прежнего RC-PDM. Профиль по умолчанию не изменён. Таблицы старых RC-PDM/Simple ниже относятся
к исходным алгоритмам без накопления ошибки, не к этому новому варианту.

- **Обычный PDM32 остаётся выходом по умолчанию.** Его пакер быстрее, а в
  проверенных тихих сигналах нет обнаруженной у RC-PDM цифровой блокировки.
  Это не означает отсутствия шума или искажений у обычного PDM.
- **Предиктивный RC-PDM32** может компенсировать часть влияния RC-фильтра
  на громком материале. Он не превосходит PDM на всех частотах и уровнях.
- **RC-PDM-Simple32** сравнивает PCM с текущим модельным напряжением.
  После ASM-оптимизации он быстрее нашего предиктивного пакера, но на всех
  пяти сохранённых радиофрагментах менее точно воспроизводит исходный PCM.
- Разные методы сравниваются **только на одной и той же частоте выхода**,
  с одинаковыми PCM и физическим RC. Коэффициент RC-модуляторов меняется
  вместе с частотой, а не остаётся 1/16 во всей матрице.
- У обоих RC-алгоритмов есть **зона нечувствительности к тихим сигналам**.
  Увеличение точности арифметики и ускорение ASM её не устраняют.

## 1. Какие битрейты здесь сравниваются

Нужно различать три параметра:

1. **Битрейт MP3/AAC**, например 64/128/320 кбит/с: сжатые данные из сети.
   Он влияет на декодер и исходное качество, но не задаёт частоту PDM.
2. **PCM**: в наших опытах 16-битное моно, 48000 сэмплов/с. Стерео и другие
   частоты преобразуются до подачи в однопроводный выход.
3. **Битрейт однобитного выхода**: `f_bit = f_PCM × N`, где N — число
   новых решений модулятора на один PCM-сэмпл. Для последовательности
   GPIO это также частота битовых интервалов; не число переключений GPIO.

| Решений на сэмпл при 48 кГц | Номинальный выходной битрейт | Что проверено |
| --- | --- | --- |
| 8 | 384 кбит/с, 0,384 МГц | Качество PDM8, RC-PDM8 и Simple8 на ПК |
| 16 | 768 кбит/с, 0,768 МГц | Качество трёх алгоритмов на ПК |
| 32 | 1536 кбит/с, 1,536 МГц | Качество на ПК; скорость всех трёх алгоритмов на ESP8266 |
| 64 | 3072 кбит/с, 3,072 МГц | Качество трёх алгоритмов на ПК |
| 128 | 6144 кбит/с, 6,144 МГц | Качество трёх алгоритмов на ПК; обычный I2S-PDM128 также есть в экспериментальной конфигурации |

У текущего ESP8266 I2S-PDM32/RCPDM32 фактическая частота из-за целочисленных
делителей — около **1,538461 МГц**, темп слов — 48076,9/с (+0,16%).
Модель качества использует номинальные частоты. Legacy SPI-PDM также
имеет 8/16-битные режимы; это иной транспорт, его межблочные паузы
не входят в численную оценку модулятора.

Отдельной сопоставимой матрицы «MP3/AAC 64/128/320 кбит/с × все модуляторы»
здесь нет. Из таблиц ниже нельзя заключить, что RC-PDM исправляет потери
сжатия MP3/AAC. Они оценивают преобразование **уже декодированного PCM**.

## 2. Как работают алгоритмы

Общий тракт: декодированный PCM → громкость/обработка → сведение/ресэмплинг
→ программный модулятор → готовые биты в DMA → GPIO → RC-фильтр → усилитель.
I2S/DMA передаёт биты; он не выполняет RC-модель аппаратно.

### Обычный PDM: накопление ошибки

В нашем первом порядке PDM беззнаковое целевое значение PCM прибавляется
к аккумулятору. Перенос через полный масштаб становится выходным битом,
а остаток сохраняется для следующего бита:

```c
sum = accumulator + target;  // target: 0..65535
bit = sum >> 16;
accumulator = sum & 0xffffU;
```

Плотность единиц передаёт средний уровень сигнала. Модулятор не моделирует
физический конденсатор, поэтому фильтр вносит свои амплитудные и фазовые
изменения. Остаток ошибки не сбрасывается на границе сэмпла.
PDM128 выполняет 128 новых решений на удерживаемый PCM-сэмпл, а не повторяет
каждый бит PDM32 четыре раза. В стенде PDM32 извлекается из исходника прошивки;
её полный путь PDM128 отдельно проверяется тестом `esp8266-direct-pdm.test.js`.

### Предиктивный RC-PDM: выбор следующего модельного напряжения

Состояние `state` — оценка напряжения на воображаемом конденсаторе.
Это **не измерение реального GPIO/конденсатора и не обратная связь через ADC**.
Для каждого бита вычисляются два кандидата — разряд к нулю и заряд к VCC;
выбирается более близкий к целевому PCM. При alpha=1/16 контрольная формула:

```c
down = state - (state >> 4);
up = state + ((UINT32_MAX - state) >> 4);
threshold = down + ((up - down) >> 1);
bit = target > threshold;
state = bit ? up : down;
```

Это прогноз **одного** следующего шага, не поиск оптимальной последовательности
на много бит вперёд. При равенстве порогу выбирается ноль.
Рабочий [rc_pdm.h](../esp8266/rtos-sdk-native/main/rc_pdm.h) использует
побитно эквивалентную оптимизацию: расстояние `up-down` постоянно,
порог частично вычисляется один раз на сэмпл. Буквального перебора двух
кандидатов в горячем цикле уже нет.

### Упрощённый RC-PDM-Simple: сравнение текущего напряжения

Сначала сравнивается **старое** состояние с PCM, затем выполняется
только выбранное обновление:

```c
if (state < target) {
    bit = 1;
    state += (UINT32_MAX - state) >> 4;
} else {
    bit = 0;
    state -= state >> 4;
}
```

Нет сравнения расстояний до следующего напряжения. Это **другой алгоритм**,
а не побитно точная оптимизация предиктивного RC-PDM. Он может давать
другое усиление и спектр искажений. При равенстве также выбирается ноль.
Код: [rcpdm_simple.h](../tests/native/rcpdm_simple.h).

У RC-вариантов используется беззнаковая фиксированная точка: состояние
`uint32_t`, PCM переводится в шкалу `((pcm + 32768) << 16)` с безопасным
приведением типов, как в исходниках. Alpha=1/2^shift реализуется сдвигом;
выше для примера показан shift=4 при 1,536 МГц. На другой частоте сдвиг
подбирается заново, см. раздел 6. Состояние сохраняется между битами,
сэмплами и пакетами.

## 3. Какие варианты есть в проекте

| Вариант | Коэффициент модели | Статус и назначение |
| --- | --- | --- |
| Обычный I2S-PDM32 | RC-модели нет | Основной профиль платы, GPIO3, I2S/SLC DMA |
| Обычный PDM8 | RC-модели нет | Контроль качества на ПК; есть отдельный legacy SPI-выход |
| Обычный I2S-PDM128 | RC-модели нет | Экспериментальный повышенный битрейт |
| Предиктивный I2S RC-PDM32 | 1/16 | Отдельный собираемый радио-профиль, не default |
| Предиктивный RC-PDM8 | 1/16 или 1/4 | Настольные эксперименты, не готовый I2S радио-профиль |
| Предиктивный RC-PDM8 matched | 15025/65536, Q16 | Контроль согласования с RC=10 мкс при 384 кГц; 64-битные произведения, не скоростная оптимизация |
| RC-PDM-Simple8 | 1/16 или 1/4 | Настольное сравнение качества |
| RC-PDM-Simple32 C | 1/16 | Переносимая реализация и резервный путь |
| RC-PDM-Simple32 ASM u1 | 1/16 | Изолированная тестовая прошивка ESP8266/LX106, один бит за итерацию |
| RC-PDM-Simple32 ASM u4 | 1/16 | Та же тестовая прошивка, разворот по четыре бита; самый быстрый проверенный Simple |
| RC-PDM fixed48 / double | Те же коэффициенты | Настольный контроль точности, не новая качественная ступень |
| PDM/RC-PDM/Simple, 16/64/128 бит | RC: 1/8, 1/32, 1/64 соответственно | Расширенная настольная матрица; это не добавляет готовые RC-профили в радио |

**Разворот u4 не означает четыре бита на сэмпл.** По-прежнему формируются
32 новых бита; цикл содержит восемь групп по четыре последовательных шага.
C, ASM u1 и ASM u4 сохраняют алгоритм Simple и проверяются на одинаковые биты.
Изменение alpha или замена predictive на Simple, напротив, меняет алгоритм.

## 4. Качество: сравнение методов только на одинаковой частоте

Методика: пять сохранённых радиофрагментов, четыре синуса, моно PCM 48 кГц,
общая временная сетка **6,144 МГц**, полоса 20 Гц–20 кГц, Hann-окна и учёт
удержания уровня GPIO. Края фрагментов исключены. Нет индивидуального подбора
задержки или громкости. Ниже один RC **1 кОм + 10 нФ**, высокоомная нагрузка;
в сырых данных также есть RC=40 мкс и пассивная двухзвенная лестница.

**Каждая строка таблиц — отдельное сравнение трёх методов на одной частоте.**
У обоих RC-алгоритмов сдвиги 2/3/4/5/6 для частот 0,384/0,768/1,536/3,072/6,144
МГц соответственно. Варианты с постоянным сдвигом 4 на иных частотах сохранены
лишь как контроль старого опыта, не используются для выводов основных таблиц.

**SINAD, дБ — выше лучше.** Это основной тон относительно шума и искажений
в полосе; изменение амплитуды/фазы самого тона учитывается отдельно.
dBFS задаёт пиковую амплитуду входного синуса относительно полного масштаба.

  алгоритмом, но полезный сигнал слабее совокупной ошибки.

  лучше на тихом −40 dBFS и на 7 кГц. RC с меньшим alpha уже не теряет
  проверенный тон −40 dBFS, однако его SINAD остаётся ниже PDM на той же частоте.
- На всех пяти частотах обычный PDM лучше обоих RC-методов на синусе 7 кГц.
  Большее число битов само по себе не гарантирует монотонного улучшения
  каждого показателя RC-PDM — важны также коэффициент и характер сигнала.

но штрафует попытку RC-PDM компенсировать фильтр; не использовать только
эту меру для объявления победителя. Ни одна мера не заменяет прослушивание
и измерение аналогового выхода.

## 5. Общий недостаток RC-PDM: потеря тихих сигналов

При чередовании `1010…` модель может застрять в двух состояниях вокруг
середины шкалы. Малые изменения PCM тогда не меняют выходные биты.
В прежних проверках alpha=1/16 и 1/4 синус −40 dBFS исчез полностью,
что подтверждено самими битовыми файлами, а не только низким уровнем FFT.
При alpha=1/4 исчезновение наблюдается уже на −20 dBFS. Это не следует
переносить на меньший alpha при большей частоте: граница зависит от сдвига.

При идеальной арифметике граница установившегося чередования по нормированной
пиковой амплитуде приблизительно равна `alpha*(1-alpha)/(2-alpha)` для
predictive и `alpha/(2-alpha)` для Simple:

| Alpha | Предиктивный RC-PDM | RC-PDM-Simple |
| --- | --- | --- |
| 1/16 | около −30,4 dBFS | около −29,8 dBFS |
| 1/4 | около −19,4 dBFS | около −16,9 dBFS |

Это граница конкретного установившегося режима, а не универсальный
порог для любой музыки/предыстории. Возможное следствие — потеря тихих
деталей и нелинейность при уменьшении цифровой громкости.

[Проверка fixed32/fixed48/double](benchmarks/esp8266-rcpdm-precision-2026-09-06/README.md)
не обнаружила улучшения битов или качества на девяти сигналах при большей
точности. Основная проблема — алгоритм выбора бита, не нехватка дробных
разрядов. Dither и интегратор ошибки могли бы быть отдельными исследованиями;
они **не реализованы как подтверждённое исправление**.

## 6. Согласование с реальным RC

Для идеального RC коэффициент за один бит связан с постоянной времени:

`alpha = 1 - exp(-1 / (f_bit * R * C))`.

В основных таблицах RC=10 мкс остаётся **физически одинаковым**. Для обоих
RC-алгоритмов берётся ближайшее приближение alpha степенью двойки:

| Частота однобитного потока | Alpha | Делитель | Сдвиг | RC внутренней модели, мкс |
| --- | --- | ---: | ---: | ---: |
| 0,384 МГц | 1/4 | 4 | 2 | 9,052 |
| 0,768 МГц | 1/8 | 8 | 3 | 9,751 |
| 1,536 МГц | 1/16 | 16 | 4 | 10,088 |
| 3,072 МГц | 1/32 | 32 | 5 | 10,253 |
| 6,144 МГц | 1/64 | 64 | 6 | 10,335 |

Удвоение частоты примерно вдвое уменьшает шаг за бит: делитель удваивается,
сдвиг увеличивается на один. Это приближение, а не точное согласование:
для произвольных частот/RC нужен расчёт alpha по формуле, а не только N.
В рабочем профиле RC-PDM выход фиксирован на 32 бита и около 1,538 МГц,
поэтому его `RC_PDM_SHIFT=4` соответствует этому режиму. Варианты других
частот в новом сравнении являются симуляциями, не изменением прошивки.

При 1,536 МГц и alpha=1/16 модель соответствует RC≈10,09 мкс; при фактической
частоте платы — около 10,07 мкс. При 384 кГц тот же alpha=1/16 соответствует
уже RC≈40,35 мкс. Поэтому уменьшение частоты без изменения коэффициента
одновременно меняет моделируемый фильтр. Alpha=1/4 при 384 кГц даёт RC≈9,05 мкс;
Q16 matched подбирался к 10 мкс точнее, но не устранил потерю слабых сигналов.

Таблицы выше используют **одинаковый физический RC=10 мкс** для всех вариантов;
это сравнение на одной схеме, а не индивидуальная подгонка фильтра под каждого.
Усиление фильтрации может улучшить SINAD ценой полосы/фазы. Две пассивные
ступени 1к/10н нагружают друг друга: они не равны двум изолированным RC-полюсам.

Подключение GPIO3, разделительный конденсатор, высокоомный вход усилителя
и ограничение конфликта с USB-UART описаны в
[аппаратной инструкции](ESP8266_I2S_RCPDM.md#rc-фильтр-и-усилитель).
Модель не учитывает разброс компонентов, сопротивление GPIO, нагрузку
USB-UART, питание, шум усилителя и провалы DMA. Нельзя считать её оценку
гарантированным качеством реального устройства.

## 7. Скорость и память на ESP8266

CPU160, QIO40, GCC 8.4.0 `-O3`, 48-кГц PCM из RAM, сеть и декодеры выключены,
общие 2×512 слов I2S/SLC DMA. Сводка **отдельных физических опытов**:

| Реализация 32 бит/сэмпл | Пакер, мс/48000 сэмплов | Производитель без DMA-ожидания, мс/с аудио | Источник |
| --- | ---: | ---: | --- |
| Обычный PDM32 | 56,337 | 96,458 | [Первый PDM/RC-PDM тест](benchmarks/esp8266-output-compare-2026-09-06/README.md) |
| Предиктивный RC-PDM32, оптимизированный | 112,275 | 122,843 | [Контроль в ASM-тесте](benchmarks/esp8266-rcpdm-simple-lx106-asm-2026-09-06/README.md) |
| Simple32, буквальный C | 139,047 | 155,637 | [C-тест](benchmarks/esp8266-rcpdm-simple-literal-2026-09-06/README.md) |
| Simple32, ASM u1 | 107,175 | 119,845 | [Прямой u1/u4 тест](benchmarks/esp8266-rcpdm-simple-unroll4-2026-09-06/README.md) |
| Simple32, ASM u4 | 78,283 | 90,957 | [Прямой u1/u4 тест](benchmarks/esp8266-rcpdm-simple-unroll4-2026-09-06/README.md) |

Числа `write - DMA_wait` — не полная загрузка CPU: они не учитывают ISR
во время ожидания и могут включать вытеснения вне ожидания. Почти десять
секунд внутри блокирующего `write` не означают десять секунд занятого CPU.
Результаты полной радиопрошивки с MP3/AAC/Wi-Fi требуют отдельного теста.

Прямой ABBA u1 → u4 → u4 → u1 подтвердил **−26,96% времени пакера** и
**−24,10% времени производителя**. Для остальных строк обвязка/компоновка
между опытами различались: таблица не является единым свежим ABC-сравнением.
В частности, меньшая цифра полного пути Simple u4 относительно старого
PDM-теста не доказывает, что Simple всегда дешевле PDM в радио.

Состояние модулятора — 4 Б во всех основных вариантах. DMA — 4096 Б,
новых буферов от RC-модели/ASM нет. В u1/u4 свободная/минимальная heap
одинакова: 108532/105752 Б **в диагностике без сети/декодеров**.
Разворот увеличил scalar/batch код с 45/175 до 93/271 Б flash, стек
scalar/batch сохранился 0/16 Б. 493216 слов/состояний, 2144 batch-слова
и 1980 случаев диспетчера совпали на каждом физическом старте;
ошибок DMA не было. Все 72 сохранённых битовых потока остались прежними.

Более простая формула сама по себе не гарантирует более быстрый C:
результат зависит от GCC, ветвлений и регистров. Побитно точная оптимизация
меняет скорость, но **не улучшает качество алгоритма**.

## 8. Плюсы, минусы и выбор

| Вариант | Плюсы | Минусы/ограничения |
| --- | --- | --- |
| Обычный PDM | Малый и быстрый аккумулятор; нет требования подгонять внутреннюю RC-модель; хороший контроль для сравнения | Шум и искажения при малом числе битов/тихом PCM; не компенсирует сам RC-фильтр |
| Предиктивный RC-PDM | Учитывает следующий RC-шаг; иногда точнее исходного PCM после фильтра, особенно на громком материале | Зона нечувствительности; зависит от RC/alpha; дороже по CPU; не универсально лучше PDM |
| RC-PDM-Simple | Прямое правило, переносимый C и ускоренный LX106 ASM; та же RAM | Другой алгоритм; дополнительное ослабление; на наших радиофрагментах хуже predictive32; зона нечувствительности шире |
| 8 бит/сэмпл | Меньше битов на секунду и решений модулятора | Измеримое ухудшение качества; изменение связи alpha/RC; ускорение всей программы не обязано быть четырёхкратным |

Все варианты позволяют использовать однобитный GPIO с внешним RC вместо
дополнительного DAC; фильтр и подходящий вход усилителя всё равно нужны.
Это не делает выход равноценным выделенному аудио-DAC по шуму/линейности.

Текущее решение проекта: сохранить PDM32 по умолчанию; RC-PDM и Simple —
отдельные варианты исследования. Если выбирать из двух RC32 по точности
на наших радиофрагментах — предпочтительнее predictive. Если исследовать
компромисс CPU/качество — Simple ASM u4. Решение о методе модуляции надо
принимать внутри выбранной частоты, не сравнивая RC8 с PDM32 как равные
условия. Автоматической смены профиля этот документ не выполняет.

Повышение RCPDM8 до 1,536 Мбит/с с четырьмя **новыми** 8-битными группами
на удерживаемый PCM даёт ровно RCPDM32 при том же alpha и состоянии.
Экономии решений тогда нет. Простое повторение каждого готового бита
четыре раза лишь растягивает импульсы и не повышает качество модуляции.

## 9. Как воспроизвести и что ещё не измерено

Качество: [методика](../tools/esp8266_audio_profile/RCPDM8_QUALITY.md),
[PDM/RC-PDM8](benchmarks/esp8266-rcpdm8-quality-2026-09-06/README.md),
[Simple](benchmarks/esp8266-rcpdm-simple-2026-09-06/README.md).
Полный расчёт требует Python с NumPy, Node, C++17-компилятор и сохранённые
локальные PCM с совпадающими SHA-256. Эфирные записи в Git не включены.
Команды из корня проекта, без доступа к плате:

```powershell
node --test tests/esp8266-rcpdm-simple.test.js tests/esp8266-rcpdm-precision.test.js tests/esp8266-rcpdm8-quality.test.js tests/esp8266-rcpdm.test.js
python tests/rcpdm8_quality_model_test.py
python tools/esp8266_audio_profile/measure_rcpdm_simple.py --output radio_output/rcpdm-simple-repeat
node tools/esp8266_audio_profile/verify_rcpdm_simple_rewrite.js .build/rcpdm-simple-proof-repeat
node --test tests/esp8266-pdm-matrix.test.js tests/esp8266-direct-pdm.test.js
python tests/pdm_matrix_quality_model_test.py
python tools/esp8266_audio_profile/measure_pdm_matrix.py --output radio_output/pdm-frequency-matrix-repeat
```

Сборка predictive: профиль `sdkconfig.i2s-rcpdm.defaults` и
`CONFIG_YORADIO_AUDIO_OUTPUT_I2S_RCPDM`.
Simple пока ограничен изолированным benchmark:
`YORADIO_ESP8266_RCPDM_VARIANT=simple`, `OUTPUT_COMPARE` и
`AUDIO_OUTPUT_BENCHMARK`. ASM u4 выбирается флагом
`YORADIO_ESP8266_RCPDM_SIMPLE_UNROLL4=ON` / параметром `-SimpleUnroll4`
[скрипта сборки](../tools/esp8266_audio_profile/build_rcpdm_speed.ps1).
`RCPDM_SIMPLE_FORCE_C=1` сохраняет явный C-фолбэк; другие архитектуры
и коэффициенты также используют C.

Ещё нужны: запись аналогового выхода и измерение SNR/THD с реальными
компонентами; сравнение при одинаковой воспринимаемой громкости;
единый актуальный PDM/predictive/Simple тест CPU под MP3/AAC и Wi-Fi;
проверка CPU/DMA режимов 3,072/6,144 МГц на плате; отдельное исправление зоны нечувствительности
с повторной проверкой качества и стоимости. Пока нет данных, эти пункты
не считаются ни улучшениями, ни гарантированными возможностями.
