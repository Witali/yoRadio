# ASM eBands pair: две границы полосы через word-load

2026-09-17, независимый кандидат поверх принятого exp2-table32.
Основание — [census eBands](ESP8266_OPUS_EBANDS_PROFILE.md),4200 пар/с
тестового аудио192кбит/с в поиске allocation vector.

## Изменение

В clt_compute_allocation две L16SI по0x402484ae и0x402484b1 заменены
CALL0 и NOP. Leaf-helper0x4024dcc4 возвращает a2=p[1],a11=p[0]: одно
выровненное L32I для чётного индекса, два для нечётного. Знаковое расширение
int16 сохранено. Нужны8/11 исполняемых инструкций с CALL0/NOP/RET вместо2,
поэтому сам по себе подсчёт инструкций не обещает ускорения. Проверяется
выигрыш от отсутствия двух узких чтений flash, а не уменьшение всей функции.

42байта размещения — прежняя доказанно недоступная decoder-потоку
encoder-область quant_partition;36байт helper и6байт неисполняемого padding.
Прежняя32-B exp2-таблица не затронута. Размер app903216B, адреса остальных
инструкций, static RAM/IRAM и192-B frame не меняются; leaf не использует стек.
Патчи всего48байт. C fallback и production defaults не меняются.

Вход a3=eband5ms+2*j, j=0..20; стандартная таблица0x402d5c5c содержит
22 int16/44байта и выровнена на4. Все word-чтения остаются внутри неё,
включая последнюю пару. Не опираемся на соседний padding или ограничение
битрейта. Произвольные custom CELT modes не включены в используемый профиль.

Все GPR и SAR в точке возврата совпадают, кроме a0, изменённого CALL0.
Отдельный анализ всех176 достижимых инструкций до следующего вызова
подтверждает отсутствие чтения старого a0; исходный внешний return address
остаётся в штатном frame. ABI-допущение не заменено сравнением только PCM.
