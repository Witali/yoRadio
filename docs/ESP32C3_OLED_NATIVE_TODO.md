# TODO: ESP32-C3 OLED native

## Параметры исходного аудиопотока в WebUI — 2026-09-10

Статус: выявлено чтением кода, исправления ниже **ещё не реализованы**.
Точный дефект ESP8266 «всегда mono» на C3 не подтверждён. Однако формат
кэшируется по первому кадру, поэтому последующая смена параметров теряется.

### Что исправить

- [ ] В `decoder_task()` обновлять подтверждённые частоту, каналы и разрядность
  при изменении `latest_info`, а не только bitrate после первого кадра.
- [ ] Убрать такое же ограничение первого формата в `custom_legacy_output()`
  и проверить `custom_flac_output()`. Передавать актуальные параметры текущего
  PCM-блока в `send_pcm()` и расчёт длительности аудио: это не только текст UI.
- [ ] В общем Helix AAC adapter разделить номинальную частоту исходного потока
  (`AACGetStreamSampRate()`, учитывает наличие SBR) и фактическую частоту PCM
  (`AACGetSampRate()`, учитывает реально включённый синтез SBR). Первую
  использовать для статуса, вторую оставить для PCM, ресемплера и I2S.
  Не заменять частоту PCM номинальной частотой HE-AAC.
- [ ] Разделить исходные каналы потока и каналы после downmix, если выходной
  профиль выполняет преобразование в mono. Не выводить неподтверждённые PS
  stereo-каналы как достоверные.
- [ ] Публиковать изменение формата в WebUI без повторной рассылки неизменных
  значений и без зависимости от изменения bitrate. При reconnect возвращать
  актуальный snapshot; при Stop/смене станции не оставлять старый формат.
- [ ] Сохранить стабильный снимок параметров на время прокрутки OLED-строки,
  но не замораживать из-за него формат PCM и статус WebUI на весь поток.

### Проверка исправления

- [ ] Исполняемые регрессионные тесты callback/state: stereo -> mono -> stereo
  и смена частоты в одном поколении потока при неизменном bitrate.
- [ ] AAC-LC и HE-AAC с разными stream/PCM rate: статус показывает исходный
  поток, а число PCM-отсчётов, скорость вывода и длительность не изменены.
- [ ] Проверить Espressif, Helix и custom callbacks; отдельно Stop/Play,
  смену станции и WebUI reconnect. Не ограничиваться поиском строк в исходниках.
- [ ] Собрать профили Espressif AAC и Helix AAC; затем проверить WebUI/OLED
  на физической C3 без регрессии воспроизведения и без лишних статусных событий.

Контекст профиля: `sdkconfig.defaults` выбирает Helix AAC, но сохранённый
`sdkconfig` на момент проверки выбирает Espressif. Поэтому фактический backend
нужно проверять по конфигурации конкретной сборки, а не предполагать Helix всегда.
