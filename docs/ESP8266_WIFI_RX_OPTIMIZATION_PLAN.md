# План оптимизации приёма Wi-Fi/HTTP на ESP8266

Дата: 2026-09-08. Wemos D1 mini, native ESP8266 RTOS SDK.
Статус: пункт 1 проверен в 89 попытках на плате; пункты 2 и 6 в работе.
Production-default пока не изменён. [Ход работы и результаты](ESP8266_WIFI_RX_OPTIMIZATION_2026-09-08.md).
Основание: [измерения на плате](ESP8266_NETWORK_BENCHMARK_2026-09-08.md).

## Цель и ограничения

Уменьшить CPU и задержки приёма сжатого аудиопотока, сохранив RAM,
правильность HTTP/ICY и отзывчивость BOOT/WebUI. Сначала оптимизировать
текущий однозадачный тракт; отдельный reader добавлять только при
доказанном выигрыше и достаточной памяти.

Не менять декодеры и PDM. Сохранить CPU160/QIO40, I2S PDM32 GPIO3/RX,
два DMA-буфера по 512 слов. Провалы PCM/DMA уже наблюдались без сети:
сетевые изменения сами по себе не решают независимые проблемы вывода.
Не возобновлять автоматически отдельную
[приостановленную оптимизацию WebUI](ESP8266_WEBUI_LATENCY_PLAN.md).

## Исходная точка

- [x] Сохранены воспроизводимые MP3/AAC-источники, образы, логи и JSON.
- [x] Измерены приём без декодирования, полный тракт и время задач.

| Входной поток | Задача чтения | TCP/IP + сетевая задача SDK | Всё время вне idle |
| --- | ---: | ---: | ---: |
| 64,23 кбит/с | 16,14% | 5,43% | 22,27% |
| 128,14 кбит/с | 16,25% | 8,45% | 25,39% |
| 518,77 кбит/с | 16,72% | 25,12% | 42,55% |

Окна около 20 с, без декодирования. Фон без потока — 2,17% вне idle.
FreeRTOS относит прерывания к прерванной задаче; измеритель не бесплатен.
При 128 кбит/с получено 18 200 EAGAIN из 18 793 чтений за 20,02 с.

Лучший отдельный результат среди профилей — 816,5 кбит/с за 20 с,
но были тайм-ауты и паузы приёма до 947 мс. CPU-прогон 320 кбит/с
оборвался через 17,38 с: это не успешный полный тест.

Текущие размеры: вход декодера 1536 байт, чтение до 1024 байт,
TCP MSS 536, окно 2440 байт, mailbox 6; inactivity timeout 1000 мс.
Свободная heap в приёмных тестах порядка 11–14 КиБ, но при прежнем
стрессе WebUI падала намного ниже. Нельзя отдавать весь остаток буферу.

## 1. Ожидание готовности вместо опроса раз в 1 мс — первый приоритет

- [x] Проверить `select()`/уведомления готовности именно в используемой
  версии Espressif SDK/lwIP: EOF, закрытие, EINTR и EAGAIN после readiness.
- [x] После EAGAIN усыплять задачу до готовности сокета. Начать с предела
  ожидания 20–50 мс для обработки команд; готовые данные читать сразу,
  без фиксированной задержки. Сокет оставить неблокирующим.
- [x] Проверять generation/cancel до и после ожидания и перед декодером.
  Старое соединение не должно оживать после Stop/смены станции.
  Закрытие и повторное использование descriptor согласовать с владельцем.
- [x] Считать inactivity timeout от последнего принятого байта.
  EAGAIN/пробуждение не продлевают его. Сохранить build-time параметр
  и текущий default 1000 мс.
- [x] Читать прямо в существующий вход декодера. Когда нет места,
  ждать освобождения, не выделять дополнительную память.
  Не допускать двух параллельных читателей одного соединения.
- [x] Сохранить уступки планировщику, watchdog, работу Wi-Fi и WebUI.
  Постоянно готовый сокет не должен занимать процессор бесконечно.
- [x] Сравнить A/B на плате. Ориентир, не обещание: уменьшить ~16%
  времени reader хотя бы вдвое; желаемый результат — до 5% на 64/128 кбит/с.
  Получено 15,42 → 6,12% на 64 и 15,37 → 7,61% на 128 кбит/с;
  по 11–12 попыток на комбинацию, ошибки сохранены. Цель до 5% не достигнута.
  Окончательное включение по умолчанию ждёт полного аудиотракта и оценки
  неоднозначной максимальной скорости. Значение 0 пока остаётся default.

Принятие: меньше пустых чтений/CPU, не ниже скорость, нет регрессии Stop/
Next/Prev. Отмена сетевого ожидания укладывается в выбранные 20–50 мс;
это не обещание запуска декодированного звука за такое время.

## 2. Накладные расходы полезного чтения

- [ ] Измерить полезные байты на вызов, стоимость чтения и копирования.
- [ ] Сравнить лимиты 512/1024/1536 байт внутри фактически свободной
  ёмкости входа, не добавляя новый буфер.
- [ ] Проверить обработку нескольких готовых порций за пробуждение,
  ограниченную по байтам/времени. Не ждать заполнения большой порции.
- [x] Не использовать FIONREAD в горячем пути: здесь он недоступен.
  Не включать SO_RCVBUF только ради диагностического счётчика.
- [x] Сохранить прямую запись в буфер декодера, без лишней полной копии.

Принятие: меньше CPU на килобайт, не хуже задержка, не больше RAM,
байты на входе декодера идентичны.

## 3. Отделить радиопомехи от TCP

- [x] Сопоставить временные ряды RSSI, байтов, ожиданий и reconnect.
  Не ограничиваться RSSI в начале/конце; не печатать лог на каждый пакет.
- [ ] На сервере сопоставить паузы с ACK, retransmission, advertised/
  zero window. Принятое send-буфером ПК ещё не доставлено плате.
- [ ] Сравнить текущие условия и отдельную серию с хорошим сигналом.
  Не менять адаптеры Wi-Fi ПК; перемещение платы отмечать как отдельное
  условие, не смешивать результаты.
- [ ] Только после установления причины по одному проверять MSS/окно/
  mailbox и режим энергосбережения Wi-Fi. Сверяться с кодом/ограничениями
  используемого SDK; учитывать служебную память TCP/pbuf.
- [x] Сохранять тайм-ауты и длинные ожидания. Их исключают из активного
  CPU, но не из оценки непрерывности.

Принятие: установлена причина класса пауз, а не только корреляция с RSSI.
Изменение TCP-параметров не ухудшает RAM, WebUI, OTA и смену декодеров.

## 4. Буферизация после подтверждённой экономии RAM

- [ ] Повторить [аудит памяти](ESP8266_AUDIO_MEMORY_TODO.md):
  heap minimum, крупнейший блок, стеки, MP3/AAC, переключения, WebUI/OTA.
  Не уменьшать утверждённый стек WebUI 5120 байт ради входного буфера.
- [ ] Рассчитать запас: байты = битрейт_бит_с × пауза_с / 8.
  При 320 кбит/с и 947 мс нужно около 37,9 кБ до добавления запаса:
  столько нельзя безопасно взять из текущей свободной heap.
- [ ] Переиспользовать только области с доказанно раздельным временем
  жизни. Не считать IRAM автоматически свободной DRAM; без malloc на пакет.
- [ ] Если бюджет позволяет, сделать размер и порог предзаполнения
  параметрами сборки; документировать добавленную задержку старта.

Принятие: нет новых OOM, фрагментации, stack overflow или потери WebUI.
Новый default не выбирается по одиночному удачному прогону.

## 5. Отдельная задача чтения — условный этап

- [ ] Если задержки чтения во время декодирования/PDM сохраняются,
  оценить существующий producer KaRadio-профиля, а не второй HTTP-клиент.
- [ ] До включения посчитать стек, TCB, очередь сжатых данных,
  URL/HTTP/ICY workspace и объекты синхронизации.
- [ ] Единственный владелец сокета, ограниченная очередь. Producer спит
  при заполнении, consumer — при пустой очереди. Общий workspace
  не используется одновременно двумя задачами.
- [ ] Отмена: уведомление обеих сторон, подтверждение остановки,
  затем освобождение/переиспользование. Не держать mutex/критическую
  секцию во время ожидания сети или DMA.
- [ ] Приоритеты выбирать по замерам, сохраняя время для Wi-Fi/WebUI.
  Сравнить с однозадачным вариантом.

Принятие: выигрыш на плате при безопасной памяти. Без измеримого
улучшения усложнение не становится production-default.

## 6. Регрессии и принятие каждого изменения

- [ ] Host-тесты: частичные чтения, EAGAIN после readiness, EINTR, EOF,
  inactivity deadline, частичные HTTP-заголовки, chunked и ICY на границах.
- [ ] Гонки: Stop/Next/Prev во время ожидания/чтения/декодирования,
  быстрое повторное переключение, запрет запуска старой generation.
- [ ] A/B на одинаковых собственных tone/noise-фрагментах:
  64/128/320 кбит/с и unlimited; минимум десять попыток окон по 20 с.
  Отдельно receive-only и decode+PDM. AAC высокого битрейта
  не является обязательным условием этого этапа.
- [ ] Считать reader, tiT/ppT, idle, реальные байты, ожидания/reconnect,
  heap/стеки и DMA underrun. Не складывать пересекающийся elapsed
  вызовов с runtime задач и не называть underrun числом MP3-кадров.
- [ ] Проверить WebUI/BOOT при приёме, две вкладки и OTA.
  Существующие проблемы отмечать отдельно, новые регрессии не допускать.
- [ ] После коротких прогонов — не менее 5 минут каждого выбранного
  рабочего режима; неудачные прогоны также сохранять.
- [ ] Отдельный логичный коммит на принятое улучшение с A/B-результатами.
  Если ускорения нет — убрать усложнение, сохранить отрицательный результат.
- [ ] Сохранить production-образ в firmware/development/<variant>/app.bin,
  конфигурацию, SHA-256 и запись changelog. OTA и проверка реально
  запущенного слота; без автоматического перехода к USB-восстановлению.
