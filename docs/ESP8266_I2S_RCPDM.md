# ESP8266: I2S RCPDM32

Сводное описание алгоритмов, плюсов/минусов, Simple, выходных битрейтов,
качества и скорости: [RC-PDM и обычный PDM](RC_PDM_OVERVIEW.md).
Ниже — история реализации и настройки аппаратного профиля.

Настольное сравнение с RCPDM8 и обычным PDM, включая обнаруженную зону
нечувствительности к тихим сигналам:
[оценка качества 2026-09-06](benchmarks/esp8266-rcpdm8-quality-2026-09-06/README.md).
Это не изменение профиля по умолчанию и не физический замер аналогового выхода.

Дополнительная [проверка fixed32 / fixed48 / double](benchmarks/esp8266-rcpdm-precision-2026-09-06/README.md)
подтвердила: текущая модель уже fixed-point; повышение разрядности не изменило
выходные биты на девяти тестовых сигналах и не устранило потерю тихих тонов.

Также добавлен настольный [RCPDM-Simple](benchmarks/esp8266-rcpdm-simple-2026-09-06/README.md):
прямое сравнение текущего RC-аккумулятора с PCM, без прогноза следующего
значения. Это отдельный алгоритм для исследования, не замена рабочего профиля.

[Первый физический тест Simple32](benchmarks/esp8266-rcpdm-simple-board-2026-09-06/README.md)
обнаружил лишние ветвления GCC. После удаления промежуточного `high`
[повторный тест](benchmarks/esp8266-rcpdm-simple-one-branch-2026-09-06/README.md)
показал сокращение времени пакера на 25,54% без изменения битов и RAM.
В той версии Simple был на 12,77% медленнее predictive в пакере, на 6,34% —
в пути без DMA-ожидания. Обычная PDM32-прошивка восстановлена.

По следующему уточнению пользователя Simple записан буквальным циклом заряда/
разряда (2026-09-06):

```c
word <<= 1;
if (state < target) {
    state += (UINT32_MAX - state) >> shift;
    word |= 1U;
} else {
    state -= state >> shift;
}
```

Здесь нет `high`, `next`, расчёта порога или общей константы шага. Сравнение
идёт до изменения аккумулятора; равенство выдаёт 0. Состояние `uint32_t`
остаётся в пределах шкалы. Для Simple32 `shift=4`, цикл повторяется 32 раза;
Simple8 использует тот же алгоритм. Буферы и профиль радио не меняются.
Эта запись побитно эквивалентна прежнему Simple; приведённые выше физические
тайминги относятся к прежней записи, **не к этому циклу**. GCC может сам
переносить арифметику перед ветвлением; ускорение здесь не заявляется.

Проверка буквального цикла: 20 host-тестов пройдены, все 72 сохранённых
битовых потока совпали с прежними; self-test включает 1972864 проверки слов/
состояний, 20000 проверок непрерывности, 5 равенств и 2144 batch-слова.
Затем выполнен [физический ABBA-тест буквального цикла](benchmarks/esp8266-rcpdm-simple-literal-2026-09-06/README.md):
пакер 139,047 мс на 48000 слов, путь без DMA-ожидания 155,637 мс на секунду
аудио. Это на 23,85% и 26,70% больше predictive соответственно. RAM прежняя,
DMA без ошибок; после теста восстановлено обычное радио и проверен HTTP 200.
Для читаемости оставлено `UINT32_MAX - state`: GCC и так заменяет его на
инверсию через `xor`. Повторить настольное сравнение битов:
`node tools/esp8266_audio_profile/verify_rcpdm_simple_rewrite.js .build/rcpdm-simple-literal-proof`.

Для Simple добавлен [ASM-backend Xtensa LX106 с C-фолбэком](benchmarks/esp8266-rcpdm-simple-lx106-asm-2026-09-06/README.md).
Он включается автоматически только для ESP8266 при `shift=4` и ненулевом
числе битов. Другие платформы/коэффициенты используют прежний читаемый
`rcpdm_simple_bits_c()`; определение `RCPDM_SIMPLE_FORCE_C=1` принудительно
оставляет C и на ESP8266. Нулевой счётчик безопасно обрабатывает C-фолбэк.
На плате: 107,177 мс/48000 слов и 120,053 мс/секунду аудио без DMA-ожидания,
примерно на 23% меньше времени, чем у буквального C. Алгоритм Simple не
изменён; новые буферы и маскирование прерываний не добавлялись. Профиль
обычного радио остаётся прежним — I2S-PDM32.

Также проверен [разворот ASM Simple по четыре бита](benchmarks/esp8266-rcpdm-simple-unroll4-2026-09-06/README.md):
**107,175 → 78,283 мс** на 48000 слов (−26,96%), полный производитель без
DMA-ожидания **119,845 → 90,957 мс** на секунду аудио (−24,10%). Все биты
и RC-состояния совпали, RAM и стек прежние; scalar/batch во flash выросли
с 45/175 до 93/271 Б. Включение: `-SimpleUnroll4` в скрипте сборки Simple
или `YORADIO_ESP8266_RCPDM_SIMPLE_UNROLL4=ON`. Однобитный вариант и C-фолбэк
сохранены; обычный профиль радио не меняется. После ABBA восстановлена
исходная прошивка, DHCP и HTTP 200 проверены.

Отдельный экспериментальный выход **I2S RCPDM**, добавлен 2026-09-05.
Обычный I2S PDM остаётся вариантом по умолчанию. Это альтернатива модулятора,
а не замена декодеров MP3/AAC, WebUI или драйвера DMA.

Основа — предиктивная беззнаковая RC-модель из пользовательского материала
`RCPDM_recent.md`. По последующему уточнению пользователя приняты **ровно
32 бита на выходной PCM-сэмпл**, а не частота 2 MHz с дробным числом бит.

## Параметры

| Параметр | I2S RCPDM |
| --- | --- |
| Флаг | `CONFIG_YORADIO_AUDIO_OUTPUT_I2S_RCPDM=y` |
| Профиль | `esp8266/rtos-sdk-native/sdkconfig.i2s-rcpdm.defaults` |
| Выходной PCM | моно, номинально 48 kHz |
| Модуляция | 32 последовательных RC-решения, одно слово `uint32_t` |
| Несущая | номинально 1,536 MHz; делители 8×13 дают 1,5384615 MHz |
| Коэффициент RC | alpha=1/16 |
| Вывод | GPIO3/RX через существующий I2S/SLC DMA |
| DMA | прежние 2×512 слов, суммарно 4096 байт |
| Состояние RC | 4 байта вместо 4-байтового аккумулятора обычного PDM |
| Остальная конфигурация | CPU 160 MHz, QIO 40 MHz, Helix MP3 SSO + AAC |

Ресэмплер, громкость, баланс, нормализация и сведение стерео в моно сохранены.
Входной PCM 44,1/32/24 kHz проходит тот же существующий ресэмплер к 48 kHz.
32 бита относятся к сэмплу **после** этого преобразования. Ресэмплер сохраняет
фазу между пакетами; RC-модель также сохраняется между словами/пакетами.
При stop/init RC-состояние возвращается к половине полной шкалы.

Как и у текущего PDM32, реальная частота I2S на 0,1603% выше номинальной:
физический темп слов около 48076,9 в секунду. Это существующая погрешность
целочисленного делителя ESP8266, не режим 2 MHz и не смена PCM на 62,5 kHz.

## Алгоритм

Для каждого бита сравниваются прогнозы разряда и заряда:

```c
down = state - (state >> 4);
up = state + ((~state) >> 4);
threshold = down + ((up - down) >> 1);
```

Если целевое напряжение выше порога, выдаётся 1 и принимается `up`, иначе 0
и `down`. Подписанный PCM переводится в беззнаковую шкалу как
`((uint32_t)((int32_t)pcm + 32768)) << 16`.

Использована эквивалентная форма: `up - down == UINT32_MAX >> 4` для любого
32-битного состояния. Поэтому шаг и половина шага — константы, включая
эффект целочисленного округления. Суммы остаются в диапазоне `uint32_t`.
Нет float, 64-битных операций, умножений, делений или таблиц в цикле модулятора.
Первый бит помещается в старший разряд слова, как у существующего DMA PDM.
Постоянный нулевой PCM формирует `0xaaaaaaaa`, совпадая с нейтральным DMA-словом.

Вычисления выполняются в audio task; ISR и драйвер DMA не изменены. Новых
задач, аудиобуферов и выделений heap нет. Это программная модуляция, I2S только
передаёт готовые биты. При DMA underrun остаётся существующий нейтральный поток;
совпадение цифровой модели и физической RC-цепи при возобновлении требует
аппаратной проверки. Модель не является точным физическим вольтметром.

## RC-фильтр и усилитель

Для alpha=1/16 постоянная времени `RC = -1 / (f_bit * ln(15/16))`.
При фактической несущей и R=1 kΩ расчётный C≈10,0715 nF,
эквивалентный срез модели ≈15,80 kHz. Практический исходный вариант:
**R=1 kΩ, C=10 nF** (срез идеальной физической цепочки ≈15,92 kHz).
Если нужно ближе попасть в расчёт, 10 nF + 68 pF параллельно; допуски деталей
и сопротивление выхода GPIO всё равно влияют на совпадение модели.

```text
GPIO3 ── 1 kΩ ──●── разделительный конденсатор ── вход усилителя
                │
               10 nF
                │
GND ────────────┴────────────────────────────── GND усилителя
```

Разделительный конденсатор убирает постоянное смещение около VCC/2;
например, неполярный 1 µF для высокоомного линейного входа. Входное
сопротивление желательно 47 kΩ и выше: низкоомная нагрузка изменит RC-модель.
Динамик или наушники напрямую не подключать. Для контроля модели сначала
измерять выход высокоомным щупом, без дополнительной нагрузки усилителя.
8 nF из варианта 2 MHz здесь не является согласованным номиналом.

GPIO3 остаётся UART0 RX: прошивка UART-команды не принимает. Сохраняется
существующее ограничение конфликта с TX USB-UART-моста; не передавать байты
с компьютера на UART RX во время звука. GPIO16 и управление изоляцией не добавлены.

## Сборка и проверка

Использовать обычное настроенное окружение ESP8266 RTOS SDK и новый каталог:

```powershell
cmake -S esp8266/rtos-sdk-native -B .build/esp8266-native-i2s-rcpdm -G Ninja `
  "-DSDKCONFIG_DEFAULTS=$PWD/esp8266/rtos-sdk-native/sdkconfig.i2s-rcpdm.defaults"
cmake --build .build/esp8266-native-i2s-rcpdm
node --test tests/esp8266-rcpdm.test.js tests/esp8266-i2s-pdm-output.test.js
```

Не использовать прежний build-каталог с другим `sdkconfig`: defaults не
перезаписывает уже выбранные значения. В сгенерированном `config/sdkconfig.h`
должен быть выбран только `CONFIG_YORADIO_AUDIO_OUTPUT_I2S_RCPDM` из вариантов
аудиовыхода. В консоли профиль явно называется `I2S RCPDM`.

- [x] C-регрессия: все 65536 значений PCM при шести граничных RC-состояниях
  и 100000 последовательных случайных сэмплов; всего 493216 слов совпали
  побитно с независимой 64-битной эталонной моделью.
- [x] Проверены нулевой сигнал, оба края PCM, reset и сохранение состояния.
- [x] Та же C-регрессия прошла GCC ASan/UBSan без ошибок.
- [x] Прошла сборка ESP8266 Xtensa GCC 8.4.0, main с `-O3`.
- [x] Обычный PDM: повторно скомпилированы `native_audio_output.c` и `app_main.c`.
- [x] Дизассемблер: RC-пакер 55 байт кода, одна условная ветка на бит,
  нет вызовов функций, деления, 64-битной арифметики или стекового кадра.
- [x] ELF: DRAM data=1640, bss=18600 байт, IRAM text=23096, bss=4040 байт;
  RAM-секции равны прежней обычной сборке. Это статические секции, не оценка
  всей runtime RAM со стеками и динамическими декодерами.
- [x] Общие регрессионные тесты: 304 успешно.
- [ ] Аппаратная проверка RCPDM-фильтра, звука, SNR/THD и idle CPU при MP3/AAC.

Host-тесты подтверждают арифметику, но не качество аналогового звука.
При добавлении варианта основная прошивка на плате не перезаписывалась.

2026-09-06 выполнено [физическое сравнение PDM/RCPDM без декодеров и Wi-Fi](benchmarks/esp8266-output-compare-2026-09-06/README.md).
Формирование 48000 слов: PDM **56,337 мс**, RCPDM **119,216 мс**.

RCPDM сейчас медленнее; RAM одинакова, DMA underrun в обоих вариантах нет.
Скорость передачи I2S одинакова. Аналоговые SNR/THD и работа RCPDM под нагрузкой
MP3/AAC ещё не измерены. После тестов возвращена обычная PDM32-прошивка.
