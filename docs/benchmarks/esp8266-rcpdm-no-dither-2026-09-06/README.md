# RC-PDM без dither: меньше шума, но хуже линейность слабых сигналов

2026-09-06. Проверены Predictive и Simple, каждый с feedback и без него.
**Удаление dither не является безусловным улучшением:** на громких тонах
SINAD растёт, но гармоники усиливаются, а передача очень слабых сигналов
становится менее стабильной. Без feedback возникает мёртвая зона.

Это численная симуляция, не запись аналогового выхода и не бенчмарк CPU.
Прошивка, конфигурация и файлы подключённой платы не изменялись.

## Условия и контроль

- PCM 48 кГц, 32 новых бита/сэмпл, однобитный выход **1,536 МГц**.
- Одинаковые fixed-point шкала `2^29`, RC alpha=1/16 и линейная интерполяция.
- Predictive сравнивает цель с серединой двух прогнозируемых напряжений;
  Simple — с текущим напряжением до его обновления. Simple здесь — настольный
  вариант в формате Feedback32, не старый ASM без интерполяции.
- Единственная разница с предыдущим исследованием — `dither=0` вместо TPDF
  ±полшага (`dither=2`). При отключении PRNG вообще не вызывается.
- Те же пять радиофрагментов, шесть тонов и цифровая тишина: **12 входов**.
  Те же три физических фильтра: RC 10 мкс, RC 40 мкс, RC-лестница.
- Общая сетка 6,144 МГц удерживает каждый бит 4 отсчёта, не добавляя решений.
  Полоса 20 Гц…20 кГц, Hann-окна 1 с, края минимум по 250 мс исключены.
  Все таблицы ниже — RC 10 мкс, без подгонки усиления.
- Повторно сгенерированы и побитно сверены **оба** прежних dither-on потока
  для всех 12 входов и 15 пар LSB-тестов каждого метода. Их SHA-256 совпали.
  Поэтому отличие не связано с изменением других частей симулятора.

Сырые данные: [Predictive](predictive/results.json), [Simple](simple/results.json).
Контрольные dither-on результаты: [Predictive](../esp8266-rcpdm-feedback-ab-2026-09-06/README.md),
[Simple](../esp8266-rcpdm-simple-feedback-ab-2026-09-06/README.md).

## С feedback: SINAD, дБ — выше лучше

| Сигнал | Predictive: dither | Predictive: без | Simple: dither | Simple: без |
| --- | ---: | ---: | ---: | ---: |
| 1 кГц, −3 dBFS | 55,95 | 62,58 | 56,60 | 62,38 |
| 1 кГц, −20 dBFS | 43,87 | 47,05 | 43,83 | 46,98 |
| 1 кГц, −40 dBFS | 23,86 | 26,54 | 23,86 | 26,72 |
| 1 кГц, −60 dBFS | 3,89 | 8,13 | 3,82 | 8,24 |
| 1 кГц, −80 dBFS | −16,28 | −15,27 | −16,35 | −14,76 |
| 7 кГц, −3 dBFS | 54,92 | 61,40 | 55,56 | 61,10 |

На громких тонах выигрыш около 5,5–6,6 дБ; на −20…−60 dBFS около 2,7–4,4 дБ.
Однако улучшение SINAD не означает уменьшения всех искажений:

| THD для 1 кГц −3 dBFS, ниже лучше | С dither | Без dither |
| --- | ---: | ---: |
| Predictive + feedback | −76,69 | −67,07 |
| Simple + feedback | −77,03 | −66,55 |

Гармоническая составляющая выросла примерно на 10 дБ, но уменьшение фонового
шума перевесило её в суммарном SINAD. На входе 1 кГц −40 dBFS также выросли
гармоники 13/15 кГц: например, Predictive 13 кГц около −80,89 dBFS без dither
против −91,11 dBFS с dither (мощность трёх FFT-бинов Hann).

### Очень тихий синус: важная оговорка

На 1 кГц −80 dBFS коэффициент передачи основной частоты без dither:
**−11,22 дБ Predictive / −10,54 дБ Simple**. С dither в тех же коротких
окнах оценка около −0,23/−0,22 дБ, хотя шум тогда выше самого сигнала.
Отношение гармоник к ослабленной основной частоте без dither превышает 0 дБ.
Поэтому нельзя оценивать этот случай только по слегка улучшившемуся SINAD.

| 1 кГц, −20 dBFS | 20,03 | 17,61 | 19,88 | 17,71 |
| 1 кГц, −40 dBFS | 0,02 | нет тона | −0,15 | нет тона |
| 1 кГц, −60 dBFS | −20,19 | нет тона | −20,30 | нет тона |
| 1 кГц, −80 dBFS | −36,17 | нет тона | −36,17 | нет тона |

При −40, −60 и −80 dBFS после исключения переходного участка оба off-варианта
выдают только `0x55555555`: постоянное чередование битов. Это аудионоль, а не
«идеально чистый тихий сигнал». В JSON для этих случаев `tone_detected=false`,
`sinad_db=null`; мёртвая зона проверяется отдельно по самим битам.

## Цифровая тишина: RMS в полосе, dBFS — ниже лучше

| Вариант | С dither | Без dither |
| --- | ---: | ---: |
| Predictive + feedback | −66,94 | −89,32 |
| Simple + feedback | −66,89 | −89,38 |
| Predictive без feedback | −43,08 | ниже расчётного порога |
| Simple без feedback | −43,46 | ниже расчётного порога |

С feedback шум тишины снижается примерно на **22,4–22,5 дБ**. Без feedback
постоянный чередующийся поток не имеет аудиосоставляющей в модели; это не
утверждение об абсолютном отсутствии шума на физической плате.

## Радиозаписи

SNR относительно исходного PCM после общей **фиксированной** компенсации
задержки интерполяции 10,091 мкс. Сырые SNR также сохранены. Ни задержка,
ни усиление не подгонялись по записи. В ячейках: **с dither → без dither**.

| Запись | Predictive + feedback | Simple + feedback |
| --- | ---: | ---: |
| Маяк | 35,21 → 35,76 | 35,09 → 35,62 |
| Record | 34,34 → 34,34 | 34,25 → 34,25 |
| Ретро | 35,28 → 35,32 | 35,18 → 35,22 |
| Symphony | 36,04 → 38,63 | 36,02 → 38,48 |
| Вести | 36,93 → 38,26 | 36,81 → 38,08 |

С feedback на этом наборе влияние от практически нулевого до +2,6 дБ.
Разница Record у Predictive фактически −0,003 дБ, скрытая округлением.

| Запись | Predictive без feedback | Simple без feedback |
| --- | ---: | ---: |
| Маяк | 17,59 → 13,24 | 16,83 → 11,81 |
| Record | 30,54 → 32,86 | 22,37 → 23,48 |
| Ретро | 27,05 → 27,87 | 21,85 → 21,88 |
| Symphony | 12,27 → 9,03 | 12,30 → 8,17 |
| Вести | 16,08 → 12,18 | 15,64 → 10,92 |

Без feedback результат неоднозначен: в тихих записях потеря мелких сигналов
ухудшает SNR сильнее, чем помогает уменьшение шума.

## ±1 LSB: среднее скрывает нестабильность

Восьмисекундная когерентная оценка передачи тона относительно эталона:

| Вариант | С dither | Без dither |
| --- | ---: | ---: |
| Predictive + feedback | 1,00014 | 1,01072 |
| Simple + feedback | 0,99761 | 1,01504 |
| Predictive без feedback | 0,94434 | 0 |
| Simple без feedback | 0,91373 | 0 |

Средняя передача DC ±1 LSB с feedback без dither — +0,99733/−1,00267 LSB
у обоих методов. Без feedback — 0/0. Три seed при отключённом PRNG дают
**одинаковые биты**, это проверка детерминизма, не три независимых измерения.
Фаза при нулевой амплитуде не определена и не интерпретируется.

Но разбиение тех же данных на восемь односекундных окон выявляет:

| С feedback, seed 2654435769 | Диапазон коэффициента с dither | Без dither |
| --- | ---: | ---: |
| Predictive | 0,9766…1,0214 | 0,4704…1,3061 |
| Simple | 0,9750…1,0154 | 0,4670…1,3107 |

Это коэффициент когерентной передачи одной и той же тональной составляющей,
а не субъективная оценка громкости. Среднее комплексных коэффициентов точно
воспроизводит результат полного окна. Удаление dither не убило этот конкретный
±1 LSB тест при feedback, но сделало его передачу существенно менее стабильной.
Отличающийся по форме квантованный синус −80 dBFS также выявил нелинейность;
успех одного LSB/DC теста нельзя распространять на все слабые сигналы.

Спектральные пики и каждое временное окно: [spurs-and-windows.json](spurs-and-windows.json).
Пики шума с dither не объявляются устойчивыми паразитными тонами только
потому, что один FFT-бин оказался выше соседних. Сравнение гармоник делается
на периодических тональных входах.

## Итог и ограничения

1. **Feedback сохранять:** отключение его вместе с dither возвращает мёртвую
   зону даже для проверенного тона −40 dBFS.
2. **Без dither и с feedback** меньше шум и лучше SINAD обычных уровней,
   однако хуже гармоники и стабильность самых слабых сигналов. Это компромисс,
   а не безусловная замена прежнего режима.
3. Simple ведёт себя очень похоже на Predictive при включённом feedback.
4. Разумный следующий эксперимент — меньшая амплитуда dither. Это предложение,
   не внесённое изменение. Адаптивное отключение потребует отдельной проверки
   переходов и не исследовано здесь.
5. CPU, энергопотребление, слышимость дефектов и аналоговый выход не измерялись.
   Профиль платы и исходник производственного модулятора оставлены прежними.

## Воспроизведение

Нужны NumPy, MSVC/C++ и сохранённые PCM. Скрипты сверяют их хеши; радио не
скачивается заново. Из корня проекта:

```powershell
python tools/esp8266_audio_profile/measure_rcpdm_feedback_ab.py --method predictive --dither 0 --output radio_output/rcpdm-predictive-no-dither-20260906
python tools/esp8266_audio_profile/measure_rcpdm_feedback_ab.py --method simple --dither 0 --output radio_output/rcpdm-simple-no-dither-20260906
python tools/esp8266_audio_profile/inspect_rcpdm_no_dither.py --output radio_output/no-dither-spurs.json
node --test tests/esp8266-rcpdm-feedback-ab.test.js tests/esp8266-rcpdm-no-dither-report.test.js
python -m unittest discover -s tests -p '*pdm*quality_model_test.py' -v
```

По 141 312 кадров самопроверки для каждого правила, дополнительно проверки
производственного PCM→DMA, 1 654 296 сравнений общего Feedback-алгоритма,
проверки отчётов и **12 тестов численной модели** прошли. Выходные слова
32-битных путей (Predictive + feedback и оба Simple) проверяются независимым
64-битным эталоном; Predictive без feedback формируется буквальной 64-битной моделью.
Логи: [A/B](ab-tests.log), [регрессии](regressions.log), [модель](model-tests.log).
JSON содержит хеши исходников/PCM/битов; аудиоматериал в Git не добавлен.
