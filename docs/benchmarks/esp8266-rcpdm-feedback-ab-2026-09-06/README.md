# RC-PDM32: обратная связь включена / выключена

2026-09-06. **С накоплением ошибки качество существенно лучше при тех же
интерполяции и dither.** Это симуляция, не замер аналогового выхода или CPU.
Прошивка и настройки платы не изменялись.

Продолжение: [Simple с feedback и без него, сводная таблица четырёх вариантов](../esp8266-rcpdm-simple-feedback-ab-2026-09-06/README.md).

## Условия

- PCM 48 кГц, 32 новых бита на сэмпл, несущая 1,536 МГц, RC alpha=1/16.
- Оба пути: fixed-point шкала `2^29`, одна линейная интерполяция, один и тот же
  xorshift32 seed/битовая последовательность, TPDF dither ±полшага решения.
- On: настоящая функция `rc_pdm_feedback_sample`, на каждом сэмпле сравненная
  с независимой 64-битной моделью. Off: та же буквальная модель, но вклад
  накопителя в решение равен нулю и сам накопитель не обновляется.
- Единственная разница: накопление ошибки. Это **не** старый RC-PDM без
  интерполяции/dither. Смысл `high`: цель + feedback + dither > середина
  прогнозируемых напряжений после нуля и единицы.
- Общая сетка анализа 6,144 МГц: каждый выходной бит удерживается 4 отсчёта,
  без дополнительных решений. Фильтры RC 10 мкс, RC 40 мкс и двухзвенная
  ненагруженная RC-лестница; полоса 20 Гц…20 кГц. Таблицы ниже — RC 10 мкс.
- Те же пять сохранённых радиозаписей и четыре тона; дополнительно −60/−80 dBFS
  и цифровая тишина. Окна Hann 1 с, края минимум по 250 мс исключены.

## SINAD — выше лучше

| Тестовый тон | Feedback on, дБ | Feedback off, дБ |
| --- | ---: | ---: |
| 1 кГц, −3 dBFS | 55,95 | 36,31 |
| 1 кГц, −20 dBFS | 43,87 | 20,03 |
| 1 кГц, −40 dBFS | 23,86 | 0,02 |
| 1 кГц, −60 dBFS | 3,89 | −20,19 |
| 1 кГц, −80 dBFS | −16,28 | −36,17 |
| 7 кГц, −3 dBFS | 54,92 | 35,72 |

Уровень выходного шума при нулевом PCM: **−66,94 dBFS on / −43,08 dBFS off**
в указанной полосе. Разница 23,86 дБ. При слабом входе фиксированный шум
dither доминирует над сигналом; отрицательный SINAD не означает исчезновения
сигнала. Не следует интерпретировать оценку усиления очень слабого тона
по короткому FFT как точную характеристику передачи.

## Радиофрагменты

SNR относительно исходного PCM после одинаковой фиксированной компенсации
задержки интерполяции `31/(2*1536000)` = 10,091 мкс. Задержка/усиление по
записи **не подгоняются**. Сырые SNR без компенсации также сохранены в JSON.

| Запись | Feedback on, дБ | Feedback off, дБ |
| --- | ---: | ---: |
| Маяк | 35,21 | 17,59 |
| Record | 34,34 | 30,54 |
| Ретро | 35,28 | 27,05 |
| Symphony | 36,04 | 12,27 |
| Вести | 36,93 | 16,08 |

В данном наборе feedback лучше во всех пяти случаях. Особенно заметна
разница в более тихих фрагментах; громкий Record меньше страдает от шума off.

## Самый слабый сигнал: ±1 PCM LSB

Когерентное окно 8 с, три seed: 1, 8266, 2654435769. Измеряются обе полярности
периодического сигнала и DC ±1, плюс контроль с нулевым входом.

| Показатель | On | Off |
| --- | ---: | ---: |
| Амплитуда передачи тона, относительно эталона | 1,00014 | 0,94434 |
| Паразитная составляющая 1 кГц при нуле / тестовый тон | 0,00266 | 0,23875 |
| DC при входе +1 LSB, после вычитания нулевого контроля | +1,00089 | +0,92089 |
| DC при входе −1 LSB, после вычитания нулевого контроля | −1,00089 | −0,89600 |

Младший разряд **не исчез полностью без feedback**: dither позволяет ему
влиять на последовательность. Но шум сильнее, поэтому off-оценки имеют
большую статистическую неопределённость; это не доказательство постоянного
коэффициента усиления 0,944 для любого сигнала/seed.

## Воспроизведение и проверка

```powershell
node --test tests/esp8266-rcpdm-feedback-ab.test.js
python tools/esp8266_audio_profile/measure_rcpdm_feedback_ab.py --output radio_output/rcpdm-feedback-ab-20260906
```

Нужны NumPy, MSVC/C++ и ранее сохранённые PCM. Их SHA-256, хеши выходных
битовых потоков, исходников, все метрики/фильтры и покадровые проверки:
[results.json](results.json). Радиоматериал в Git не добавлялся.

On воспроизвёл старые выходные биты для всех девяти контрольных записей,
их метрики с допуском 1e−8 и все 15 контрольных потоков теста LSB.
Самопроверка: 141 312 кадров, 135 068 разных слов on/off, одинаковые PRNG
и интерполяция. Off не зависит от содержимого отключённого накопителя.
Результаты относятся к версии инструментов с хешами из JSON.
