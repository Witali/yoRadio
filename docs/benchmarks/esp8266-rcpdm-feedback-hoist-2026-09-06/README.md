# RC-PDM Feedback: подготовка вне битового цикла

2026-09-06. Побитно эквивалентная оптимизация экспериментального Feedback,
без изменения обычного PDM32 и профиля платы по умолчанию.
**Новая версия собрана, но не прошивалась: нового замера скорости на ESP8266 нет.**
Прежние 748,28 мс/48000 PCM относятся к [предыдущему коду](../esp8266-rcpdm-feedback-board-2026-09-06/README.md).

## Что перенесено и что осталось

- При подготовке профиля вычисляются `step`, масштаб и смещение dither,
  сдвиг uniform dither, постоянная часть порога и число битов в слове.
  В аппаратном профиле `32/4/0/2/1` это **константы времени компиляции**:
  отдельные поля в RAM и дополнительная динамическая инициализация не нужны.
  Универсальная функция для тестовых параметров готовит их перед битовым циклом.
- Целевой PCM и шаг интерполяции вычисляются один раз **на сэмпл**, как и раньше.
  Их нельзя вычислить один раз при запуске: они зависят от новых PCM.
- Упаковка организована по словам. Внутренний цикл выдаёт одно слово, после
  него выполняется запись. Проверок `%32`, последнего бита и индекса выходного
  слова внутри битового цикла больше нет. Сохранены варианты 8/16/32/64/128 бит.
- Постоянное смещение шума перенесено на сторону порога:
  `adjusted + (raw_noise - bias) > down + half_step` эквивалентно
  `adjusted + raw_noise > down + (half_step + bias)`.
  Например, для TPDF32 `bias=65535*256`, `decision_offset=33554176`.
  Убрано вычитание bias на каждом бите, две константы сведены в одну.
- Сумма `desired + error` используется и для решения, и для обновления ошибки
  при единичной обратной связи. Выбор высокого бита одновременно меняет RC
  и выходное слово. Для сдвига обратной связи 0 предусмотрен явный identity-путь:
  после перестройки выражений GCC 8.4 сохранял лишнее ветвление по знаку;
  явный случай нулевого сдвига предотвращает эту регрессию.
- Генерация нового dither, RC-спад, накопление/ограничение ошибки и выбор бита
  остаются в цикле: они зависят от предыдущего состояния. Число вызовов PRNG,
  порядок битов, округление, интерполяция и формула обратной связи не изменены.

После переноса bias величина `adjusted + raw_noise` по-прежнему помещается
в `int32_t`: максимум меньше `2^30 + 2^29 + 2^28 < 2^31`, включая
`shift=2`, dither полного шага и положительный предел ошибки. Отрицательные
границы и промежуточная сумма `error + desired - rc` также безопасны.

## Что показывает GCC

Сравнение одного и того же C-wrapper, Xtensa LX106 GCC 8.4.0, `-O3`:

| Изолированная функция | Код до → после, байт | Стек до → после, байт |
| --- | ---: | ---: |
| Один PCM-сэмпл | 220 → 173 | 48 → 32 |
| Заполнение блока | 285 → 239 | 64 → 32 |

Это размеры функций, **не размер приложения или всего стека задачи**.
Состояние модулятора осталось 16 байт; два DMA-буфера — по 512 слов.
В обоих вариантах нет внешних арифметических helper-вызовов. В новом
ассемблере убраны проверки границ слова, отдельное смещение шума и ветвление
по знаку ошибки, возникшее в промежуточном кандидате при unity feedback.
Часть загрузок литералов и загрузка
шага интерполяции со стека внутри цикла **остались**. Перенос в C-коде не
гарантирует, что компилятор удержит все константы в регистрах.

Уменьшение кода/стека не следует пересчитывать в процент ускорения.
Следующий необходимый этап — сопоставимый A/B-замер на плате с восстановлением
текущей прошивки. До него прежние численные результаты производительности
не заменяются оценкой по числу инструкций.

Данные: [comparison.json](comparison.json), [до](before.asm.txt), [после](after.asm.txt).
Базовый коммит `8047b476f47f081590c46806f2284cc57a67cf11`; хеши исходников и
версия компилятора включены в JSON. Команда воспроизведения из корня:

```powershell
node tools/esp8266_audio_profile/compare_rcpdm_feedback_codegen.js .build/rcpdm-feedback-codegen
```

## Проверки

- 1 654 296 сравнений выходных слов и всех полей состояния с неизменённым
  независимым 64-битным эталоном, включая полный диапазон PCM и пределы ошибки.
- Все пять размеров кадра × все RC shift 2…6 × gain 0…6 × dither 0…3 ×
  интерполяция вкл/выкл. Контрольные слова вокруг выхода проверяют границы записи.
- Дополнительно 116 795 вызовов аппаратной обёртки с постоянными параметрами.
- Mono/stereo блоки сравнены с эталоном; 16 сценариев разбиения на блоки,
  пустой блок и восстановление после длительного полного размаха.
- Производственный PCM→DMA: пять модуляторов, шесть частот входа,
  mono/stereo, нормализация вкл/выкл, разные границы блоков, EOF, отмена и stop.
- Полный выбранный набор: **21 Node-тест + 9 Python-тестов модели — PASS**.
  Это настольные проверки, не аппаратные измерения аналогового выхода.

[Лог тестов](tests.log), [лог модели](model-tests.log).
