# RCPDM-Simple: сравнение текущего аккумулятора с PCM

После этого настольного опыта выполнен отдельный
[физический тест Simple32](../esp8266-rcpdm-simple-board-2026-09-06/README.md).
Ниже сохранены именно условия и результаты сравнения качества на ПК.

## Что добавлено

Отдельный **настольный эксперимент RCPDM-Simple**, с 8 или 32 импульсами на
PCM-сэмпл. Вместо выбора лучшего прогнозируемого RC-напряжения выходной бит
зависит только от текущего состояния. Рабочие исходники модулятора, профиль
по умолчанию и прошивка платы не изменены. Подключение этого варианта к
драйверу I2S/DMA и измерение скорости на ESP8266 здесь не выполнялись.

Код: [rcpdm_simple.h](../../../tests/native/rcpdm_simple.h).
Состояние — прежние 4 байта `uint32_t`, с 16 дробными разрядами относительно
16-битного PCM. Новых буферов, выделений памяти или 64-битной арифметики в
самом модуляторе нет. 64-битный контроль используется только в тестах.

## Правило одного выходного бита

```c
target = ((uint32_t)((int32_t)pcm + 32768)) << 16;
high = target > state;                  // сравнение ДО изменения state
if (high)
    state += (UINT32_MAX - state) >> shift;
else
    state -= state >> shift;
```

При равенстве выдаётся **0**. Нет расчёта двух следующих состояний и
сравнения расстояний до них, midpoint-порога, dithering или интегратора
ошибки PCM. После выбранного бита обновляется RC-модель; состояние сохраняется
между битами, сэмплами и блоками. Порядок передачи — старший бит первым.

В реализации использована точная эквивалентная форма обновления:

```c
high = target > state;
state -= state >> shift;
if (high) state += UINT32_MAX >> shift;
```

Она использует один сдвиг, поскольку для верхней границы `UINT32_MAX`
разность между RC-кандидатами постоянна. Важно: сначала сравнивается **старое**
состояние, иначе получится другой алгоритм. Переполнения нет. Например,
при нулевом PCM после инициализации Simple выдаёт `0x55555555`, исходный
predictive RCPDM — `0xaaaaaaaa`.

Исходный рабочий predictive RCPDM уже оптимизирован и не перебирает
кандидатов буквально: его цикл также содержит один сдвиг, сравнение и
условное сложение. Поэтому из упрощённого правила нельзя автоматически
вывести существенное ускорение CPU; это требует отдельного замера на плате.

## Настольная проверка качества

Те же пять сохранённых радиофрагментов и четыре синуса, что в
[предыдущем сравнении](../esp8266-rcpdm8-quality-2026-09-06/README.md).
Всего 3 455 601 отсчёт моно PCM 48 кГц. MP3/AAC ранее декодированы FFmpeg;
этот опыт начинается с готового PCM. Входы сверены по SHA-256, сетевого
чтения нет. Все пять исходных вариантов воспроизвели прежние битовые файлы
побитно для каждого входа; изменились только три добавленных Simple-варианта.

Восемь вариантов: обычный PDM8/PDM32, predictive/Simple RCPDM8 с alpha=1/16,
predictive/Simple RCPDM8 с alpha=1/4 и predictive/Simple RCPDM32 с alpha=1/16.
Для восьми импульсов несущая 384 кГц, для 32 — 1,536 МГц; PCM остаётся 16-битным.

Единая сетка, аналоговый zero-order hold, полоса 20 Гц–20 кГц, односекундные
Hann-окна; исключены края фрагментов. Проверены один RC=10 мкс, один RC=40 мкс
и нагруженная пассивная лестница 1к/10н + 1к/10н. Никакого подбора задержки
или усиления отдельно под вариант. Это численная модель, не физический замер.

SINAD, дБ, для одного RC=10 мкс; выше лучше:

| Вариант | 1 кГц, −3 dBFS | 1 кГц, −20 dBFS | 7 кГц, −3 dBFS |
| --- | ---: | ---: | ---: |
| Обычный PDM8 | 29,75 | 9,70 | 29,61 |
| RCPDM8 alpha=1/16 | 29,69 | 11,27 | 20,38 |
| **RCPDM8-Simple alpha=1/16** | **31,22** | **9,89** | **24,34** |
| RCPDM8 alpha=1/4 | 25,60 | Тон пропал | 23,47 |
| RCPDM8-Simple alpha=1/4 | 24,95 | Тон пропал | 24,90 |
| Обычный PDM32 | 44,25 | 26,64 | 43,88 |
| RCPDM32 alpha=1/16 | 44,61 | 20,61 | 35,31 |
| **RCPDM32-Simple alpha=1/16** | **46,16** | **18,17** | **35,68** |

SINAD исключает амплитуду/фазу основного тона из искажений. У Simple также
изменяется усиление: на 1 кГц, −3 dBFS, alpha=1/16 оно составляет −0,30 дБ
для восьми импульсов и −0,53 дБ для 32, против +0,26/+0,02 дБ у predictive.
Полные значения усиления, THD и обеих мер SNR сохранены в JSON.

На радиофрагментах SNR относительно исходного PCM (включая RC-ответ), дБ:

| Фрагмент | RCPDM8 | Simple8 | RCPDM32 | Simple32 |
| --- | ---: | ---: | ---: | ---: |
| Маяк | 4,65 | 4,85 | 13,64 | 12,18 |
| Record | 9,82 | 10,28 | 30,94 | 23,34 |
| Ретро FM | 8,15 | 8,75 | 28,31 | 22,32 |
| Симфония | 3,86 | 3,68 | 9,13 | 8,25 |
| Вести FM | 5,16 | 5,16 | 12,48 | 11,19 |

Здесь alpha=1/16. Simple32 хуже по этой мере на всех пяти фрагментах; Simple8
имеет смешанные результаты. Для сравнения с идеальным DAC через тот же RC
сохранена отдельная мера SNR: она штрафует компенсацию RC, поэтому не должна
использоваться как единственная оценка всех алгоритмов.

## Тихие сигналы и вывод

Синус −40 dBFS по-прежнему исчезает во всех RC-вариантах, в том числе Simple:
весь файл состоит только из постоянного чередования уровней. При alpha=1/4
это происходит уже на −20 dBFS. Для отсутствующего тона SINAD не выдаётся.

Прямой компаратор не устраняет зону нечувствительности. В установившемся
режиме `1010…` её граница по нормированной пиковой амплитуде примерно
`alpha/(2-alpha)`: −29,83 dBFS для alpha=1/16 и −16,90 dBFS для alpha=1/4.
Это даже шире, чем у predictive (`alpha*(1-alpha)/(2-alpha)`). Формула — для
установившегося режима и идеальной RC-арифметики, не универсальный порог
для любого переходного процесса или сложного звука.

**Сохранить Simple как отдельный эксперимент, не заменять им автоматически
рабочий модулятор.** Он даёт лучшие SINAD на некоторых громких синусах, но
хуже на тихом синусе −20 dBFS и не решает потерю слабых сигналов. Это иной
алгоритм, его выход не должен совпадать с predictive побитно.

## Тесты и воспроизведение

```powershell
node --test tests/esp8266-rcpdm-simple.test.js tests/esp8266-rcpdm-precision.test.js tests/esp8266-rcpdm8-quality.test.js tests/esp8266-rcpdm.test.js
python tests/rcpdm8_quality_model_test.py
python tools/esp8266_audio_profile/measure_rcpdm_simple.py --archive docs/benchmarks/esp8266-rcpdm-simple-2026-09-06
```

Нужны C++17-компилятор, Node и Python с NumPy. Полный замер требует локальных
PCM прошлого опыта; native-тесты не требуют эфирных записей. Проверены
1 972 864 пары «слово + состояние» относительно независимой прямой формулы,
20 000 проверок непрерывности (четыре группы по 8 == одна по 32) и пять
случаев точного равенства target/state. Шесть native- и три model-теста прошли.

[Результаты и хеши](results.json), [native-тесты](native-tests.log),
[тесты модели](model-tests.log). Локально сохранены 72 битовых файла и 72
двухсекундных WAV в `radio_output/rcpdm-simple/`; прослушивание использует
одинаковое усиление 0,7, без индивидуальной нормализации, клиппинга нет.
Эфирный PCM и WAV в Git не включены. Прошивка/частоты платы не менялись.
