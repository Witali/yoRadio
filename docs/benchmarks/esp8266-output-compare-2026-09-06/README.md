# ESP8266: сравнение I2S PDM32 и I2S RCPDM32

Физическая Wemos D1 mini, COM8, 2026-09-06. Измерения показывают:
**текущий обычный PDM32 быстрее RCPDM32**. Скорость самой передачи I2S
одинакова; отличается время программного формирования данных.

## Условия

- CPU 160 MHz, QIO 40 MHz, Xtensa GCC 8.4.0, `-O3`.
- Общий драйвер I2S/SLC DMA, GPIO3, два буфера по 512 слов (4096 байт).
- 32 бита на слово, номинальная несущая 1,536 MHz; делители 8×13 дают
  1,5384615 MHz и 48076,9 слов/с. Расчётная передача 512 слов: **10,6496 мс**.
- Wi-Fi, WebUI и декодеры не запускаются. Воспроизводимый PCM генерируется
  один раз в RAM, файл и сеть во время измерения не читаются.
- Два независимых запуска каждого бинарника в порядке PDM → RCPDM → PDM → RCPDM.
- Настройки громкости/нормализации меняются только в RAM, без записи в NVS.

Микротест перед инициализацией DMA вызывает **настоящий production-пакер**:
первые 128 знаковых значений детерминированного LCG-шаблона, 375 повторов,
итого 48000 слов; три замера после каждого старта. Состояние модулятора
сбрасывается перед каждым замером. Время включает общий цикл и XOR-контрольную
сумму, а также обычные системные прерывания. Это не цикл с запрещёнными IRQ.

В полном тесте исходный PCM — стерео 48 kHz, 128 кадров/512 байт на вызов,
сведение в моно и громкость 64, баланс 0, нормализация выключена. После
прогрева 2 с измеряются 10 с вывода. Вход пакера здесь уже уменьшен по
громкости и сведён в моно: это не идентичные значения микротеста.

## Результаты

| Измерение | I2S PDM32 | I2S RCPDM32 |
| --- | ---: | ---: |
| Формирование 48000 слов, медиана 6 измерений | 56,337 мс | 119,216 мс |
| Диапазон этих измерений | 56,337–56,354 мс | 119,216–119,227 мс |
| Время формирования одного слова | 1,174 мкс | 2,484 мкс |
| Полный путь вывода без DMA-ожидания, на 1 с номинального аудио | 96,458 мс | 157,903 мс |
| То же на вызов с 128 исходными кадрами (округление лога) | 257 мкс | 421 мкс |
| Суммарное время `write`, один измерительный прогон | 9,977362 с | 9,982120 с |
| Из него блокирующее ожидание DMA | 9,009180 с | 8,397199 с |
| Вызовов `write` за прогон | 3764 | 3764 |
| DMA EOF за прогон | 941 | 941 |
| Underrun / partial start / blocked partial / FIFO empty | 0 / 0 / 0 / 0 | 0 / 0 / 0 / 0 |
| Free heap / minimum free heap, диагностическая прошивка | 108532 / 105752 Б | 108532 / 105752 Б |

Вторые физические прогоны дали те же итоговые счётчики и времена. Контрольные
суммы повторов стабильны: PDM `9bfa8dfa`, RCPDM `e3126451`. Различие между
алгоритмами ожидаемо: они формируют разные битовые последовательности.

RCPDM требует **в 2,116 раза больше времени** собственно на модуляцию, а
полный путь вывода без ожидания — **в 1,637 раза больше** (+63,7%). В этом
изолированном тесте оба успевают выдавать звук. Более медленный RCPDM просто
оставляет меньше времени до следующего освобождения DMA-буфера.

96/158 мс соответствуют примерно 9,65%/15,79% бюджета секунды звука, но
**не являются измерением полной загрузки CPU**. Это `write_us - dma_wait_us`:
громкость, сведение, ресэмплер, упаковка, reserve/commit и измерительная
обвязка, включая возможное вытеснение вне ожидания. Работа ISR во время
блокировки задачи сюда не попадает. Старую статистику FreeRTOS idle не
используем: её учёт при direct-ISR wakeup на ESP8266 ранее оказался ненадёжен.
Суммарные почти 10 с внутри `write` также нельзя называть занятостью CPU.

## Почему различается скорость

Алгоритмы в ходе сравнения не изменялись. Оба пакера находятся во flash.
Обычный PDM — развёрнутые 32 решения с аккумулятором, без ветвления по биту.
RCPDM — цикл из 32 шагов RC-модели с условной веткой. Дизассемблер текущих
ELF: PDM-пакер 456 байт, RCPDM-пакер 55 байт. RCPDM экономнее по коду,
но не по процессорному времени. Состояние каждого модулятора — 4 байта.

RAM-секции диагностических ELF равны: DRAM data=1012, bss=9320;
IRAM vectors=128, text=18020, bss=524 байта. Это **не** RAM всей обычной
радиопрошивки с декодером и Wi-Fi.

## Проверки и ограничения

- 15 относящихся к выводу host-тестов прошли. Среди них 493216 слов RCPDM,
  побитно совпавших с независимой RC-моделью.
- Все четыре принятых физических прогона: `invalid=0`, ошибок `write` нет,
  проверка остановившегося на 65 мс производителя — PASS.
- Первый предварительный PDM-прогон исключён: пять недостоверных временных
  интервалов. В этой версии SDK `esp_timer_get_time()` неатомарно складывает
  `g_esp_os_us` с CCOUNT, который SysTick сбрасывает. Только диагностическое
  чтение времени защищено короткой critical section; упаковка и ожидание
  выполняются с обычными прерываниями. SDK/рабочий аудиопуть не менялись.
- Тест не измеряет аналоговый SNR/THD и не доказывает качество RCPDM-фильтра.
  Нет нагрузки от MP3/AAC, Wi-Fi и WebUI: это сравнение вывода, не стресс-тест радио.
- Профиль по умолчанию оставлен **I2S PDM32**.

## Воспроизведение теста

Диагностический код и скрипты зафиксированы в `0171c60`. Бинарники собраны
до коммита и содержат прежний идентификатор `a3bc4cd-dirty`; SHA256 ниже и в
манифестах идентифицируют именно измеренные файлы. `sdkconfig-pdm` и
`sdkconfig-rcpdm` сохраняют фактическую конфигурацию; отличаются только выбором
модулятора и скрываемыми Kconfig-настройками PDM oversampling.

```powershell
# Для чистых .build/output-compare-{pdm,rcpdm}; существующий sdkconfig не перезаписывается.
./tools/esp8266_audio_profile/build_output_compare.ps1 `
  -BaseConfig docs/benchmarks/esp8266-output-compare-2026-09-06/sdkconfig-pdm
./tools/esp8266_audio_profile/run_output_compare.ps1 -Port COM8 -Repeats 2 `
  -RestoreImage firmware/development/esp8266-native-aac-speed/app.bin
node tools/esp8266_audio_profile/summarize_output_compare.js .build/output-compare-results/ab
node --test tests/esp8266-audio-output-benchmark.test.js tests/esp8266-rcpdm.test.js tests/esp8266-i2s-pdm-output.test.js
```

Скрипт прошивает только app0 по адресу `0x10000`, затем в `finally` возвращает
указанную обычную прошивку. NVS, SPIFFS, bootloader и разметку не переписывает;
UART-команды приложению не отправляет. На выходе во время теста слышен шум.
Сырые принятые UART-логи и машинная сводка `summary.json` лежат рядом.

| `esp8266-output-compare-rcpdm` | 127120 | `3DBFA0DD62F8B74F2B4E0511A9C7BCDEB2C29B90AE1A5B4DE16AB62FDC2B7E78` |

После тестов восстановлена обычная прошивка `esp8266-native-aac-speed/app.bin`,

обычной станции в этом сравнении отдельно не тестировались.
