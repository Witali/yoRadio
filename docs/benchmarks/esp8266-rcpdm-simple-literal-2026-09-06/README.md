# Буквальный RCPDM-Simple: скорость на ESP8266

## Результат

Wemos D1 mini / ESP8266EX, COM8, 2026-09-06. Проверен цикл из `7dfc1af`:
сравнение аккумулятора с целью и только выбранное обновление заряда/разряда.
Буквальный Simple **медленнее predictive RCPDM на 23,85% в пакере и на
26,70% в полном пути без ожидания DMA**. По сравнению с предыдущей записью
Simple (`next`, одна ветка) время пакера увеличилось на 9,82%.

| На секунду номинального PCM 48 kHz | Predictive RCPDM | Предыдущий Simple | Буквальный Simple |
| --- | ---: | ---: | ---: |
| Упаковка 48000 слов, медиана | 112,275 мс | 126,617 мс | 139,047 мс |
| Производитель без ожидания DMA | 122,843 мс | 130,634 мс | 155,637 мс |
| Доля бюджета секунды для этого производителя | 12,28% | 13,06% | 15,56% |
| Scalar-пакер / batch-пакер | 63 / 203 Б | 55 / 183 Б | 56 / 185 Б |

Predictive и буквальный Simple измерены заново в одном ABBA-опыте.
Предыдущий Simple — данные
[предшествующего теста](../esp8266-rcpdm-simple-one-branch-2026-09-06/README.md)
при тех же условиях. Первый вариант с `high` занимал 170,046 мс в пакере;
его не следует путать с предыдущей записью на 126,617 мс.

Шесть измерений буквального Simple: 139047–139048 мкс, predictive:
112275–112276 мкс. По два независимых старта каждого образа; в каждом
три замера. Контрольные суммы: Simple `8ebd3ff0`, predictive `e3126451`.

## Что именно проверено

```c
word <<= 1;
if (state < target) {
    state += (UINT32_MAX - state) >> shift;
    word |= 1U;
} else {
    state -= state >> shift;
}
```

Сохраняется читаемая запись `UINT32_MAX - state`. Для `uint32_t` это точно
`~state`; GCC уже выдаёт `xor` с `0xFFFFFFFF`, а не вычитание. Ручная замена
на инверсию не уберёт инструкцию из данного машинного кода.

В C рассчитывается только выбранная ветка. Однако Xtensa GCC 8.4.0 `-O3`
сам вынес оба сдвига перед сравнением: инверсия, сдвиг инвертированного
аккумулятора и сдвиг исходного. В пути единицы остался дополнительный `j`.
Predictive использует один сдвиг и не имеет этого внутреннего `j`.
Это объясняет дополнительные операции; точный вклад каждой инструкции
отдельно не измерялся. Ассемблер обоих пакеров сохранён рядом с отчётом.
Более короткий C-код не гарантирует меньшего времени выполнения.

Условия: CPU160, QIO40, alpha=1/16, **32 бита на сэмпл**, GPIO3/RX,
2×512 слов I2S/SLC DMA (4096 Б), тот же batch-путь без промежуточного PDM
буфера. Несущая номинально 1,536 MHz, фактически 1,538461 MHz. Wi-Fi,
MP3/AAC и нормализация выключены. PCM-шаблон детерминированный, из RAM.
Перед измерением пакера DMA выключен. Для полного пути: 128 стереокадров
на write, громкость 64 только в RAM, 2 с прогрева и 10 с измерения.
Вход пакера в полном пути ослаблен/сведён в моно и отличается от микротеста.

`write - DMA_wait` — wall-time оценка производителя, **не полная загрузка
CPU**: ISR во время ожидания сюда не входят. В изолированном тесте оба
варианта успевают. Это не подтверждение запаса всей радиопрошивки с сетью
и декодерами и не измерение аналогового качества звука.

## Корректность и память

- В каждом из четырёх стартов: 493216 сравнений слов/состояний и 2144
  batch-слова с независимым эталоном — PASS.
- DMA EOF 941 на прогон, underrun / FIFO empty / partial start / blocked
  partial — ноль. Проверка паузы производителя на 65 мс — PASS.
- Free / minimum free heap: 108532 / 105752 Б у обоих вариантов. Это куча
  диагностических образов без сети/кодеков, не обычного радио.
- Статическая DRAM 10332 Б, IRAM 18672 Б; состояние RC 4 Б. Увеличения RAM
  относительно остальных реализаций нет; batch-кадр стека остаётся 16 Б.
- Все [72 сохранённых потока битов](bit-exact-proof.json) пяти радиофрагментов и четырёх тонов
  совпадают с прежним Simple. Искажения от этой записи цикла не меняются.
- Повторный запуск [20 host-тестов](host-tests.log) пройден, включая полный
  путь PCM/PDM, размеры пакетов, EOF, stop и cancel.

## Восстановление платы

Перед тестом заново прочитаны все 4 MiB flash; копия совпала с предыдущей.
После четырёх прогонов восстановлен полный прежний app0, SHA-256
`d3365325c09b05a446ce280248c163fddba406b81d03ec2a5f3e295cdca94580`.
Esptool подтвердил хеш записи. Разделы NVS, SPIFFS, OTA-selection и bootloader
не перепрошивались. В логе подтверждены обычный native I2S-PDM32, station=1,
volume=254, индекс 511 станций и DHCP. GET `http://192.168.100.6/` вернул
HTTP 200, 3744 байта. Это проверка доступности, не полный тест WebUI.

## Артефакты и повторение

Образы `firmware/development/esp8266-rcpdm-speed/production-simple-literal/`
и `simple-simple-literal/` — **диагностика без Wi-Fi/WebUI/декодеров**.
Хеши и размеры указаны в manifest.json и [results.json](results.json).
Исходники модулятора после сборки не менялись; обычный профиль не переключён
на Simple. Результаты не являются основанием автоматически заменить цикл:
сохранена буквальная запись, выбранная пользователем.

```powershell
tools/esp8266_audio_profile/build_rcpdm_speed.ps1 -Variants production,simple -ArtifactSuffix simple-literal
# Перед опытом сохранить актуальные 4 MiB flash в новый приватный файл.
node tools/esp8266_audio_profile/run_rcpdm_simple_board.js <backup.bin> <new-runs-directory> COM8 simple-literal
node tools/esp8266_audio_profile/archive_rcpdm_simple_board.js <new-runs-directory> <new-report-directory>
node tools/esp8266_audio_profile/verify_rcpdm_simple_rewrite.js .build/rcpdm-simple-literal-proof
```

Runner проверяет разметку, OTA CRC, активный app0 и хеши образов. Пишется
только app0 по `0x10000`; восстановление полного app0 выполняется в `finally`.
UART приложения используется только для чтения, GPIO3 занят аудиовыходом.
Приватная flash-копия и полный restore-log с настройками Wi-Fi в Git не входят.
