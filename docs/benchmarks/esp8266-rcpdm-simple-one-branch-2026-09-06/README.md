# RCPDM-Simple: один выбор бита, повторный тест на ESP8266

## Итог

По уточнению пользователя Simple записан в том же стиле, что обычный RCPDM:
тот же fixed32 RC-аккумулятор, разряд/заряд и упаковка слова, но без
предиктивного порога. Удалён также промежуточный `high`, из-за которого GCC
создавал два условных перехода на бит. Теперь выбор бита имеет один `if`.

На Wemos D1 mini новая запись **сократила время упаковки на 25,54%** относительно
первого Simple. Время всего производителя без ожидания DMA сократилось на
28,37%. RAM не увеличилась. Но обычный predictive RCPDM всё ещё быстрее:
новый Simple требует на 12,77% больше времени пакера и на 6,34% больше
времени производителя. Профиль радио по умолчанию не менялся.

## Изменение

```c
uint32_t next = state - (state >> shift);
word <<= 1;
if (state < target) {
    next += step;
    word |= 1U;
}
state = next;
```

Сравнивается **исходное** состояние, до принятия `next`; равенство выбирает
ноль. Simple сохраняет ранее выбранное прямое сравнение PCM с аккумулятором.
Эта правка не меняет его биты, в отличие от самого перехода с predictive
RCPDM на Simple: у predictive и Simple разные правила выбора бита.

Изменение исходников: `67f3ec2`. Бинарники собраны из этого рабочего изменения
поверх `c950d19`, что отражено в manifest.json через `compiled_working_tree`.

## Измерения на плате

2026-09-06, COM8, ESP8266EX, CPU160/QIO40, Xtensa GCC 8.4.0, `-O3`.
Simple32: 48 kHz, alpha=1/16, GPIO3, прежние 2×512 слов I2S/SLC DMA.
Wi-Fi, декодеры и нормализация в диагностических образах выключены.
Порядок ABBA: predictive → Simple → Simple → predictive, по три измерения
упаковки в каждом запуске. Условия совпадают с
[первым физическим тестом](../esp8266-rcpdm-simple-board-2026-09-06/README.md).

| Показатель | Predictive RCPDM | Первый Simple | Новый Simple |
| --- | ---: | ---: | ---: |
| Упаковка 48000 слов, медиана | 112,275 мс | 170,046 мс | 126,617 мс |
| Производитель без DMA-ожидания, на секунду аудио | 122,843 мс | 182,385 мс | 130,634 мс |
| Размер scalar-пакера | 63 Б | 65 Б | 55 Б |
| Размер batch-пакера | 203 Б | 205 Б | 183 Б |
| Free / minimum heap в тесте | 108532 / 105752 Б | 108532 / 105752 Б | 108532 / 105752 Б |

Диапазон шести новых замеров Simple: 126616–126620 мкс; predictive:
112275–112276 мкс. Контрольные суммы стабильны: `8ebd3ff0` и `e3126451`.
Статическая DRAM у обоих 10332 Б, IRAM 18672 Б; RC-состояние 4 Б,
DMA 4096 Б. Batch использует стековый кадр 16 Б; scalar — leaf без него.

Во всех четырёх запусках: 493216 проверок слов/состояний, 2144 batch-слова,
941 DMA EOF; underrun, FIFO empty, partial start и blocked partial — ноль.
Проверка остановленного на 65 мс производителя — PASS.

Дизассемблер подтверждает один условный переход выбора бита; отдельный
переход цикла остаётся. Simple всё ещё требует сохранения старого состояния
для сравнения и содержит дополнительный безусловный переход/перемещение.
Меньшее число байт кода само по себе не гарантирует ускорения относительно
predictive. Измерения выше — фактические, не оценка по числу C-операций.

`write - DMA_wait` — wall-time оценка работы производителя, **не полная
загрузка CPU**: ISR во время ожидания не учитываются. Свободная куча относится
к изолированному тесту, не к работающему радио. Аналоговый выход не измерялся;
одновременная работа MP3/AAC, сети и WebUI этим тестом не проверяется.

## Корректность и восстановление

- [72 сохранённых потока битов](bit-exact-proof.json) для пяти радиофрагментов
  и четырёх тонов совпали с результатами до правки, включая все 27 Simple.
  Дополнительно 1972864 word/state, 20000 continuity, 5 tie и 2144 batch
  проверок. Качество и искажения от этой записи цикла не изменились.
- [20 host-тестов](host-tests.log) пройдены: реальный путь PCM/PDM, шесть
  частот, моно/стерео, нормализация, границы пакетов, EOF, stop и cancel.
- После ABBA восстановлен точный прежний app0, SHA-256
  `d3365325c09b05a446ce280248c163fddba406b81d03ec2a5f3e295cdca94580`;
  esptool подтвердил запись. NVS, SPIFFS, bootloader и OTA-selection не менялись.
- Подтверждены обычный native I2S-PDM32, station=1, volume=254, 511 станций,
  DHCP; GET `http://192.168.100.6/` вернул HTTP 200, 3744 байта.
  Это проверка доступности, не полное тестирование WebUI.

Бинарники и их хеши: `firmware/development/esp8266-rcpdm-speed/production-simple-one-branch/`
и `simple-simple-one-branch/`. **Оба диагностические, без Wi-Fi/декодеров.**
[Результаты](results.json), UART-логи и ассемблер сохранены рядом с документом.
Приватная flash-копия с настройками Wi-Fi в Git не включена.

```powershell
node tools/esp8266_audio_profile/verify_rcpdm_simple_rewrite.js
tools/esp8266_audio_profile/build_rcpdm_speed.ps1 -Variants production,simple -ArtifactSuffix simple-one-branch
# Перед новым опытом: актуальная приватная копия flash, свободный каталог runs.
node tools/esp8266_audio_profile/run_rcpdm_simple_board.js <backup.bin> <new-runs-directory> COM8 simple-one-branch
node tools/esp8266_audio_profile/archive_rcpdm_simple_board.js <new-runs-directory> <new-report-directory>
```

UART приложения используется только для чтения: GPIO3 занят аудиовыходом.
Данные отправляются только ROM-загрузчику при прошивке. Runner восстанавливает
app0 в `finally` и отказывается прошивать его при активном app1.
